OWNS
====
The wiring that turns "player stepped on the exit portal" into "route map opens, player picks a
node, the NEXT floor is generated according to that node." This is the connective tissue between
the pure route data (order-1/2) and the actual game. It touches World.java, GameState/RunPhase,
and the transition flow — and it REPLACES the current hard-coded generator selection with a
node-driven one. No overlay pixels here (order-4); this part can be validated by logging the
chosen node + generator to the console/run-stats.

THE NODE -> FLOOR PIPELINE (the core of this part)
==================================================
Given `pendingNode` and the incremented `currentDepth`:
  step 1  Resolve NodeTypeDefinition from NodeTypeRegistry.get(pendingNode.type).
  step 2  Resolve its NodeLevelProfile by levelProfileId (order-7 defines profiles; order-3 must
          define the INTERFACE and a trivial default so combat works before order-7 lands).
          NodeLevelProfile.resolve(node, depth, seed) returns a LevelPlan:
             { GeneratorId generatorId, LevelGenConfig config, List<GuaranteedContent> guarantees }
          - COMBAT/ELITE: generatorId = node.chosenGeneratorId (pre-rolled order-2); config =
            a depth-scaled default LevelGenConfig, ELITE bumps hazard/large-room weights + sets an
            affix flag.
          - CACHE/REST/SHOP/MYSTERY/EVENT/BOSS: generatorId + config come from their profile.
  step 3  ILevelGenerator generator = GeneratorRegistry.create(plan.generatorId,
             floorSeed(runSeed, depth), plan.config).
  step 4  Level level = generator.generate(depth).
  step 5  Apply GuaranteedContent to the generated Level (guaranteed pickups, shop flag, heal
          station, etc. — see order-7). Guarantees are applied POST-generation so any generator
          can host any node's guarantees (a cache can be a cavern OR a room map and still get its
          crates). This keeps generators and node contents orthogonal — the extensibility win.
  step 6  rebuildForLevel(level) exactly as today (this already re-seeds enemies via EnemyManager,
          rolls shop stock via seedVendingMachines, places credit chips, etc.). The node's config
          drives those existing systems (e.g. SHOP profile sets the vending-machine-guaranteed
          flag; REST profile suppresses enemy spawn budget).

CRITICAL INVARIANT: difficulty scaling (roguelike_order_16) still reads RAW currentDepth. A node
only changes the KIND/flavour of the floor and its rewards — it NEVER pauses the depth ramp.
Choosing "safe" nodes costs loot/tempo, never the clock. Enforce by NOT letting any NodeLevelProfile
override the depth passed to generate() or to the enemy scaler.


WHERE THE ROUTEMAP IS CREATED / OWNED
=====================================
- World owns a `RouteMap routeMap` field.
- Generate it once, right when the real run begins: in the FADING_OUT completion branch where
  `isStartingRoom` flips false (World.java ~line 1007) — i.e. when leaving the staging room and
  the first dungeon floor is about to build. Call
     routeMap = RouteMapGenerator.generate(runSeed, RegionPlan.defaultPlan());
  and set its CURRENT node to depth 1. (Generating at staging-room exit, not at World ctor, means
  the map lines up with the existing "floor 1 is first dungeon floor" convention.)
- Persist nothing across runs (permadeath); the map dies with the run. Its seed is already in
  runStats for reproducibility/seed-share (roguelike_order_17).
- RouteRegistries.bootstrap() (order-1) must run before the first generate — call it once in the
  World construction path (guard against double-registration for the death->new-run rebuild).


RUN STATS / TELEMETRY
=====================

  "C-C-!-$-R-BOSS-...") — a compact, shareable summary of the run (roguelike_order_17 synergy) and
  exactly the "readable story of the incursion" the vision promises.
