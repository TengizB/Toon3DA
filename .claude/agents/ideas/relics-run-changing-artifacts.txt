OVERVIEW
--------
A RELIC is a rare, named artifact that changes one rule for the rest of the
run: kills heal you, doors you open explode, the first hit on each floor does
nothing, enemies arrive weaker. There are 36 of them in four tiers (COMMON,
RARE, LEGENDARY, CURSED). A run collects about five: one chosen at the start of
the run, one after each of the first four bosses, and the odd one from a
MYSTERY sector or a quarantine-locker EVENT. Each one is offered as a
"choose one of N" card screen, so two runs never play the same way.

What the owner said: "rare items that change the rules for the rest of the run
... a lot of different relics ... integrate it with the game balance."
What the owner wants: runs that feel different from the first floor on,
without a new power source that quietly breaks the balance contract. The
second half of that is the reason for the size of this file. Every relic is
priced in the balance contract's own terms: a carry lift measured on the eight
reference scenarios by the existing build valuation. Each rarity has a band.
The relics a run is expected to hold are capped against what one committed
perk build is worth. The simulator checks that no relic is a trap and none is
mandatory.

Rarity alone is not enough to make runs feel different: today most runs end
before the first boss (TACTICAL median death depth is 3, and the first boss is
at depth 5). So every run also opens with a choice of three COMMON relics.
That is the decision that makes run one differ from run two.


SCOPE
-----
IN
  - A new headless package ge.tbegvadze.toon3d.relic: the relic catalog (36
    register() rows), the run's held relics, the offer roller, and the trigger
    runtime.
  - Relics fold into the EXISTING build seam: their effects are PerkEffect
    rows (PerkModifier kind + magnitude). PlayerBuild applies them into the same
    BuildStats aggregate that every damage, heal, kill and shop seam already
    reads. Seventeen new PerkModifier kinds cover the rules perks never had.
  - Runtime seams for the new kinds: Player (damage taken, first-hit shield),
    EnemyManager (kill heal, armour, credits, XP, ammo refund, corpse burst,
    spawn health, low-health damage), ExplosiveBarrelManager (the relic blast),
    DoorManager (a player-opened-door listener), floor arrival (heal, armour,
    ammo). Every seam is shared by World and SimWorld.
  - Four acquisition sources: RUN_START (3 COMMON), BOSS (3 cards, bosses 1-4),
    MYSTERY outcome RELIC_CACHE (2 cards, COMMON/RARE), EVENT "QUARANTINE
    LOCKER" (2 CURSED cards, or sell the seal for credits).
  - A new RunPhase.RELIC_OFFER with a touch card overlay, a RELICS section on
    the inventory's BUILD page, a RELICS line on the run report, one new sound
    row, and event-text feedback for discrete triggers.
  - BALANCE: BalanceConfig SECTION 26 RELICS. Four new schema rule kinds
    (R-RELIC, R-RELIC-CURSE, R-RELIC-STACK, R-RELIC-SOURCE) with
    BalanceAuditTest coverage. RelicValuationModel. Route pricing of relic
    offers. BalanceReport RELICS and RELIC STACK tables. The simulator gets
    relic choice, five probe rows and an S-RELIC band, with BalanceSimTest
    coverage, plus SimReport RELIC REPORT, RoundSummary and LadderReport
    lines.
  - Docs: new docs/relic-system.txt; game-balance-authority.txt;
    game-balance-knowledge.txt; route-map-system.txt; sound-system.txt;
    xp-level-progression.txt; .claude/CLAUDE.md.

OUT (deliberately not doing now)
  - Any new tile symbol, pedestal prop or ground item for relics. Relics are
    never on the floor. They are offered on a card screen.
  - Relics in the shop. The shop economy (R-CREDITS v2, S-SHOP) is
    deliberately left alone.
  - Relics from ELITE floors. That would change the ELITE node's priced EV
    and R-RISK-PREMIUM band mid-feel-pass.
  - Dropping, swapping, selling or removing a held relic, cursed or not. A
    relic is for the run. There is no slot cap to manage; there is a safety
    cap of 8.
  - Any persistence: no "discovered relics" list, no codex shelf, no new
    StatsStore or StoryStore key, no schema bump. A follow-up idea can add a
    discovery log.
  - ORA lines, barks, a TeachingTopic, or codex entries about relics. The
    offer card is the teaching: it says what the relic does. A story pass can
    add lines later through docs/narrative-authority.txt.
  - Barrel relics. Barrel value is read only on the BARREL_OPENER niche, not
    on the carry the rarity bands use, so a barrel relic would price at about
    1.00 and fail every band. Follow-up: teach carryOf about barrel openers
    first.
  - Folding relic power into ExpectedPlayer. Bosses, TP and the ladder stay
    derived from the relic-free on-curve player. See D3.
  - Per-relic art. A card shows a rarity frame, a trigger badge, the name and
    the text. There is no per-relic glyph.
  - Weapon-mechanics relics that would rewrite a Weapon subclass's fire path
    (extra projectiles, pierce for every class).
  - New non-balance tests. No test for the overlay, catalog, runtime or route
    wiring. See the Testing Policy note in IMPLEMENTATION PLAN step 5.


GAMEPLAY LOOP
-------------
Every action is still exactly one turn. Taking a relic costs NO turn: the
offer is a hard-pause overlay, like the level-up screen.

  RUN START
  1. The player arms up in the staging room, picks a route node and arrives on
     depth 1. On the first frame where the world is in PLAYING and the player
     is idle, the RELIC_OFFER overlay opens with 3 COMMON cards plus a LEAVE
     IT plate.
  2. Tap a card: that relic is bonded. Its effects fold into the build at
     once, the RELIC_BONDED sound plays, and event text reads
     "RELIC BONDED — <NAME>". The overlay closes and play resumes on the same
     turn. Tap LEAVE IT: nothing is bonded and the overlay closes.

  BOSS (depths 5, 10, 15, 20 — never 25, which is the run's VICTORY)
  3. The boss dies. World notices it in the same poll that asks for the
     BOSS_DEFEATED bark and queues a BOSS offer. The overlay opens on the next
     idle PLAYING frame with 3 cards rolled from that boss's rarity weights,
     at least one RARE or better, never CURSED.

  MYSTERY SECTOR (outcome RELIC_CACHE)
  4. The player leaves the sector. The mystery payout queues a MYSTERY_CACHE
     offer of 2 cards (COMMON or RARE). It opens on the first idle PLAYING
     frame of the next floor.

  EVENT "QUARANTINE LOCKER"
  5. Choose BREAK THE SEAL: an offer of 2 CURSED cards opens as soon as the
     event overlay closes. Choose SELL THE SEAL: the large credit payout, and
     no relic.

  WHILE HELD (all inside turns the world already resolves; never per frame)
  6. On a kill credited to the player: kill heal and armour, the credit
     bonus, the XP bonus, the ammo refund roll, and the corpse burst. They
     resolve during the kill, inside the turn that killed it.
  7. When the player opens a door (the turn spent opening it): the door blast
     and the door heal. Each door triggers at most once per floor, and the
     blast resolves before the enemies act that turn.
  8. On floor arrival, before the first turn: the arrival heal, armour and
     ammo, and the first-hit shield re-arms.
  9. On every hit the player takes: the shield is spent first if armed, then
     the damage-taken multiplier, then the existing guard, armour and
     toughness pipeline. Second Wind still has the last word.
 10. When an enemy spawns (floor load or a mid-floor summon, never a boss):
     its health is multiplied.
 11. On every weapon hit while the player is below
     BUILD_BERSERK_LOW_HEALTH_FRACTION (30%) of max HP: the low-health damage
     bonus applies.
 12. The player dies: the held relics are listed on the run report and are
     gone. The next run starts with none.


RULES
-----
  Identity and holding
  R1  A relic is one RelicDefinition row: id (lower_snake), display name
      (UPPER), RelicRarity, RelicTrigger (UI badge), RelicValuation (CARRY or
      SUPPLY), optional BuildTag affinity, 1..4 PerkEffects, an effect line,
      and a cost line (required for CURSED, forbidden otherwise). Every
      magnitude is a BalanceConfig constant named
      RELIC_<RELIC_ID>_<PERK_MODIFIER_KIND>.
  R2  A run holds each relic at most once, up to RELIC_MAX_HELD = 8. Held
      relics are never removed during the run. Death or a new run clears them.
  R3  Relic effects apply after the perks and before the keystones in
      PlayerBuild.recompute. The PerkModifier stacking rule is unchanged:
      bonus kinds add, cost and multiplier kinds multiply, and boolean kinds
      OR.

  Offers
  R4  RelicSource defines each offer:
        RUN_START        3 cards, COMMON only.
        BOSS             3 cards, rarity rolled per card from
                         RELIC_BOSS_OFFER_RARITY_WEIGHTS[bossIndex]
                         ({COMMON, RARE, LEGENDARY}); if no card is RARE+, the
                         last card is re-rolled as RARE.
        MYSTERY_CACHE    2 cards, from RELIC_MYSTERY_OFFER_RARITY_WEIGHTS
                         {COMMON, RARE}.
        QUARANTINE_LOCKER 2 cards, CURSED only.
      Every offer has a LEAVE IT plate.
  R5  Eligibility. A relic is never offered when:
        - it is already held;
        - it has a BuildTag affinity and the player neither carries a weapon
          of that tag nor holds a perk rank in it;
        - every one of its effects is a boolean that is already true in the
          build.
      If a rarity has too few eligible relics, the card falls back to the
      nearest rarity: RARE, then COMMON, then LEGENDARY (CURSED never stands
      in for anything else). With zero eligible relics the offer is skipped
      and logged. At RELIC_MAX_HELD, offers are skipped.
  R6  Offers are deterministic. The seed is GameMath.floorSeed(runSeed ^
      RELIC_OFFER_SEED_SALT, depth) mixed with the source ordinal. Same seed,
      same cards, in World and SimWorld alike.
  R7  At most RELIC_PENDING_OFFER_CAPACITY = 2 offers wait, first in first
      out. A pending offer survives floor transitions and is dropped on
      death. It opens only in PLAYING, with the player IDLE, no bark panel
      mid-reveal blocking, and no other overlay. It opens before a pending
      story exchange and after a pending level-up.

  Triggered rules (the new PerkModifier kinds; see TECHNICAL NOTES)
  R8  A "kill" means a death that awards XP through KillXpListener. A kill by
      a corpse burst never causes another corpse burst (no chains).
  R9  Relic blasts hit ENEMIES ONLY. They never damage the player, never
      detonate barrels, deal EXPLOSIVE damage through the matchup with the
      hazard-blast flag set (no weapon build terms, no Sapper multiplier),
      and use the reference soldier's HP at the floor's depth as the 1.0
      unit.
        Door blast: centre on the tile beyond the door, opposite the player.
                    If that tile is a wall, centre on the door tile. Centre
                    takes fraction x 1.0; the 4 neighbours take fraction x
                    RELIC_BLAST_RING_SHARE.
        Corpse burst: the 4 orthogonal neighbours of the dead enemy's tile,
                    each at fraction x 1.0. The centre is empty.
  R10 Door triggers (blast, heal) fire on a CLOSED -> OPENING transition the
      player requested, once per door tile per floor.
  R11 FIRST_HIT_SHIELD: the first hit each floor from an enemy attack, a
      heavy, or an explosion deals 0 and is spent. A status tick never spends
      it.
  R12 Multiplier clamps: damage taken x is clamped to >= 0.50 and enemy
      health x to >= 0.50. A positive hit always deals at least 1.
      Arrival ammo refunds once per AMMO TYPE carried, not once per gun.
  R13 ENEMY_HEALTH_MULTIPLIER never applies to EnemyRole.BOSS and only
      changes enemies spawned after the relic is bonded.

  Phase machine
  R14 RunPhase gains RELIC_OFFER. Legal transitions:
        PLAYING -> RELIC_OFFER (pending offer, idle);
        RELIC_OFFER -> PLAYING (card tapped or LEAVE IT);
        RELIC_OFFER -> PAUSE_MENU -> RELIC_OFFER (the pause button works and
        returns to the same offer).
      Nothing else enters or leaves it. Death cannot happen in it (the world
      is frozen). RELIC_OFFER is a hard-pause overlay: barks queue, no
      exchange opens, and the thumb clusters are not drawn.
  R15 Taps on the overlay are ignored for RELIC_OFFER_INPUT_LOCKOUT_SECONDS
      = 0.4 s after it opens, so a thumb mashing FIRE cannot pick a card
      blind.


PLAYER EXPERIENCE
-----------------
At the start of the run, three small rule-benders: heal on every floor, kills
pay more, doors heal you. The pick is "what kind of run do I want", and it is
legible before the first enemy. After the first boss, the bigger cards
arrive: VAMPIRIC CORE ("every kill heals"), BREACHING CHARGE ("doors you open
explode"). The player starts playing differently: opening doors on purpose
with enemies behind them, diving into a pack because kills refund health. The
CURSED tier is the bargain card. BLOOD PACT (+35% damage, take 25% more) is
offered only behind a seal the player chose to break, so a cursed relic is
never forced on anyone.

Death stays explainable. Every effect is printed on the card, listed on the
BUILD page and named on the run report ("RELICS: BLOOD PACT, KEVLAR WEAVE").
A cursed cost is printed in red on the same card as the gain.

Teaching is the card itself: one plain line per effect, a trigger badge (ON
KILL, ON DOOR, ON ARRIVAL, ALWAYS, ON HIT, LOW HP, LETHAL HIT, ON SPAWN), and
a rarity frame. Discrete triggers also confirm themselves in play
("ABLATIVE SHELL — HIT ABSORBED", "+9 HP — FIELD DRESSING"). No ORA line is
needed.


TECHNICAL NOTES
---------------
Package decision: new ge.tbegvadze.toon3d.relic. It holds the data and
selection classes, with no LibGDX imports. RelicRuntime touches only
simulation types (entity, level, hazard, door), exactly as SimWorld does.
Dependencies point one way: route -> relic -> progression/util. relic never
imports route; the boss index and depth are passed in. util.RelicValuationModel
imports relic, the same util <-> content pattern BuildValuationModel already
uses with progression.

relic/ (NEW)
  RelicRarity       enum COMMON, RARE, LEGENDARY, CURSED. Data per constant:
                    label, isCursed. No switch anywhere.
  RelicTrigger      enum ALWAYS, ON_KILL, ON_DOOR_OPEN, ON_FLOOR_ARRIVAL,
                    ON_HIT_TAKEN, ON_LOW_HEALTH, ON_LETHAL_HIT, ON_ENEMY_SPAWN.
                    Data: badge label ("ALWAYS", "ON KILL", "ON DOOR",
                    "ON ARRIVAL", "ON HIT", "LOW HP", "LETHAL HIT",
                    "ON SPAWN").
  RelicValuation    enum CARRY, SUPPLY. Which metric the rarity band reads.
  RelicSource       enum RUN_START, BOSS, MYSTERY_CACHE, QUARANTINE_LOCKER.
                    Data per constant: card count, allowed rarities, a
                    guarantee flag (BOSS: one RARE+). The rarity weights come
                    from BalanceConfig arrays.
  RelicDefinition   immutable row plus Builder. Required builder fields: id,
                    name, rarity, trigger, valuation, effectText, and >= 1
                    PerkEffect. costText is required iff rarity == CURSED.
                    affinity (BuildTag) is optional. build() throws
                    IllegalStateException on a missing required field.
                    Accessors: id(), name(), rarity(), trigger(), valuation(),
                    affinity(), effects() (a copy-free PerkEffect[] view),
                    effectText(), costText().
  RelicRegistry     register(RelicDefinition) (rejects a duplicate id),
                    get(String id), all(), allOfRarity(RelicRarity),
                    size(). Iteration order = registration order.
  RelicCatalog      static bootstrap(RelicRegistry): THE CONTENT FILE. 36
                    register() calls, one per relic (catalog below). Adding a
                    relic = one register() call plus its BalanceConfig
                    magnitudes.
  RelicText         static String percent(float) helper for card text (the
                    Perk.percent idiom). Card text is built from BalanceConfig,
                    so text never drifts from numbers.
  RelicHand         the run's held relics: fixed RelicDefinition[RELIC_MAX_HELD],
                    count().
                      add(RelicDefinition, PlayerBuild): boolean. False if held
                        or full. Otherwise calls
                        playerBuild.addRelicEffects(def.effects()).
                      holds(RelicDefinition), get(int index), clear().
                    Allocation-free after construction.
  RelicOffer        mutable, pre-allocated output: source, depth,
                    cards[RELIC_OFFER_MAX_CARDS], count. The roller fills it;
                    it is never allocated per offer.
  RelicOfferRoller  static roll(RelicSource source, int depth, int bossIndex,
                    RelicHand hand, BuildStats stats, EnumSet<BuildTag>
                    carriedOrRankedTags, long seed, RelicOffer out).
                    Implements R4-R6.
  RelicRuntime      per-run trigger runner, owned by World and by SimWorld
                    (one class, never mirrored code). implements
                    door.DoorOpenedListener.
                      beginFloor(Level level, Player player, PlayerInventory
                        inventory, RelicBlastTarget blastTarget): resets the
                        per-floor door-trigger grid (allocated here, at floor
                        start, sized to the level, never in render), then
                        applies FLOOR_ARRIVAL_HEAL / _ARMOR / _AMMO and
                        reports each through the feedback listener.
                      onDoorOpenedByPlayer(int tileColumn, int tileRow):
                        R9/R10 door blast plus door heal.
                      setFeedbackListener(RelicFeedbackListener): World
                        routes it to EventTextSystem; null in SimWorld.
  RelicFeedbackListener  void onRelicTriggered(String text, boolean
                    positive).

progression/ (EXTEND — the single seam, see D1)
  PerkModifier      17 NEW constants, each owning its apply body:
                      ALL_WEAPON_DAMAGE (add to every class),
                      KILL_HEAL, KILL_ARMOR, KILL_CREDIT_BONUS,
                      KILL_AMMO_REFUND (chance, min 1), XP_MULTIPLIER,
                      DOOR_BLAST, DOOR_OPEN_HEAL, CORPSE_BLAST,
                      FLOOR_ARRIVAL_HEAL, FLOOR_ARRIVAL_ARMOR,
                      FLOOR_ARRIVAL_AMMO, FIRST_HIT_SHIELD (boolean),
                      LOW_HEALTH_DAMAGE (all classes), DAMAGE_TAKEN_MULTIPLIER
                      (x), ENEMY_HEALTH_MULTIPLIER (x), CLIP_SIZE_MULTIPLIER
                      (x on the existing clipSizeCostMultiplier field).
  BuildStats        new package-private fields with identity defaults. The
                    new fields are reset in reset() and copied in copyFrom().
                    Public accessors:
                      killHealFraction(), killArmorFraction(),
                      killCreditMultiplier() (1 + sum),
                      killAmmoRefundChance(), experienceMultiplier() (1 + sum),
                      doorBlastFraction(), doorOpenHealFraction(),
                      corpseBlastFraction(), floorArrivalHealFraction(),
                      floorArrivalArmorFraction(), floorArrivalAmmoFraction(),
                      firstHitShield(), lowHealthDamageBonus(),
                      damageTakenMultiplier() (clamped,
                      RELIC_DAMAGE_TAKEN_MULTIPLIER_MIN),
                      enemyHealthMultiplier() (clamped,
                      RELIC_ENEMY_HEALTH_MULTIPLIER_MIN).
                    New public static ofEffects(PerkEffect... effects): a

                    Every existing accessor's result for a relic-free build

  PlayerBuild       addRelicEffects(PerkEffect[] effects): boolean (false at

                    LOW_HEALTH_DAMAGE: the BERSERKER read

BALANCE NOTES
-------------
Balance-bearing: BalanceConfig SECTION 26, four new BalanceSchema rule kinds,
balance-bearing GameMath formulas, BuildValuationModel/RelicValuationModel,
and sim/. TESTS step 5 is therefore the balance branch. THE CHANGE PROTOCOL
(authority SECTION 7) applies in full: green audit, green sim, regenerated
SECTION 6 and SECTION 8, and one CHANGELOG line.

The pricing model
  - A relic's GAIN is measured exactly the way R-CARRY measures a build: the
    kill-speed lift times the survival lift, geometric means over S1..S8,
    with a two-gun kit (the affinity tag's kit, else the best pair). Supply
    the relic adds is converted to heal at the Fabricator's price. This is
    computed by BuildValuationModel.carryOf on BuildStats.ofEffects(relic).
    Economy relics (valuation SUPPLY) are banded on the SUPPLY_TOTAL ratio
    instead, because the carry conversion under-reads supply. That is the
    same reason SCAVENGER's R-CARRY row is waived (D3 of balance-overhaul
    order 5).
  - Scale: a perk rank is worth about x1.08 carry at depth 15 (MARKSMAN
    1.751 over 7 ranks). So COMMON is about half a rank to one rank, RARE
    about one to one and a half, LEGENDARY about one and a half to two and a
    half, and CURSED nets about one rank after its cost.

New schema rules (RuleKind values; evaluated by BalanceSchema.evaluate)
  R-RELIC (RELIC)  For every non-CURSED relic, at every RELIC_REFERENCE_DEPTH:
        gain in the band for its rarity x valuation. The band floor is the
        "felt" test: a relic whose kinds the valuation does not read prices
        at 1.00 and fails, so an unpriced effect kind cannot ship.
  R-RELIC-CURSE (RELIC_CURSE)  For every CURSED relic: gain in the CURSED
        band for its valuation at every reference depth, AND worstLoss(stats,
        null, d) >= RELIC_CURSED_MIN_LOSS at some reference depth (the
        R-KEYSTONE cost idiom).
  R-RELIC-STACK (RELIC_STACK)  At every BossTable depth:
        expectedHandLift(d) <= the WORST non-waived R-CARRY tag score ("a
          run's expected relics never out-carry one committed build"), and
        bestHandLift(d) <= the BEST non-waived R-CARRY score x (1 +
          BUILD_CARRY_TOLERANCE) ("even the luckiest hand stays inside the
          build spread").
        Both ceilings are read live from buildCarryResults(). No new number.
  R-RELIC-SOURCE (RELIC_SOURCE)  Structural:
        each rarity has >= RELIC_OFFER_MAX_CARDS non-affine relics (an offer
          always fills);
        each weight row sums to 1 (+/- 1e-4);
        no duplicate ids;
        every CURSED relic has a cost line and at least one cost kind (a
          multiplier below 1 on a player stat, or above 1 on damage taken /
          enemy health);
        RELIC_PERK_RANK_EQUIVALENT_LIFT is within
          RELIC_PERK_RANK_EQUIVALENT_TOLERANCE of
          (worst non-waived carry)^(1 / its row's ranks + keystone count);
        nodeOfferRatePerFloor() > 0.
  Existing rules that now read relics: R-ROUTE-PRICED (the RELIC_CACHE
  NodeEconomics row), R-MYSTERY-EV v2 and R-HONEST-SAFE (the new outcome),
  R-EVENT-VALUE (quarantine_locker: SELL THE SEAL alone already meets it, the
  same payout as distress_beacon's IGNORE). COVERAGE gains: every relic
  resolves its rarity, trigger and valuation.

  - S-RELIC (RuleKind.SIM_RELIC), in BehavioralBands. Uses MEAN ending depth,
    because medians are integers at about 3:
      SR1 for COMMON / RARE / LEGENDARY rows: mean depth / NO-RELIC in
          [1 - SIM_RELIC_ROW_TRAP_TOLERANCE, 1 + SIM_RELIC_ROW_MAX_LIFT];
      SR2 CURSED row: in [1 - SIM_RELIC_CURSED_ROW_TOLERANCE,
          1 + SIM_RELIC_ROW_MAX_LIFT];
      SR3 rarity is felt: mean depth LEGENDARY >= COMMON;
      SR4 per non-affine relic with >= SIM_RELIC_MIN_RUNS_PER_RELIC probe runs:
          its mean depth / NO-RELIC in [1 - SIM_RELIC_PER_RELIC_TRAP_TOLERANCE,
          1 + SIM_RELIC_PER_RELIC_MAX_LIFT] ("no trap, nothing mandatory");
      SR5 sample: every non-affine relic got >= SIM_RELIC_MIN_RUNS_PER_RELIC
          probe runs (always enforced);
      SR6 wiring: standard TACTICAL mean relics held at run end >= 1.0.
    Tag-affine relics are banded by the audit only. A probe start weapon may
    not carry their tag, which would make them look like traps. This is
    recorded in docs/relic-system.txt.
  - Reports:
      SimReport RELIC REPORT: per probe row mean/median depth; per relic
        runs, mean depth and ratio; TACTICAL offers seen / taken / left by
        source; MODEL vs PLAYED kills and doors opened per floor
        (DoorManager.getOpenedDoorCount) against RELIC_VALUATION_KILL_SHARE
        and _DOORS_PER_FLOOR, report-only.
      RoundSummary row "R1 relic rows mean-depth lift LEGENDARY / NO-RELIC",
        IN/OUT.
      LadderReport column "relics (expected)".

EDGE CASES
----------
  - Action lock: an offer opens only when the PlayerController is IDLE. It
    never interrupts an animation.
  - Player dies on the turn a boss dies (mutual kill): DEAD wins and the
    pending offer is discarded.
  - Final boss (depth 25): no offer. The VICTORY flow is untouched.
  - Floor transition with a pending MYSTERY offer: it opens on the next
    floor's first idle frame.
  - App paused (onApplicationPause) in RELIC_OFFER: on resume the same offer
    is still open, and the 0.4 s tap lockout re-arms. App killed: the run is
    lost exactly as a mid-level-up kill loses it today. Nothing is persisted.
  - Pause button in RELIC_OFFER: PAUSE_MENU, then back to the same offer
    (R14). Abandon run from pause discards it.
  - Inventory full / RELIC_MAX_HELD reached: offer skipped, event text
    "RELIC CAPACITY REACHED".
  - Too few eligible relics: the R5 fallback; zero means skip and log.
  - A door blast centred on a wall tile: the R9 fallback to the door tile.
    Blast tiles outside the level are skipped by the existing bounds check.
  - A corpse burst killing more enemies: they award XP and kill terms, but
    never burst (R8).
  - Second Wind (perk) plus SECOND HEART (relic): the boolean is already
    true. The relic stays eligible for its max-HP part, and the card text is
    honest about both.
  - ENEMY_HEALTH_MULTIPLIER mid-floor: only enemies spawned later; a boss
    never.
  - Hand-made levels vs generated: relics do not touch generation. Door and
    kill triggers work on both.
  - New run / NEW OPERATOR wipe: RelicHand.clear() and PlayerBuild.reset()
    are part of the run reset. There is no persistent state to wipe.
  - Hard-pause overlay already open when an offer is queued: it waits (R7).
  - Sim determinism: offers are seeded (R6). theSameSeedReplaysTheSameRun
    must stay green.

ASSUMPTIONS
-----------
  AS1  About 5 relics per full run is "rare": 1 start, 4 bosses, and about
       0.3 from nodes. Roughly one relic per region feels like an event; one
       per floor would be loot.
  AS2  Choose one of N with a LEAVE plate, rather than a single fixed drop.
       It is the Slay the Spire/Hades idiom, it makes every relic a decision,
       and it is what lets S-RELIC claim "nothing is mandatory".
  AS3  There is no slot cap or swap UI. Five relics never need managing; the
       old draft's 2-slot cap existed to stop stacked legendaries, and
       R-RELIC-STACK now does that with numbers.
  AS4  Relic text is UI text built from BalanceConfig, the Perk/Keystone
       idiom. It does not use story string ids (D5).
  AS5  Boss offers never contain CURSED cards. A cursed relic is only ever
       met behind a seal the player chose to break, so curses are never
       forced.
  AS6  Kills count only when the player is credited (XP-awarding deaths).
       That matches the existing BLOODLETTING path.
  AS7  Relic blasts are enemies-only and never chain barrels. The
       fairness pillar: the player must never die to their own relic. Barrel
       chains would also make door blasts unpredictable.
  AS8  Door triggers fire once per door per floor. That closes the
       open-close farm without a cooldown (there are no time-based
       cooldowns).
  AS9  The first-hit shield ignores status ticks. A burn eating the shield
       would feel like a bug.
  AS10 The enemy-health relic never touches bosses. Boss HP is derived by
       BossBalance and the R-BOSS bands. Bending it would need its own rule.
  AS11 Kill heals use applyHealing, not applyTreatment, so Field Medic and
       MEDIC'S GLOVE do not double-dip. This is the melee-kill-heal
       precedent.
  AS12 Arrival ammo refunds per ammo type (not per gun), so two guns sharing
       BULLETS do not double the refill.
  AS13 The RUN_START offer opens on depth-1 arrival, after the staging-room
       weapon pick, so tag affinity can read the chosen weapon.
  AS14 The weights and magnitudes in this file are starting values. CP5 tunes
       magnitudes inside the bands. The bands and weights are the design.
  AS15 HOARDER takes the start relic (offered[0]). S-GATE must still hold.
       A COMMON relic must not let the start loadout clear the first boss;
       if it does, that is a real finding and the COMMON is retuned.
  AS16 Valuation model assumptions (kill share 0.60, 3 doors per floor, 30%
       of fights through a door, 0.5 corpse adjacency, 50% locker take rate)
       are stated constants. The RELIC REPORT prints played-vs-model kills
       and doors, so they can be corrected from data later.
  AS17 Tag-affine relics are excluded from sim probes and banded by the
       audit only (S-RELIC note above).
  AS18 The overlay's card art is procedural layout and colour only. There
       are no textures and no per-relic glyphs.
  AS19 Relic UI geometry lives in HudConstants and blast visuals in
       EffectConstants. No new Constants file is created.
  AS20 The roguelike_order_14 draft's dependencies (inventory-loot-ransack,
       secret rooms) are not needed. Every source here already exists.


DECISIONS
---------
  D1  Relics reuse the perk/keystone build seam (PerkModifier + PerkEffect ->
      PlayerBuild -> one BuildStats aggregate) instead of a parallel effect
      system. Reason: that aggregate is already wired into every runtime seam
      in World and SimWorld, and into the valuation the audit uses. A parallel
      system would need double wiring and a second pricing model.
      (2026-10-18)
  D2  No tile symbol and no ground item. Relics arrive by offer from four
      existing channels: run start, boss defeat, a mystery outcome, and an
      event. Reason: the STRICT RULE cost, a pickup-symbol budget, and the
      supply planner (R-SUPPLY) would all be touched for no player benefit.
      (2026-10-18)
  D3  ExpectedPlayer is not changed. Relics are bounded bonus power, capped by
      R-RELIC-STACK against the existing R-CARRY scores. Reason: folding them
      into the on-curve player would re-derive boss HP, TP and every ladder
      band in the middle of the order-7 feel pass. A cap expressed in the
      build contract's own scores integrates relics without moving anything
      else. (2026-10-18)
  D4  Every run opens with a 3-COMMON relic choice. Reason: the owner wants
      every run to feel different, and today most runs end before the first
      boss, so boss-only relics would be invisible to most players.
      (2026-10-18)
  D5  No narrative content (no ORA line, codex entry, teaching topic or story
      string id). Reason: the card text is the teaching, and new story lines
      carry their own contract (docs/narrative-authority.txt) and process.
      A story pass is a follow-up. (2026-10-18)
  D6  No persistence (run-scoped only; no discovery log). Reason: a new
      StatsStore/StoryStore key is a schema change, and the "new game" wipe
      would need to know about it. Discovery can be a follow-up idea.
      (2026-10-18)
  D7  CP5 and CP8 may retune only the NEW SECTION 26 relic magnitudes and the
      relic-cache mystery weight to pass the gates. Pre-existing numbers and
      bands are never moved, and a sim waiver is allowed only for a
      depth-derived S-RELIC line made unmeasurable by order 7's
      round-pending state. Reason: the owner pre-approved this design with
      implementation starting immediately, so the implementer needs a bounded
      tuning license, not a question. (2026-10-18)
  D8  Single file, not split into order files, despite ten checkpoints.
      Reason: the owner asked for exactly one file. Each checkpoint still
      leaves the build green. (2026-10-18)
  D9  The relic package sits between route and progression. relic never
      imports route (the boss index and depth are passed in). Reason: this
      avoids a route <-> relic cycle while letting EventEffect carry a
      RelicSource. (2026-10-18)
  D10 Barrel relics, shop relics and ELITE-floor relics are cut (SCOPE OUT).
      Reason: each would either price at 1.00 in today's carry model
      (barrels) or move an existing balance band (R-CREDITS v2 / S-SHOP;
      ELITE R-RISK-PREMIUM). (2026-10-18)
