OVERVIEW
--------
The owner, replying to the series: "there must be some rules that when new
content such as enemies, weapons or anything else will be added it must follow
the rules to fit the balance."

Orders 1-7 rebuild the balance around a handful of models — the power ladder
(R-LADDER), the supply planner (R-SUPPLY / R-DENSITY), weapon roles and matchups
(R-ROLE), heavy attacks (R-HEAVY), builds (R-PERK / R-KEYSTONE / R-CARRY) and the
finite run (bosses, economy, events). Every one of them can be broken by one
careless addition: an enemy with no trait, a weapon that wins every scenario, a
room blueprint that drops its own medkits, a shop offer with a literal price.
The project has been bitten by exactly this before (the necrotic faction shipped
unpriced and corrupted every floor budget for weeks).

This order turns the series into a permanent CONTRACT with three parts:
  1. an ADMISSION CHECKLIST per content kind — what must be declared, which band
     or role it must land in, how it is priced, which registry it goes through,
     how the player is told, and what "done" means;
  2. STRUCTURAL ENFORCEMENT — BalanceSchema's COVERAGE grows into a family of
     ADMISSION rules (C-*) checked by the existing BalanceAuditTest, so an
     undeclared, unpriced or out-of-band addition FAILS `./gradlew test` with a
     message naming the rule and the missing item — plus a catch-all for any new
     balance number;
  3. PROCESS BINDING — one "ADD CONTENT" section in
     docs/game-balance-authority.txt that every content-creating agent, doc and
     idea file is pointed at and bound by.

    identity rule; the contract only notes that a new master knob MAY get a dial.


GAMEPLAY LOOP
-------------
The contributor's loop (any agent, any future feature):
  1. A designer writes an idea file that adds content. The template's BALANCE
     ADMISSION section forces the checklist for each content kind it adds to be
     filled in (numbers declared, band, price, registry, communication).
  2. The implementer adds the content through its registry and declares every
     field the kind requires. A forgotten abstract declaration will not compile;
     a forgotten pricing row, band miss or unresolved id fails `./gradlew test`
     with "ADMISSION C-<KIND>: <content id> — <what is missing>".
  3. The implementer runs both gates and regenerates the living tables; the new
     content appears in BalanceReport's tables and the sim reports.
  4. reviewer checks the idea file's BALANCE ADMISSION block against the
     checklist and fails the work if any "done" item is missing.


RULES
-----
General
  G1  "Balance-bearing content" = anything that changes damage, HP, supply,
      threat, XP, credits, prices, run shape or player power. Every such addition
      belongs to exactly one kind K1-K18 below; if none fits, it is K18 (a new
      balance number) and the designer extends this contract in the same idea.
  G2  Every kind's checklist has six parts: DECLARE (numbers and flags that must
      exist), BAND (the rule/range it must land in), PRICE (how its cost/value is
      computed — never hand-set where a formula exists), REGISTER (the only way
      in), COMMUNICATE (how the player learns it), DONE (the checkable state).
  G3  Every number lives in BalanceConfig; every formula in GameMath; every row is
      a register() or enum row — never a switch (unchanged project rules; the
      C-rules assume them).
  G4  Adding balance-bearing content is FULL LANE (idea file + checkpoints). The
      short lane stays open only for content that is supply-, spawn- and
      power-neutral (a decorative room blueprint, a sprite, a bark line) — and
      K12 checks the neutrality.
  G5  An ADMISSION failure caused by a MISSING declaration or pricing row can
      never be waived. A value outside its band may be waived only through the
      existing waiver policy (reason + expiry, mirrored in the authority doc).

Admission checklists
  K1  ENEMY ARCHETYPE (EnemyType row)
      DECLARE  role(), family() (trait inherited, override explicit), base HP,
               base damage, cadence, range, positional multiplier, move-set with
               every SpecialAbility, HEAVY flags, min spawn depth / region, the
               EncounterGroupTemplate slots it may fill, tacticalVerb().
      BAND     TP in its role band; the order-1 R8 TTK/TTD role targets at
               depth 1 (R-LADDER L1 across 1..25); trait-aware eHP (order 3);
               heavy verbs in the R-HEAVY band and avoidable.
      PRICE    TP via EnemyType.baseThreatPoints (cycle-averaged, heavy
               avoidance discount); XP derived from TP (never hand-set).
      REGISTER EnemyType row; spawn symbol — a new FIXED spawn symbol follows the
               CLAUDE.md STRICT RULE in one commit; at least one group template
               slot; family voice (audio) and bestiary lines come structurally.
      COMMUNICATE trait glyph (from family/trait), intent icons for its verbs,
               danger markers for heavies, ORA archetype line (BestiaryCatalog
               string id resolves).
      DONE     C-ENEMY green; it appears in BalanceReport ENEMIES/LADDER tables
               and spawns in the sim FLOOR REPORT at its depths.
  K2  ENEMY FAMILY / TRAIT (EnemyFamily, EnemyTrait)
      DECLARE  trait; trait glyph id; a MatchupCatalog row for EVERY DamageClass;
               family voice binding (audio); family bestiary lines.
      BAND     R-ROLE-1..3 still hold with the new trait's scenario added (a new
               trait adds one reference scenario to R-ROLE).
      DONE     C-FAMILY green; matchup table complete (no missing cell).
  K3  ENEMY SPECIAL VERB (SpecialAbility)
      DECLARE  pricing equivalence (special-verb pricing row), HEAVY flag stated
               explicitly (true/false), danger-tile shape if HEAVY, telegraph
               (commits >= 1 turn ahead if > 25% eHP), ORA ability line id.
      BAND     R-TELEGRAPH; R-HEAVY if heavy; SUMMON verbs under the hard caps.
      DONE     C-VERB green; TELEGRAPH AUDIT table lists it.
  K4  BOSS (boss EnemyType + BossTable row)
      DECLARE  BossTable row (depth, archetype, target fight turns, survival
               ratio); phase count; verb fractions; heavy verbs flagged.
      BAND     R-BOSS-* (gate, fair, verb cap incl. the 50% heavy cap, reward,
               ammo); S-BOSS consistency.
      PRICE    derived by BossBalance from ExpectedPlayer — never literal HP.
      DONE     C-BOSS green; every BossTable depth resolves to a declared boss.
  K5  WEAPON (Weapon subclass + ItemType)
      DECLARE  DamageClass, role/niche scenario, ammo type, base damage / clip /
               range / falloff / reload at LV1 COMMON, ladder participation
               (only the Fist is exempt), special properties (pierce, splash,
               knockback, stagger).
      BAND     R-ROLE-1..5: it must be best in >= 1 reference scenario OR add a
               new scenario (then every existing class is re-checked); it may not
               take the ONLY niche of an existing class; no class best in > 2.
               R-LADDER (it follows the ladder).
      PRICE    scenario turns-to-clear; ammo feasibility; shop price via
               GameMath.shopPrice from its PP.
      REGISTER ItemType + weapon classification (COVERAGE), WeaponRoller tier
               rules, ground sprite and HUD per docs/weapon-creation-guide.txt.
      COMMUNICATE class glyph + colour, STRONG VS / WEAK VS on the compare card,
               switch-hint eligibility (MatchupAdvisor sees it automatically).
      DONE     C-WEAPON green; SCENARIO table row; sim MATCHUP REPORT shows it
               when carried.
  K6  WEAPON ABILITY (WeaponAbility)
      DECLARE  magnitude per level, cap, BuildTag, melee/ranged eligibility,
               MAJOR flag, signature flag.
      BAND     priced PP >= ABILITY_MIN_FELT_PP at its expected level; fits the
               tier budgets (R-ABILITY).
      PRICE    GameMath.abilityPowerPoints.
      DONE     C-ABILITY green; roll sweep never exceeds a tier ceiling.
  K7  PERK / KEYSTONE (Perk, Keystone)
      DECLARE  BuildTag, ranks, per-rank modifiers, attribute grant; keystone
               gain AND cost modifiers.
      BAND     R-PERK (felt, focused), R-KEYSTONE (>= 30% niche gain, >= 10%
               cost elsewhere), R-CARRY re-checked for every tag.
      DONE     C-PERK green; PERKS/BUILDS tables list it; name/effect ids resolve.
  K8  ITEM / PICKUP / CONSUMABLE (ItemType; heal, armour, utility)
      DECLARE  category; effect as a FRACTION of max (HP/armour) or an explicit
               non-HP utility effect; stack cap; cleanse behaviour; supply
               category (which SupplyPlan category it counts toward) or the
               explicit declaration NOT_FLOOR_SUPPLIED; pickup symbol (existing,
               or STRICT RULE).
      BAND     R-HEAL (survival-turns bought) for HP/armour items; R-SUPPLY
               (counted in the plan).
      PRICE    supply value in PP; shop price via GameMath.shopPrice.
      COMMUNICATE inventory icon + name/description ids; HUD feedback on use.
      DONE     C-ITEM green; placed only by SupplyPlanner (or declared shop/
               reward-only).
  K9  AMMO TYPE (AmmoType)
      DECLARE  generosity factor, reserve cap, box size, shop box price source.
      BAND     R-ROLE-5 (feasible), reserve banking target, R-SUPPLY.
      DONE     C-AMMO green.
  K10 STATUS EFFECT
      DECLARE  ONE definition (R-DOT); magnitude as a fraction of max HP (DoT) or
               a multiplier; duration; stacking; armour-shield interaction
               (blocked or not, cost); cleanse (which item); HUD icon id.
      BAND     R-DOT; its appliers' TP includes it (special-verb pricing).
      DONE     C-STATUS green; status row shows it with turns remaining.
  K11 HAZARD / GAMEPLAY PROP (explosive barrel kinds, fire / toxic tiles, any
      prop or tile that deals damage or applies a status)
      DECLARE  damage as a FRACTION (of the floor's reference enemy HP for
               enemies, of max HP for the player); two-sidedness (hits player,
               enemies, or both); the status it applies (K10); DamageClass for
               matchups (EXPLOSIVE / FIRE / ...); lifetime and spread; placement
               rule (which planner places it, near which groups).
      BAND     hazard TP via GameMath.hazardTileThreatPoints inside the floor
               budget; un-telegraphed player damage <= 25% (R-TELEGRAPH).
      REGISTER existing symbols only, or the STRICT RULE; placement only through
               the encounter/supply planners (never hand-placed by a generator).
      COMMUNICATE a readable sprite/tile and, if it can hit the player, a visible
               warning before it does (fuse, glow, danger marker).
      DONE     C-HAZARD green; BalanceReport HAZARDS table lists it.
  K12 ROOM BLUEPRINT (RoomBlueprint)
      DECLARE  its supply stance: SUPPLY_NEUTRAL (emits NO pickup and NO enemy
               symbols — only slots) or SLOT_PROVIDER (tagged supply / group
               slots the planners may use).
      BAND     building it in isolation emits no pickup or enemy-spawn symbol.
      DONE     C-ROOM green. (A neutral blueprint may stay short-lane, G4.)
  K13 LEVEL GENERATOR (GeneratorId)
      DECLARE  SupplySlotProvider implementation; footprint band per region;
               the node types it serves.
      BAND     R-SUPPLY and R-DENSITY sweeps pass for every node type it serves.
      DONE     C-GENERATOR green; sim FLOOR REPORT row per node type.
  K14 ROUTE NODE TYPE (RouteNodeType + profile)
      DECLARE  NodeSupplySpec row; NodeLevelProfile; route-card threat/reward
               lines (C1 of order 2); region weights.
      PRICE    NodeEconomics derived from the spec (never hand-set); DangerTier
               derived (R-PIPS-DERIVED).
      DONE     C-NODE green; R-ROUTE-* green.
  K15 ROUTE EVENT / MYSTERY OUTCOME / NODE AFFIX
      DECLARE  every reward and cost in ladder currencies (weapon LV, perk rank,
               HP/armour fraction, credits in floors of income, weapon drop);
               an affix that raises threat declares its matching reward.
      BAND     R-MYSTERY-EV; event value rule (order 6 F15); R-RISK-PREMIUM.
      DONE     C-EVENT green.
  K16 SHOP OFFER TYPE
      DECLARE  its value in PP; category weight; availability rules.
      PRICE    GameMath.shopPrice only — a literal credit price fails.
      BAND     R-CREDITS v2 still holds.
      DONE     C-SHOP green.
  K17 REGION (RegionSpec)
      DECLARE  REGION_TP_BUDGET_MULTIPLIER entry, elite weight, BossTable row for
               its last floor, ambience + crest rows, story-region mapping.
      BAND     R-REGION; run-outcome bands.
      DONE     C-REGION green.
  K18 ANY NEW BALANCE NUMBER (the catch-all)
      DECLARE  every new public numeric field in BalanceConfig is either the
               SUBJECT of at least one schema rule, or listed in
               BalanceSchema's UNBANDED table with a one-line reason.
      DONE     C-CONSTANT green.

Enforcement
  E1  RuleKind.ADMISSION holds sub-rules C-ENEMY, C-FAMILY, C-VERB, C-BOSS,
      C-WEAPON, C-ABILITY, C-PERK (incl. keystones), C-ITEM, C-AMMO, C-STATUS,
      C-HAZARD, C-ROOM, C-GENERATOR, C-NODE, C-EVENT, C-SHOP, C-REGION,
      C-CONSTANT. Each iterates the game's OWN content collections (enum values(), or the
      registry after its headless bootstrap), so new content is found without
      anyone listing it. The existing COVERAGE rule is folded in (C-WEAPON,
      C-ITEM, C-AMMO, C-VERB absorb its four checks).
  E2  Failure messages name the kind, the content id and the missing or
      out-of-band item: "ADMISSION C-WEAPON: FLECHETTE_CARBINE — no reference
      scenario where it is best (R-ROLE-1)".
  E3  DECLARATION HARDENING: role, family, damage class, supply stance, BuildTag,
      HEAVY flag and pricing hooks become abstract methods / required builder
      fields where the type allows, so forgetting them fails compilation. Silent
      defaults are allowed only for the documented inheritances (trait from
      family; ladder participation for weapons).
  E4  C-CONSTANT is FORWARD-ONLY: BalanceConfig fields that exist when this order
      lands are recorded in a GRANDFATHERED list in BalanceSchema (with a comment
      that it only ever shrinks). Any field not on it must be covered or
      UNBANDED-with-reason.
  E5  Communication checks are structural only: the glyph id / icon id / string
      id exists and resolves (StoryLocalizationTest already covers story ids);
      whether it reads well is reviewer's call.
  E6  The negative drill: for each C-rule, the implementer adds a deliberately
      unpriced/undeclared dummy LOCALLY, confirms `./gradlew test` fails with the
      E2 message, and reverts it (never committed). The observed messages are
      recorded in the checkpoint handover.

EDGE CASES
----------
  - Content that fits two kinds (a hazard that is also an enemy, e.g. a turret):
    it satisfies BOTH checklists.
  - Hand-made .txt levels: exempt from K12/K13 supply rules (authored), but every
    symbol and every content item they use is still admitted.
  - Removing content: removing an enemy/weapon must not leave a template slot,
    BossTable row, niche scenario or shop offer pointing at it — the same C-rules
    catch the dangling reference.
  - A registry that can only be bootstrapped with LibGDX: not allowed for
    balance-bearing content (the audit must see it headless); if one exists, it
    is split (headless data / render half) as the tileset and audio packages do.
  - An idea file written before this order: its implementer fills the BALANCE
    ADMISSION block at CP0 before building.

RISKS AND UNKNOWNS
  - Switching the rules on may expose existing gaps (an ability never priced, a
    room that places a pickup). Budget CP1-CP4 for small declaration fixes;
    genuine band misses become waivers.
  - Some registries may need a small headless split to be audited; do it in the
    checkpoint that needs it.
  - Editing CLAUDE.md and agent files is a process change: keep each addition to
    a few lines pointing at the authority doc, which stays the single source.
