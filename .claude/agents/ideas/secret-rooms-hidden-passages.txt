OVERVIEW
========
Some wall tiles are lies. A Secret Wall looks, sounds, and raycasts exactly
like a normal wall until the player presses the SEARCH/interact key while
facing it from an adjacent tile. On discovery the wall "breaks" — it converts
to a passable floor tile and reveals whatever is behind it: a loot cache, a
panic-room safe spot, a UAC lore terminal, or a shortcut that skips a chunk of
the level. This is the classic Doom pushwall / DCSS hidden-door staple, adapted
to the strict tile + turn + cardinal constraints of toon3D.

It belongs here because the game is already a corridor crawler about reading
walls. Adding walls that *reward* reading them — a faint seam in the texture, a
hollow thunk when you bump it — turns the act of looking into a skill. It feeds
the exploration and risk/reward roguelike pillars without any new movement
rules: a secret is still just a wall that becomes a floor.


DISCOVERY MECHANIC
==================
Two complementary discovery paths. Both fully respect tile + turn rules.

PATH A — ACTIVE SEARCH (primary, deterministic)
1. Player stands in a floor tile, faces a tile that contains a secret-wall char
   ('h' or 'H' — see TILE SYMBOLS). To the player it looks like a normal wall.
2. Player presses KEY_INTERACT (E, per the keycard-doors doc which rebinds
   strafe-right to F). This is one consumed turn.
3. InteractionDispatcher (from the keycard-doors design) inspects the tile
   directly in front. If it is a secret wall:
      - SecretManager.reveal(column, row) is called.
      - The tile begins its RECESSING animation (a short slide/crumble, like a
        door, but it does NOT auto-close — once open, always open).
      - PlayerController enters the existing INTERACTING lock for
        SECRET_REVEAL_DURATION seconds; player does not move; one turn spent.
   If the tile in front is a plain wall ('x', 'c', etc.) the SEARCH still
   "succeeds" as an action (turn consumed) but produces only a dull
   "nothing here" thunk — no reveal. This means searching is never free and
   spamming it has a small turn cost (relevant once hunger/alert ticks exist).
4. After the animation the tile is permanently a passable floor (the floor
   lighting char it converts to is authored — see TILE SYMBOLS). Player presses
   W to step through.

PATH B — BUMP HINT (passive, non-revealing)
- When the player tries to step (W) into a secret-wall tile, the move is blocked
  exactly like a normal wall (so secrets never break collision expectations),
  BUT the bump produces a distinct hollow "thunk" SFX and a one-frame HUD
  whisper ("...this wall sounds hollow.") on the FIRST bump only.
- The bump never reveals the secret. It only nudges the player to try SEARCH.
- This makes secrets discoverable by feel for players who never read the visual
  seam, while keeping deliberate SEARCH the actual mechanic.

No auto-reveal, no proximity reveal, no random "you found a secret" rolls.
Discovery is always a player decision. (Roguelike pillar: player understands
exactly why they did or did not find it.)


TILE SYMBOLS (new chars)
========================
Checked against all reserved chars (x c v t w space l u f P d p b B T L C m s . O)
and the keycard-doors doc (R Y B doors; r y b decals; E rebind for barrel).
The two new chars below are unused.

| Char | Meaning                                                              |
|------|----------------------------------------------------------------------|
| `h`  | Secret wall — SUBTLE. Raycasts as a plain wall ('x' texture) with a   |
|      | faint authored seam overlay. Hardest to spot. Use for the deepest     |
|      | caches.                                                               |
| `H`  | Secret wall — OBVIOUS. Raycasts as a plain wall but with a visible    |
|      | cracked / mismatched-panel texture. The "fair" secret a careful       |
|      | player will notice. Use for shortcuts and most caches.                |

Both behave identically in logic (solid until searched-revealed); they differ
ONLY in how loud the visual hint is. Designers pick `h` for cruel, `H` for fair.

REVEAL-TARGET FLOOR (what the tile becomes after reveal):
The char a secret converts to is authored via a tiny metadata convention so the
revealed opening matches the room behind it. Default if unspecified: `l`
(normal floor). Authoring options, in order of simplicity:
  - SIMPLE (v1): always convert to `l`. No metadata needed.
  - METADATA LINE (v2): an optional block after the grid in the .txt, one line
    per secret: "SECRET col row floorChar contentTag" (see LEVEL DESIGN).

NOTE: `h`/`H` must be added to Level.isWall() returning TRUE (they are solid
until SecretManager flips them). They must also be reported by a new
Level.isSecretWall(char) helper. After reveal, SecretManager overrides the cell
to the target floor char; Level.isWall then returns FALSE for it.


VISUAL HINTS IN 3D VIEW
=======================
A secret must read as a wall by default, with an honest-but-quiet tell.

WHILE HIDDEN ('H' obvious):
- WallRenderer selects the plain wall texture ('x' = lab_wall_generic.jpg) so
  the silhouette and shading match neighbours exactly, THEN composites a
  secret-overlay texture (lab_wall_cracked.jpg) — a hairline crack, a panel with
  a slightly offset seam, a smear of dried blood pointing at the gap. Same
  distance-shade is applied so it never "pops" brighter than its neighbours.

WHILE HIDDEN ('h' subtle):
- Same plain texture, but the overlay is a single near-invisible vertical seam
  (lab_wall_seam.jpg) at ~25% alpha. Only visible up close and head-on. A player
  who never looks will walk past forever.

DELIBERATELY NO MINI-MAP TELL while hidden — secret walls draw on the mini-map
as ordinary walls (same fill colour). Revealing it is the only way to see the
opening on the map.

REVEAL ANIMATION (RECESSING, reuses door UV-crop math):
- The wall stripe shrinks from full height to zero over SECRET_REVEAL_DURATION
  using the same doorPanelTop / doorTextureSourceHeight helpers the door system
  added to GameMath — the slab sinks into the FLOOR (not the ceiling, to read as
  "panel drops away" rather than "door"). Optional dust puff: a brief brown
  additive flash on that column set.
- During RECESSING the cell still occludes the ray (no early peek), identical to
  a half-open door.
- After reveal: the cell renders as floor; the wall behind/beyond is now visible
  and the mini-map shows the new opening.

POST-REVEAL FRAMING (v2): draw a short ragged "broken edge" sprite at the top of
the opening so revealed secrets look torn open rather than like clean doorways.


LEVEL DESIGN GUIDELINES
=======================
- ONE secret guaranteed per level, TWO max in early levels, up to THREE in big
  late levels. Scarcity keeps them special (DCSS-style — finding one is an event).
- A secret wall tile MUST have: floor on the player-approach side, and a
  reachable floor pocket on the far side (the reward space). Never place a
  secret that opens into another solid wall — it must reveal real space.
- Place subtle `h` secrets where a careful player would suspect: a corridor that
  is one tile shorter than its symmetric twin, a room with a suspicious alcove,
  a dead-end that "should" continue. Reward map-reading, not pixel-hunting.
- Use `H` (obvious) for SHORTCUTS — a cracked wall that lets the player skip back
  to an earlier corridor. Players should be able to find these without frustration.
- Never gate MANDATORY progression (the level exit, the only keycard) behind a
  secret. Secrets are always optional enrichment. (Anti-softlock rule, mirrors
  the keycard placement rules.)
- Pair secrets with environmental storytelling: a corpse ('m') slumped against a
  hollow wall, a blood-smear ('.') pointing at the seam, an oil trail ('O')
  leading to it. The decals ARE the diegetic hint.
- Good spots: behind explosive/radioactive barrels, at the back of unlit ('u')
  dread rooms, beside terminal walls ('t').

METADATA AUTHORING (optional, v2):
After the tile grid, an optional section lets the designer tag each secret:

    ---SECRETS---
    SECRET 14 9 l CACHE
    SECRET 31 22 u SAFEROOM
    SECRET 5 40 l SHORTCUT

Fields: column, row, floor-char-after-reveal, content-tag. If omitted, the
secret converts to 'l' and its content is just whatever decals/props are
authored in the tiles behind it. The tag is a hint to the content/loot system
(see CONTENTS), not strictly required.


CONTENTS / REWARD TYPES
=======================
Each secret opens into a small authored pocket of tiles. Reward archetypes:

1. LOOT CACHE (most common) — 1–3 reward tiles behind the wall: dropped shotgun
   ('s'), medkit/ammo decals (from medkit + shotgun docs), crates ('C') to break.
   The "you found the good stuff" payoff.
2. SAFE ROOM — a tiny sealed pocket (1–4 floor tiles) with NO enemy spawns and
   often a lit ('  ') floor. A place to heal between fights. The secret IS the
   safety; nothing flashy inside. Tag SAFEROOM.
3. LORE TERMINAL — a terminal wall ('t') or terminal prop ('T') inside the pocket
   that, on interact, prints a UAC log fragment (corporate-cynicism flavour:
   "MEMO: do not feed the test subjects after 18:00"). Pure flavour + worldbuilding.
   Tag LORE.
4. SHORTCUT PASSAGE — the pocket is actually a corridor connecting back to an
   earlier part of the level, letting the player skip backtracking or escape a
   pursuing enemy pack. Often an `H` (obvious) secret. Tag SHORTCUT.
5. AMBUSH / MIMIC (rare, spicy) — the cache contains loot AND one dormant enemy
   that activates on reveal. Teaches that greed has a price. Use sparingly
   (≤ 1 per 4 secrets). Tag AMBUSH.

Reward weighting (placeholder): CACHE 45%, SHORTCUT 25%, SAFEROOM 15%,
LORE 10%, AMBUSH 5%.


TECHNICAL NOTES
===============
NEW PACKAGE / CLASSES (ge.tbegvadze.toon3d.secret — sibling of door package):

  secret/SecretState (enum)
    HIDDEN, RECESSING, REVEALED.

  secret/SecretWall (POJO)
    int tileColumn, int tileRow
    SecretState state
    float animationProgress      // 0..1 during RECESSING
    char hiddenChar              // 'h' or 'H' (drives overlay choice)
    char revealedFloorChar       // what the cell becomes (default 'l')
    String contentTag            // optional, from metadata; may be null

  secret/SecretManager
    Built once at level load by scanning the matrix for 'h'/'H'.
    Mirrors DoorManager's architecture exactly.
    Fields:
      Map<Long, SecretWall> secretsByPackedKey   // key = (col<<32)|(row&0xFFFFFFFF)
      pre-sized to count found at load; no runtime growth.
    Public API:
      void update(float deltaTime)
        Advances RECESSING walls; promotes to REVEALED at progress >= 1,
        then writes revealedFloorChar back into Level so collision/raycast flip.
      boolean isSecretWall(int column, int row)        // state == HIDDEN/RECESSING
      boolean isHidden(int column, int row)
      SecretState getStateAt(int column, int row)
      float getRecessFractionAt(int column, int row)   // 0 hidden, progress recessing, 1 revealed
      char hiddenCharAt(int column, int row)           // 'h' or 'H', for overlay selection
      boolean reveal(int column, int row)              // HIDDEN -> RECESSING; returns true if a secret was here
      boolean searchEmptyHit(int column, int row)       // not a secret -> returns false (caller plays dull thunk)

MODIFIED CLASSES:

  level/Level
    - Add: public static boolean isSecretWall(char cell) { return cell=='h'||cell=='H'; }
    - isWall(): return TRUE for 'h' and 'H' (solid until revealed).
    - Add a runtime override hook so SecretManager can rewrite a revealed cell's
      char to the floor char (Level already mutates 'd' state externally; mirror
      that). Simplest: Level.setCell(column,row,char) package-or-controlled
      setter used only by SecretManager.update on promotion to REVEALED.
    - isBlockedAt(column,row,...) (added by doors): also consult SecretManager so
      a HIDDEN/RECESSING secret blocks movement and a REVEALED one does not.
      Recommend a unified BlockerQuery the controller passes both DoorManager and
      SecretManager to, OR have SecretManager rewrite the cell to floor on reveal
      so the existing isWall check just works (preferred — minimal coupling).

  level/LevelLoader
    - No parse change for the grid ('h'/'H' are just chars).
    - Parse the optional ---SECRETS--- block (v2) into a list passed to World,
      which feeds SecretManager. v1: skip the block, default everything.

  input/PlayerController
    - SEARCH/interact (E) already routes through InteractionDispatcher
      (keycard-doors doc). Add a secret-wall branch: if the front tile is a
      secret wall, call SecretManager.reveal and enter the existing INTERACTING
      lock for SECRET_REVEAL_DURATION; one turn consumed.
    - W into a HIDDEN secret: blocked (normal wall behaviour) + fire a
      SecretBumpEvent the FIRST time per tile (drives the hollow-thunk SFX + the
      one-time HUD whisper). Track "bumped" per SecretWall to fire only once.

  render/WallRenderer
    - Load lab_wall_cracked.jpg ('H' overlay) and lab_wall_seam.jpg ('h' overlay)
      in constructor; add to disposed list. Hold a SecretManager reference.
    - When the DDA hit cell is HIDDEN: draw the plain wall stripe ('x' texture)
      as usual, then draw the matching overlay stripe at the same drawBottom/
      drawTop/texColumn with the same shade. ('h' overlay at low alpha.)
    - When RECESSING: reuse the door UV-crop path but anchor the shrink to the
      ceiling-side so the slab sinks into the FLOOR (invert door's anchor), via
      a getRecessFractionAt lookup. Treat as occluding until fraction >=
      SECRET_REVEAL_THROUGH_THRESHOLD (mirror DOOR_OPEN_THROUGH_THRESHOLD).
    - When REVEALED the cell is already floor (Level rewrote it) — nothing special.

  render/LevelRenderer (mini-map)
    - HIDDEN secrets: draw as ordinary wall fill (NO tell). REVEALED: draw as
      floor (the new opening appears). This is the only map change.

  world/World
    - On construction (after LevelLoader): new SecretManager(level, secretMetadata).
      Pass it into PlayerController, WallRenderer, LevelRenderer, and
      InteractionDispatcher.
    - In update(): call secretManager.update(deltaTime) BEFORE
      playerController.update(deltaTime) (fresh state this frame), same ordering
      rule as DoorManager.
    - On dispose: nothing — SecretManager owns no GPU resources.

  util/GameMath
    - Reuse doorPanelTop / doorTextureSourceHeight. Add a sibling
      secretRecessPanelBottom(drawBottom, drawTop, recessFraction) if the
      floor-anchored sink needs different geometry (standard 3-line comment block,
      derivation: slab top fixed at drawTop, bottom rises toward drawTop as
      recessFraction -> 1).

BALANCE NOTES
=============
- SECRET_REVEAL_DURATION 0.45s (placeholder): deliberately longer than a step
  (0.12) and a door (0.30) so revealing feels like prying open a panel.
- SEARCH always costs one turn, even on a plain wall ("nothing here"). This is
  the cost that keeps wall-tapping from being free; it only matters once
  hunger/alert/global-tick consequences exist. Until then it is harmless and
  the dull thunk is the only feedback. Flag for revisit when tick costs land.
- Density: 1 guaranteed, 2 typical, 3 max per level (placeholder). Tune toward
  "a run averages finding ~1 secret it didn't have to" — secrets the player
  misses are fine and intended.
- `h` (subtle) vs `H` (obvious) ratio: lean ~70% `H` so the game feels fair;
  reserve `h` for the one cruel deep cache per several levels.
- AMBUSH frequency capped at ~1 per 4 secrets so opening a wall stays mostly
  positive — greed punished occasionally, not reflexively distrusted.


INTERACTIONS
============
1. DOORS / DoorManager: SecretManager is a near-clone of DoorManager (state
   machine + UV-crop reveal + load-time scan). Shares the GameMath panel helpers
   and the World update-ordering rule. A revealed secret does NOT auto-close
   (the single behavioural difference) — once open, always open.
2. KEYCARD DOORS / InteractionDispatcher: SEARCH reuses the same E (interact)
   key and dispatcher routing the keycard doc introduced. The dispatcher checks
   secret walls in the same front-tile lookup it uses for doors and terminals.
3. ENEMY SYSTEM: AMBUSH secrets spawn a dormant Corruptor/Vortex Eye that
   activates on reveal. Enemies cannot reveal or path through HIDDEN secrets
   (they are walls for AI). A SHORTCUT secret, once revealed, becomes valid
   pathfinding space — pursuing enemies can follow the player through it.
4. LABORATORY LIGHTING: a secret behind an unlit ('u') wall is dramatic; the
   revealed pocket's authored floor char sets its brightness — a SAFEROOM opening
   into lit ('  ') space gives a literal "light at the end" beat.
5. BILLBOARD PROPS / DECALS: corpses, blood, and oil are the diegetic hints
   pointing at secrets; cache rewards (shotgun 's', crates 'C', medkits) live in
   the revealed pocket using the existing billboard pipeline.
6. GLOBAL TICK / RED ALERT: SEARCH consuming a turn ties into any global-tick
   consequences; revealing during a RED ALERT could be louder and alert enemies
   (mirrors the keycard denial-during-alert idea).


OPEN QUESTIONS
==============
1. Should a found-secret counter appear on the end-of-level summary ("SECRETS:
   2/3"), Doom-style? Strongly recommend yes once a level-end screen exists.
2. Floor-anchored sink vs ceiling-anchored slide for the reveal — does the
   "panel drops into floor" read clearly in the raycaster, or should it crumble
   in place (alpha fade)? Prototype both; alpha-fade is the cheap fallback.
3. Should `h` secrets ever be SFX-only (no visual seam at all) for maximum
   cruelty, relying solely on the bump-thunk? Probably reserve for a single
   "vault" secret per game; default `h` keeps the faint seam.
4. Does the first-bump HUD whisper persist if the player reloads / re-enters?
   Per-run state; reset on level load. Confirm with save-system design later.
5. Should revealing a SHORTCUT secret update enemy pathfinding immediately, or
   only on the next enemy turn? Recommend next-turn for consistency with the
   turn engine.
6. Multiple secret walls forming a 2+ tile secret door (wide opening): allowed?
   v1 treats each 'h'/'H' tile independently (search each). A multi-tile combined
   reveal is a v2 nicety.
