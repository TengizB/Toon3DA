B. Scavenger Rounds — ON_KILL (gun only)
──────────────────────────────────────────────
On kill, chance to refund ammo to the player's reserve for THIS weapon's
ammo type. Never refunds above the ammo capacity cap.

In AbilityResolver.onKill():

    if (weapon.hasAbility(WeaponAbility.SCAVENGER_ROUNDS) && !weapon.isMelee()) {
        float refundChance = weapon.abilityMagnitude(WeaponAbility.SCAVENGER_ROUNDS);
        if (rng.nextFloat() <= refundChance) {
            int refundAmount = (weapon.getWeaponLevel() >= GameBalance.SCAVENGER_HIGH_LEVEL_THRESHOLD)
                               ? GameBalance.SCAVENGER_REFUND_HIGH_LEVEL
                               : GameBalance.SCAVENGER_REFUND_BASE;
            AmmoType ammoType = getAmmoTypeForWeapon(weapon);
            inventory.addAmmo(ammoType, refundAmount);
            eventTextSystem.showText("+" + refundAmount + " AMMO", EventTextSystem.AMMO_COLOR);
        }
    }

getAmmoTypeForWeapon(WeaponProfile weapon) — a private helper in AbilityResolver
that maps weapon display name (or a weapon type enum) to AmmoType:
  - Shotgun, DoubleBarrel → AmmoType.SHELLS
  - Chaingun, Railgun     → AmmoType.BULLETS
  - PlasmaRifle           → AmmoType.CELLS
  - GrenadeLauncher       → AmmoType.ROCKETS
  - Incinerator           → AmmoType.CELLS  (or a FUEL type if it exists)

A cleaner approach: add getAmmoType() to the WeaponProfile interface and have
each gun subclass return its AmmoType. Then AbilityResolver calls
weapon.getAmmoType() without needing a switch.

Inventory.addAmmo(AmmoType ammoType, int amount): verify it exists and respects
the ammo cap (ItemConstants.AMMO_CAP_*). If the method is named differently
(e.g., addItem, giveAmmo), use the existing name.

E. Field Medic Rounds — ON_KILL (universal)
──────────────────────────────────────────────
Chance on kill to spawn a Small Medkit pickup at the dead enemy's tile.

In AbilityResolver.onKill():

    if (weapon.hasAbility(WeaponAbility.FIELD_MEDIC_ROUNDS)) {
        float dropChance = weapon.abilityMagnitude(WeaponAbility.FIELD_MEDIC_ROUNDS);
        if (rng.nextFloat() <= dropChance) {
            groundItemSpawner.spawnItem(killedEnemy.tileColumn, killedEnemy.tileRow,
                                        ItemType.MEDKIT_SMALL);
            eventTextSystem.showText("MEDKIT DROP!", EventTextSystem.MEDKIT_COLOR);
        }
    }

groundItemSpawner.spawnItem(int tileColumn, int tileRow, ItemType itemType):
  - Creates a GroundItem at the specified tile.
  - If ItemType.MEDKIT_SMALL does not exist, use the closest equivalent medkit type.
  - If the tile is occupied (wall, another item), try the player's adjacent tile as
    a fallback; if that too is occupied, skip the drop silently.

GameBalance.FIELD_MEDIC_HEAL_AMOUNT is not used here — it specifies how much the
medkit itself heals when the player picks it up. That value should already be part
of the medkit's ItemType definition. If not, add it to ItemConstants.java.

IMPLEMENTATION NOTES
====================
- Scavenger Rounds refunds to the RESERVE (not the clip). It does not refill
  the current clip; the player must reload manually. This keeps reload decisions
  meaningful.
- Field Medic Rounds and Salvage Strike (order-6) can both fire on the same kill
  if the weapon has both. They are independent rolls and both can succeed.
- Credit Fang does not display credits during combat in the main HUD (the right
  panel is for ammo). Show credits total only in the shop/inventory screen (order-11).
  The event text "+N CR" is the only in-combat feedback.
- If the shop system is not yet implemented, Credit Fang still accumulates credits
  in PlayerStats. No functionality is lost; the credits just aren't spendable yet.
- Run `./gradlew build` after implementation.
