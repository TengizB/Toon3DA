ONE-PARAGRAPH VISION
====================
Instead of a blind staircase down, the descent becomes a CHOICE. The whole run is laid out
as a randomly generated, forward-only branching map of the UAC facility — a holographic
"FACILITY NAV" console the player reads like Slay the Spire's act map or FTL's sector chart.
Each node advertises its flavour (procedural icon + one-line risk/reward): combat, elite
hotzone, supply cache, shop, med-bay/rest, mystery, narrative/event, region gate, and forced
boss convergences. Picking a node routes you through a DIFFERENT kind of level — sometimes a
bespoke, hand-feeling layout, sometimes a re-parameterised standard floor. The map is DIFFERENT
EVERY RUN (seeded from the run's master seed). Two extensibility promises are load-bearing:
(1) adding a NEW level generator later means registering it once and it can appear on the map,
and (2) adding a NEW node type later means registering it once and it joins the pool. All
visuals are 100% procedural — no image assets, ever — drawn with ShapeRenderer / FrameBuffer
the way the vitals HUD and weapon sprites already are.

HOW THE SPLIT MAPS ONTO THE REAL CODEBASE (verified 2026-07-08)
===============================================================
- Generators already share `level/ILevelGenerator` with `generate(int dungeonDepth)`. Existing
  impls: LevelGenerator, LinearCorridorGenerator, CavernGenerator, BossArenaGenerator,
  StartGameLevelGenerator. order-1's GeneratorRegistry formalises this list into a lookup.
- `World.pickLevelGenerator(int depth, long seed)` (World.java ~line 1851) is the CURRENT
  generator-selection choke point and already special-cases boss floors via
  `GameMath.isBossFloor(depth)`. order-3 replaces its body with "ask the chosen RouteNode".
- `World.onDescentRequested()` (~line 394) currently flips straight to `RunPhase.FADING_OUT`.
  order-3 inserts `RunPhase.ROUTE_SELECT` in front of it.
- `RunPhase` enum (World.java line 76) gains `ROUTE_SELECT`; it already models overlays exactly
  like this (INVENTORY_OPEN, SHOP_OPEN, LEVEL_UP_OVERLAY) so the pattern is established.
- `floorSeed(runSeed, depth)` (World.java ~1837) is the deterministic per-floor seed the map
  generation reuses so a run's whole map is reproducible from its master seed.
- `LevelGenConfig` (mutable POJO) is exactly the object a node hands the generator to bias a
  floor (order-3/order-7). Boss floors, shop seeding (`seedVendingMachines`) already keyed on depth.
- Visuals follow the established procedural-only pipeline (procedural-vitals-hud.txt,
  WeaponHudRenderer FrameBuffer, ShapeRenderer). No new texture assets anywhere.


DELETED FROM THE ORIGINAL PITCH / CHANGED ON REFINEMENT
=======================================================
- Original proposed revealing "only the next 1-2 hops." Refined: the WHOLE run graph is
  generated up front and revealed region-by-region (StS act reveal), because it makes the map
  a real planning object and the "random each time" promise legible. Fog + scanner still exist
  as a reveal LAYER on top (order-6).
- Original left generation ad-hoc. Refined: an explicit seeded DAG with region bands so new
  generators/nodes slot in by weight, not by code edits (the core extensibility promise).
- Original bundled visuals into one paragraph. Refined: a dedicated visual spec (order-4/5/6)
  because the product owner flagged look & feel as first-class.
