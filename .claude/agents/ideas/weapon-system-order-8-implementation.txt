TITLE: Weapon System Order 8 — DoT & Status Abilities

WHAT WAS BUILT
==============
Three ON_HIT weapon abilities that apply status effects through the unified
StatusEffectController pipeline: REND (bleed DoT), INCENDIARY (burn DoT),
and STAGGER_ROUNDS upgraded from a stub to proper status system integration.

=============

  - Order determines iteration priority in tickAll() and ordinal-indexed
    color arrays. All downstream arrays updated to match.

status/StatusEffectController.java
  - applyPlayerTickEffect() / applyEnemyTickEffect(): added BLEED case —
    calls applyDoTDamage(effect.magnitude), same as BURNING (fixed magnitude,
    no stacks).
  - stackModeFor(): BLEED returns REFRESH_DURATION (re-applying refreshes

HOW IT CONNECTS TO THE EXISTING SYSTEM
=======================================
- AbilityResolver.onHit() is called by Weapon.fire() after damage is applied.
  REND and INCENDIARY run after CLEAVE; STAGGER_ROUNDS is in the original
  position but now calls the status controller instead of the stub.
- StatusEffectController.tickAll() runs once per world turn (StatusEffectSubscriber,
  before enemy AI). BLEED ticks like BURNING — deals magnitude DoT, decrements
  duration, removes on expiry.
- Enemy/Player EnumMaps auto-expand when BLEED was added to StatusType because
  buildEffectsMap() iterates StatusType.values().
- STAGGER_ROUNDS stun is now subject to enemy resistance: SHELL_BRUTE halves
  duration (existing rule), bosses are immune (new rule).
- INCENDIARY reuses BURNING; the REFRESH_DURATION stack mode means firing an
  INCENDIARY weapon at a burning enemy refreshes (keeps the longer timer),
  never duplicates the effect.

WHAT IS NOT IMPLEMENTED
=======================
- Incinerator-specific extend-burn bonus (INCENDIARY_INCINERATOR_EXTRA_TURNS)
  was deferred. The REFRESH_DURATION mode already refreshes burns; the extra
  turn extension would require knowing the weapon is the Incinerator subclass,
  which is not exposed cleanly through WeaponProfile. Implement in a dedicated
  Incinerator pass when the weapon is revisited.
- abilityMagnitude(REND/INCENDIARY) returns the pre-scaled value from
  AbilityInstance. The WeaponRoller (order-11) must roll these abilities using
  REND_DAMAGE_PER_TURN_BASE/PER_LEVEL/CAP and INCENDIARY_BURN_PER_TURN_BASE/
  PER_LEVEL/CAP from GameBalance when generating loot. Until order-11, weapons
  with REND/INCENDIARY won't appear in the wild.
