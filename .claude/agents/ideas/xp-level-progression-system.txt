OVERVIEW
========
The numeric spine of per-run character growth. Killing enemies grants XP; XP
fills a level curve; each level-up pauses the world and offers THREE concrete
stat upgrades (+max HP, +armor, +weapon damage multiplier). Descending to a new
dungeon floor scales every enemy's HP and damage by a depth coefficient. All
tuning lives in ONE class, GameBalance.java, so a designer can rebalance the
whole economy without touching gameplay code.

This is the deliberately SIMPLE, ship-first version of progression: three fixed
stat choices, a closed-form XP curve, multiplicative enemy scaling. It is the
concrete foundation the richer boon system
(levelup-stim-boon-choice-progression.txt) can later be built on top of — that
doc's ProgressionManager + LevelUpOverlay become the home for these mechanics,
and the three stat choices here are exactly that doc's "CORE STAT BOONS" with
hard numbers attached. See DEDUPLICATION below: this doc OWNS the numbers, the
curve, the HUD bar, and enemy scaling; it does NOT re-invent the boon-pool /
meta-unlock layer.

- enemy_system.txt (IMPLEMENTED): defines Enemy with int health, melee/ranged

NO NEW TILE SYMBOL IS REQUIRED for this feature. Progression is entirely an
entity/UI/state-layer system. (The boon doc says the same.)


GAMEPLAY LOOP
=============
EARN XP (passive, every kill):
1. Player fires → enemy HP <= 0 → EnemyManager removes it and stamps a corpse
   (existing behavior).
2. On that death, EnemyManager calls
   progressionManager.awardExperience(enemy.getXpReward()).
3. enemy.getXpReward() = base XP for that type, already baked at spawn time from
   GameBalance (NOT scaled by depth — see BALANCE NOTES, "why XP is flat").
4. A "+N XP" entry posts to the message log / kill feed (reuse existing feed).
5. The HUD XP bar (left panel) advances toward the next-level threshold.

LEVEL-UP TRIGGER (turn-gated, never mid-animation):
1. After the kill/damage resolution for the turn completes, ProgressionManager
   checks: experience >= experienceForNextLevel(currentLevel)?
2. If yes, it sets pendingLevelUps += 1 (a COUNT, so a chain explosion that
   dumps a big XP lump can queue multiple level-ups). It does NOT interrupt the
   in-flight turn.
3. World only OPENS the upgrade overlay when the turn engine is idle
   (PlayerController is IDLE, no fade/transition in progress). This guarantees
   the choice never appears mid-slide or mid-enemy-phase.

THE UPGRADE CHOICE (the decision):
1. World enters phase LEVEL_UP. The 3D view dims; an overlay renders three
   cards. The turn engine is frozen — this costs NO turn; the marine stands on
   the same tile, same facing.
2. PlayerController input is suppressed; a dedicated overlay input reads
   1 / 2 / 3 (and optionally LEFT/RIGHT + ENTER).
   - Card 1 — VITALITY: max HP += GameBalance.LEVEL_UP_MAX_HP_BONUS, and
     current HP += the same amount (you gain the new headroom immediately, NOT a
     full heal — see BALANCE NOTES).
   - Card 2 — PLATING: max armor += GameBalance.LEVEL_UP_MAX_ARMOR_BONUS, and
     current armor += the same amount.
   - Card 3 — WEAPON: weaponDamageMultiplier *= (1 +
     GameBalance.LEVEL_UP_DAMAGE_MULT_BONUS). Stacks multiplicatively each pick.
3. Player presses 1/2/3 → the chosen stat applies → currentLevel += 1 →
   experience -= experienceForNextLevel(oldLevel) (carry the overflow XP) →
   pendingLevelUps -= 1.
4. If pendingLevelUps > 0, present the next card screen back-to-back. Else the
   overlay slides out and World returns to PLAYING; the player resumes from the
   same tile/facing.

DUNGEON DESCENT SCALING (on '>' transition, existing system):
1. Player steps on '>' → existing descent flow runs (stairs doc): depth += 1,
   World.rebuildForLevel(nextFloor).
2. Inside rebuildForLevel, AFTER the new EnemyManager is built, World calls
   enemyManager.applyDepthScaling(depth) (or each enemy is spawned already
   scaled — see TECHNICAL NOTES "where scaling applies").
3. Each enemy's effective HP and damage are multiplied by the depth coefficient
   (see GameBalance). The marine's level/XP/stats PERSIST (the stairs doc
   already carries HP/armor/weapons down). XP rewards stay at base.


PLAYER EXPERIENCE
=================
- Every kill ticks a bar the player watches fill. The level-up is a reward beat
  that breaks combat tension and hands the player agency.
- The three-card choice is a real decision under run state: bleeding out and low
  on a deep floor? Take VITALITY for the immediate HP. Tanking a Corruptor pack?
  PLATING. Want to two-shot Revenants instead of three-shot? WEAPON. Over a run
  these picks compound into a recognizable lean (glass-cannon damage stack vs
  bunker tank), satisfying the run-identity pillar.
- Descent escalation is FELT, not told: floor 4 enemies visibly soak more shells
  and hit harder than floor 1. The player learns "deeper = deadlier" and weighs
  "sweep this floor for one more level before I take the stairs?" against the
  stairs doc's commitment tension.
- Readable death: because scaling is a published coefficient and damage is
  turn-based, a dead player can reconstruct "the depth-5 Corruptor hit for 28,
  not 14 — I should have leveled VITALITY."

NEW PACKAGE & CLASSES
---------------------
- ge.tbegvadze.toon3d.progression  (NEW package; same package the boon doc
  proposes, so the two designs converge cleanly).

- GameBalance  (ge.tbegvadze.toon3d.progression.GameBalance)
  ALL tuning constants for XP, curve, level-up bonuses, and enemy scaling.
  Pure constants + a few pure helper methods. No LibGDX, no state.
  NOTE: per project rule, raw magic numbers normally live in Constants.java.
  GameBalance is a DESIGNER-FACING grouping of balance knobs; treat it as a
  themed extension of Constants (the java-architect may instead choose to put
  these directly in Constants.java with an XP_/LEVEL_UP_/ENEMY_SCALE_ prefix —
  either is acceptable; the constant NAMES below are the contract). Recommend a
  dedicated class so a designer edits one small file.

  Fields (defaults in GAMEBALANCE CONSTANTS section):
    XP reward per enemy type (indexed by spawn type 1-5).
    XP curve coefficients (base, linear, exponent or growth factor).
    Level-up stat bonuses (HP, armor, damage mult step).
    Enemy depth-scaling coefficients (HP factor, damage factor, optional caps).

  Helper methods (pure, mirrored into GameMath if they involve a real formula):
    static int xpRewardForEnemyType(int enemyType)
    static int experienceForNextLevel(int currentLevel)
    static float enemyHealthScale(int depth)
    static float enemyDamageScale(int depth)

- ProgressionManager  (ge.tbegvadze.toon3d.progression.ProgressionManager)
  Owns the live run-progression state. One instance, owned by World, PERSISTS
  across floors (must survive rebuildForLevel — keep it in a World field that is
  NOT rebuilt, like the player/inventory).
  Fields:
    int currentLevel            (starts at 1)
    int experience              (XP toward next level, carries overflow)
    int experienceForNextLevel  (cached = GameBalance.experienceForNextLevel(currentLevel))
    int pendingLevelUps         (queued, drained by the overlay)
    float weaponDamageMultiplier (starts 1.0; the WEAPON upgrade scales it)
  Methods:
    void awardExperience(int amount)   // experience += amount; while
                                       // experience >= experienceForNextLevel:
                                       //   experience -= experienceForNextLevel;
                                       //   pendingLevelUps++;
                                       //   (recompute the NEXT threshold using
                                       //    currentLevel + pendingLevelUps)
                                       // does NOT mutate stats — only queues
    boolean hasPendingLevelUp()        // pendingLevelUps > 0
    void applyUpgrade(UpgradeChoice c, Player player)
                                       // mutate stat, currentLevel++, recache
                                       // experienceForNextLevel, pendingLevelUps--
    float getXpBarFraction()           // experience / (float) experienceForNextLevel, clamp 0..1
    int getCurrentLevel()
    float getWeaponDamageMultiplier()
  THREADING/ALLOC: all integer math, no per-call allocation.

- UpgradeChoice  (enum in the progression package)
    VITALITY, PLATING, WEAPON
  Lightweight; the overlay maps key 1/2/3 → enum → applyUpgrade.

- LevelUpOverlay  (ge.tbegvadze.toon3d.render.LevelUpOverlay implements
  Renderable, Disposable)
  Pre-allocates everything in its constructor (BitmapFont/Glyph layouts, a
  reusable ShapeRenderer or the shared whitePixel pattern). render() draws the
  dim quad + three cards. NO allocation in render(). Reads ProgressionManager +
  Player to display current/after values.
  (If the boon doc later ships, this overlay is reused / generalized to draw
  boon cards; for v1 the three cards are fixed.)

XP CURVE (closed form, configurable)
------------------------------------
Use a polynomial-with-exponent curve so early levels come fast and later levels
stretch out, without runaway numbers:

    experienceForNextLevel(level) =
        round( XP_CURVE_BASE * pow(level, XP_CURVE_EXPONENT) )
        + XP_CURVE_LINEAR * (level - 1)

  - level is the player's CURRENT level (>= 1); the result is XP needed to reach
    level+1.
  - XP_CURVE_BASE scales the whole curve.
  - XP_CURVE_EXPONENT between 1.0 (linear-ish) and 2.0 (steep). ~1.5 gives a
    pleasant ramp.
  - XP_CURVE_LINEAR adds a flat slope so very early levels are not trivially
    cheap.
  Edge cases: level >= 1 always (clamp). pow with float base/exponent — fine for
  small level counts; cache experienceForNextLevel so pow runs once per level-up,
  never per frame.

ENEMY DEPTH SCALING (geometric)
-------------------------------
    enemyHealthScale(depth) = pow(ENEMY_HP_SCALE_PER_DEPTH,  depth - 1)
    enemyDamageScale(depth) = pow(ENEMY_DMG_SCALE_PER_DEPTH, depth - 1)

  - depth starts at 1 (STARTING_DEPTH from stairs doc) → scale = 1.0 on floor 1
    (no scaling, floor 1 stays gentle per the stairs doc's "depth 1 GENTLE"
    rule and the meaningful-death pillar).
  - Geometric (multiplicative) so each floor is a fixed % harder than the last.
  - Optional hard caps (ENEMY_HP_SCALE_CAP / ENEMY_DMG_SCALE_CAP) so very deep
    runs do not become unkillable; clamp the result.
  Edge case: depth < 1 clamps to 1.

BALANCE NOTES
=============
- Why XP is FLAT (not depth-scaled): if XP scaled with depth, the player's level
  would track depth automatically and the curve would feel meaningless. Keeping
  XP flat means deeper floors give the SAME XP per kill but enemies are tougher,
  so the player levels SLOWER relative to threat the deeper they push — the
  classic roguelike pressure that rewards thorough early floors. Flag as a knob:
  if deep runs feel under-leveled, add a small XP_DEPTH_BONUS_PER_FLOOR.
- Why VITALITY/PLATING add headroom + current (not full heal): a full heal makes
  VITALITY the auto-pick when hurt and trivializes attrition (the stairs doc's
  "carry your wounds down" tension). Adding only the bonus amount keeps the
  choice honest. The boon doc's heal-to-full Vitality is a SEPARATE, stronger
  rarer option for the later boon pool — do not conflate.
- WEAPON multiplier is multiplicative and uncapped by design: a player who
  stacks it 5x reaches ~1.61x damage — strong but not absurd, and they paid for
  it by skipping survivability. Watch for it trivializing bosses; cap via a soft
  ceiling if needed.
- Curve first promotion at ~18 XP (1-2 kills) is intentional: the player learns
  the level-up flow in room 1. Primary tuning knob is XP_CURVE_BASE.
- Floor 1 scale = 1.0x is mandatory (pillar: a fresh run must be clearable with
  starting kit). Enemy scaling only bites from floor 2.
- All five XP rewards should be re-checked against each enemy's actual HP once
  the full roster (Ghoul/Crawler/Revenant) is finalized in enemy_system.
