B. Rend (BLEED) — ON_HIT
──────────────────────────────────────────────
Applies or refreshes a Bleed status effect on the hit enemy.
If the enemy already has Bleed, REFRESH the duration (do not stack damage separately).

In AbilityResolver.onHit():

    if (weapon.hasAbility(WeaponAbility.REND)) {
        float bleedPerTurn = weapon.abilityMagnitude(WeaponAbility.REND);
        int bleedDamage = Math.max(1, Math.round(bleedPerTurn));
        enemyManager.applyStatusEffect(hitEnemy,
            StatusEffectType.BLEED, bleedDamage, GameBalance.REND_DURATION_TURNS);
        eventTextSystem.showText("BLEED!", EventTextSystem.BLEED_COLOR);
    }

StatusEffectType.BLEED behavior (in the status effects system):
  - Each player turn, all bleeding enemies take `bleedDamage` (stored on the effect).
  - Duration counts down; on expiry the bleed clears.
  - Bleed does not respect armor (it is internal bleeding).
  - Bleed CAN kill an enemy.
  - Visual: enemy tint shifts toward red while bleeding (optional, if EnemyRenderer
    supports a status tint — check roguelike_order_8).

C. Incendiary (BURN) — ON_HIT
──────────────────────────────────────────────
Applies a Burn status effect. For the Incinerator specifically, Incendiary
instead extends an existing burn's duration by INCENDIARY_INCINERATOR_EXTRA_TURNS.

In AbilityResolver.onHit():

    if (weapon.hasAbility(WeaponAbility.INCENDIARY)) {
        float burnPerTurn = weapon.abilityMagnitude(WeaponAbility.INCENDIARY);
        int burnDamage = Math.max(1, Math.round(burnPerTurn));

        boolean isIncinerator = "Incinerator".equals(weapon.getDisplayName());
        if (isIncinerator && hitEnemy.hasStatusEffect(StatusEffectType.BURN)) {
            // Extend existing burn duration
            hitEnemy.extendStatusEffect(StatusEffectType.BURN,
                                         GameBalance.INCENDIARY_INCINERATOR_EXTRA_TURNS);
        } else {
            enemyManager.applyStatusEffect(hitEnemy,
                StatusEffectType.BURN, burnDamage, GameBalance.INCENDIARY_BURN_DURATION);
        }
        eventTextSystem.showText("BURN!", EventTextSystem.BURN_COLOR);
    }

BETTER APPROACH than string-matching the display name: add a WeaponTag enum or
a boolean isIncinerator() method to the Incinerator subclass, and expose it through
WeaponProfile as getWeaponTag(). Alternatively, the Incinerator's base burn
effect (applied in its own marchShot, not via this ability) already extends
duration; the Incendiary ability on a non-Incinerator simply applies a fresh burn.
The distinction can be removed if complexity isn't worth it.

StatusEffectType.BURN behavior:
  - Same as BLEED but deals fire damage (may respect fire immunity on some enemies).
  - Incinerator enemies and fire-type enemies may be immune (check enemy flags).
  - Visual: enemy tint orange/yellow while burning.

D. Stagger Rounds (STUN) — ON_HIT (finalized here)
──────────────────────────────────────────────
Stagger Rounds was sketched in order-4 using a stub. Finalize it via the status
effects system:

In AbilityResolver.onHit():

    if (weapon.hasAbility(WeaponAbility.STAGGER_ROUNDS)) {
        if (hitEnemy.canBeStunned()) {
            float stunChance = weapon.abilityMagnitude(WeaponAbility.STAGGER_ROUNDS);
            if (rng.nextFloat() <= stunChance) {
                enemyManager.applyStatusEffect(hitEnemy,
                    StatusEffectType.STUN, 0, GameBalance.STAGGER_STUN_DURATION);
                eventTextSystem.showText("STUN!", EventTextSystem.STUN_COLOR);
            }
        }
    }

StatusEffectType.STUN behavior:
  - Enemy skips its next `duration` AI turns.
  - `damage` parameter is 0 (stun deals no per-turn damage).
  - canBeStunned() is a flag on Enemy / EnemyType. Boss enemies are not stunable.
  - Replace any stub EnemyManager.applyStun() added in order-4 with this call.

  public void applyStatusEffect(Enemy enemy, StatusEffectType type,
                                  int damagePerTurn, int turns) {
      // If enemy already has this type, refresh duration:
      for (StatusEffect e : enemy.statusEffects) {
          if (e.type == type) { e.turnsRemaining = turns; return; }
      }
      enemy.statusEffects.add(new StatusEffect(type, damagePerTurn, turns));
  }

  // In EnemyManager's per-turn tick handler — add after all enemy actions:
  for (Enemy enemy : livingEnemies) {
      Iterator<StatusEffect> iterator = enemy.statusEffects.iterator();
      while (iterator.hasNext()) {
          StatusEffect effect = iterator.next();
          if (effect.type != StatusEffectType.STUN && effect.damagePerTurn > 0) {
              enemy.takeDamage(effect.damagePerTurn);
          }
          effect.turnsRemaining--;
          if (effect.turnsRemaining <= 0) iterator.remove();
      }
  }

  // STUN is handled in the AI turn: skip enemy action if any STUN effect is active.

IMPLEMENTATION NOTES
====================
- Bleed and Burn can coexist on the same enemy (they are separate effect types).
- A burning enemy that receives Incendiary again refreshes the burn if not the
  Incinerator. This is consistent with roguelike_order_8's "refresh on reapply" rule.
- Stun from Stagger Rounds stacks in duration if applied to an already-stunned
  enemy: if (existing stun) extend turnsRemaining by STAGGER_STUN_DURATION.
  Capped at 3 turns total to prevent chain-stun locks.
  Add to EnemyManager.applyStatusEffect:
    if (effect.type == StatusEffectType.STUN) {
        effect.turnsRemaining = Math.min(effect.turnsRemaining + turns, 3);
        return;
    }
- If the Incinerator already applies burn natively (in its marchShot), the
  INCENDIARY ability on an Incinerator is an upgrade — extension behavior is
  the bonus. The marchShot burn and the ability burn are the SAME StatusEffect
  type (BURN) so they merge/refresh, never duplicate.
- Run `./gradlew build` after implementation.
