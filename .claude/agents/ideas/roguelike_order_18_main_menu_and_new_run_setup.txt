TITLE: Main Menu & New Run Setup — The Front Door
---

OVERVIEW
========
The game currently boots straight into gameplay; there is no front door. This doc
defines the title screen, the main menu (New Run, Continue, Leaderboard, Options,
Quit), the difficulty-selection step before a run, a short character/lore blurb,
the options menu (sound, display), and the menu-to-game transition framed as
DESCENDING INTO THE DUNGEON (fade to black, ambient sound, a held beat). It also
defines "Continue" as a SUSPEND-not-save mechanic that respects the roguelike no-
save-scum rule: one active run at a time, resumable but never reloadable.

This is the framing device for the whole roguelike. The first thing the player sees
should set the UAC-cynicism, lone-marine-survivalism tone and make pressing "NEW
INCURSION" feel like volunteering for a one-way drop.

MENU STRUCTURE
==============
TITLE SCREEN (first thing on app launch):
- Game logo/title, the lone-marine silhouette / facility backdrop, ambient
  facility drone audio. "PRESS ANY KEY" or auto-advances to the main menu after a
  beat. Reusable as the backdrop for the main menu.

MAIN MENU (vertical list, keyboard + mouse, controller-friendly focus model):
  1. NEW INCURSION   -> difficulty select -> new-run setup -> descent transition.
  2. CONTINUE        -> resume the suspended active run. GREYED OUT / hidden when
                        no run is in progress (see CONTINUE SEMANTICS).
  3. LEADERBOARD     -> opens the leaderboard screen (order 24).
  4. OPTIONS         -> opens the options submenu.
  5. QUIT            -> confirm -> Gdx.app.exit().

CONTINUE SEMANTICS (roguelike-correct):
- "Continue" resumes a SUSPENDED in-progress run held in memory (and optionally a
  single on-disk suspend slot so quitting the app and reopening can resume). It is
  NOT a save you can reload after death and NOT a checkpoint you can roll back to.
- There is exactly ONE active run at a time. Starting "NEW INCURSION" while a run
  is in progress prompts: "ABANDON CURRENT INCURSION? (it will be lost)" — choosing
  yes discards the suspended run (no reload of it later). This enforces no save-
  scumming: you cannot keep a "good" save and retry.
- On death/win, the active run is CLEARED, so "Continue" greys out until a new run
  starts. The run's RECORD persists to the leaderboard (order 24), but the run
  itself is gone.
- If an on-disk suspend slot is used: it is overwritten on every floor transition /
  periodically, and DELETED on death/win. It can never represent a pre-death state.

DIFFICULTY SELECT (before every NEW INCURSION):
- Three cards: EASY / NORMAL / NIGHTMARE, each with a one-line description and the
  Nightmare warning ("no supplies on the ground — and the dead are your only mercy").
- Selecting sets the run's DifficultyMode (handed to order 23) and proceeds to the
  setup blurb. Default focus = NORMAL.

NEW-RUN SETUP / LORE BLURB:
- A short briefing screen: a few lines of UAC-cynicism lore framing THIS incursion
  ("UAC Site Delta-9 went dark 14 hours ago. You are the response. There is no
  extraction plan for the response."). Optionally a randomized facility name/seed
  flavor per run so each drop feels distinct.
- "[BEGIN DESCENT]" confirms -> the descent transition -> gameplay.

OPTIONS SUBMENU:
- SOUND: master volume, music volume, SFX volume (0-100 sliders). Persisted.
- DISPLAY: fullscreen/windowed toggle, resolution (if supported by the lwjgl3
  backend), optional brightness/gamma. Persisted.
- Possibly: minimap toggle, control reminder. "BACK" returns to main menu.
- All options stored via the same Preferences blob used by stats (order 1/24) under
  an "options.*" key namespace.

GAMEPLAY LOOP (menu -> game)
============================
1. App launches -> Main sets the initial Screen to TitleScreen (not the game).
2. Title -> any input -> MainMenuScreen.
3. Player selects NEW INCURSION -> (if a run is active, abandon prompt) ->
   DifficultySelect -> SetupBlurb -> "[BEGIN DESCENT]".
4. DESCENT TRANSITION: ambient drone swells, screen fades to black over
   MENU_DESCENT_FADE_SECONDS, a low "we're going down" rumble plays; at full black
   the game world is constructed (fresh seed, full HP, starting loadout, selected
   DifficultyMode) and GameState.phase set to PLAYING; then fade-in reveals floor 1.
   Reuses the level-transitions fade overlay pattern.
5. During play, the run is the single active run; pausing (ESC) can offer
   "RESUME / OPTIONS / ABANDON TO MENU" (abandon = suspend + go to menu, NOT
   delete; menu's Continue then resumes it).
6. On death (order 1) or win (order 26): result screen -> "RETURN TO STAGING" ->
   MainMenuScreen, with the active run cleared.

PLAYER EXPERIENCE
=================
The menu sets tone before a single demon appears: a dark facility, a cynical
briefing, a difficulty choice that feels like signing a waiver. The descent
transition makes starting a run feel like a commitment — fade to black, the rumble,
and you're in. "Continue" being a suspend-not-save quietly teaches the roguelike
contract: you can step away, you cannot rewind. The whole front door reinforces
that this is a one-way trip you chose to take.

- screen/DifficultySelectScreen.java (NEW) or a sub-state of the menu screen.
- screen/SetupBriefingScreen.java (NEW) or a sub-state — the lore blurb + BEGIN.
- screen/OptionsScreen.java (NEW): sliders/toggles; reads/writes Preferences.

  wrap it in a Screen.

- util/AudioManager (NEW or existing): volume settings + ambient/transition SFX,

Turn-based fit: menus and transitions are real-time/cosmetic and advance ZERO
turns. The world only ticks once GameState.phase == PLAYING (the order-1 pollInput
gate already enforces this). The descent fade is a render overlay, not a turn.

No allocations in render(): each screen pre-builds its labels/layout in show().
Menu navigation reuses pre-built option rows. The fade is a single tinted quad.

Constants to add (Constants.java):
- MENU_DESCENT_FADE_SECONDS = 0.6f   (fade-out before world build; placeholder)
- MENU_TITLE_AUTO_ADVANCE_SECONDS = 0f (0 = wait for input)

  transitions reads "SUBLEVEL 1 — <FACILITY NAME>".
- Options: clean sliders + toggles, same amber palette, immediate audio preview on
  volume change.

BALANCE NOTES
=============
- No combat balance here. The only "balance" lever is the abandon-prompt friction:
  it must be present (to enforce no save-scum) but not annoying — a single clear
  confirm, not a multi-step gate.
- Difficulty descriptions must honestly preview order-23 stakes so the choice is
  informed (fairness pillar starts at the menu).
- Default focus = NORMAL so a thoughtless Enter-mash gives the intended experience,
  not accidental Easy or Nightmare.
