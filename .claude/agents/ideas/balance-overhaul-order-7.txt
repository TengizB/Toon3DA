OVERVIEW
--------
The owner: "the goal is to have something like 20-25 levels, then the game
ends"; "every 5 levels there is a boss"; "for a skilled player levels 10-15
should feel very challenging but fair if the player was prepared well enough";
first boss "reachable without many attempts, but still challenging"; bosses are
"sometimes OK, sometimes too hard, sometimes too easy"; "shops everywhere are too
expensive"; EVENT / MYSTERY "no".

Today the descent is ENDLESS: three named acts, then "THE BREACH" appended
forever; the story's Core ending exchange already waits at the depth-25 boss
(route region index 4 maps to StoryRegion.CORE) but fires only once per SAVE,
after which runs continue downward with nothing to reach. This order makes the
run FINITE: five fixed regions of five floors, bosses at 5/10/15/20/25, and the
depth-25 boss ends the run as a VICTORY. It then re-derives the things that only
make sense against a finite run and the finished player model: a region
difficulty curve with its peak where the owner wants it, boss fights derived
from the on-curve player and checked for consistency, a shop economy an on-curve
player can actually use, and EVENT/MYSTERY rewards in the new currencies.

GAMEPLAY LOOP
-------------
  1. Run start: NAV console header reads "FLOOR 1 / 25"; five region crests
     along the map's spine, the last one THE CORE's.
  2. Floors 1-5 (Outer Facility): the teaching region; the depth-5 boss is a
     real test a prepared first-timer can pass.
  3. Floors 10-15 (Research Wing boss, Reactor Depths): the peak — the hardest
     COMBAT/ELITE floors relative to an on-curve player.
  4. Floors 16-25 (The Breach, The Core): hard, but a player who built well and
     managed resources stays on top.
  5. Depth 25: the final boss dies -> the run ends as a VICTORY. The instance
     report is labelled "DESCENT COMPLETE". The story ending follows Q1's answer.


RULES
-----
Run shape
  F1  The route map has exactly RUN_FINAL_DEPTH (25) floors in 5 fixed regions:
      A OUTER FACILITY 1-5, B RESEARCH WING 6-10, C REACTOR DEPTHS 11-15,
      D THE BREACH 16-20, E THE CORE 21-25. No band is appended after E;
      RouteMap never creates a layer beyond 25; the old lazy Breach extension
      path is removed. StoryRegion.fromRouteRegionIndex is unchanged (index 4 ->
      CORE), so the story's five regions and the route's five regions now align
      exactly.
  F2  Region E display name: "THE CORE" on the NAV console only if it does not
      break the vocabulary ladder — if "Core" has a StoryTerm row whose earliest
      region is CORE, the NAV console shows the neutral name "DEEP SHAFT" until
      the save's deepest region has reached CORE. (Check StoryTermCatalog.)
  F3  Bosses every 5 floors via a BossTable (register() rows: depth, archetype,
      target fight turns, survival ratio): 5 OVERSEER 22, 10 CORRUPTOR 26,
      15 HELL_BARON 30, 20 OVERSEER 32, 25 CORRUPTOR 36 (the existing modulo
      cycle made explicit, so the current Core ending boss is unchanged).
  F4  VICTORY: when the depth-25 boss is defeated, the run ends. The player is
      never sent to a floor 26. RunStats outcome = VICTORY; the instance report
      page shows "DESCENT COMPLETE" (a framing-strings chrome id); StatsStore
      increments runs won and records the best win (fewest turns). NEW OPERATOR
      wipes both.
  F5  STORY AT VICTORY — DEFAULT (pending Q1): if the save has not reached an
      ending, the Core ending exchange opens exactly as today and its answer ends
      the run through commitPendingStoryEnding. If the save HAS reached an ending,
      the ending exchange opens again (the choice is the victory; the player may
      choose differently), and the launch screen from then on prints the LATEST
      ending. The exchange's one-shot "seen" flag is not consulted for this one
      id at a final clear; every other exchange keeps its one-shot rule.
  F6  NAV console header shows "FLOOR n / 25" (route overlay chrome).

Difficulty curve
  F7  REGION_TP_BUDGET_MULTIPLIER = {A 0.85, B 1.00, C 1.25, D 1.20, E 1.30}
      (the Reactor Depths peak the owner asked for; D dips slightly as the build
      comes online, E is the finale). ELITE weight multipliers: A 0.6, B 1.0,
      C 1.6, D 1.4, E 1.6. R-REGION bounds widen to [0.8, 1.5] and its
      "monotonic non-decreasing" clause is replaced by "C >= B >= A and E >= D".
  F8  RUN-OUTCOME bands (sim, replacing S-FAIR's median-death-depth [8,14]):
        TACTICAL   win rate (clears 25) in [0.20, 0.40]; >= 0.60 reach depth 10;
                   median death depth of losses in [11, 18].
        NAIVE      win rate <= 0.03; median death depth in [4, 8].
        S-SKILL    TACTICAL median depth - NAIVE median depth >= 5.
        FIRST BOSS TACTICAL clears it on >= 0.75 of seeds that reach it; NAIVE
                   reaches it on >= 0.40 and clears it on >= 0.15.
        S-GATE     HOARDER-START-WEAPON first-boss clears = 0 (unchanged).
        Readable deaths >= 0.90 (unchanged).

Bosses
  F9  Boss HP/damage derive from ExpectedPlayer(depth) and the row's targets
      (R-BOSS-* rules kept, inputs updated): an on-curve TACTICAL player's fight
      lasts the target +/- 25%.
  F10 BOSS CONSISTENCY (S-BOSS, sim): for each boss row, over seeds where
      TACTICAL reaches it: fight turns coefficient of variation <= 0.30; median
      player HP fraction at the kill in [0.30, 0.60]; no boss's TACTICAL clear
      rate outside [0.50, 0.90] (first boss: >= 0.75 per F8).
  F11 Pre-boss provisioning guarantee (the layer before every boss offers SHOP
      or CACHE) is kept; the boss floor's arena supply follows R-BOSS-AMMO.

Economy
  F12 R-CREDITS v2: for every region, modelled on-curve credit income per floor
      / the price of the NEEDED BUNDLE per floor in [1.10, 1.40]. NEEDED BUNDLE =
      one order-2 LEVEL UP rung + 1.5 consumables at the on-curve player's
      typical need + one tier upgrade per region amortised over its floors.
      SHOP_CREDITS_PER_POWER_POINT and SHOP_DEPTH_PRICE_SCALE are re-fitted to
      hold it.
  F13 Machines: exactly 1 Fabricator per non-boss floor; SHOP nodes have 2 with
      prices x SHOP_NODE_PRICE_MULTIPLIER (0.80). The guaranteed LEVEL UP rung
      (order 2) stays.
  F14 S-SHOP (sim): TACTICAL buys >= 1.5 offers per floor visited; its median
      unspent credits at death <= 1.5 floors of income.

Events and mysteries
  F15 Every EVENT choice and MYSTERY outcome reward is re-expressed in ladder
      currencies (EventEffect data): weapon LEVEL +1 (capped at d+1), a perk rank
      of a carried tag, a heal fraction, an armour fraction, credits (in floors
      of income), a weapon drop at d..d+1. Costs likewise (HP fraction, credits,
      a harder next floor). R-MYSTERY-EV re-derived: MYSTERY expected value >=
      COMBAT's, with higher variance; each EVENT offers >= 1 choice whose value is
      >= a COMBAT floor's supply.


PLAYER EXPERIENCE
-----------------
A run has a shape and an end: five acts, five bosses, a peak in the middle, a
finale, and a win that means something. The player can see how far they are
("FLOOR 12 / 25"). Shops become a place to spend, not to window-shop. Events and
mysteries speak the same currencies as everything else, so their choices read.

EDGE CASES
----------
  - Death on the depth-25 boss floor after the boss dies but before the ending
    exchange opens: the kill already counts as VICTORY (the run ends on the
    defeat, the exchange is presented as the victory's first beat).
  - App killed during the ending exchange: the exchange is spent when answered
    (existing rule), so it re-asks — but the run is over; on relaunch the title
    screen shows the previous state and the victory counts (recorded at the
    defeat, F4).
  - OBEY ending: continues into a fresh print — that is a new run starting at
    depth 1 (unchanged behaviour).
  - DEV START at depth 25: a dev run's victory is logged but never recorded in
    StatsStore or StoryStore (order-1 sandbox).
  - Route-map node types forced by guarantees on layer 24 (pre-boss) still hold.
