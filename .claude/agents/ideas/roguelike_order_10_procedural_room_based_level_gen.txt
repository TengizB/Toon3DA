TITLE: Room-and-Corridor Procedural Level Generator (v2, typed rooms)

OVERVIEW
========
A room-and-corridor dungeon generator that builds each 80x45 floor of the run.
It places rectangular rooms, links them with corridors, guarantees full
connectivity, and then TYPES each room (start, exit, shop, boss, armory, standard)
to drive what spawns inside. Enemy and item placement is depth/tier-driven so the
same generator produces a gentle floor 1 and a lethal floor 12. Output is a valid
Level using ONLY symbols from docs/tile-symbols.txt.

This belongs here because procedural generation is the heart of the roguelike
(Pillar #2): no two runs share a map, so mastery is of systems, not memorized
corridors. IMPORTANT CONTEXT: a room-placement generator ALREADY EXISTS and is
IMPLEMENTED (procedural-level-generation.txt) — three phases (place / connect /
decorate), greedy-MST corridors, flood-fill connectivity audit, wall variety,
loop corridors, seeded RNG, and a planned-but-unbuilt room-typing list. This doc
is the v2 that turns that "FUTURE IMPROVEMENTS" list into spec: room TYPING with
per-type painters, the START/EXIT/SHOP/BOSS special rooms the brief asks for, and
the depth/tier hookup that orders 7 and 9 depend on. It EXTENDS the existing
LevelGenerator; it does not replace the working pipeline. An optional BSP layout
backend is offered as an alternative to room-placement (see TECHNICAL NOTES).


GAMEPLAY LOOP
=============
(The generator runs at floor load — the PLAYER never sees it directly; they see
its output. This section describes the generation pipeline as ordered steps.)
1. World requests a floor: generate(floorSeed, depth, tier) where tier =
   DifficultyTier.fromDepth(depth) from order 9.
2. LAYOUT — place rooms (existing room-placement OR new BSP backend). Rooms are
   5x5 to 15x12 tiles (interior; +1 perimeter wall). Reject overlaps within the
   room margin. Record each room's rectangle and centre.
3. CONNECT — link all rooms (greedy MST + L-shaped corridors, EXISTING). Corridors
   are 1-3 tiles wide (the existing impl carves 1-wide; widen via a corridor-width
   roll). Add loop corridors for shortcuts (EXISTING).
4. AUDIT — flood-fill from the start room; any unreachable room gets an emergency
   wall-piercing corridor (EXISTING). Connectivity is GUARANTEED before typing.
5. TYPE rooms (NEW):
     - START room  = room 0 (or the room nearest a chosen edge). Holds 'p'. No
       enemies, no hazards. Exactly one per floor.
     - EXIT room   = room furthest from START (graph/euclidean distance). Holds
       the single '>' stairs tile on a clear interior tile. Exactly one per floor.
       (On BOSS floors, '>' is withheld until the boss dies — see step 7.)
     - BOSS room (only when depth % 5 == 0) = the EXIT room is upgraded to a boss
       room: larger, one boss spawn, '>' gated behind the boss.
     - SHOP room (optional, ~50% of non-boss floors) = a room behind a keycard
       door; terminal + lockers, no enemies, sells via the shop system.
     - ARMORY room (optional, rare) = dense lockers/crates, guaranteed ammo/weapon
       reward, light enemy presence.
     - STANDARD = everything else.
6. PAINT each room by type (NEW per-type painters), applying the EXISTING floor-
   lighting variety, wall variety, and prop placement, but with COUNTS and MIX
   scaled by tier (more/tougher enemies, fewer recovery pickups deeper).
7. STAMP special tiles: 'p' in START, '>' in EXIT (after the audit so it is
   provably reachable; withheld on boss floors until objective flag flips),
   keycard door + matching keycard pickup for the SHOP, recovery pickups
   (order 7 glyphs) and weapon/ammo ground spawns (orders 5/8) per tier density.
8. VALIDATE & emit the Level (char[][] + enemy spawn list) via the package-private
   constructor. World rebuilds renderers for it (order 9 / level-transitions).


PLAYER EXPERIENCE
=================
The player never reads the algorithm — they read its RESULT: a facility that
feels hand-built but is different every run. Typed rooms give the descent texture:
the relief of finding the SHOP, the dread of a BOSS room's reinforced glass walls,
the jackpot of an ARMORY. Because the EXIT is always the furthest room, finding
the stairs is a real navigation goal, and the choice to sweep for loot vs bolt for
the stairs (the order-9 tension) has a spatial shape. Depth/tier scaling means the
SAME generator quietly tightens the screws — floor 1 is roomy and lit, floor 12 is
cramped, dark, and crawling — so escalation is felt through level texture, not
just enemy stat numbers.


TECHNICAL NOTES
===============
DEPENDENCIES (must exist first):
- procedural-level-generation.txt (IMPLEMENTED): LevelGenerator in
  ...toon3d.level, its place/connect/audit phases, LEVEL_GEN_ constants, the
  package-private Level(char[][], List<EnemySpawnPoint>) constructor, and World's
  World(Level) constructor. This doc extends those. HARD dependency (met).
- ORDER 9 (multi-floor / DifficultyTier): supplies depth + tier; the tier scalars
  (enemiesPerRoomBase, toughEnemyShare, recoveryDensityMultiplier, unlitTileShare,
  roomCountBonus) ARE this generator's spawn-policy inputs. Hard dependency.
- ORDER 7 (recovery pickups): the recovery glyphs '+ H a A' and their per-floor
  counts the painter stamps. Soft — degrades to "no recovery placed" if absent.
- ORDER 5/8 (loot / loadout): weapon + ammo ground spawns. Soft.
- enemy_system.txt: enemy spawn markers '1'-'5' and the trash/tough/heavy mix.
- uac-keycard-doors-security-tiers.txt: shop keycard door + pickup. Soft (shop
  room degrades to a plain locked door or is skipped if keycards absent).

NEW / MODIFIED CLASSES (all in ...toon3d.level, pure Java, NO LibGDX imports —
keep LevelGenerator unit-testable):
- level/RoomType.java (NEW enum): START, EXIT, BOSS, SHOP, ARMORY, STANDARD.
- level/Room.java (extend existing room struct): add RoomType type; keep
  rectangle (column, row, width, height) and centre. Helper interiorTiles().
- level/RoomTyper.java (NEW): assigns types after the audit. Algorithm:
    type room 0 -> START; argmax-distance room from START -> EXIT;
    if depth % 5 == 0 -> EXIT becomes BOSS (and may be enlarged);
    among remaining rooms, with probability SHOP_ROOM_CHANCE pick one furthest
    from START but not the EXIT -> SHOP; optionally one -> ARMORY; rest STANDARD.
  Pure; takes depth + Random; no render state.
- level/RoomPainter.java (NEW) with per-type paint methods that REUSE the existing
  decoration helpers (lighting variety, wall variety, prop placement) but pull
  counts from the tier:
    paintStandard(room, tier, rng), paintStart(room), paintExit(room, depth),
    paintBoss(room, tier, rng), paintShop(room, rng), paintArmory(room, rng).
- level/LevelGenerator.java (MODIFY): add generate(long seed, int depth,
  DifficultyTier tier); keep generate(seed) -> depth 1 / EASY for tests. Insert
  RoomTyper between the audit (Phase 5) and the paint phase; route painting
  through RoomPainter. Stamp '>' AFTER the audit using the EXIT/BOSS room.
- level/BspLayout.java (OPTIONAL NEW): an alternative LAYOUT backend that
  recursively splits the 80x45 grid into sub-regions and carves one room per leaf,
  connecting siblings up the tree. Selectable via a flag; produces tighter,
  fuller floors than random placement. Both backends feed the SAME connect/audit/
  type/paint phases downstream. Ship room-placement first; BSP is a swappable
  layout module, not a rewrite. (See OPEN Q — recommend room-placement v1.)

GRID + SYMBOL CONSTRAINTS:
- Grid is always 80x45 (LEVEL_GEN grid size) = 1280x720 at CELL_SIZE 16. First
  emitted line = top row of the world (LevelLoader convention).
- Rooms: interior 5x5 to 15x12 (the brief). NOTE: the existing impl uses 3x12 x
  3x7 interiors; widen the room-size bounds to the brief's 5x5..15x12 via the
  LEVEL_GEN room-size constants. Corridors 1-3 wide via a per-corridor width roll.
- USES ONLY EXISTING SYMBOLS. Full inventory the generator emits:
    walls: x c v t w h j G k N Q S M Z U X D F (context-aware variety, EXISTING)
    doors: d (plain), R/Y/B (shop keycard door)
    floor lighting: ' ' l u f (variety per tier; unlit share rises with depth)
    special: p (START), '>' (EXIT/BOSS), P (columns in large rooms)
    props: g E T L C # % & = @ I J W (per-type painter density)
    decals: m s . O e (atmosphere)
    pickups: r y b + H a A (keycards for shop; recovery per order 7)
    enemy spawns: 1 2 3 4 5 (mix per tier)
  NO NEW SYMBOL IS REQUIRED. Every glyph above already exists in
  docs/tile-symbols.txt. If a future special room wants a new tile (e.g. a shop
  vendor terminal glyph or a trap plate), that is a SEPARATE change — requires
  new symbol: add to docs/tile-symbols.txt and Level.java before implementing.

CONSTANTS TO ADD (Constants.java, LEVEL_GEN_ prefix; PLACEHOLDER):
  LEVEL_GEN_ROOM_MIN_INTERIOR_WIDTH   = 5
  LEVEL_GEN_ROOM_MAX_INTERIOR_WIDTH   = 15
  LEVEL_GEN_ROOM_MIN_INTERIOR_HEIGHT  = 5
  LEVEL_GEN_ROOM_MAX_INTERIOR_HEIGHT  = 12
  LEVEL_GEN_CORRIDOR_MIN_WIDTH        = 1
  LEVEL_GEN_CORRIDOR_MAX_WIDTH        = 3
  LEVEL_GEN_SHOP_ROOM_CHANCE          = 0.50f
  LEVEL_GEN_ARMORY_ROOM_CHANCE        = 0.20f
  LEVEL_GEN_BOSS_FLOOR_INTERVAL       = 5      (depth % 5 == 0 -> boss floor)
  LEVEL_GEN_COLUMN_ROOM_MIN_AREA      = 60     (place 'P' columns in big rooms)
  (room count / enemy density / recovery density / unlit share come from the
   DifficultyTier scalars in order 9, NOT duplicated here.)

TURN-BASED FIT: generation is a one-shot build at floor load (during the order-9
fade) — it touches no turns and no render state. Pure integer tile math. Seeded
Random (floorSeed = mix(runSeed, depth) per level-transitions) -> reproducible
floors for QA and shareable run seeds.


VISUAL DESIGN (how typed rooms READ in the 3D view)
=============
- START room: bright (' ' lit floor), clean walls ('x'), no props/enemies — a
  calm staging point. 'p' spawn faces into open space.
- EXIT room: the red-pulsing '>' grate (level-transitions visual) on a lit tile
  with lit neighbours so it is never lost in shadow; furthest from start.
- BOSS room (depth % 5): larger, reinforced — use N (glass) / Q (quarantine) /
  X (blast) wall variety, sparse columns 'P' for cover, dramatic lighting (some
  'u'/'f'). The boss spawn centred; '>' hidden until boss dies.
- SHOP room: behind a colored keycard door; M (medical) / D (holo-data) walls,
  terminals 'T', lockers 'L', no enemies, a 'lit' calm vibe — reads as a safe
  vendor cache.
- ARMORY: dense 'L' lockers + 'C' crates + '=' weapon racks, dim, light guard
  presence — a high-value detour.
- STANDARD: the existing variety mix (conduit/vent/wires walls, barrels, blood,
  corpses), darkening with depth via the tier's unlitTileShare.
- Large rooms (area > LEVEL_GEN_COLUMN_ROOM_MIN_AREA) get 2-4 'P' columns for
  cover and depth (the existing FUTURE IMPROVEMENT, now spec).


BALANCE NOTES (all PLACEHOLDER — tune in playtest)
=============
- Room count: scale with tier (EASY ~6-8 rooms, NIGHTMARE ~10-12). The brief's
  5x5..15x12 rooms in an 80x45 grid comfortably fit ~8-12 rooms with margins.
- Enemy count/room and the trash/tough/heavy MIX come straight from the tier
  scalars (order 9). The painter just rolls per-room counts against the tier base
  and clamps to the soft cap. Floor 1 must be clearable with the starting kit.
- Recovery pickup density = base count * tier.recoveryDensityMultiplier (order 7).
  Place recovery in STANDARD/ARMORY rooms; NEVER in START or on '>'/'p'/door tiles.
- Special-room frequency: SHOP ~50% of non-boss floors (so it is a treat, not a
  guarantee); ARMORY ~20%; BOSS strictly every 5th floor. Avoid stacking SHOP +
  ARMORY + BOSS on the same small floor — cap special rooms at ~2 per floor.
- Corridor width: bias narrow (mostly 1, occasional 2-3) so the floor reads as
  tight UAC maintenance halls, with the wider ones as "main thoroughfares."
- Connectivity is non-negotiable: the flood-fill audit must pass before emit, and
  '>' / SHOP must be provably reachable (audit runs before stamping them).


INTERACTIONS
============
1. procedural-level-generation (IMPLEMENTED): this is its planned v2. Reuses the
   place/connect/audit phases and decoration helpers verbatim; adds RoomTyper +
   RoomPainter + the depth/tier signature. The "ROOM TYPES (planned extensions)"
   and "FUTURE IMPROVEMENTS" lists in that doc become this doc's spec.
2. Order 9 (multi-floor/DifficultyTier): the generator's depth/tier parameter is
   the difficulty curve made concrete. Boss-floor detection (depth % 5 == 0) and
   the EXIT->BOSS upgrade + gated '>' live here. The generator is the consumer of
   the tier scalars.
3. level-transitions-stairs-down (IMPLEMENTED): the generator stamps exactly one
   '>' in the EXIT/BOSS room after the audit; floorSeed = mix(runSeed, depth).
4. Orders 5/7/8 (loot/recovery/weapons): the painter places recovery glyphs,
   weapon/ammo ground spawns, and shop keycard doors using ONLY existing symbols.
5. uac-keycard-doors-security-tiers + boss-encounter-facility-overseer: SHOP gated
   by a keycard door (matching keycard placed elsewhere on the floor); BOSS room
   gates the stairs behind the boss death flag.
6. Fog-of-war / mini-map: each generated floor starts unexplored; mini-map resets
   per floor (the layout is new every descent).


OPEN QUESTIONS
==============
1. LAYOUT backend: keep room-placement (EXISTING, ship it) or add the BSP backend?
   Recommend room-placement v1 (already works, audit guarantees connectivity); add
   BspLayout as a swappable module later only if floors feel too sparse/random.
2. Where does the SHOP keycard live? On the same floor (a fair fetch), or always
   carried-in? Recommend same-floor placement in a STANDARD room so the shop is an
   earned detour. Confirm with the keycard doc (keycards reset per floor).
3. Should the EXIT always be the furthest room, or sometimes hidden behind a
   keycard/secret to force exploration? Recommend furthest-and-open for v1;
   gated-exit is a fun variant for deep floors (flag).
4. Column placement ('P') threshold and count — tie to room area; verify the
   ray-circle column renderer handles clustered columns at the chosen density.
5. Do special rooms (SHOP/ARMORY) appear from floor 1, or unlock at a depth (e.g.
   shop from floor 2+)? Recommend shop from floor 2+ so floor 1 stays simple.
6. Boss-room size/shape: reuse a STANDARD-shaped large room, or author a small set
   of boss-room TEMPLATES (prefab stamps) the generator drops in? Templates give
   more control for set-pieces; defer to the boss-encounter doc.
7. Trap rooms / secret rooms (in the original FUTURE list): out of scope here to
   keep the special-room set to START/EXIT/BOSS/SHOP/ARMORY. They are clean future
   additions and may need new tile symbols (pressure plate, secret door) — flag at
   that time per the strict symbol rule.
