--------------------------------------------------------------------------------
PROBLEM
--------------------------------------------------------------------------------
Knowledge doc SECTION 17, problem 6: difficulty modes change ONLY the player's
starting attributes. Enemy numbers, scaling, scarcity, XP and loot are
identical across RECRUIT/MARINE/NIGHTMARE/ULTRA, and the entire contract is
anchored to MARINE's 205 eHP. So RECRUIT is "MARINE with padding" (trivializes
the scarcity model that assumes 205 eHP), and ULTRA is "MARINE while poor"
(silently violates the telegraph cap: 25% of MARINE eHP is a much bigger
fraction of ULTRA's). The other modes are balanced only by accident — the exact
opposite of "challenging but fair" at every setting.

--------------------------------------------------------------------------------
DESIGN — A MODE IS A PROFILE, THE SCHEMA IS SHARED
--------------------------------------------------------------------------------
A) BalanceProfile (BalanceConfig SECTION 17): per-mode struct of the SEMANTIC
   dials the earlier orders created — never raw stat overrides scattered in
   code. Every rule in BalanceSchema evaluates against EACH profile's own
   anchors; all four modes must pass the SAME bands. Four fair games, not one
   fair game and three accidents.

   Dial philosophy (roguelike-honest: harder = SCARCER + LESS FORGIVING, not
   damage-sponge enemies; easier = FORGIVING, not power fantasy):

     dial                        RECRUIT  MARINE  NIGHTMARE  ULTRA
     startingStats (existing)    3/3/4/3  2/2/2/2  1/1/1/1   0/1/1/0
     enemyDamageMultiplier         0.85     1.00     1.12      1.25
     enemyHealthMultiplier         0.90     1.00     1.05      1.10   (small!)
     scarcityTargetS            0.90–1.05 0.75–0.95 0.70–0.88 0.62–0.80
     healNetDrainBand (of eHP)    2–8%     5–15%    8–18%    10–22%
     xpYieldBand (levels/floor)  1.1–1.4  1.0–1.3  1.0–1.3   0.9–1.2
     creditIncomeRatio band     1.1–1.6  0.9–1.4  0.8–1.2   0.7–1.1
     emergencySupplyFraction      0.35     0.25     0.15      0.0 (off)
     bossSurvivalRatio band     0.55–0.8 0.4–0.7  0.35–0.6  0.3–0.55
     enrageRampPerTurn            +5%      +8%      +10%      +12%

   Deliberate choices:
     - enemyHEALTH barely moves: TTK feel (and every golden-ratio band) stays
       intact on all modes; danger comes from incoming damage and scarcity.
     - ULTRA has NO emergency ammo floor — resource mistakes are fully lethal.
       That is the promise of the mode, and it's a dial, not a code path.
     - The gear gate and boss gate (orders 2, 6) hold on ALL modes: the
       R-BOSS-GATE assertion runs per profile (RECRUIT must ALSO be unable to
       start-weapon the boss — easier must never mean progression-optional,
       or the user's original bug returns on easy mode).

B) PER-MODE ANCHORS (fixes the 205-eHP monoculture):
   referencePlayerEHP(mode) computed from that mode's starting stats through
   the same eHP formula. The telegraph cap (25% un-telegraphed, 35% boss) is
   evaluated against EACH mode's eHP — ULTRA's cap protects ULTRA's actual
   pools. Where a single attack passes MARINE but breaches ULTRA's cap, the
   attack's telegraph requirement follows the STRICTEST mode it can appear in
   (telegraphs are cheap; unfair one-shots are not).

C) MODE INTEGRITY RULES:
   R-MODE-MONOTONE: for every derived difficulty metric (TTD at reference
   depth, S target midpoint, net drain midpoint), RECRUIT <= MARINE <=
   NIGHTMARE <= ULTRA must hold — no dial combination may accidentally make a
   "harder" mode easier anywhere on the curve. The audit sweeps depths 1..15.
   R-MODE-COMPLETE: every dial in the profile struct must be explicitly set
   for every mode (no silent inheritance) — adding a new dial without pricing
   all four modes fails the build, same coverage discipline as content.

D) UI TRUTH: the difficulty-select copy states what actually changes ("fewer
   supplies, deadlier hits" — not "enemies are stronger"), sourced from the
   profile so the description can't drift from the numbers. (Copy only; no new
   UI systems in this order.)

--------------------------------------------------------------------------------
TECHNICAL NOTES
--------------------------------------------------------------------------------
  - BalanceProfile as a plain final class with four static instances in
    BalanceConfig SECTION 17; the active profile is selected at run start and
    threaded where the multiplied values are read (EnemyManager damage/HP at
    spawn, drop planners, XP award, boss derivation, emergency rule).
  - GameMath methods stay pure — profile values are passed IN as parameters
    (no global mode state inside formulas).
  - BalanceAuditTest parameterizes every existing rule over all four profiles
    (JUnit parameterized tests) — this quadruples audit coverage for free.
  - BalanceReport prints per-mode tables (or a mode column) for DEPTH COUPLING,
    SCARCITY, TELEGRAPH, BOSS.
  - StatsStore records the run's mode with its stats (order 8 telemetry needs
    per-mode death curves).
