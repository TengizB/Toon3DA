Requires: orders 1–6 (schema; curves; economy; threat pricing; boss gate).
Read docs/route-map-system.txt FIRST — this order builds on the existing route

--------------------------------------------------------------------------------
PROBLEM
--------------------------------------------------------------------------------
Orders 1–6 balance FLOORS. But the player never plays "a floor" — they play a
JOURNEY through the route map's branching DAG, choosing between COMBAT, ELITE,
CACHE, REST, SHOP, MYSTERY, EVENT nodes. That macro layer is where run
difficulty is actually decided, and today none of it is in the contract:
  1. Calm-node payoffs (CACHE_MEDKITS/CACHE_AMMO_BOXES, REST_HEAL_FRACTION)
     are hand-set in RouteMapConstants, OUTSIDE the scarcity/heal economy of
     order 3. The order-3 bands are audited per COMBAT floor — a player who
     chains caches and rests sails far above the supply band; one who never
     routes calm starves below it. The audited game and the played game
     diverge at the first branch.
  2. ELITE's risk/reward (ELITE_BUDGET_SCALE vs its ~1.5x vault) and every
     AFFIX budget multiplier (OVERCLOCKED, SWARM, …) are unpriced — an
     affixed elite's true threat and its reward have no enforced relation.
  3. MYSTERY's outcome table claims "EV ≈ a normal combat floor" — asserted,
     never audited, and it drifts silently whenever any outcome's payoff or
     any order 1–6 re-tune changes the baseline it is compared to.
  4. Risk pips (DangerTier 1–4) are hand-assigned per node type. The overlay
     is the player's ONLY information for route decisions — if pips don't
     track priced threat, the map lies, and informed choice (the whole point
     of a route map) collapses.
  5. Nothing guarantees a REACHABLE fair journey: guarantees like "an upgrade
     per region" (order 2) and "provisioning before the boss" (order 6) are
     floor-level promises that a branching map can strand on the lane not
     taken.

--------------------------------------------------------------------------------
DESIGN — PRICE NODES, THEN AUDIT JOURNEYS, NOT JUST FLOORS
--------------------------------------------------------------------------------
A) THE NODE EV LEDGER (every node type gets a price):
   For each RouteNodeType (and each affix and mystery outcome), register a
   NodeEconomics entry alongside its NodeTypeDefinition (same registry
   discipline — data, never switches):
     threatCost     expected TP faced (budget scale x affix multiplier;
                    0.x for calm nodes' "light stragglers")
     resourceDelta  expected ammo damage-value, heal value, credits GAINED
                    minus expected consumption fighting its threat (all
                    computable from orders 3/5 models)
     progressValue  expected XP + upgrade-opportunity value (order 2/4)
   GameMath.nodeExpectedValue(...) folds these into one comparable EV number.
   COVERAGE RULE R-ROUTE-PRICED: a node type, affix, or mystery outcome with
   no NodeEconomics entry fails the audit — the map can never again gain
   content the contract can't see (same rule that fixed enemies in order 5).

B) THE RISK-REWARD CONTRACT (choices must be real trade-offs):
   R-RISK-PREMIUM: reward must scale with priced risk, in a band:
     ELITE (and each affixed variant): (reward premium) / (threat premium) in
     [1.0, 1.2] — danger pays, slightly better than fair, never free and
     never a sucker bet. SWARM/OVERCLOCKED raise threatCost -> their vaults
     must price up with them.
   R-CALM-COST: a calm node's total EV must sit BELOW a standard combat
   node's by [10%, 30%] — safety is bought with tempo and loot (the doc's
   "costs loot/tempo, never the clock" invariant, now a number). Rest heal +
   cache supply are re-priced as order-3 economy inputs so routing calm is a
   real strategic spend of the heal/ammo budget, not free income on top.
   R-MYSTERY-EV: the weighted EV of the mystery table within ±15% of a
   standard combat node at every audited depth; worst outcome (MALFUNCTION)
   bounded: expected resource loss <= 1 floor's net drain band max — "bad but
   survivable" as arithmetic, not adjective.

C) HONEST INFORMATION (the map may tempt, never lie):
   R-PIPS-DERIVED: DangerTier is DERIVED from threatCost thresholds
   (fractions of the standard combat node's TP at that depth), not
   hand-assigned. Pip thresholds live in BalanceConfig; every node type's
   displayed pips are recomputed by the audit and must match.
   R-HONEST-SAFE: CACHE/REST threatCost <= 0.3x standard combat — the
   honest-safe-node rule as an enforced bound. Mystery scan-tone buckets must
   partition outcomes consistently with their priced EV (REWARD-RICH bucket
   EV > QUIET > ... verified).

D) TRAJECTORY AUDIT (the journey replaces the floor as the audited unit):
   Generate real route maps (RouteMapGenerator, 100 seeds) and walk three
   deterministic path policies through each DAG:
     SAFEST     always the lowest-threatCost selectable node
     DEADLIEST  always the highest
     BALANCED   alternates / mid EV
   For EVERY policy x seed, the cumulative order-3/4 bands must hold at each
   region boundary: scarcity S, heal net-drain, depth-coupling, XP pace —
   evaluated over the ACTUAL nodes visited, with each node's resourceDelta,
   not the combat-floor average. R-TRAJECTORY: all three policies stay in
   band (SAFEST may ride the generous edge, DEADLIEST the starved edge —
   the band ENDS are the route's difficulty range, and both must stay fair).

E) REACHABILITY GUARANTEES (no lane strands a run):
   R-ROUTE-GUARANTEES, enforced at map-gen (RouteMapGenerator post-pass, the
   same place BOSS convergence is forced): from EVERY reachable node, the
   remaining DAG must still satisfy:
     - >= 1 upgrade-bearing node (ELITE/SHOP/CACHE-with-rack) per region
       (order 2's pity rule becomes a graph property, not a spawn hope)
     - >= 1 calm node (CACHE or REST) per region
     - order 6's pre-boss provisioning node in the layer before each boss
     - >= 2 distinct node types in every selectable layer (no fake choices;
       branch width 2–4 and spread chance become audited constants)
   Where a guarantee would fail, the generator rewrites the offending layer
   (re-roll from the node sub-stream — determinism preserved).

TECHNICAL NOTES
--------------------------------------------------------------------------------
  - Balance-bearing RouteMapConstants values (budget scales, affix
    multipliers, mystery weights, cache/rest payoffs, pip thresholds) move to
    BalanceConfig SECTION 19 — ROUTE ECONOMICS, with re-export shims (order-1
    discipline). Cosmetic overlay layout stays in RouteMapConstants.
  - GameMath: nodeExpectedValue, nodeThreatCost, rewardPremiumRatio,
    trajectoryResourceLedger — pure, formula blocks.
  - The trajectory audit reuses the REAL RouteMapGenerator + planner models
    headlessly (route pkg is already LibGDX-free by design — the doc
    guarantees it). It belongs to the fast `./gradlew test` tier; the full
    played-out simulation of trajectories is order 9's job (its policies
    gain a route-choice layer on top of this order's path policies).
  - Region danger dial (order 5) composes: a region's TP multiplier scales
    threatCost for all its nodes; the trajectory audit runs per region lane.
  - BalanceReport: ROUTE ECONOMICS table (per node type/affix/outcome: threat,
    delta, EV, pips) + TRAJECTORY table (policy x region: S, drain, coupling).
  - docs/route-map-system.txt carries an UPDATE CONTRACT — this order edits
    route behaviour (map-gen guarantees, derived pips), so update that doc in
    the same commit, as its STRICT RULE requires.
