CATEGORY: UI
TITLE: Fog of War — Three-State LOS Exploration
---

OVERVIEW
========
The mini-map currently renders the whole window with full knowledge. This doc
upgrades fog of war from a binary "visited / not visited" toggle to a three-state
exploration model — UNSEEN, REMEMBERED, VISIBLE — driven by line-of-sight from the
marine's facing cone. Unexplored tiles are black; tiles you have seen but cannot
currently see are dim grey "memory"; tiles in your current view are full bright.
This turns the mini-map from a cheat-sheet into a flashlight: exploration becomes a
reward that builds the map, and the dark edges create real tension.

This is the "informed-decisions" roguelike pillar made tactile. You should always
be able to reconstruct why you walked into the Revenant — because that corridor was
grey memory, not live VISIBLE, so you couldn't know it had moved.

NO NEW TILE SYMBOL IS REQUIRED. Fog is a per-tile visibility OVERLAY tracked in a
side grid; it never changes the level's tile characters. The Facility Schematic is
a consumable item, not a tile. (Existing pickup symbols suffice if a ground form is
wanted later — none needed for v1.)

VISIBILITY STATE MODEL
======================
Per tile, one of three states stored in a side grid (byte enum, not boolean):
- UNSEEN (0): never had LOS. Rendered black on the mini-map (FOG_UNSEEN color).
  Walls, doors, props, pickups all hidden.
- REMEMBERED (1): had LOS at some point but not this turn. Rendered at the tile's
  normal color multiplied by FOG_MEMORY_DIM (~0.50). STATIC features (walls,
  doors, layout) are shown from memory; DYNAMIC entities (enemies, moving things)
  are NOT — they only show while VISIBLE. Pickups: show as remembered (they don't
  move), so you can navigate back to that medkit you skipped.
- VISIBLE (2): currently in the marine's LOS this turn. Full brightness; enemies in
  these tiles appear on the map.

Transition rules each turn:
- Start of recompute: every tile currently VISIBLE demotes to REMEMBERED.
- LOS pass: every tile with current line-of-sight is set VISIBLE; REMEMBERED and
  UNSEEN both upgrade to VISIBLE when seen.
- REMEMBERED never reverts to UNSEEN (memory is permanent for the floor).

GAMEPLAY LOOP
=============
1. New floor loads: entire visibility grid = UNSEEN. The spawn tile and its
   immediate neighbors are seeded VISIBLE so the player isn't blind on turn 1.
2. The visibility recompute runs ONCE per resolved turn (after the player's move/
   rotate settles and before the next input is accepted) — turn-gated, never
   per-render-frame. Rotating counts as a turn, so turning to look down a corridor
   legitimately reveals it.
3. LOS source: a 360-degree (or facing-biased, see OPEN QUESTIONS) set of DDA rays
   from the player's tile center. Each ray walks tiles until it hits a wall/closed
   door (which blocks sight) or reaches FOG_SIGHT_RADIUS tiles. Every tile a ray
   passes through (and the blocking wall tile itself, so you SEE the wall) is
   marked VISIBLE for this turn.
4. The mini-map renderer reads the visibility grid per tile and picks the
   black / dim / full color path. Enemies and the player dot draw only on VISIBLE
   tiles (enemies) or always (player).
5. FACILITY SCHEMATIC consumable: when used (inventory action = one turn), every
   tile on the floor is bumped to at least REMEMBERED — the full LAYOUT is revealed
   as memory, but tiles are not VISIBLE, so enemy positions stay hidden until you
   actually see them. Secret tiles are NOT revealed by the schematic (they're
   secret); discovering them still requires the secret mechanic.
6. Descending (stairs) resets the grid to all-UNSEEN — fog is level-scoped, never
   persisted across floors or runs (roguelike convention).

PLAYER EXPERIENCE
=================
The map filling in IS the dopamine of exploration. The grey "memory" layer creates
a specific, valuable tension: you remember the room is there, but you don't know
what's in it NOW — perfect for a dungeon crawler where demons roam. Rotating to
peek down a hall feels meaningful because it actually reveals. Burning a Facility
Schematic before a boss floor feels like a smart, earned advantage (you see the
arena shape) without removing the threat (you still don't see the demons).

TECHNICAL NOTES
===============
DEPENDENCIES (must exist first):
- LevelRenderer.java (IMPLEMENTED) — the mini-map this hooks into.
- A turn hook to run the recompute once per resolved turn. global-tick-event-
  system.txt (IMPLEMENTED) is the natural home: register a VisibilitySubscriber,
  or call recompute from World right after PlayerController settles.
- RayCaster's DDA (IMPLEMENTED) for the LOS walk. We do NOT need the render rays;
  add a lightweight tile-walk LOS helper in GameMath (pure function).
- level-transitions-stairs-down.txt (IMPLEMENTED) for the per-floor reset.
- secret-rooms-hidden-passages.txt (soft) for the secret-exclusion rule.

New / modified classes:
- level/FogOfWarMap.java (NEW or upgraded from the binary doc, ...toon3d.level):
  wraps a byte[][] of states (0/1/2). Methods: state(col,row),
  demoteVisibleToRemembered(), markVisible(col,row), markRememberedAtLeast(col,row)
  (for the schematic), resetAllUnseen(), and isSecretExcluded(col,row) check. No
  LibGDX dependency. Sized from level dimensions at construction.
- world/World.java or a VisibilitySubscriber: orchestrate the per-turn recompute
  (demote, then cast LOS rays, then mark).
- util/GameMath.java: add a pure tile-space LOS walk helper, e.g.
  losBlockedBetween / a per-ray tile stepper, with the required derivation comment
  block. All in tile space, integer-ish DDA. No allocations (pass a callback or
  write into the grid directly via an index-based loop — see "no alloc" note).
- render/LevelRenderer.java: per-tile branch on FogOfWarMap.state to choose
  black / dim-multiplied / full color. Enemy and dynamic-entity draws gated on
  VISIBLE. One extra enum read per tile — negligible cost, zero allocation.
- items/ (or inventory): FacilitySchematic consumable -> calls
  markRememberedAtLeast across the whole grid (skipping secret tiles).

Turn-based fit: the recompute is one O(rays x radius) pass per resolved turn, NOT
per frame. With FOG_SIGHT_RADIUS ~12 and a modest ray count this is trivially cheap
and deterministic. Rotation is a turn, so it triggers a recompute (intended).

No allocations in render(): the visibility grid is allocated once per floor in
buildLevelDependentResources (where the binary doc resets fog). The recompute
writes into the pre-allocated byte[][]; the LOS ray stepper uses primitive locals
only. LevelRenderer's per-tile branch allocates nothing.

Constants to add (Constants.java):
- FOG_SIGHT_RADIUS = 12          (tiles of LOS reach; placeholder)
- FOG_LOS_RAY_COUNT = 120        (rays for the 360 LOS sweep; placeholder — tune
                                  for no gaps at the radius edge)
- FOG_MEMORY_DIM = 0.50f         (brightness multiplier for REMEMBERED tiles)
- FOG_UNSEEN_R/G/B = 0.05f       (near-black for UNSEEN)
- FOG_SEED_SPAWN_NEIGHBORS = true (seed spawn + neighbors VISIBLE on floor load)
- FOG_SCHEMATIC_REVEALS_SECRETS = false

VISUAL DESIGN
=============
- UNSEEN: flat near-black (FOG_UNSEEN color). No grid lines, no tile detail —
  literal darkness at the map's edge.
- REMEMBERED: the normal tile color (wall blue-grey, door amber, floor dim)
  multiplied by FOG_MEMORY_DIM, giving a desaturated "from memory" look. Subtle
  desaturation toward grey reads better than pure dimming — optional polish.
- VISIBLE: full normal mini-map colors; this is the only state where enemy blips
  render. Consider a faint warm tint or 1px brighter grid lines on VISIBLE tiles
  so the live view "pops" from the grey memory.
- The boundary between VISIBLE and REMEMBERED naturally traces the marine's LOS
  cone, giving the map a "flashlight beam" silhouette that updates as you turn.
- Facility Schematic use: a quick sweep animation (map fills in grey from the
  player outward over ~0.4s, render-only) sells "schematic uploaded."

BALANCE NOTES
=============
- FOG_SIGHT_RADIUS is the master knob: too small = tedious blind shuffling, too
  large = no exploration tension. Start at 12 tiles (~ a large room across).
- FOG_LOS_RAY_COUNT must be high enough that no tile inside the radius is missed
  at the circle's edge; if you see speckled "missed" tiles, raise it. 120 is a
  safe placeholder for a 12-tile radius.
- Facility Schematic should be UNCOMMON loot — revealing layout is strong but not
  game-breaking since it withholds enemy positions. One per ~2-3 floors feels
  right; tune against inventory-loot-ransack drop tables.
- On Nightmare difficulty (roguelike_order_23), consider reducing FOG_SIGHT_RADIUS
  (e.g. x0.75) to deepen the dread — flag for that doc.

INTERACTIONS
============
1. Secret rooms (secret-rooms-hidden-passages): secret tiles are flagged in the
   FogOfWarMap as secret-excluded; LOS does NOT reveal them and the schematic skips
   them. They flip to normal fog behavior only after the secret is discovered.
2. Difficulty scaling (roguelike_order_23): sight radius is a per-difficulty knob;
   Nightmare's darkness pairs with the lurker/blindspot AI.
3. Artifacts (roguelike_order_21): Night Vision Goggles affect 3D-view lighting,
   NOT fog state — fog is about KNOWLEDGE (have you seen this tile), lighting is
   about VISION CLARITY. Keep them orthogonal: goggles do not auto-reveal the map.
4. Run stats (roguelike_order_24): "tiles explored" / "% of floor seen" can feed a
   completionist stat; secrets-found ties to the secret-exclusion flag.
5. Turn system: the recompute is a clean per-turn subscriber — rotation revealing
   new tiles reinforces that turning is a real, costed action.

OPEN QUESTIONS
==============
- 360-degree LOS vs facing-biased cone? Recommendation: 360 around the player tile
  (you're aware of your surroundings), since cardinal-only facing already limits
  info and a cone makes turning-to-map tedious. Decide in playtest.
- Should closed doors block LOS (yes, recommended) and open doors pass it (yes)?
  Confirm DoorManager state is queryable from the LOS walk.
- Do pickups in REMEMBERED tiles stay shown after collection by someone/something?
  v1: pickups are static, show as remembered until collected; once collected the
  tile reverts to plain floor memory.
- Should there be a "deep memory fade" where very old REMEMBERED tiles dim further?
  Defer — three states is enough for v1.
- Mark this doc as superseding fog-of-war-minimap.txt, or merge? Recommend marking
  the binary doc REJECTED: superseded by roguelike_order_22 when this is approved.
