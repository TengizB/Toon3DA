MASTER INDEX of the generated-wall-art series. The work lives in generated-wall-art-order-1.txt ..
generated-wall-art-order-4.txt, built strictly in ascending order, each with its own STATUS and

THE METHOD IS docs/sprite-art-creation-guide.txt (the enemy-art kit). Walls are made with THE SAME KIT,
light rig, material library, outline and cleanup rules as the generated enemies. Order 1 adds a WALLS
section to the guide; every later order updates it in the same commit as any change to the method.

Written by the main thread directly with the owner (2026-10-22), not by creative-game-designer, because
the request came with a prototype step that needed the kit run in the same session. Revised the same day
after the owner's review (D5-D9): region separation, room sets, region doors, the old system removed
completely, and four orders instead of ten.


OVERVIEW
--------
The walls are on screen every frame, so they make the atmosphere - and they are the weakest art in the
game: image-model JPEGs (lab_wall_*.jpg) and flat Java Pixmap programs, with no shared light or palette.
Worse, there is NO REGION SEPARATION: any wall can appear on any floor. SymbolAllocator binds wall
symbols with a seeded weighted grab, the cavern generator reskins walls with random chars, six other
generators use one global legacy table, and RegionAmbience carries a per-region `wallPalette` string
that nothing reads. One screenshot cannot tell you where you are.

The story is a descent through five strata of a living planet (story/05-descent-structure.md). The
walls must tell it. This series REPLACES THE WHOLE WALL LAYER:
  - every region gets its own large REGION WALL SET, and only that set builds the region's halls and
    rooms - nothing crosses regions;
  - inside a region: a dominant BASE wall (with variants), VARIETY walls from the same set appearing now
    and then by rule, a distinct ROOM SET per room family (a medical room looks medical and different
    from the hall, in that region's style), a SIGNATURE set for the region's special rooms, the region's
    own DOORS and COLUMNS, and its own FLOOR and CEILING;
  - the old walls, their generators and files, and the old random picking are deleted in the same order
    that switches the game over (order 2) - no old wall is ever drawn again;
  - a new wall runtime: one atlas per region, base variants per tile face, an emissive glow layer exempt
    from the mood grade, a few animated walls, and distance LOD so detailed pixel art does not shimmer.

Room families are DATA: each RoomBlueprint (and each special generator) names its family in its
registration row. A new room is one row naming an existing family; a new family is one enum row plus a
room set in every region's kit. Never a switch.

How each region's room set differs: SAME FAMILY, REGION'S STYLE. A MEDICAL room in A is white livery
with a dispenser and a sealed scrub hatch; in B it is a tiled surgical bay with a drain; in C a pattern-
archive infirmary; in D a medical wall overgrown with membrane; in E an Organization field-medical panel
bolted into the lattice. Each order's VISUAL DESIGN lists all six families + signature for its regions.


THE SYMBOL TABLE (21 wall symbols, no new symbol, no removed symbol)
-------------------------------------------------------------------
A wall symbol no longer names a picture. It names a SLOT; the floor's region set decides the picture.
21 wall symbols exactly cover the slots (data in TilesetConstants; order 2):
  HALL         x BASE   k STRUCTURE   S LIGHT   c SERVICE   ' VENT   h MARKER   G BREACH
  MEDICAL      M base   Q accent
  SECURITY     X base   w accent
  CONTAINMENT  Z base   N accent
  MACHINERY    U base   j accent
  RESEARCH     t base   D accent
  STORAGE      v base   " accent
  SIGNATURE    F base   ` accent
BASE slots (x and every room base) carry their variants: the RENDERER picks the variant per tile face
(stable hash), so variants need no symbols. Doors (d R Y B) and the column (P) are FIXED symbols whose
pictures come from the region set. Every symbol stays a WALL exactly as today (Level.isWall) - the 2D
game cannot tell the difference.


THE PLACEMENT RULES - how a level's walls are chosen (order 2 builds them)
--------------------------------------------------------------------------
Replaces the old randomizer entirely. Seeded from the floor seed on its OWN RNG stream (never the
generator's), so layout, spawns and supply are untouched. Rates in LevelGenConstants (WALL_SET_*).
  P1  REGION: the floor's region (RegionPlan, like the lighting mood) picks the region set. Every wall
      on the floor comes from that set. Start room and hand-made levels: set A.
  P2  ROOMS: every room's perimeter walls are its family's room BASE; the room ACCENT appears on
      1-3 tiles per room (the wall facing the entrance first, never adjacent to another accent).
      Generic rooms (entrance, standard) and corridors are HALL.
  P3  SPECIAL FLOORS: MED_BAY floor -> MEDICAL; gate airlock -> SECURITY; event room, boss arena ->
      SIGNATURE; cavern floors -> HALL with BREACH weighted up.
  P4  HALL RHYTHM: along a straight exposed hall run >= 5 tiles, every 4th tile (phase seeded per run)
      is STRUCTURE; the tiles flanking a door are STRUCTURE (door frames).
  P5  HALL LIGHT: no exposed hall run >= 7 tiles without a LIGHT; never two LIGHTs adjacent.
  P6  HALL VARIETY: SERVICE / VENT scattered on 6-10% of remaining hall base, in 1-3 tile clusters;
      MARKER 1-3 per floor, near the arrival point and the exit.
  P7  BREACH: hall density = breachBase(region) + floorIndexInRegion x breachStep(region), grown as
      seeded clusters, never on a door frame. 0 on a region's first floor; clearly visible on its last.
  P8  Only exposed wall tiles (a walkable 4-neighbour) are dressed; only a wall symbol is ever written
      over a wall symbol (rule W7 below).
Result on a typical floor: ~65-75% hall base (in 3 variants), a steady rhythm of structure and light,
an occasional service/marker wall, rooms that read as what they are, and the region's own doors.


SERIES RULES (every order, by reference)
----------------------------------------
  W1  ORIGINALITY. No existing wall/door/column/floor texture or generator is reference material -
      never opened for inspiration, traced, recoloured or re-created. Designs come from story/00-premise.md,
      03-the-planet.md, 05-descent-structure.md, the region's mood and the room family's purpose.
  W2  GENERATED IN CODE with the enemy-art kit (guide N1). The game ships only the PNG atlases + JSON
      manifests the script writes. Deterministic, byte-identical regeneration, no hand edits. Enemy
      sprites regenerate byte-identical after every kit change (new materials are APPENDED).
  W3  ONE STYLE LOCK. Same LIGHT / RIM / wrap / cavity / cast occlusion / ramps / cleanup / outline as
      the enemies. New environment materials are appended to kit.MATERIALS, never tinted per wall.
  W4  TILEABLE. A wall is one TILE FACE, 256x256 (row 0 = ceiling line, row 255 = floor line), and tiles
      HORIZONTALLY with every wall of its region set: each region declares TRIM LINES (cornice, rail,
      kick plate) that every wall of the set honours, so different walls join along the same lines.
      Built on a 3-tile canvas and cropped (the prototype's method). Surfaces tile in both axes.
  W5  SEMANTIC COLOURS SACRED (art-direction V5). No saturated red/green/blue/purple/yellow decoration;
      SUIT_AMBER never on a wall; no red medical cross. Facility light = cyan; planet tissue = ichor;
      harvested soul = the pale SOUL ink. Keycard colours appear ONLY on keycard doors' lock panel and
      frame stripe, emissive, in the exact keycard colours.
  W6  READABILITY BEATS MOOD (V8). Walls are the backdrop: mid-value, never brighter than the enemies
      in front of them; emissives small (lamps, seams, cores - guide lesson 12.8). A room set must read
      as different from the hall at 4 tiles by SHAPE and MATERIAL, not by colour alone.
  W7  THE 2D GAME IS UNTOUCHED. No tile symbol added or removed, no wall becomes walkable or vice versa,
      no rule, turn, balance number, spawn, supply slot or persistence key changes.
  W8  STORY ON THE WALL. Every region set carries story details (serials, quota boards, a cradle
      print, a buried drill) as things a player notices, never text the player must read.
  W9  OWNER APPROVAL GATE (guide N7): per region set, a contact sheet (every wall, every variant, the
      tiled hall strip, one strip per room family) + in-engine captures under its mood; STOP until the
      owner answers; the answer goes into that order's DECISIONS.
  W10 NO TESTS (Testing Policy). Not balance-bearing. Existing tileset / level tests that encode the
      old catalog or the old allocator are UPDATED in the same commit - never deleted wholesale,
      disabled or weakened. Verified by build + run-game captures.
  W11 PERFORMANCE IS PART OF DONE. No allocation in render(); one region atlas per floor (one bind for
      walls, doors and columns); the base pass keeps its opaque/unblended + equal-column merge
      (render-performance-full-hd R16/R18); measured with run-game --probe.
  W12 THE OLD LAYER GOES COMPLETELY, in order 2: every old wall/door/column/floor generator, file,
      sprite id, the variety grab and the legacy table. Until a region's own set ships (orders 3-4), that
      region borrows set A (D8) - never an old wall.

ASSUMPTIONS (series-wide)
-------------------------
  AS1  Region = route region (RegionPlan.defaultPlan(): A..E), resolved like the lighting mood.
  AS2  256x256 per wall face (enemy texel density ~240 px per wall height), opaque, Nearest.
  AS3  PNG atlases are shipped (generator OUTPUT, never authored) - this overrides visual-identity V1
       ("no new image assets") exactly as the enemy series did.
  AS4  Same LIGHT as enemies (upper-left-front). Directional light on a periodic height field shades
       periodically, so tiling is unaffected.
  AS5  Wall glow = enemy glow idea: emissive pixels in a glow atlas, NORMAL blend over the graded base,
       exempt from the grade (art-direction V6 gains "wall emissives").
  AS6  Animation = a 2-8 frame cycle of the GLOW layer only. Animated walls: A LIGHT flicker (a seeded
       ~1 in 6 lamps), C LIGHT + cradle-bay pulse, D LIGHT heartbeat + one containment sac, E LIGHT
       synapse pulse + the memory window. The manifest flags each ("animate": all / some).
  AS7  One region atlas <= 2048x2048 (36 faces x 256^2 with 3 mips ~3.1 Mpx fits) + one glow atlas.
       Only the floor's region is resident (~16 MB GPU worst case), disposed on floor teardown.
  AS8  Same seed -> same walls (fairness, seed sharing).
  AS9  walls.py lives beside bestiary.py in .claude/skills/enemy-art/ (guide 13 "OTHER CONTENT").
  AS10 The stellar observatory and gore nest keep their room shapes and props; their walls become the
       region's SIGNATURE set (their old themed walls are deleted with the rest).
