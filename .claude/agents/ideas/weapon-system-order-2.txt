B. GameMath.java — new methods
──────────────────────────────────────────────
Add these pure static methods. Follow the required comment block convention.

    /*
     * Formula: Weapon level damage scaling
     * Derivation: scaledDamage = round(baseDamage * (1 + DAMAGE_PER_LEVEL * (level - 1)))
     * Edge cases: level=1 returns baseDamage unchanged; clamp level to [1, MAX].
     */
    public static int weaponScaledDamage(int baseDamage, int weaponLevel) { ... }

    /*
     * Formula: Weapon level accuracy scaling
     * Derivation: clamp(baseAccuracy + ACCURACY_PER_LEVEL * (level - 1), MINIMUM, 1.0)
     * Edge cases: melee passes 1.0 base and always returns 1.0.
     */
    public static float weaponScaledAccuracy(float baseAccuracy, int weaponLevel) { ... }

    /*
     * Formula: Weapon level reload scaling
     * Derivation: max(RELOAD_MIN_TICKS, round(baseReloadTicks - RELOAD_STEP * (level - 1)))
     * Edge cases: weapons already at 1 tick return 1.
     */
    public static int weaponScaledReloadTicks(int baseReloadTicks, int weaponLevel) { ... }

    /*
     * Formula: Weapon level clip scaling
     * Derivation: baseClip + floor(CLIP_PER_LEVEL * (level - 1) * baseClip)
     * Edge cases: clip-1 weapons (Shotgun/Railgun) stay 1 until accumulated bonus >= 1.
     *             Melee weapons pass 0 and return 0.
     */
    public static int weaponScaledClipSize(int baseClipSize, int weaponLevel) { ... }

    /*
     * Formula: Weapon level range scaling
     * Derivation: baseRange + min(floor((level-1) * RANGE_PER_2_LEVELS / 2), RANGE_MAX_BONUS)
     *             Simplified: +1 tile every 2 levels, max +3.
     * Edge cases: melee range is ALWAYS 1 — caller must guard: if(isMelee) return 1.
     */
    public static int weaponScaledRange(int baseRange, int weaponLevel, boolean isMelee) { ... }

    /*
     * Formula: Ability magnitude linear scaling
     * Derivation: clamp(baseMagnitude + perLevel * (level - 1), 0, maxMagnitude)
     * Edge cases: level=1 returns baseMagnitude.
     */
    public static float abilityMagnitude(float baseMagnitude, float perLevel,
                                         int weaponLevel, float maxMagnitude) { ... }

    /*
     * Formula: Ability count stepped scaling
     * Derivation: clamp(baseCount + floor((level-1) / levelsPerStep), minCount, maxCount)
     * Edge cases: level=1 returns baseCount.
     */
    public static int abilityCountScaled(int baseCount, int levelsPerStep,
                                         int weaponLevel, int minCount, int maxCount) { ... }

        this.weaponLevel = weaponLevel;

5. Add recomputeEffectiveStats() — called from configureRoll and Soulforge level-up:
    private void recomputeEffectiveStats() {
        effectiveDamage      = GameMath.weaponScaledDamage(baseDamage, weaponLevel);
        effectiveAccuracy    = GameMath.weaponScaledAccuracy(baseAccuracy, weaponLevel);
        effectiveClipSize    = GameMath.weaponScaledClipSize(baseClipSize, weaponLevel);
        effectiveReloadTicks = GameMath.weaponScaledReloadTicks(baseReloadTicks, weaponLevel);
        effectiveRange       = GameMath.weaponScaledRange(baseRange, weaponLevel, isMelee());
        // Apply EXTENDED_MAG ability bonus on top of level scaling
        if (hasAbility(WeaponAbility.EXTENDED_MAG)) {
            int bonus = abilityCount(WeaponAbility.EXTENDED_MAG);
            effectiveClipSize = Math.min(effectiveClipSize + bonus,
                                         WeaponConstants.WEAPON_CLIP_HARD_CAP);
        }
        // Apply QUICK_HANDS ability bonus on top of level scaling
        if (hasAbility(WeaponAbility.QUICK_HANDS)) {
            effectiveReloadTicks = Math.max(WeaponConstants.WEAPON_RELOAD_MIN_TICKS,
                                            effectiveReloadTicks - 1);
        }
    }

6. Implement all WeaponProfile getters:
    @Override public WeaponTier getTier()              { return tier; }
    @Override public int        getWeaponLevel()       { return weaponLevel; }
    @Override public int        getEffectiveDamage()   { return effectiveDamage; }
    @Override public float      getEffectiveAccuracy() { return effectiveAccuracy; }
    @Override public int        getEffectiveClipSize() { return effectiveClipSize; }
    @Override public int        getEffectiveReloadTicks() { return effectiveReloadTicks; }
    @Override public int        getEffectiveRange()    { return effectiveRange; }
    @Override public int        getAbilityCount()      { return abilities.length; }
    @Override public AbilityInstance getAbility(int index) { return abilities[index]; }
    @Override public boolean    hasAbility(WeaponAbility a) {
        for (AbilityInstance inst : abilities) if (inst.ability == a) return true;
        return false;
    }
    @Override public float      abilityMagnitude(WeaponAbility a) {
        for (AbilityInstance inst : abilities) if (inst.ability == a) return inst.magnitude;
        return 0f;
    }
    @Override public int        abilityCount(WeaponAbility a) {
        for (AbilityInstance inst : abilities) if (inst.ability == a) return inst.countValue;
        return 0;
    }

IMPLEMENTATION NOTES
====================
- Keep the existing final fields (baseDamage, baseClipSize, baseReloadTicks,
  damageDropCoefficient, baseRange) exactly as they are — they are the L1 reference.
  Only ADD new fields. Rename only if the field was previously named "damage"
  without a "base" prefix — in that case rename to baseDamage consistently.
- recomputeEffectiveStats() is called only on: spawn (configureRoll), Soulforge level-up,
  and once during construction. It is NEVER called in render() or per-tick — it is safe
  to keep small array iterations in hasAbility/abilityMagnitude since abilities.length <= 5.
- Do NOT change the fire() / marchShot() body yet — that is weapon-system-order-3.
- After all subclasses are updated, run `./gradlew build` to verify no compilation errors
  before proceeding to order-3.
- The shotsInClip field is reset to effectiveClipSize inside configureRoll(). Before
  configureRoll() is called on a fresh weapon (e.g., start weapons), shotsInClip is still
  initialized to baseClipSize in the constructor — that's correct for the default L1 path.
