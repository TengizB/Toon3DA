TITLE: Weapon System Orders 1–6 — Implementation Review
DATE: 2026-06-18
---

SUMMARY
=======
Orders 1–6 are largely implemented correctly — all data types compile, all
scaling math is present, and melee abilities work end-to-end. However there is
one critical bug that silently disables every hit-triggered ability for all
ranged weapons, plus one minor documentation error in Shotgun.java.


════════════════════════════════════════════════════════════════════════════════
CRITICAL — Hit-callback pipeline broken for all gun weapons
════════════════════════════════════════════════════════════════════════════════

AFFECTED FILES
  Shotgun.java          line 62
  DoubleBarrelShotgun.java  line 63
  Chaingun.java         line 163
  PlasmaRifle.java      line 59
  Railgun.java          line 139
  Incinerator.java      line 134
  GrenadeLauncher.java  line 170

ROOT CAUSE
  Every gun subclass calls:
    enemyHitTarget.applyDamageTo(hitEnemy, damage);
  but never calls:
    setLastHitEnemy(hitEnemy, damage);

  Weapon.dispatchHitCallbacks() (Weapon.java line 570) immediately returns when
  lastHitEnemy == null:
    if (abilityResolver == null || lastHitEnemy == null) return;

  Because no gun ever populates lastHitEnemy, dispatchHitCallbacks() is a no-op
  for every ranged shot regardless of which abilities are equipped.

CONSEQUENCE — abilities that never trigger for guns:
  ON_HIT:    CRITICAL_STRIKE, EXECUTIONER, STAGGER_ROUNDS, LIFESTEAL,
             KINETIC_SLAM (guarded by isMelee anyway), CLEAVE (same)
  ON_CRIT:   VAMPIRIC_CRIT
  ON_KILL:   HEMORRHAGE_HARVEST, ADRENAL_SURGE, SALVAGE_STRIKE (guarded),
             SCHOLARS_EDGE (guarded), BERSERKERS_OATH (guarded)

  In practice this means the entire ability system is silently inoperative for
  every gun in the game. Melee works correctly because MeleeWeapon.java line 99
  calls setLastHitEnemy() before applyDamageTo().

FIX (same pattern for every gun)
  Immediately before the applyDamageTo() call in each gun's marchShot(),
  add a call to setLastHitEnemy(). For example, Shotgun.java line 62 becomes:

    setLastHitEnemy(hitEnemy, damageAtDistance(distanceTiles));
    enemyHitTarget.applyDamageTo(hitEnemy, damageAtDistance(distanceTiles));

  Note: damageAtDistance() should be computed once into a local variable to
  avoid calling it twice:

    int damageThisHit = damageAtDistance(distanceTiles);
    setLastHitEnemy(hitEnemy, damageThisHit);
    enemyHitTarget.applyDamageTo(hitEnemy, damageThisHit);

  The same pattern applies to every hit site in the remaining six gun classes.
  GrenadeLauncher's splash loop and Incinerator's burn tick each have their own
  applyDamageTo() call that also needs the setLastHitEnemy() prefix.

  IMPORTANT: After adding setLastHitEnemy(), the base class clears lastHitEnemy
  in fire() at line 511 (start of fire) and line 543 (after each burst shot),
  so there is no risk of stale state carrying across separate fire events.


════════════════════════════════════════════════════════════════════════════════
MINOR — Shotgun.java class-header damage table is stale
════════════════════════════════════════════════════════════════════════════════

FILE
  Shotgun.java lines 10 and 17–22

PROBLEM
  The class-level Javadoc comment was written when SHOTGUN_DAMAGE was 24.
  WeaponConstants.SHOTGUN_DAMAGE is now 50. The damage table in the comment
  shows the old numbers:
    "distance 1: 24 × 0.82 = 20"   (actual: 50 × 0.82 = 41)
    "distance 5: 24 × 0.15 =  4"   (actual: 50 × 0.15 =  8)
  Also "Stats: damage 24" on line 10 is wrong.

  The constant and the gameplay math are correct; only the comment is wrong.

FIX
  Update the Javadoc to reflect damage = 50 and recompute the table, or delete
  the worked table and just reference WeaponConstants.SHOTGUN_DAMAGE.
