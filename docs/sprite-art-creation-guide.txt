SPRITE ART CREATION GUIDE — HOW toon3D MAKES ITS ART IN CODE
==============================================================
PURPOSE: the permanent, single source of truth for HOW a sprite, an animation or a visual effect is
         created for this game: the method, the rules, the tools, the engine constraints, the checks
         and every lesson already paid for. Read it before creating or changing ANY generated sprite
         - enemies first, but the same method applies to bosses, props, pickups, effect particles and
         anything else that needs pixels.

Created 2026-10-21 from the session that prototyped generated enemy art (three prototype enemies,
two approved by the owner, one rejected). Update it in the SAME commit as any change to the kit, the
style lock, the clip set, the reaction rules or the engine contract. A section marked [PLANNED: order N]
describes something the generated-enemy-art series has designed but not built yet; when that order
ships, it removes the marker.

Related: .claude/skills/enemy-art/SKILL.md (the tool's quick reference),
         .claude/agents/ideas/generated-enemy-art*.txt (the series that rebuilds every enemy),
         docs/art-direction.txt (the game's style bible - this guide must never contradict it).

====================================================================================================
1. NON-NEGOTIABLES
====================================================================================================
  N1  GENERATED IN CODE. Every sprite pixel comes from a script. No hand-painted pixel, no
      image-model output, no manual edit of an output PNG. To change art, change its code and
      regenerate. Same input -> byte-identical output (every noise source is seeded).
  N2  ORIGINALITY. The old enemy textures (assets/textures/enemies/ outside generated/) were made
      by image models; they do not fit the game and are NOT reference material - never opened for
      inspiration, traced, recoloured or re-created. Designs come from the story (story/00-premise.md),
      the entity's mechanics and role, and ORA's lines about it. The same applies to any future
      content: never "redo" an existing image-model asset, design the thing anew.
  N3  ONE STYLE LOCK. One light rig, one outline rule, one cleanup pass, one dither, one material
      library for everything. Never override them per sprite; extend the library instead.
  N4  SEMANTIC COLOURS ARE SACRED (art-direction V5). No saturated red / green / blue / purple /
      yellow as decoration. SUIT_AMBER belongs to the player and is never used on an enemy.
  N5  READABILITY BEATS MOOD (art-direction V8). A threat must read at two tiles under the darkest
      mood. Silhouette first; detail last.
  N6  STORY ON THE BODY. Every creature carries at least one detail that ties it to the premise
      (an Organization tag, a harvest port, a shackle, a stencilled serial). Story goes ON anatomy,
      never by removing anatomy the creature should have (see lesson 12.6).
  N7  OWNER APPROVAL GATE. Nothing generated enters the game until the owner has seen it - a
      contact sheet, animated clips and in-engine screenshots - and said yes. The answer is written
      into the idea file's DECISIONS. An agent's own opinion is never the gate.
  N8  NO TESTS (CLAUDE.md Testing Policy). Art is verified by building and running the game and by
      the checks in section 11.

    <creature>_rig.py                  one per creature: its rig function, pose defaults and clips
                                       (warden_rig.py, harvest_tick_rig.py, iron_stalker_rig.py; order 5:
                                       plague_hulk_rig.py, eye_tyrant_rig.py, gore_biter_rig.py, mire_wraith_rig.py,
                                       sump_wretch_rig.py - the first Mire Wraith, kept for its own enemy; order 6:
                                       ghoul_rig.py, crawler_rig.py, revenant_rig.py, vortex_eye_rig.py,
                                       blight_corruptor_rig.py - the undead, on kit.Humanoid)
    bestiary.py                        the CREATURES table (rig, clips) + the command line
    sheet.py                           contact sheets
  assets/textures/enemies/generated/   shipped output per creature: <name>.atlas.png, <name>.glow.png,
                                       <name>.clips.json (PNG binary alpha; section 7.6)

  Requirements: Python 3, numpy, Pillow (pre-installed in the cloud container). Nothing else.

  Commands:
    cd .claude/skills/enemy-art
    python3 bestiary.py ../../../assets/textures/enemies/generated        # ship: atlases + manifests
    python3 bestiary.py /tmp/out --preview /tmp/out/preview warden         # + clip GIFs and strip sheet
    python3 bestiary.py /tmp/out --stills [--halo] warden                  # rest pose only (sheets)
    python3 sheet.py /tmp/out /tmp/out/sheet.png 3                         # contact sheet at 3x
  A full bake takes ~0.3 s per unique frame (the Iron Stalker's 100 frames ~80 s).

  Why offline Python and not Java at runtime: the kit is ~400 lines of array numerics that would
  have to be duplicated in Java, would add load time on phones, and buys nothing visible. The game
  only needs the atlases and the clip manifests.


====================================================================================================
3. THE RENDERING TECHNIQUE, STEP BY STEP
====================================================================================================
The kit is a tiny offline "sculpt and light" renderer. It produces pixel art that looks hand-shaded
because every pixel's value comes from a real surface normal lit by one consistent light.

3.1 Shapes are HEIGHT FIELDS, not flat stickers.
  Every primitive returns a signed height h(x, y): positive inside (the surface height above the
  canvas), negative outside (minus the distance to its edge).
    blob      ellipsoid dome: depth * sqrt(1 - q^2) inside, depth * (1 - q) outside (q = normalised radius)
    limb      tapered capsule: the same profile around a segment, radius r1 -> r2
    chain     a bent limb = consecutive limbs with a tapering radius
    slab      bevelled plate: rises from the edge at `slope` to a plateau, optionally tilted
    spike     (order 4) a tapered, curved blade/spike: a chain along a quadratic spine whose radius falls
              from the base to a point, fast near the tip, with an optional raised EDGE strip of another
              material along one flank (the Iron Stalker's bone-pale scythe edges, its spines, mandibles)
    riveted_plate (order 4) a slab plus `add` rivets inset from its edge (one per corner, then every
              ~spacing px). op="add" fits the plate ON a body - it follows the body's curve and its edges
              step up (the Stalker's chest plate, helm, collar, arm cuffs); a union plate in its own layer
              reads as a separate, liftable piece (its pauldrons: they lift, ring and tear)
  Why: a height field has a gradient, so lighting, occlusion and outlines all come for free and
  stay consistent between every sprite.

3.2 Shapes inside a LAYER merge with a SMOOTH MAXIMUM.
  smax(a, b, k) = max(a, b) + h^2 * k / 4, h = max(k - |a - b|, 0) / k.
  k is the blend radius in pixels. k ~ 4-10 makes a leg GROW out of a body (a fillet forms where
  they meet); k = 0 is a hard union. Signed heights matter: because outside is negative, fillets only
  form where shapes are close - empty canvas never fills up.
  Shape operations: union (smooth max), add (raise a detail and paint it its own material: veins,
  rivets, eyes, blisters), carve (subtract: grooves, panel seams, fractures).
  Material at a pixel = the union shape with the highest (h + prio); `prio` decides overlaps.

3.3 LAYERS are back to front, with hard edges between them.
  A later layer always sits in front. Use a separate layer only when a part must read as IN FRONT
  of another (a front leg over the thorax, an arm over the hull). Everything that should look like
  one organic mass stays in ONE layer (lesson 12.1).

3.4 Normals come from the gradient.
  n = normalise(-dH/dx, -dH/dy, 1) by central differences inside each layer (a neighbour in a
  different layer counts as the edge). Image y points DOWN; the light vectors are written in the
  same convention.

3.5 The light rig (shared, never per sprite).
  Key light     upper-left-front  L = normalise(-0.50, -0.72, 0.48)
  Wrap          v = 0.06 + 0.62 * wrap(n.L) + 0.30 * max(n.L, 0)   - a soft terminator, no harsh black side
  Rim           FACILITY_CYAN from the right, strongest on silhouette edges - "LIT BY THE MACHINE":
                the facility's light catches every creature, whatever it is
  Specular      Blinn half-vector, per material (strength, shininess): metal and wet chitin shine,
                stone does not. A specular hit replaces the pixel with the ramp's top step + white.
  Cavity AO     a pixel lower than its blurred neighbourhood is darker (crevices, seams, joints)
  Cast AO       a pixel just behind a nearer layer is darker (up to 3 px, fading)

3.6 Quantise to the material RAMP.
  Each material is a 6-step ramp (section 4). The lit value v picks the step; a 4x4 Bayer dither
  of amplitude 0.08 breaks banding only at step boundaries. Surface variety comes from GRAIN (value
  noise added to the height field per material), never from heavy dither (lesson 12.4).

3.7 Emissives and translucency.
  Emissive materials (cyan, ichor, magma, ...) ignore the light: value = 0.22 + 0.74 * I^1.4, where
  I is the shape's OWN normalised height - so a glow part is hottest at its own centre (lesson 12.3).
  Translucent materials (sac) are lit like a surface, then mixed toward a glow ramp by their own
  thickness: a blister glows from inside, strongest where it is thickest.

3.8 Cleanup.
  A pixel whose four neighbours all agree on another shade takes that shade (two passes). This is
  the step that separates "rendered" from "pixel art": no orphan pixels, no salt-and-pepper.

3.9 Outlines.
  Interior: where a nearer layer overlaps a farther one, the far side's edge pixel is darkened.
  Exterior: a 1-px selective outline in the DARKEST step of the neighbouring material (slightly
  lighter on the lit upper-left side), never one flat black for everything. Emissive neighbours get
  their glow ramp's second step, so a glow has a coloured edge rather than a black one.

3.10 Stencils and decals.
  stencil(img, "W-07", x, y, colour): 3x5 pixel digits/letters painted only onto opaque pixels.
  Legible at close range, invisible at four tiles - right for story detail, never for information
  the player needs (lesson 12.7).

3.11 Glow halo (presentation only).
  --halo paints a soft translucent spill around emissives. The engine alpha-cuts enemy textures,
  so shipped sprites are written WITHOUT it; in-game glow comes from the emissive (glow) layer, laid
  over the body as a NORMAL-blend overlay in its baked colour, exempt from the mood grade (art-direction
  V6; order 2 D2 — never additive, the glow pixels are a copy of the body's and adding doubles them).


====================================================================================================
4. MATERIALS, PALETTES AND INKS
====================================================================================================
4.1 A material is: a 6-step ramp (dark -> light), specular (strength, shininess), grain (amplitude,
    cell size), and optionally emissive=True or glow=<emissive ramp> (translucent).
4.2 Ramp rules: hue-shift - shadows cooler, lights warmer; no step pure black or pure white
    (outlines and specular own the extremes); neighbouring steps clearly distinct at 1x; saturation
    stays moderate (N4).
4.3 The library (kit.py MATERIALS):
    gunmetal, darkmetal, livery (Organization white)       Organization hardware
    chitin, chitin_dk, bone, sac (translucent, ichor glow) creatures of harvested tissue
    flesh, flesh_dk, sclera, membrane (translucent,       (order 5) the aberrations: desaturated rose-grey and
      ichor glow), pupil                                  violet-grey, never red; every one carries the WET SHEEN
    overalls, hazmat, labcoat, visor, deadskin,            (order 6) the undead: slate suit, olive-grey (never green)
      spore (translucent, soul glow), redeye (emissive)   quarantine rubber, off-white lab coat, smoked glass (masks,
                                                          visors, the riot shield), ash grey (a torn cuff, a split seam -
                                                          never a face), soul-lit pods, the Ghoul's red eyes (owner D1)
    basalt, basalt_lt                                      stone (see lesson 12.2 before using)
    cyan, ichor, magma                                     emissives
4.4 Family glow inks (one per family, so a family reads at a glance):
    MACHINE cyan (the Organization's light) | INSECT + ABERRATION ichor (harvested tissue, coral; shipped for both) |
    UNDEAD soul (shipped order 6: pale, cold, low saturation; the Ghoul's eyes are the one red exception) | GOLEM + DEMON magma
    (the planet's heat; elemental golems add their element on the surface).
4.4b WET SHEEN (order 5): a material may carry wet=(strength, shininess) - a second, tight specular lobe that
    leaves a near-white glint (kit.WET_GLINT, never pure white) on the lit curve; the glint is its own cleanup shade.
    Only the flesh materials carry it, so no earlier sprite changes. Glow ceiling: a translucent or emissive part whose
    glow passes ~1.1 tops out in the ramp's near-white - cap gland / iris light (white belongs to the hit flash, V5).
4.5 Adding a material: add a row to MATERIALS, never tint one sprite by hand. Check it beside the
    existing ramps on a contact sheet and under the darkest and the brightest mood.


====================================================================================================
5. DESIGNING A CREATURE
====================================================================================================
5.1 THE BRIEF (write it in the idea file before any code)
    What it IS        its place in the story - who made it, what happened to it (premise table)
    Role -> mass      CHAFF small | SOLDIER medium | BRUISER heavy | MINI_ELITE larger and spiked |
                      BOSS huge
    Verb -> pose      its tacticalVerb() as a body: a charger leans its battering front forward, a
                      sniper points one line at you, a flanker reaches sideways, a tank plants wide
    The attack        visible on the body (emitter, blades, fists, jaws, spout)
    ORA's line        the sprite must say it before she does
    Materials + ink   from section 4; the family ink
    Story detail      at least one (N6)
    Distinctness      how it differs from every other member of its family at two tiles
    Motion character  how it idles, moves, attacks, flinches and dies (section 7)
5.2 BUILD ORDER (each step judged at 1x before the next)
    a. Silhouette: big masses only, one layer, flat - does the black shape read the role and verb?
    b. Masses merged with smooth max; limbs as chains; decide which parts need their own layer.
    c. Materials and prio.
    d. Detail as add/carve: seams, ridges, rivets, veins, eyes, teeth.
    e. Story detail and stencil.
    f. Contact sheet beside its family; then in-engine.
5.3 Symmetry: design half with mirror(), then break it on purpose (a clamp, a torn hose, an arm
    holding a weapon). Perfect symmetry reads as a toy.
5.4 Distance: judge at 1x, 3x and in-engine at 2 and 4 tiles. Thin parts (antennae, blades) vanish
    first - thicken their base and let the rim light catch them.


====================================================================================================
6. COMPOSITION: CANVAS, SCALE, GROUND LINE, HOVER
====================================================================================================
  - Regular enemies 160x240, bosses 240x360 (both 2:3, the aspect the renderer draws). Origin
    top-left in the kit (y down); feet on row ~232 (regular) / ~352 (boss); centred on the middle column.
  - The renderer scales the whole canvas to heightMultiplier() walls. Compose the creature to fill the
    canvas for its role; never change heightMultiplier to fix art.
  - A floating creature the renderer does NOT hover bakes its hover into the canvas (empty rows
    under it, like the Warden); a creature the renderer hovers (EYE_TYRANT) stands on the canvas floor.
  - Leave clear air where the renderer draws overlays on top (e.g. the Auric Sentinel's shard ring).
  - Animation frames share ONE canvas and ONE ground line, so a creature never pops between clips.
    A pose must never push a part off the canvas: the bake warns (naming the edge) and the fix is to
    clamp the pose, never to grow the canvas. Long parts that rotate (the Warden's prod) swing across
    the body, not outward past the edge.


====================================================================================================
7. ANIMATION: RIGS, POSES, CLIPS, ATLASES, MANIFEST
====================================================================================================
7.1 The model. A sprite function becomes a RIG: build(pose) -> layers, where `pose` is a dict of
    named parameters (joint angles, offsets, squash, jaw open, lid closed, glow intensity, ...).
    A CLIP is a list of keyframes (time, pose values) with easing; the kit renders each frame by
    evaluating the rig at the interpolated pose. Because every frame is lit by the same rig, shading
    is automatically consistent across frames - the core advantage of generating animation in code.
7.2 Why pre-rendered frames and not a runtime skeleton: the smooth-max merging and per-pixel
    lighting cannot be decomposed into rigid quads without losing the look. Frames keep the quality.
7.3 THE STANDARD CLIP SET (every enemy; durations are real seconds, the game is turn-based). Frame
    counts follow from duration x fps (12 fps default, AS1); the shipped Warden / Harvest Tick counts are
    in brackets (the Iron Stalker: IDLE 18, ALERT 5, ATTACK 6, DEATH 11). IDLE is the atlas's biggest cost - a creature that must fit more clips lowers it first.
    IDLE        loop, 0.8-1.6 s at 12 fps [16 / 18 frames]: breathing, hover sway, antenna twitch,
                blister pulse. Alive even when nothing happens. DORMANT plays it at half speed and
                6 fps (same frame count), eyes dimmed.
    ALERT       one-shot, 0.3-0.5 s [5 / 6 frames]: the startle when it wakes (eyes ignite, rears up).
    MOVE        loop, 4 frames, plays during the tile slide: a step cycle, a scuttle, a thrust surge.
    WIND_UP     one-shot into a HELD last frame: the telegraph. It holds for the whole player turn,
                so the anticipation pose IS the warning (pillar: readable threats).
    ATTACK      one-shot within ENEMY_ATTACK_ANIM_DURATION (0.30 s today), baked at 20 fps [6 frames]:
                anticipation -> strike (smear frame allowed) -> recovery. The strike frame carries a
                manifest EVENT: "emit" for a ranged shot (it leaves the muzzle anchor), "impact" for a
                melee hit (Clip(events={time: name}), 7.7).
    HURT_LIGHT  2 frames: a flinch.     HURT_HEAVY  ~0.4 s [5 frames]: a knock back, a stagger.
    DEFEND      one-shot into a held brace.
    DEATH       0.6-1.0 s [11 frames]: collapse / break apart / power down - in the creature's
                own character - ending on the frame that becomes its corpse.
    + ability clips where the type has one (SUMMON, AREA_STRIKE, SELF_DESTRUCT priming, the lance,
      a shard absorb ...), named in the order that builds the type. SHIPPED (order 4, the Iron Stalker):
      BUFF_SELF (once, 0.58 s: plates lift and LOCK, the ichor seam flares) and AREA_STRIKE (once, 0.40 s
      at 20 fps, "impact" on the crossing frame: from the WIND_UP's cocked blades, a two-blade scissor sweep
      with smear frames). SHIPPED (order 5): DEBUFF_PLAYER (the Eye Tyrant's pinpoint iris, the Mire Wraith's volley
      with an "emit"), SELF_DESTRUCT (the Plague Hulk's countdown swell - a HOLD clip played as a one-shot, it stays
      one level up while the state holds), plus PRIMING (HELD by the SELF_DESTRUCTING state) and DEATH_BURST (variant
      of DEATH for a self-destruct). SHIPPED (order 6): SUMMON (the Blight Corruptor's pods swell and split, 0.6 s) and
      the Vortex Eye's DEBUFF_PLAYER (the vortex winds tight and lashes, "emit" at 0.28). An ability clip is named exactly as the SpecialAbility constant; the runtime maps
      the ability to it by a rule row (8.2) and plays ATTACK for a creature that does not ship one.
7.4 Principles (they matter more at low frame counts): anticipation before every action; squash
    and stretch on impacts; overlapping action (cables, antennae, tails lag a frame); hold the key
    pose longer than the in-betweens; a clip must read in its first two frames.
7.5 Texture must stick to the body. Grain noise is sampled in each SHAPE'S OWN coordinates, not
    canvas coordinates, or the surface "swims" over a moving part. The Bayer dither is screen-fixed
    and may shimmer slightly on moving edges - acceptable, keep it at 0.08.
    How: every Shape carries `frame`, a 3x3 affine map canvas -> its own material coordinates. A new
    shape gets an intrinsic frame (ellipse: centre + angle; capsule: start point + axis; slab:
    centroid), and every rigging transform composes into it, so the grain rides the part. Grain is
    `value_noise_at` - an integer lattice hash seeded per material by crc32 (never Python's hash(),
    which is randomised per process) - blended across overlapping shapes by their height, so the
    joints of a chain show no seam.

7.6 THE API (kit.py)
    spike(x1, y1, x2, y2, r, mat, bend=0, tip=0.4, segments=5, edge=None, edge_side=1)   (order 4) a blade:
                          base -> tip, bowed `bend` px toward (-dy, dx); `edge` = the cutting-edge material.
    riveted_plate(points, mat, rivet_mat="darkmetal", spacing=8, inset=2.6, rivet_r=1.25, bevel=2.5, **slab)
                          (order 4) an armour plate with rivets; slab kwargs (op, tilt, prio, k, slope) pass through.
    eyeball(cx, cy, r, look=(0, 0), iris=0.55, pupil=0.42, slit=1, lid_top=0, lid_bottom=0, lids=False, ...)
                          (order 5) wet sclera + emissive iris (family ink) + pupil + a fixed catch-light glint; `look`
                          moves and foreshortens the iris, `slit` narrows the pupil to a line; a lid is a CAP of flesh
                          (a crease at 0, shut at 1; lids=True always builds them so they never pop). One layer.
    teeth_row(x1, y1, x2, y2, count, length, r, mat="bone", side=1, sag=0, rake=0, jitter=0.25, seed=0, **kw)
                          (order 5) seeded spikes along a jaw line, pointing along its normal x side. On a face pass
                          op="add" (a union tooth loses to the head's height); protruding teeth stay union in a front layer.
    jiggle(source_clip, param, duration, out_param=None, freq=4, damping=0.35, gain=1, fps=24, loop=True)
                          (order 5) SECONDARY MOTION: keys for "<param>_jig" = a damped spring LAGGING the param's track
                          (flesh rolling after the breath, a shroud after the sway). Baked (a rig has no memory); a loop
                          integrates four periods so it wraps without a seam. Merge into the clip's keys.
    Humanoid(pelvis, spine, neck, head, shoulder_half, hip_half, upper_arm, fore_arm, hand, thigh, shin, foot, arm_rest,
             leg_rest)   (order 6) THE HUMANOID RIG: one skeleton, many bodies. joints(p) -> named canvas points (pelvis,
                          waist, chest, neck, head, l_/r_ shoulder, elbow, wrist, hand, hip, knee, ankle, toe + the hand /
                          foot / head / chest angles) from joint ANGLES in the pose: every limb angle is measured from
                          straight DOWN and MIRRORED per side (+ = outward for both), children relative; torso / chest /
                          neck / head lean; squat folds the legs; <limb>_fore foreshortens a whole limb toward the viewer,
                          <side>_upper_fore the upper arm alone (the elbow brought forward - lesson 12.22). A NEGATIVE
                          spine / neck / head hangs it upside down = a body on all fours seen head-on (the Crawler).
                          Humanoid.params(**defaults) gives every skeleton parameter (0) for a rig's defaults.
    hand(wrist, angle, side, length, mat, fingers=4, finger_length=, finger_r=, palm_r=, spread=, curl=, thumb=True)
                          (order 6) a palm + chained fingers fanned about the hand; curl 0 open .. 1 a grab. For OPEN
                          hands only (the Ghoul's reach) - never for a hand gripping a held object (lesson 12.21).
    fold_lines(x1, y1, x2, y2, count, length, width=, mat=, angle=, jitter=, seed=, side=)   (order 6) seeded carved
                          creases along a line: what turns a smooth capsule into cloth (elbows, knees, a pulled chest).
    lag(clip, param, delay, duration, out_param=, fps=, loop=True)   (order 6) keys for "<param>_lag" = the param's own
                          track `delay` seconds late (a hem, a badge, a hose following its limb; no spring, unlike jiggle).
    Figure.transformed(xf)   (order 6) the figure carried through one more transform - layers, anchors, stencil
                          positions (a whole-body collapse on DEATH, a NARROW of a too-wide creature).
    Xf                    a 2D affine transform. Image space: origin top-left, y DOWN, so a positive
                          angle turns CLOCKWISE on screen.
      Xf.move(dx, dy)  Xf.turn(angle, pivot)  Xf.scale(sx, sy, pivot)  Xf.reflect_x(axis)
      Xf.segment(rest_a, rest_b, new_a, new_b, stretch=True)   carries a part riding a limb segment
      a.then(b)           apply a, then b (build a hierarchy: child.then(parent))
      xf(shapes)          transformed copies of a shape list;  xf.pt((x, y)) a transformed point
    with_glow(shapes, level)   glow level of emissive / translucent shapes: 0 dead (<= GLOW_DEAD 0.05
                          is shaded at the ramp bottom and leaves the glow atlas), 1 rest, > 1 flare.
                          Also Shape(..., glow=) on any primitive.
    Figure(layers, anchors, stencils)   what a rig returns for one pose: layers back to front,
                          anchors {name: (x, y)} on the canvas, stencils [(text, x, y, colour)].
    Rig(name, build, defaults, seed, width=160, height=240, ground_y=232)
                          build(pose) -> Figure. `defaults` names EVERY pose parameter (plain floats);
                          the rest pose = all defaults = the approved still. rig.pose(**values),
                          rig.render(pose, halo=False) -> (image, glow image, anchors).
    Clip(name, keys, duration=None, fps=12, mode="loop", variant_of=None, overrides=None)
      keys                [(time_s, {param: value}, easing), ...]. EACH PARAMETER IS ITS OWN TRACK: it
                          interpolates only between the keys that name it, so a clip names only what
                          moves. The easing shapes the segment LEAVING that key: linear, in, out, inout
                          (default), hold (step). A loop wraps the last key back to the first; a
                          one-shot track whose first key is late eases in from the rig default at t=0.
      mode                loop | once (play, then the runtime moves on) | hold (hold the last frame:
                          WIND_UP, DEFEND, DEATH).
      sampling            n = round(duration x fps) frames, each duration / n long, so the clip lasts
                          exactly `duration`. A loop samples t = 0 .. duration excluded; a one-shot
                          samples t = 0 .. duration included, so its last frame IS the end pose.
      clip.variant(name, speed=1, keys=(), fps=None, **overrides)   time-stretched copy with extra keys
                          and pinned parameters (DORMANT = IDLE at half speed and fps 6, dimmed;
                          WOUNDED = IDLE + damage parameters + its own extra tracks).
    write_creature(rig, clips, out_dir, preview_dir=None)   the bake: render every frame, trim to the
                          alpha bounds, merge consecutive identical frames (durations add), share one
                          atlas rect between identical frames of different clips, shelf-pack into a
                          power-of-two atlas (ERROR above 2048x2048), write the glow atlas in the same
                          packing, the manifest and (optionally) the previews. Warns when any frame
                          touches a canvas edge.
    Timing that fits the game (rule R3 of order 1): ATTACK within EffectConstants.
    ENEMY_ATTACK_ANIM_DURATION_SECONDS (0.30 s) - bake it at fps 20 for 6 frames; WIND_UP is a `hold`
    clip whose last frame can be held for a whole player turn; MOVE is a short loop (0.33 s).

7.7 THE MANIFEST (<name>.clips.json, MANIFEST_VERSION 1) - the contract order 2's runtime reads with
    LibGDX's JsonReader. Plain JSON, one frame per line.
    {
     "version": 1,
     "creature": "warden",
     "canvas": [160,240],              the common canvas every frame was rendered on
     "groundY": 232,                   the ground line on that canvas
     "atlas": "warden.atlas.png",      sibling files, same folder
     "glow": "warden.glow.png",
     "atlasSize": [1024,2048],
     "clips": {
      "IDLE": {
       "mode": "loop",                 loop | once | hold
       "fps": 12,                      the rate it was sampled at (informational; use frame durations)
       "duration": 1.33,               seconds; the sum of its frame durations
       "variantOf": "IDLE",            only on a variant (DORMANT, WOUNDED)
       "frames": [
        {"rect":[x,y,w,h],             the trimmed frame in the atlas (and in the glow atlas)
         "offset":[left,top],          where that rect's top-left sits on the canvas
         "duration":0.0833,            seconds this frame shows
         "glow":true,                  false = the glow rect is empty, skip the additive draw
         "anchors":{"eye":[x,y], ...}, canvas coordinates, sorted by name
         "event":"emit"}               OPTIONAL, only on the frame the runtime acts on: "emit" (a ranged
                                       shot leaves the muzzle anchor) | "impact" (a melee hit lands).
                                       Shipped: Warden ATTACK frame 1 = emit, Harvest Tick ATTACK
                                       frame 2 = impact, Iron Stalker ATTACK + AREA_STRIKE = impact. Never merged into a neighbouring frame.
       ]}}}
    COORDINATES: everything is IMAGE space - origin TOP-LEFT, y DOWN - in pixels of the canvas or the
    atlas. LibGDX's TextureRegion(texture, x, y, w, h) takes the atlas rect as-is; canvas positions
    must be flipped (canvasHeight - y) when placed in the world's y-up space.
    Shipped clip names (the standard set, 7.3): IDLE, DORMANT, ALERT, MOVE, WIND_UP, ATTACK,
    HURT_LIGHT, HURT_HEAVY, DEFEND, WOUNDED, DEATH; ability clips BUFF_SELF, AREA_STRIKE (order 4), DEBUFF_PLAYER,
    SELF_DESTRUCT, PRIMING, DEATH_BURST (order 5), SUMMON (order 6). The corpse frame is the last DEATH frame. Its
    lowest pixels may sit a few rows BELOW groundY (the Warden's wreck reaches row 236): parts lying
    toward the viewer read lower on screen. Place a frame by its offset on the canvas, never by
    snapping its bottom edge to the ground line.
    Anchors every creature reports: ground, hit_centre, eye; plus muzzle (anything that emits -
    the Warden's prod tip, the Eye Tyrant's PUPIL (the beam leaves it), the Mire Wraith's maw, the Vortex Eye's eye ports)
    or mouth (the Harvest Tick's jaws; order 6: the Ghoul's clamping hands, the Revenant's shield face, the Corruptor's
    sprayer tip).
    Deterministic: the same script writes byte-identical atlases and manifests (rule R4).

7.8 Previews for the owner (bestiary.py --preview DIR): an animated GIF per clip, nearest-neighbour
    3x on the game's near-black, one-shot clips holding their last frame for a beat; plus
    <name>_strip.png, every clip as a labelled row of frames at 2x with the frame durations and the
    anchors marked. Previews are for the gate and are never committed.

7.9 Atlas budget. Order 6: ghoul 93 (1024x2048), crawler 64 (1024x1024), revenant 62 (1024x2048), vortex_eye 97
    (1024x1024), blight_corruptor 96 (1024x2048). Order 5: plague_hulk 98, eye_tyrant 96, mire_wraith 95, sump_wretch 96 (all 2048x2048),
    gore_biter 83 (1024x2048). The Warden (81 unique frames) packs into 1024x2048; the Harvest Tick (88) fills
    2048x2048 exactly; the Iron Stalker (100, 13 clips incl. two ability clips) fits 2048x2048. A creature that needs more clips gets them by lowering frame counts (a slow
    variant at a lower fps, shorter idles) or by splitting its atlas - a runtime change for the order
    that owns the runtime - never by growing the limit.

====================================================================================================
8. REACTIONS: HOW AN ENEMY ANSWERS EVERY EVENT              [order 2: core clips; order 3: reactions]
====================================================================================================
The simulation stays headless: EnemyManager fires visual MOMENTS through a listener seam (the same
idiom as enemy/EnemyVoiceListener, so the enemy package never imports a renderer). The visual layer
maps each moment to a clip and an effect. Minimum behaviour every creature must show:
    woken               ALERT, eyes/emitters ignite
    moves a tile        MOVE during the slide, then back to IDLE
    telegraphs          WIND_UP, held through the player's turn
    attacks             ATTACK synced to the hit; ranged emits from the muzzle anchor
    takes damage        HURT_LIGHT or HURT_HEAVY by damage tier; a brief recoil AWAY from the hit;
                        a family hit effect at the hit anchor; the white flash kept
    resists / blocks    no flinch - an armour spark or a block shimmer instead (the matchup layer's
                        RESISTED must look different from a hit that hurt)
    staggered / knocked HURT_HEAVY + displacement
    braces (DEFENDING)  DEFEND, held
    low health          WOUNDED state: a damage layer generated by the kit (cracks, sparks, leaks,
                        a limping idle) fades in below 50% HP
    status effects      burning / poisoned / slowed tint and particles where the status applies
    dies                DEATH plays even though the simulation already removed the enemy (the visual
                        layer keeps a dying instance), then hands over to the corpse decal
Nothing here changes a rule, a number or a turn: reactions are cosmetic and never block input.

8.1 THE SEAM (shipped, order 2). enemy/EnemyVisualListener.onEnemyVisualMoment(EnemyVisualEvent), set on
    EnemyManager (null by default - sim/ and the tests never see it). EnemyVisualEvent is ONE reused payload
    (never keep it); EnemyVisualMoment's per-constant data says which fields a moment fills. Fire sites:
      ALERTED           perception, chain alert, the HUNTED hunter, any spawn (a summon arrives awake)
      MOVE_STARTED      a real tile step (from/to tiles); a charge's whole rush is ONE move
      WIND_UP_STARTED   every committed wind-up (announceWindUp)
      ATTACK_COMMITTED  melee, ranged (after the shard check), charge, lance, sow
      ABILITY_USED      executeSpecial (ability named) - never also ATTACK_COMMITTED
      DAMAGED           every player hit (amount, healthFraction, matchup outcome, absorbed, blocked, source)
      STAGGERED / KNOCKED_BACK / DEFEND_STARTED / STATUS_APPLIED
      DIED              killEnemy(enemy, cause) - FIRST, while the enemy still stands on its tile
    Damage-over-time ticks fire no DAMAGED on purpose (order 3): status visuals are read from the enemy every
    frame, and a DoT death still fires DIED (cause STATUS). A splash hit names its BLAST tile as the source
    (EnemyHitTarget.setVisualBlastOrigin - grenade impact, barrel, relic blast; cosmetic, no rule reads it).
    Bosses are moved by BossFloorController (unmigrated).
8.2 CLIP SELECTION (shipped, order 2) - render/enemyvisual/EnemyAnimationRules, data rows, highest wins:
      DEATH 7 > HURT_HEAVY / HURT_LIGHT 6 > ATTACK 5 > WIND_UP (held) 4 > DEFEND (held) 3 > ALERT 2 >
      MOVE 1 > IDLE / DORMANT 0
    ABILITY_USED (order 4) is Kind.ABILITY: the ability's own clip from the ability rows (abilityClip(BUFF_SELF,
    BUFF_SELF), abilityClip(AREA_STRIKE, AREA_STRIKE)) when the creature ships it, else ATTACK, at ATTACK's
    priority. A new ability clip is one EnemyClipId constant + one abilityClip row. The strike AREA MARKER stays
    with EnemyAttackEffectSystem: the clip owns the body, the system owns the marker.
    HURT_HEAVY when the hit cost >= EffectConstants.ENEMY_VISUAL_HURT_HEAVY_HEALTH_FRACTION (25%) of max HP,
    and always for a stagger or knockback; a hit a shard absorbed or Block swallowed does not flinch.
    WIND_UP is held while the enemy is WINDING_UP / SELF_DESTRUCTING, DEFEND while DEFENDING (a state
    table, not a timer) - and (order 4) WIND_UP while a HEAVY is committed (plannedAction.heavyAttack): a heavy
    SPECIAL such as AREA_STRIKE is planned while the state stays ATTACKING / CHASING, so the state row alone
    dropped its telegraph. EnemyAnimationRules.holdFor(Enemy) is the one lookup; holdsWindUp drives CHARGE. A finished one-shot falls back to the best ongoing condition every frame.
    ORDER 5 rows: a Hold may name a FALLBACK (SELF_DESTRUCTING holds PRIMING, else WIND_UP; holdsWindUp counts the
    fallback, so a priming body seeps its CHARGE burst); a hold that REPLACES one already showing starts at frame 0
    (WIND_UP_STARTED arrives before the state flips to SELF_DESTRUCTING); a HOLD-mode one-shot keeps its last frame while
    the enemy still holds a clip; DEATH by CAUSE is a DeathRow (SELF_DESTRUCT -> DEATH_BURST + the DETONATE burst, else
    DEATH), and the dying instance and its remains keep that clip. A hovered type (EYE_TYRANT) falls from its hover to
    the floor over ENEMY_VISUAL_HOVER_FALL_PORTION of its death clip (GameMath.hoverRemainingWhileFalling).
    ORDER 6 row: abilityClip(SUMMON, SUMMON) - the summoned dead arrive through ALERTED like any spawn.
    MOVE: the simulation moves an enemy instantly; the visual layer slides a migrated body one MOVE cycle
    per tile (ENEMY_VISUAL_SLIDE_SECONDS_PER_TILE 0.33 s, max 0.5 s), never snapping back mid-slide.
    Idle phase = frac(enemyId x 0.618) x IDLE duration, so a pack never breathes in unison - and (order 5, A3) the MOVE
    loop starts at the same phase fraction of MOVE, or a pack whose slides begin on one turn steps in lock-step.
    DEATH plays from DyingEnemyPool (8 slots, oldest dropped) at the body's last visual position and, on its
    last frame, hands the body to the creature's REMAINS (8.6).
8.3 HOW A HIT IS ANSWERED (order 3) - EnemyAnimationRules.HitReaction, one data row per outcome, so the
    four reads can never collapse into one (R2):
      outcome      clip        family burst  recoil (tiles)  drop   white flash  extra
      HURT_LIGHT   HURT_LIGHT  HIT           0.06            3 px   yes
      HURT_HEAVY   HURT_HEAVY  HIT_HEAVY     0.11            6 px   yes          >= 25% of max HP
      STAGGERED    HURT_HEAVY  -             0.11            6 px   (the hit's)
      RESISTED     none        RESIST        0.035 (shove)   0      NO           one hard spark / a dull chip
      BLOCKED      none        -             0.02            0      NO           steel-blue band down the body
      ABSORBED     none        -             -               -      (gold)       the Auric gold flash, untouched
    Classified in that order: shard absorb > Block > matchup RESISTED > the 25% rule. A KILLING blow is not a
    row: DIED follows it at once and plays DEATH with the KILL burst. RECOIL pushes the body AWAY from the hit's
    source tile (the blast tile for splash, else the player; on the source tile itself, straight back into the
    screen) and eases out over 0.22 s as (1 - t)^2; hits in one turn add up to a cap (0.16 tiles, 9 px) so a
    chaingun never walks the body off its tile. The BLOCKED band is a LIGHT pass (the body atlas, additive,
    Block's tint) like the muzzle light - never the glow atlas. Constants: EffectConstants ENEMY_VISUAL_*.
8.4 WOUNDED (order 3): below ENEMY_VISUAL_WOUNDED_HEALTH_FRACTION (50%) an awake creature's resting loop is
    its WOUNDED clip and its family LEAK burst repeats from its leak placement (the Warden's cracked visor
    sparks, the Tick's burst blister drips). Read live from health every frame - no moment needed.
8.5 STATUSES AND THE DAZED HOLD (order 3) - render/enemyvisual/EnemyStatusVisuals, one row per StatusType:
    the repeating burst while active and where it comes from, the onset burst (STATUS_APPLIED: a fire catching),
    a body tint for a status the shared pass does not already tint (EMPOWERED = buff green). Shipped: BURNING
    flames + smoke, POISONED toxin bubbles, BLEED the family leak, STUNNED three orbiting stars. A STUNNED enemy
    (or one whose next action is still cancelled) holds HURT_HEAVY's last pose with a slow sway (DAZED, which
    wins a tie with a held WIND_UP). A shotgun stagger reads as the heavy flinch + kick: the sim cancels that
    turn's action at once and the enemy may commit a fresh wind-up, so a long daze would lie.
8.6 DEATH AND REMAINS (order 3, A4): DIED fires the KILL burst (weapon / blast kills) at the hit centre and the
    DEATH burst of the creature's own materials from its body placement, on the killing frame. The dying
    instance plays DEATH; its remains are registered at the same moment and revealed when DEATH ends - the last
    DEATH frame, standing on the tile for the rest of the floor (RemainsRegistry: 32 slots, one per tile, the
    oldest recycled - past 32 kills on a floor the OLDEST kill's tile shows the generic corpse decal again,
    allowed by R4). PropRenderer skips a stamped corpse decal 'm' on a tile with remains; the corpse TILE is
    untouched (R5). Remains sort a hair behind a live enemy on the same tile. Cleared with the floor.
8.7 TELEGRAPH AND ATTACK EFFECTS (order 3): while WINDING_UP / SELF_DESTRUCTING (and not dazed) the CHARGE
    burst repeats from the charge placement (the Tick's grit + dust at its feet; the Warden's prod crackle is
    ready but the Warden never winds up in the sim). A ranged creature whose family ships PROJECTILE: on
    EVERY ranged shot (the attack AND the debuff shot - every EnemyAttackListener.onRangedAttack) is scheduled
    by EnemyVisualLayer.scheduleShot for the ATTACK clip's emit frame (at once when that clip is not playing),
    then a MUZZLE flash and the projectile leave the current frame's EMITTER anchor for the COMMITTED lane
    target tile - a player who stepped off the lane sees it fly down the old lane and miss (the cardinal-line
    rule stays visible). It sheds TRAIL drops and fades 1 - t^2 as it arrives. When the layer cannot draw it
    (no animator, no PROJECTILE) scheduleShot returns false and the procedural glob is drawn as before.
    ORDER 5: the shot leaves on the emit frame of WHICHEVER one-shot is playing (the Mire Wraith's DEBUFF_PLAYER
    volley), and a creature whose set gives it an IMPACT burst (the acid) bursts ENEMY_EFFECT_PROJECTILE_IMPACT_LEAD_TILES
    (1.1) short of its target (GameMath.projectileImpactSeconds) - at the target itself it sat at the lens, clamped tiny.
    The Eye Tyrant ships NO projectile: the renderer's beam stays, launched from the frame's EMITTER anchor.

9. EFFECTS                                                                  [shipped: order 3]
====================================================================================================
Effects are generated by the same kit, from the same materials, so a hit on a machine throws sparks in its
own metal and a tick bleeds its own ichor. The builder is .claude/skills/enemy-art/effects.py.
9.1 SETS. One per FAMILY, named by the EnemyFamily constant in lower case (machine, insect; later orders add
    undead, golem, ...), plus the shared "status" set (fire, smoke, toxin bubbles, dazed stars) whose colours
    are semantic (art-direction V5), so they are the same on every family. Each set is <set>.fx.png (every
    frame of every sprite, trimmed and packed, binary alpha) + <set>.fx.json beside the creatures.
      machine   SPARK (white-hot streak cooling to cyan, 4 orientations), ARC (cyan), DEBRIS / DEBRIS_DARK
                (hull flecks), PANEL (livery plate), HARD_SPARK (the resisted star), GLOB + TRAIL (the Warden's
                corrosive agent, cyan-tinted - AS1), MUZZLE (emit flash)
      insect    ICHOR (droplet), FLECK / FLECK_DARK (chitin), GRIT, DRIP, MIST (the death pop), CHIP + DUST
                (the resisted chip); order 4: PLATE_SPARK + PLATE_STREAK (white-hot) + PLATE_FLECK (gunmetal) =
                the RESIST_PLATE burst - a resisted hit on the Iron Stalker rings off its iron plates
      aberration (order 5, the insect's ichor ink - AS1) ICHOR, FLESH / FLESH_DARK (wet flecks), CHUNK (death gobbets),
                SPLAT, WELT (the resisted read - unreachable today: aberrations are trait FLESH, a neutral matchup row),
                DRIP, MOTE (the wind-up / priming seep), SCUFF, SPIT + SPIT_TRAIL + SPIT_MUZZLE (the acid), DETONATE
                (the self-destruct flash). Creature-only bursts taken through overrides: SPIT / SPIT_TRAIL / SPIT_MUZZLE,
                ACID_SPLASH (IMPACT), SPLASH / SPLASH_HEAVY (the Wraith is half liquid), SCUFF (the Gore Biter's CHARGE).
      undead    (order 6, the SOUL ink) WISP (soul shaken out of a wound), SOUL_FLASH (the soul leaving a body), SCRAP /
                SCRAP_PALE (torn suit / lab-coat cloth), ASH (the resisted read: a dull puff of grime, no light), MOTE
                (the wind-up seep). Creature-only, through overrides: EMBER (the Ghoul's red leak from its cracked
                visor), ARMOUR_SPARK + ARMOUR_FLECK (RESIST_ARMOUR: a resisted hit rings off the Revenant's armour and
                shield), SOUL_BOLT + BOLT_TRAIL + BOLT_MUZZLE (the Vortex Eye's projectile), SPORE + SPORE_PUFF (the Blight
                Corruptor's hits, leak, charge and death are spore dust off its pods)
      status    FLAME, SMOKE, BUBBLE, STUN
    No gore: sparks, ichor, dust - never blood (R3, the premise's restraint).
9.2 THE FX MANIFEST (FX_VERSION 1): "sprites" {NAME: emissive, mode life|loop, fps, frames[orientation][frame]
    {rect, pivot}}, "bursts" {NAME: {emitters[...], interval?}}, "creatures" {creature id: {leak | burn |
    charge | stun | poison | body: {anchor, offset, radius}}}. An emitter: sprite, count, life, speed, angle
    (degrees, 0 = right on screen, 90 = up), spread, toward (px/s at the viewer), gravity (+ = down), drag,
    radius, optional orbit (radius px, period s). EVERY NUMBER IS IN CANVAS PIXELS of the creature that throws
    it; the runtime converts with that creature's own pixel scale. Burst names the runtime reads
    (EnemyEffectSet.BurstId): HIT, HIT_HEAVY, RESIST, KILL, DEATH, LEAK, CHARGE, MUZZLE, PROJECTILE, TRAIL,
    BLEED (family), DETONATE + IMPACT (order 5) and BURNING, BURNING_ONSET, POISONED, STUNNED (status). A family ships
    what it needs; a projectile lives in a creatures row's overrides when only one member of the family shoots it.
    PER-CREATURE OVERRIDE (order 4): a creatures row may carry "bursts": {"RESIST": "RESIST_PLATE"} - that
    creature takes the named burst of the same set IN PLACE of the family's (a set may hold bursts no runtime
    id names, for exactly this). CreatureVisual.burst() reads the override first. effects.py checks the name.
9.3 EMISSIVE vs LIT. An emissive sprite keeps only its emissive pixels (no kit outline - it reads as soot on a
    2 px spark) and is drawn in its baked colour, UNGRADED, NORMAL alpha blend, faded with depth like the glow
    atlas (V6; the order-2 D2 rule - never additive). A lit sprite (debris, chitin, smoke) keeps its outline
    and takes the body's distance shade, tile light, blackout floor and mood grade.
9.4 THE RUNTIME - render/enemyvisual/EnemyEffectSystem: 320 pooled world-space particles (floor-plane tiles +
    height in walls), the oldest recycled (R4), integrated on the frozen-with-the-world clock; drawn by
    EnemyRenderer.drawEffectParticles right after the bodies and under every bar and tag, z-tested at the
    centre column against the walls and nearer props. Drawn at ENEMY_EFFECT_DRAW_SCALE (2x the creature's
    pixel - 1x read too small on screen); a sprite stops growing inside 1.2 tiles (a glob at the lens). Each
    particle fades over the last 30% of its life (batch alpha only; the art stays binary). The generic
    screen-space hit spray / death burst (ImpactEffectSystem) stands down for a migrated body.
9.5 ADD A FAMILY'S EFFECTS: one SETS entry in effects.py (sprites from that family's materials and ink, the
    bursts it needs, a creatures row per creature); regenerate; earlier sets and creatures byte-identical.
    Checked in-engine with run-game (guide 11 + run-game SKILL.md "Reactions and effects").

10. ENGINE CONTRACT (what the game does with the output)
====================================================================================================
  - Textures load with the Nearest filter. Generated atlases are loaded as-is (no alpha cut - that is
    the legacy EnemySpriteSheets path), so output must already be BINARY alpha (0 or 255).
  - Wiring a creature is ONE row in render/enemyvisual/EnemyVisualRegistry.bootstrap() (EnemyType ->
    creature id); files come from EnemyConstants.ENEMY_GENERATED_DIRECTORY. A type without a row keeps
    the legacy sprite (until order 9). Rows today: ACID_DRONE warden, SHELL_BRUTE harvest_tick, IRON_STALKER
    iron_stalker, PLAGUE_HULK plague_hulk, EYE_TYRANT eye_tyrant, GORE_BITER gore_biter, MIRE_WRAITH
    mire_wraith, SUMP_WRETCH sump_wretch (sump-wretch-acid-death; a new type with no legacy art falls back to
    the Mire Wraith's legacy region if its atlas fails to load), and (order 6) GHOUL ghoul, CRAWLER crawler, REVENANT
    revenant, VORTEX_EYE vortex_eye, BLIGHT_CORRUPTOR blight_corruptor.
  - A creature's IMPACT burst doubles as its DEATH-SPLASH burst: EnemyVisualLayer.onAcidSplash plays it on
    every tile a death splash reaches (HazardManager.AcidSplashListener), at the tile's floor, or just in
    front of the camera when the tile is the viewer's own.
  - The billboard is the whole CANVAS: heightMultiplier() wall heights tall, bottom on the floor line,
    canvas width x the same scale. Each frame is drawn at its manifest offset inside it (y-down canvas,
    flipped once in EnemyBodyDrawer), per screen column against the wall z-buffer; the contact shadow
    is drawn at the floor line. Health bar / name tag / intent sit above the canvas top. The legacy
    melee lunge (scale + drop) is skipped for a migrated type - its ATTACK clip does that job.
  - Every world pass is colour-graded by the floor's lighting mood at GRADE_STRENGTH_ENEMY 0.50 and
    fogged by depth. Emissives belong in the glow layer so they escape the grade (V6): the glow atlas
    holds the emissive pixels' BAKED colour and is laid over the graded body with NORMAL alpha blending
    at opacity 1 up to ENEMY_GLOW_FADE_START_TILES (10), easing to ENEMY_GLOW_MIN_ALPHA (0.6) at 20 tiles.
    (Not additive: the glow pixels are a copy of the body's, so adding them doubles them to white.)
  - The renderer draws overlays OVER the sprite (hit flash, health bar, name tag, matchup words,
    state tints - Auric exposed, Cinderforge crust, Rimeshell shell/frost - the shard ring, boss
    afterimages). Keep body colours mid-value so every tint and flash reads.
  - Memory: an atlas is a GPU texture. Budget per creature <= 2048x2048 RGBA, loaded per floor for the
    types on that floor (what they summon, and a HUNTED floor's hunter; anything else unforeseen loads on first sight) and disposed on
    floor teardown - render/enemyvisual/EnemyAtlasCache, owned by the per-floor EnemyVisualLayer. A 160x240 frame is 150 KB
    in RGBA; trim frames to their bounds.
  - Critical rules from CLAUDE.md hold: no allocation in render(), every Texture disposed, all GL work
    on the render thread.

====================================================================================================
12. LESSONS ALREADY PAID FOR
====================================================================================================
  12.1 Stacked shapes read as a toy. Separate ellipses and capsules look glued together; merge
       organic parts in one layer with smooth max.
  12.2 Rectangular slabs read as bricks. The rejected golem prototype (polygon slabs over a glowing
       backing) was the owner's weakest. Stone needs irregular sculpted masses, fractures carved INTO
       them, chipped edges, and glow only in seams and a core.
  12.3 Glow intensity from the merged layer height burns glow parts flat white. It must come from
       the shape's own height (fixed in kit.py - do not regress).
  12.4 Bayer dither on flat areas turns into stipple. Keep dither low; get variety from grain.
  12.5 Pasted mock-ups lie: no mood grade, fog, contact shadow or name tag. Judge in the engine.
  12.6 The owner reads anatomy as anatomy: a clamped stump read as a missing leg and was asked back.
       Put story details ON the body.
  12.7 3x5 stencils are close-range story detail only.
  12.8 Over-glowing a sprite kills its form. Emissives: eyes, sacs, emitters, seams, cores.
  12.9 A translucent halo does not survive the engine's alpha cut. Glow is a separate layer.
  12.10 What the owner liked: sculpted organic forms, wet/metal specular, visible Organization
       hardware on creatures, an off-centre detail that breaks symmetry, restrained glow.
  12.11 The approved still is the rest pose, so it must leave room to move. The first Harvest Tick
       still touched both canvas edges with a leg spur; any motion clipped it. Leave a few pixels of air
       around the widest rest silhouette, and move long parts (the Warden's prod) across the body,
       never outward past the edge.
  12.12 A stencil is painted AFTER rendering onto whatever is opaque there - when its part is covered
       (the tick's curled DEFEND), drop the stencil for that pose or it lands on the wrong surface.
  12.13 A wreck must fit above the canvas floor: a hovering creature that lands needs a little depth
       scale (it fell back) and crumpled dangling parts, or its limbs end below row 239.
  12.14 (order 4) A creature that must read TALLER than a neighbour of similar heightMultiplier gets there on
       its canvas, never through heightMultiplier: the Iron Stalker (1.10) first stood only ~6% above the Shell
       Brute (1.05) in-engine because the Tick's hose reaches row 26; the rig is now STOOD UP (a vertical STAND
       x1.065 about the ground line on every layer, anchor and stencil). Check A3-style claims in-engine.
  12.15 (order 4) Scaling an arm "toward the viewer" about its shoulder lifts its far joint off the canvas top.
       Grow reach mostly sideways (y at 35%), and make a smear arc SIGNED: it trails the way the part came from,
       so an outward swing trails inward (a trail on the wrong side pushed the open frame past both edges).
  12.16 (order 4) A held telegraph must be read from what the sim COMMITTED, not only its state: AREA_STRIKE
       never enters WINDING_UP. Trigger abilities for real (skip turns, logmoments) before trusting a clip.
  12.17 (order 5) A 2-bone arm rotated about its shoulder sweeps OUTSIDE the canvas on any overhead raise. Raise up the
       FRONT (fold the elbow inward first - the curl) and solve the key angles numerically before keying; "fists high"
       on the Hulk is beside the head, not over it. Lowering a raised forearm folds it INWARD too.
  12.18 (order 5) The owner rejected a soft round body as "an egg ... weak": a threat needs a predatory silhouette -
       a raised limb, a mouth turned at the viewer, hunched shoulders over the head. The first Mire Wraith was kept as
       sump_wretch for a low-level enemy instead of deleted - a rejected design can still be the right weak creature.
  12.19 (order 5) Separate blobs down a column read as a stack of tyres; tube drapes read as extra arms. One tapering
       chain merged INTO the torso layer, and flat bevelled slabs for cloth-like skin.
  12.20 (order 5) Wide creatures: narrow the whole figure about the centre line (NARROW, the STAND idea sideways)
       rather than redesign; widening effects (sag, swell) scale x much less than y.
  12.21 (order 6) A hand GRIPPING A HELD OBJECT does not survive generation at this resolution. The Revenant's baton
       (two attempts) was rejected as "cursed": curled finger chains on a turned wrist break into lumps, and a prop
       angle keyed separately from the hand spins through the fist between keys. A rigid grip + a solid closed gauntlet
       still read wrong. Give a humanoid a weapon that is ONE RIGID PLATE moved with the body (the riot shield: offset,
       scale toward the viewer, tilt - the shield bash), or no held weapon; keep fists closed and unarticulated.
  12.22 (order 6) Foreshortening a WHOLE arm toward the camera crushes it into a stub with a lump of a hand. Shorten the
       upper arm alone (<side>_upper_fore: the elbow comes forward, the forearm and hand keep their size), and search
       swing paths numerically: every interpolated frame - not only the keys - must keep joints and props on the canvas.
  12.23 (order 6) The owner judges BODY PROPORTION from a single still, iteratively ("too thin", "thicker legs", "longer
       body"). Change one rig constant per round (BULK, LEG_BULK, spine, arm lengths), send ONE before/after still, and
       keep the previous version committed: a version matched to a reference image was judged "fat" and reverted.
  12.24 (order 6) NO HUMAN FACE (owner rule for every undead): sealed in a hood, a respirator, a helmet - the only facial
       feature is a pair of glowing eyes behind glass. The job is told by the suit (slate hazard suit, lab coat, riot
       armour, hazmat), not the face.

14. PROPS: ENVIRONMENT OBJECTS (generated-prop-art series)
====================================================================================================
The environment objects - terminals, tubes, machines, crates, the exit portal - made with this kit. The series
is .claude/agents/ideas/generated-prop-art.txt (+ -order-<n>); its brief and rules PS1-PS8 are binding.

14.1 THE OWNER'S BRIEF (2026-10-23)
  - Reimagine, never copy: the old Pixmap props in PropRenderer are not reference material (N2).
  - What it says it is, it is: a terminal is a terminal. The look changes, never the object or its gameplay.
  - NEON ACCENTS: the levels are grey / blue-grey, so props carry the bright colour - cold lab and steel bodies
    (livery, livery_dk, steel_lt, gunmetal, darkmetal, frost) with one or two glowing NEON or RADIOACTIVE accents
    on their emissive parts only (screens, lamps, keys, fluid, energy). This is the owner's exception to N4 / V5
    for props (generated-prop-art.txt D1). Never the keycard inks; never on an enemy.
  - Living or powered things animate (tubes, screens, cores, the portal); stationary things are stills.
  - A specimen tube runs floor to ceiling; the portal is full size.

14.2 THE NEON INKS (kit.MATERIALS, appended last)
  phosphor     CRT green: terminal text and status lamps
  neon_cyan    specimen fluid, ring lights, backlit keys (brighter and more saturated than the facility cyan)
  rad          radioactive lime: hazard lamps, warning strips, emitter studs
  hot_iron     (order 3, owner D4) heated metal: deep red -> orange -> white-hot. Heat sources only (coils,
               exhausts, warning lamps); it always ramps through orange, so it never reads as the keycard red
  (order 4 adds the body paint paint_oxide - a hazard drum's brick-brown, never a saturated red - and uses the
  existing toxin ink, V5's POISONED green, for the toxic pool: the right semantic colour for once)
  Big glowing areas (a fluid column, a vortex, a screen's text) are PAINTED with numpy into the frame after the
  kit render, from these inks' ramps - the kit's translucent materials wash out to a pale tint at that size.

14.3 THE CANVAS
  The bottom row is the FLOOR (the engine stands the frame on the floor line). A full-height prop (height 1.0 in
  RenderConstants) also has its top row on the CEILING: build conduits and clamps running off the top edge.
  The frame's aspect is the billboard's aspect (width = height x frameWidth / frameHeight). One wall tile is 256
  texels tall, so a full-height prop is 256 px tall and a 0.80 prop about 200. Leave air at the sides for the bloom.
  Order 1: terminal 160x200 (0.80), bio_pod 112x256 (1.0), portal 224x256 (1.0).
  CEILING-MOUNTED (order 5, R1): a prop that HANGS is still a full-height canvas (height 1.0) - its top row is the
  ceiling line, the object is painted in the top rows, and EVERYTHING BELOW IT IS FULLY TRANSPARENT in the body
  (a glow-only effect such as the camera's scan cone may reach lower). The per-frame opaque-column masks then keep
  it out of the occluder record below the object, so an enemy behind it is drawn whole. camera 128x256 (1.0),
  body rows 0-78.

14.4 THE BAKE (props.py)
  - SMOOTH (kit.render smooth=2), as the walls: no dither, no grain speckle, anti-aliased edges (PS2).
  - One function per prop returns frame(k) -> (body RGBA, glow RGBA). Parts that do not change are rendered once
    and cached by state (the terminal's lamps, the portal's lamp chase), then the moving content is painted.
  - Layering by separate renders + alpha compositing when a part must sit BEHIND glass (the specimen behind the
    fluid). Rule: wherever an opaque front part covers a glowing back part, cut the back part out of the glow
    (glow alpha *= 1 - front alpha) - the glow is drawn on top in game and would shine through the steel.
  - BLOOM: props.bloom() puts a soft halo in each ink's own colour around every glowing pixel, INTO the glow image
    (alpha <= cap). That is the neon. Keep the cap <= 0.55 or the body under it washes out.
  - Loops are seamless: every motion is periodic in the frame count (a scroll that wraps its text stream, bubbles
    travelling whole laps, a spiral turned by exactly one arm spacing).
  - One Organization stencil per prop (kit.stencil), like an enemy's serial (N6).

14.5 THE OUTPUT (PS4) - assets/textures/props/generated/
  <id>.prop.png   body frames in a grid (frame k at column k % columns, row k // columns), RGBA
  <id>.glow.png   the glow frames on the same grid: emissive pixels + bloom
  <id>.prop.json  {"version": 1, "id", "frameWidth", "frameHeight", "frameCount", "columns", "frameSeconds"}
  Sheet <= 2048x2048. Deterministic: two bakes are cmp-identical. After a kit change, enemies and walls must still
  regenerate byte-identical.
    cd .claude/skills/enemy-art
    python3 props.py ../../../assets/textures/props/generated                  # ship every prop
    python3 props.py /tmp/p --preview /tmp/p/preview terminal                  # + GIF + still + sheet.png

14.6 THE RUNTIME (render/propvisual + PropRenderer)
  - GeneratedPropRegistry.bootstrap() is THE CATALOG: registerSprite(spriteId, sheetId) for a tileset prop (the
    binding follows the SPRITE, since the symbol is chosen per level by the palette) or registerFixedChar(char,
    sheetId) for a fixed gameplay prop (the portal '>'). One row per prop; no switch (PS5).
  - GeneratedPropSheets loads every registered sheet per PropRenderer (per floor) and disposes them with it. A
    sheet that fails to load is logged and its prop is simply not drawn (R5).
  - Frame = GameMath.wallGlowFrameIndex(time, per-tile phase, ...) - neighbouring copies never pulse together.
  - BODY pass = the ordinary prop pass on the frame's rect (shade x tile brightness x mood grade, red alert, muzzle
    light, contact shadow, occluder record of the frame's opaque columns). The portal's body stays ungraded.
  - GLOW pass = the glow frame, NORMAL blend, white, alpha = the wall glow's distance fade (WALL_GLOW_FADE_*) x
    the floor's light multiplier: walls and props glow alike, BLACKOUT dims both.
  - A migrated sprite has no Pixmap generator (TilesetGfxBootstrap.expectedGeneratorIds() excludes it, PS6).
  - registerCeilingSprite(spriteId, sheetId) (order 5) = registerSprite + the CEILING flag;
    GeneratedPropRegistry.isCeilingMounted(sheetId) / GeneratedPropSheet.isCeilingMounted(). A ceiling-mounted
    sheet gets contact-shadow fraction 0 in BOTH prop passes (PropRenderer.contactShadowFraction); body, glow,
    muzzle light and occluder record are unchanged. The next hanging prop (lamps, cable bundles) is one row.
  - Heights stay in RenderConstants (PROP_HEIGHT_TERMINAL 0.80, PROP_BIOPOD_HEIGHT 1.0, PORTAL_SPRITE_HEIGHT 1.0).
