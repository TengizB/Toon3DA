================================================================================
BALANCE RULE SYSTEM — the math contract for adding content safely
================================================================================
Companion to: .claude/agents/ideas/balance_order_2_balance_rule_system_and_math.txt
Formulas live in: util/GameMath.java   (the four primitives + derived scores)
Anchors & bands live in: util/BalanceConfig.java   (SECTION 9)
Living table generator: util/BalanceReport.java   (dev-only main, no LibGDX state)

This is the "balance contract." When a NEW weapon, enemy, item, or upgrade is
added, check it against the fixed formulas below and know IN ADVANCE whether it
breaks balance — instead of finding out by feel after the fact. Every piece of
content must pass it.


--------------------------------------------------------------------------------
WHY TURNS, NOT SECONDS
--------------------------------------------------------------------------------
The game is strictly turn-based: one player action = exactly one world turn, and
enemies act once per player turn. So TIME is measured in TURNS, never seconds.
There is no real-time DPS — only damage-per-turn. This makes the whole balance
model exact arithmetic instead of physics. Use it.


================================================================================
THE FOUR PRIMITIVES  (everything else is derived)
================================================================================
All four are pure static methods in util/GameMath.java with full
Formula/Derivation/Edge-case comment blocks (project rule: no inline formulas).

1. eHP — EFFECTIVE HIT POINTS                  GameMath.effectiveHitPoints(...)
   How much raw incoming damage a thing really absorbs.
       eHP = (rawHP + armor) * 1/(1 - dodge) * H/max(1, H - R)
   where H = average incoming hit, R = flat reduction.
   - Dodge: a dodged hit deals 0, so survivability scales by 1/(1 - dodge).
   - Flat reduction: each landed hit of size H only removes (H - R).
   MARINE start (130 HP, 75 armor, 0 dodge, 0 R)            -> 205 eHP.
   Tough/Agile (160 HP, 75 armor, 0.20 dodge, R=6, H=12)    -> 587 eHP.
   RULE: enemies currently have NO dodge or reduction, so enemy eHP == raw HP.
   If an armored enemy archetype is ever added, store its RAW hp in BalanceConfig
   and declare the reduction separately so eHP stays derivable.

2. DPT — DAMAGE PER TURN
   BURST DPT = damage in a single fire action (one turn): Shotgun 50, Railgun 90.
   SUSTAINED DPT = damage averaged over a full clip + reload cycle:
       sustainedDPT = (clipSize * damagePerShot) / (clipSize + reloadTicks)
                                                   GameMath.sustainedDamagePerTurn(...)
   Falloff: real DPT decays with range. Where falloff matters, credit a weapon
   its EFFECTIVE DPT at its intended engagement band, not its point-blank muzzle
   number. (The living table below uses muzzle sustained DPT; refining each
   weapon to its engagement band is a follow-up.)

2b. AMMO EFFICIENCY — damage per ammo unit       GameMath.ammoEfficiency(...)
       ammoEfficiency = damagePerShot / ammoPerShot
   Run-budget = ammoEfficiency * (total ammo the economy hands you). This is the
   bridge to the scarcity model (idea 3) — note it is governed by what the
   economy supplies, NOT by the reserve cap.

3. TTK — TURNS TO KILL                           GameMath.turnsToKill(...)
       turnsToKill = ceil(target.eHP / attacker.effectiveDPT)
   Feed ENEMY DPT + PLAYER eHP to get the player's Turns-To-Die (TTD).

4. TP — THREAT POINTS (one danger number per enemy)  GameMath.threatPoints(...)
       enemyDPT      = attackDamage / max(1, attackCadenceTurns)
       survivalTurns = enemy.eHP / REFERENCE_PLAYER_DPT        (= 25, the shotgun)
       TP            = enemyDPT * survivalTurns * positionalMultiplier
   positionalMultiplier (a DESIGNER classification, not auto-derived):
       1.00 melee   1.15 fast-melee   1.30 ranged   (+0.25 if it applies a
       DOT/stun/slow status). Constants: BalanceConfig.POSITIONAL_MULT_*.
   TP is the currency the encounter budget (ideas 3/4) spends: "this floor may
   contain up to N total TP" makes difficulty a dial, not an accident.

DERIVED SCORES
   weaponPowerScore = sustainedEffectiveDPT * sqrt(ammoEfficiencyNormalized)
                                                   GameMath.weaponPowerScore(...)
     ammoEfficiencyNormalized = ammoEfficiency / REFERENCE_AMMO_EFFICIENCY (= 40).
     The sqrt dampens the ammo term so per-shot damage can't dominate the score.
   goldenRatio = turnsToDie / turnsToKill          GameMath.goldenRatio(...)
   depthThreatScale = healthScale^(d-1) * damageScale^(d-1)
                                                   GameMath.depthThreatScale(...)

REFERENCE ANCHORS (BalanceConfig, SECTION 9)
   REFERENCE_PLAYER_DPT       = 25   (start shotgun sustained DPT; also the golden-ratio TTK
                                      metric since iteration 2 — option b, not best burst)
   REFERENCE_PLAYER_EHP       = 205  (MARINE start eHP)
   REFERENCE_AMMO_EFFICIENCY  = 40   (power-score normaliser)


================================================================================
DAMAGE-MITIGATION PIPELINE  (single source of truth — strategy-combat-order-3)
================================================================================
When damage D lands on ANY combat actor, it is resolved in exactly this order.
Implemented once so enemy and player agree; the numeric steps are pure GameMath.

   1. Directional/Guard modifier (player only, order-4):  D' = D * facingMultiplier
   2. Power / positioning modifiers (order-6, if present): D'' = D' * powerMult
        powerMult = weak(attacker) * vulnerable(target) * backstab(attacker-behind-facing)
        EXPOSED (order-6) is not a multiplier — it sets ignoreBlock=true for step 3 (one hit).
   3. BLOCK absorption:   absorbed = min(block, D'')  [GameMath.blockAbsorbed]
                          (skipped entirely when the target is EXPOSED — order-6 anti-turtle)
                          block -= absorbed ; D''' = D'' - absorbed
   4. Flat armor reduction (existing):  D'''' = max(0, D''' - armorReduction)
   5. Subtract from HP.

BLOCK sits ABOVE armor: it is the "I braced this turn" spike, armor is the
permanent hide. A hit fully swallowed by fresh Block deals 0 HP damage — overkill
into Block is LOST (the counterplay: do not dump your biggest shot into fresh
Block; chip it or wait the 1-turn decay out).

BLOCK is TRANSIENT eHP, priced as "turns of survival bought" (same method as a
consumable, primitive [C] below), NOT steady-state eHP:
       blockSurvivalTurns = defendBlockGain / REFERENCE_PLAYER_DPT
A single enemy DEFEND buys ~1 turn (baseBlock ≈ REFERENCE_PLAYER_DPT), never more,
so a defend-heavy enemy's EFFECTIVE TTK stays in its golden-ratio band. Block is
capped (BLOCK_MAX) and decays after BLOCK_DECAY_TURNS, so defend-spam can never
stack into immortality. STATUS DoT (burning/poison/bleed) BYPASSES Block — it is
resolved as direct HP loss (Enemy.applyDoTDamage), so status builds are the
rock-paper-scissors answer to turtling enemies. The BLOCK & DEFEND table in the
living-table section below lists each bracing role's numbers and survTurns verdict.

PLAYER GUARD (order-4) — directional, CONDITIONAL eHP. Tapping GUARD ends the turn
and braces the marine: an incoming hit inside the FRONT facing arc (±GUARD_FRONT_
HALF_ANGLE_DEGREES, default ±60°) is scaled by GUARD_FRONT_MULTIPLIER (0.35); SIDE
and BACK hits land at FULL damage (GUARD_SIDE/BACK_MULTIPLIER = 1.0). Guard is
pipeline STEP 0 for the player — the facing multiplier is applied to the raw hit
(GameMath.guardFacingMultiplier) BEFORE the dodge/armour/toughness pipeline, so it
composes with everything downstream. Pricing: guarding costs the player's own turn
1:1 (a ~1 reference-DPT opportunity cost), and because it does NOTHING vs flanks its
average value is self-limiting in any multi-enemy room, so it needs no BLOCK-style
hard cap. A single-enemy duel is NOT broken: a front-guard converts a would-be
lethal front turn into a survivable one at the cost of the offense skipped that turn,
which keeps the enemy's effective TTK inside its golden-ratio band (the enemy simply
"gets a turn back"). Since GUARD_SIDE/BACK stay at 1.0, guarding vs a flanker (a MOVE
intent repositioning off your facing) yields zero mitigation — the read-and-rotate
skill, not raw eHP, is what the stance rewards. Constants: BalanceConfig.GUARD_*.

TACTICAL MODIFIERS (order-6) — the setup-then-payoff power layer. Three new StatusTypes
plug into the SAME tick engine as EMPOWERED (no new tick system); they are passive
multipliers/flags read at pipeline STEP 2/3, never per-turn DoT. All potency lives in
EffectConstants (VULNERABLE_*, WEAK_*, EXPOSED_*, BACKSTAB_*); the pure multipliers live in
GameMath (vulnerableDamageMultiplier / weakDamageMultiplier / backstabDamageMultiplier).
   • VULNERABLE — the marked target takes +VULNERABLE_DAMAGE_PERCENT% per stack (default +50%),
     STACK_MAGNITUDE-capped at VULNERABLE_MAX_STACKS (default 2) so a stacking setup shaves
     ~1 turn off a soldier's TTK but can NEVER multiply a boss into a trivial 2-turn kill
     (respects the boss ruleset). Source: the Railgun marking slug (applied AFTER its hit, so it
     sets up the NEXT shot). Priced as an offensive conditional — see the MODIFIERS living table.
   • WEAK — the debuffed actor deals -WEAK_DAMAGE_PERCENT% (default -25%), floored at 0. Symmetric:
     enemies apply it to the player (the acid casters' DEBUFF_PLAYER → the marine's HUD damage
     dims), and it is available as an enemy-softening debuff. Folded into scaledAttackDamage /
     the player's outgoing hit, so a Weakened actor's telegraphed number AND its executed hit drop
     together — legible feedback.
   • EXPOSED — the next hit into the target ignores its Block (order-3), then the flag clears (ONE
     hit, never permanent, so it does not invalidate the DEFEND counter it answers). Source: the
     Plasma Rifle's piercing bolt. This is the build answer to turtling enemies without an
     armor-piercing weapon, alongside status-DoT (which bypasses Block entirely).
   • BACKSTAB/FLANK — a player hit landed from BEHIND an enemy's implicit facing (the cardinal it
     last moved/attacked along) deals +BACKSTAB_DAMAGE_PERCENT% (default +30%). Mirror of the enemy
     flanker vs a guarding player. Priced as a CONDITIONAL (like crit): it requires setup/
     positioning, so its reliable value is self-limiting and it stays a nudge, not an execution
     check — it must not push a weapon's effective power-score out of its role band. See the
     MODIFIERS table (BalanceReport.printModifiersTable) for each power's multiplier, cap, and its
     effect on the reference SOLDIER TTK.


================================================================================
THE CONTRACT — checklist every new piece of content MUST pass
================================================================================

[A] NEW WEAPON — must land inside the POWER BAND for its role.
    weaponPower = sustainedEffectiveDPT * sqrt(ammoEfficiency / 40)
        sidearm            power  8-14   (pistol-tier, ammo-cheap, always usable)
        workhorse          power 12-18   (assault rifle, chaingun)
        burst/specialist   power 18-26   (shotgun, plasma — high DPT, ammo-hungry)
        heavy/charge       power 24-32   (railgun, grenade — scarce ammo, slow)
    [ ] Pick a role, then tune numbers until weaponPower lands in that band.
    [ ] If it lands ABOVE the band it WILL invalidate the others — reject it.
    [ ] Higher RARITY does NOT raise the band. Rarity buys ABILITIES (idea 5),
        never raw DPT, so a legendary is never a strict numeric upgrade.

[B] NEW ENEMY — must declare a ROLE and land in that role's TP band.
    (TP bands re-scaled ~4x in the iteration-2 economy rescale; REFERENCE_PLAYER_DPT
     held at 25, so the bigger enemies have honestly higher Threat Points.)
        chaff       TP  16-34   (dies in ~2 hits, comes in packs)
        soldier     TP  36-66   (the standard threat unit; ~3-4 hits to kill)
        bruiser     TP  70-120  (forces a weapon swap / repositioning)
        mini-elite  TP 160-310  (a mid-floor spike; rare)
        boss        see idea 6 (own ruleset)
    [ ] Choose role -> set HP, damage, cadence, range so TP lands in band.
    [ ] THEN verify the golden ratio TTD/TTK (TTK uses sustained ref DPT 25 — option b):
            chaff / soldier -> [3, 8]      bruiser -> [2, 4]
        An enemy that violates the golden ratio is REJECTED even if its TP is in
        band. (Chaff is balanced around PACKS, so a single chaff's ratio reads high
        ~9; budget chaff by pack TP, not by the lone unit. A MINI-ELITE is a
        deliberate spike — tanky AND hard-hitting — so it reads UNDER the duel band
        by design; price it by its TP, do not duel it.)

[C] NEW CONSUMABLE / HEAL — priced in "turns of survival bought."
        survivalTurnsBought = healAmount / averageIncomingDPT(floor)
    [ ] A heal that buys > 10 turns on an early floor trivializes scarcity.
        Price heals against the floor's average incoming DPT, not a flat number.

[D] NEW UPGRADE / LEVEL-UP CARD — must cost the POWER BUDGET (idea 5, IMPLEMENTED).
    Power points (PP) are the common currency: a card's value = its %-gain to the
    reference DPT (offence) or reference eHP (survivability).
        offence PP    = GameMath.damagePerTurnPowerPoints(dptGain, REFERENCE_PLAYER_DPT)
        survival PP   = GameMath.effectiveHitPointPowerPoints(eHpGain, REFERENCE_PLAYER_EHP)
    eHpGain itself comes from GameMath.effectiveHitPoints, so armour, dodge and flat
    reduction are all priced in the same eHP unit. A card's net PP is the sum of both
    halves (UpgradeCard.estimatedPowerPoints()); a trade-off card's downside enters as
    negative PP, so its NET still lands in band.
    [ ] Price the card. It MUST land in the budget band
        [BUDGET*(1-TOL), BUDGET*(1+TOL)] = [10.2, 13.8] PP at the current
        LEVEL_UP_BUDGET_PP=12, LEVEL_UP_BUDGET_TOLERANCE=0.15 (BalanceConfig).
    [ ] Give it a distinct UpgradeCard.Lever so the deck never offers it alongside a
        card that moves the same stat (anti-redundancy).
    [ ] If it's above band, add a downside (make it a trade-off) until the NET fits,
        or move it to a rarer source. Caps (crit 0.30, dodge 0.35, …) are this same
        mechanism — every conditional value must declare a cap so a build can't stack
        it past ~budget.
    [ ] Add it to the UPGRADE CARDS living table below and rerun BalanceReport.
    THE TOTAL-PP INVARIANT: because every card is budget-equal, the player's total
    power at level L is L * LEVEL_UP_BUDGET_PP regardless of WHICH cards were taken —
    only its SHAPE differs. That is what keeps every build inside the depth-coupling
    band [0.9, 1.2] (below), so build diversity never becomes power creep.


================================================================================
DEPTH SCALING — keep the player and enemy curves COUPLED
================================================================================
Define the two curves relative to each other, never independently:

    enemyThreatAtDepth(d) = baseTP * healthScale^(d-1) * damageScale^(d-1)
                          = baseTP * 1.045^(d-1) * 1.035^(d-1)  (current values)
                          = baseTP * GameMath.depthThreatScale(1.045, 1.035, d)
    playerPowerAtDepth(d) = 1 + LEVEL_UP_BUDGET_PP * levelsPerDepth * (d-1) / 100
                          = GameMath.playerPowerAtDepth(12, 1.0, d)   (current values)

The player curve is LINEAR (every level grants a fixed power-point budget, idea 5;
the total-PP invariant makes total power at level L = L*budget for EVERY build), while
the enemy curve COMPOUNDS. A compound curve always eventually outruns a linear one, so
the only lever that keeps them coupled over the run's depth range is the enemy compound
RATE: pick it gentle enough that it does not pass the player curve before the deepest
floor. (The player model conservatively ignores found weapons/armour, which only help,
so the real ratio is at least this favourable.)

THE INVARIANT (must hold, or the game goes unfair-hard or trivial-easy):
        0.9  <=  playerPowerAtDepth(d) / enemyThreatScale(d)  <=  1.2
                                                   GameMath.depthCouplingRatio(...)
Stay roughly even-to-slightly-ahead: no more than +20% ahead or -10% behind. If
found-loot and XP let the player outscale this, lower the loot/XP rate; if they
fall behind, lower the enemy depth scale (the primary lever) or raise XP/levels.
Bounds: BalanceConfig.DEPTH_COUPLING_RATIO_MIN/MAX.

TUNING PASS — the enemy depth scale WAS 1.08/1.06, which broke this invariant: the
compound enemy curve outran the linear player curve from depth 5 (ratio 0.86) and
collapsed to ~0.40 by depth 15 — the game became unwinnable at depth. Trimmed to
1.045/1.035 (BalanceConfig SECTION 3), which holds the ratio in band through depth 14
(depth 15 lands at the 0.89 band edge). Enemies still gain ~8% threat per floor; they
just no longer outpace the player's expected upgrades.

================================================================================
TUNING PASS — what the contract flagged and what was done
================================================================================
The weapon power bands have been brought into compliance. The enemy golden-ratio
flags — previously documented as an unresolvable band-vs-scale conflict — have now
been CLOSED by the iteration-2 economy rescale (a coordinated eHP/damage/anchor/band
re-derivation, summarised in the ENEMIES section below).

WEAPONS — REBALANCED (all now in band except the Railgun, intentionally)
  * Shotgun 50 -> 44/shot (power 28.0 -> 23.1). Was OVER: best sustained DPT AND
    best ammo efficiency of the non-charge guns. Trimmed into the burst band so it
    no longer invalidates the others; keeps its 1-shell identity.
  * Plasma Rifle 18 -> 28/shot (power 9.7 -> 18.7). Was far UNDER; now a real
    burst option, still the lowest per-shot of the class.
  * Assault Rifle 14 -> 20/shot (power 8.0 -> 13.7). Was UNDER; now the reliable
    mid-band workhorse.
  * Chaingun 10 -> 19/shot (power 4.8 -> 12.6). Was far UNDER; sustained fire is
    now worth its slot.
  * Grenade Launcher centre splash 30 -> 42 (power 15.6 -> 25.8); falloff 16 -> 22,
    self 20 -> 24 (self kept modest). Was UNDER; now in the heavy band.
  * Railgun full charge (power 45.0) — LEFT OVER on purpose. Its 90/slug efficiency
    is held in check by slug scarcity (RAILGUN_MAX_SLUGS = 12) and charge cost, not
    raw damage. Per the depth/scarcity model (idea 3, not yet built) nerfing the raw
    number would make it worthless once scarcity lands. Revisit with idea 3.

ENEMIES — THE ECONOMY RESCALE (iteration 2): golden-ratio conflict RESOLVED
  The previous pass proved the golden ratio could NOT be fixed by tuning individual
  enemies: with player eHP 205 and reference DPT 25, the TP band [9-16] and the
  golden-ratio band [3-8] were mutually unsatisfiable, because the player one-shot
  anything <= ~44 eHP, pinning TTK at 1 and the ratio sky-high. It listed three
  contract-level fixes: (a) widen the golden bands, (b) use sustained ref DPT for TTK,
  (c) rescale the whole eHP/damage economy. THIS iteration did the proper coordinated
  rescale — (b) AND (c) together, since (b) alone leaves TTK pinned at 1 for low-eHP
  enemies. The exact identity that forced it: gr_continuous = playerEHP * ttkMetricDPT
  / (enemyDPT * enemyEHP), and TP fixes enemyDPT*enemyEHP = TP * refDPT / posMult; the
  two bands only both hold once enemy eHP rises ~3x so a soldier survives 3-4 turns of
  the reference DPT instead of being one-shot.
  WHAT CHANGED (all re-derived together, every band verified via the standalone harness):
    * Metric (option b): golden-ratio TTK now divides enemy eHP by the SUSTAINED
      reference DPT (25), not best burst (44). BalanceReport.printEnemyRow updated.
    * Enemy eHP ~3x, damage ~1.5x (BalanceConfig SECTION 2) so soldiers take 3-4 hits.
      Result: every soldier gr 4.0-5.2, Shell Brute bruiser 2.2 — all IN band. Chaff
      reads ~9 (exempt, pack-budgeted). Iron Stalker mini-elite reads 0.9 (a deliberate
      spike — tanky AND hard-hitting reads under the duel band by design).
    * TP role bands re-scaled ~4x (SECTION 9) to the honestly-higher Threat Points
      (REFERENCE_PLAYER_DPT held at 25 — survivalTurns = eHP/25 keeps its meaning).
    * Encounter base budget 120 -> 500 (SECTION 11); enemy COUNT is scale-invariant
      (budget and per-enemy TP scaled by the same factor), so floors are ~11-13 enemies
      as before, each tankier.
    * Scarcity: model-floor DEMAND 288 -> 720, so ammo box sizes ~2.5x and reserve caps
      re-derived to ~1.5 floors (SECTION 5); heal magnitudes ~1.8x (SECTION 1) so net HP
      drain stays in the 5-15% band. All re-verified below.
    * Weapons UNCHANGED (their power scores never depended on enemy eHP) — the weapon
      table is identical; the Railgun stays the documented heavy-band exception.
  GAME-FEEL NOTE: this deliberately shifts combat from "one-shot the horde" toward
  "every enemy is a short fight" (more Doom-RPG, less bullet-hell). Verified by harness

================================================================================
RESOURCE SCARCITY MODEL — make every bullet and medkit a decision (idea 3)
================================================================================
Companion to: .claude/agents/ideas/balance_order_3_resource_scarcity_economy.txt
Formulas: util/GameMath.java (scarcity + heal-economy block, after the four primitives)
Levers & bands & model floor: util/BalanceConfig.java (SECTION 5 levers, SECTION 10 bands)

Scarcity is what converts a shooter into a roguelike. With infinite ammo there are
no resource DECISIONS — the player fires the best weapon at everything and never
asks "shoot or save / fight or flee". The goal is NOT to starve the player; it is
to land supply JUST BELOW comfort so clever spending is rewarded and careless
spending is punished.

THE CENTRAL EQUATION (per floor, "fight everything" basis):
    DEMAND = sum of every enemy's eHP   (the damage needed to clear the floor)
    SUPPLY = sum over ammo pickups of (boxSize * damagePerAmmoUnit)   (ranged only)
    S = SUPPLY / DEMAND
  TARGET:  S in [0.75, 0.95] floor-wide, and < 0.60 for any SINGLE weapon.
  Ammo alone covers ~75-95% of the floor; the rest comes from melee (free but
  slow/risky), avoidance, or carried reserves. S >= 1.0 means infinite ammo (the
  pre-idea-3 bug: S was ~5.8 — one weapon's ammo cleared the floor six times over).

THE FOUR LEVERS (all in BalanceConfig):
  1 DROP FREQUENCY  ENEMY_AMMO_DROP_CHANCE, LEVEL_GEN_AMMO_CHANCE_PER_ROOM  (SECTION 5)
  2 DROP SIZE       AMMO_BOX_*                                              (SECTION 5)
  3 RESERVE CAP     AMMO_RESERVE_CAP_* / *_MAX_*  (anti-hoard ceiling)      (SECTION 5)
  4 DEMAND          enemy density / eHP per floor (the TP budget, idea 4)   (SECTION 2)
  Tune LEVER 4 (demand) and LEVER 2 (drop size) first — biggest, most predictable
  effect. Frequency adds variance (texture), a poor primary dial. Caps only matter
  once supply is low enough that hoarding is possible.

ANTI-HOARD: reserve caps are tuned to bank only ~1.5 floors of a weapon's run-demand
(GameMath.reserveBankingFloors, BalanceConfig.RESERVE_BANKING_FLOORS_TARGET). The math
also erodes stockpiles with depth: enemy eHP compounds (1.08/floor) while the ammo
depth bonus is linear/gentler, so S tightens as you descend and hoards get spent.

HEAL ECONOMY (HP is a resource too):
    INCOMING   = totalEnemyDPT * turnsEngaged * (1 - avoidanceFactor)
    HEAL_SUPPLY= medkits * avgHeal + armour * avgArmour
    netHpDrain = INCOMING - HEAL_SUPPLY   (target: small NET LOSS, 5-15% of eHP/floor)
  Each floor should cost some HP you don't recover, so HP slowly becomes precious and
  you can't face-tank — but the run total stays survivable for a skilled player.

THE MODEL FLOOR (depth 1) — the canonical reference encounter (BalanceConfig SECTION 10):
  6x Gore Biter (40) + 3x Eye Tyrant (40) + 2x Shell Brute (120) + 1x Plague Hulk (120)
  DEMAND = 720 dmg, ~432 TP (ECONOMY-RESCALED iteration 2). The SECTION 5 levers are tuned
  against this floor.

  Credits are awarded (5-40/kill, 3-7 chips/floor) but there is NO shop to spend them
  (roguelike_order_11 shop NOT IMPLEMENTED). Currency with no sink is a meaningless
  counter, not a resource, so credits cannot yet participate in the scarcity economy.
  This idea models the AMMO + HP half (which can be done now); the CREDIT half is
  blocked on a shop/vending/fabricator sink. When that sink lands, price each item at
  (its TP-equiv or survival-turns-bought) * a scarcity markup, the same method used here.

ENCOUNTER BUDGET — difficulty as a dial (idea 4, Pillar 1)
================================================================================
Companion to: .claude/agents/ideas/balance_order_4_tactical_combat_depth.txt
Formulas: util/GameMath.java (floorThreatPointBudget + enemyThreatAtDepth, after depthThreatScale)
Knobs: util/BalanceConfig.java (SECTION 11). Planner: level/EncounterBudgetPlanner.java.

The level generator SPENDS a per-floor Threat-Point budget instead of rolling enemies at
random — this is what makes difficulty a controllable DIAL rather than an accident.

    floorThreatPointBudget(depth) = FLOOR_BASE_THREAT_POINT_BUDGET * depthThreatScale(depth)
    enemyThreatAtDepth(type, depth) = type.baseThreatPoints() * depthThreatScale(depth)

Because both the budget AND each enemy's TP cost scale by the same depth curve, the enemy
COUNT stays roughly constant across floors while each enemy gets stronger — difficulty rises
through per-enemy power, never an exploding horde, and the depth curve is never double-counted.
type.baseThreatPoints() is the Threat-Point primitive (PRIMITIVE 4) computed from the type's own
stats, so the budget is anchored to the same contract as the enemy living table above.

COMPOSITION RULES the planner enforces (BalanceConfig SECTION 11):
  - reserve 15–30% of the budget for ONE anchor (bruiser/mini-elite), placed in the deepest
    room and exempt from the per-room cap; rare depth-gated elite-gauntlet floors exceed it.
  - no single non-anchor TYPE over 40% of budget (variety); no non-anchor ROOM over 35%.
  - every roster contains both ranged AND melee archetypes (the core tactical tension).

================================================================================
TERRAIN HAZARDS — two-sided danger folded into the TP contract (idea 4, Pillar 3)
================================================================================
Formula: util/GameMath.java (hazardTileThreatPoints). Knobs: BalanceConfig SECTION 12.
Simulation: hazard/HazardManager.java, ticked by world/HazardTickSubscriber.

Fire ('i') and toxic ('q') floor tiles tick the existing BURNING/POISONED status onto ANY host
standing on them — player AND enemies. That two-sidedness is the whole tactic: a hazard can win
the fight for you OR kill you if you misposition. A hazard tile has no HP, so its Threat-Point
value uses turns-stood instead of survival-turns:

    hazardTileThreatPoints = hazardDamagePerTurn * HAZARD_THREAT_TURNS_STOOD * positionalMultiplier

so N hazard tiles raise a room's effective floor TP by ~N× this — "a room full of fire raises its
effective TP" is now quantitative. Fire spreads and chain-detonates explosive barrels; toxic is a
static area-denial pool (a Plague Hulk leaves one on death). See BalanceReport's HAZARDS section.

TELEGRAPH & COUNTERPLAY — the fairness contract (idea 4, Pillar 5)
================================================================================
Knob: BalanceConfig SECTION 13 (TELEGRAPH_MAX_UNTELEGRAPHED_HIT_FRACTION = 0.25).

RULE: every attack that can deal > 25% of reference eHP (~51 of 205) in ONE hit MUST be
telegraphed or avoidable. BalanceReport's TELEGRAPH AUDIT checks every attack:
  - UN-telegraphed melee (bite/smash/strike/brute-melee/stalker-melee) all sit well under the cap
    at depth 1 (max 16) and only cross it deep beyond their spawn bands — PASS.
  - The only big single hits are the Shell Brute CHARGE and boss slams, which are TELEGRAPHED
    wind-ups; ranged attacks are "telegraphed" by the cardinal-line tell (you can see the lane).
No attack FAILS the contract.

POST-INTENT-MODEL (strategy-combat-order-1): every enemy now COMMITS its next action at the end of
its turn and the player reads that PlannedAction for the entire following turn, so EVERY direct
attack — melee, ranged, and charge — is pre-committed one full turn ahead. The
TELEGRAPH_MAX_UNTELEGRAPHED_HIT_FRACTION rule is therefore satisfied by construction for all
committed attacks. The only remaining untelegraphed damage is DoT ticks (Burning/Poison) and
environmental hazards; all direct attacks are telegraphed by the intent system.

SPECIAL MOVE-SETS (strategy-combat-order-5): scripted archetypes weave SPECIAL abilities into their
commit logic on a fixed cadence, each shown a full turn ahead inside the purple SPECIAL intent frame
with a per-ability sub-glyph (buff up-arrow, debuff down-arrow, summon spawn-rune, area burst). The
only DAMAGING special is AREA_STRIKE, which carries a predicted-damage number and is dodged by
stepping out of its cross radius — telegraphed like every other committed attack, so the fairness
contract still holds. BUFF_SELF (self EMPOWERED), DEBUFF_PLAYER (SLOWED/BLINDED down a cardinal
line) and SUMMON deal no direct HP damage.
  - A buff/debuff/area move raises the caster's EFFECTIVE DPT; price it as a blended cycle-averaged
    DPT when it drifts a scripted archetype out of its TP band (the base-stat TP bands above still
    gate each archetype's raw numbers — BalanceReport's SPECIAL MOVE-SETS table lists who is scripted).
  - SUMMON is bounded by HARD CAPS, not a soft budget: a per-summoner cap (SUMMON_PER_ENEMY_CAP) and a
    per-room live-enemy ceiling (SUMMON_ROOM_LIVE_CAP) cap the spawned TP a floor can accrue, so the
    EncounterBudgetPlanner headroom stays bounded without per-spawn accounting.

SCOPE NOTE: idea 4 is a 5-pillar epic. Implemented across two PRs: Pillar 1 (encounter budget) and
the enemy role/verb taxonomy in the first; the mechanical verb hooks (Pillar 2), the hazard
chain-reaction system (Pillar 3), and the telegraph audit (Pillar 5) in the second. Pillar 4
(positioning incentives) is partly served by existing column/chokepoint generation plus the new
flanker hook; further generator positioning work remains optional follow-up.

BOSS APPENDIX — the boss balance ruleset (idea 6)   RULES NOW, FIGHTS LATER
================================================================================
Companion to: .claude/agents/ideas/balance_order_6_boss_balance_ruleset.txt
Formulas: util/GameMath.java (BOSS BALANCE RULESET block, after the TP primitives + hazards)
Anchors & bands: util/BalanceConfig.java SECTION 14
Living table: util/BalanceReport.java (BOSS RULESET section)

Bosses break the normal threat math: a SINGLE entity meant to survive many turns and
threaten a PREPARED player. The trash-mob golden ratio (idea 2) and the TP role bands do
NOT apply — a boss tuned like a big trash mob is either a 2-shot anticlimax or an
un-counterable HP wall. So a boss is tuned to a fight-LENGTH target and a phase-structured
threat curve instead. This is a CONTRACT, not a feature: boss FIGHTS are deferred (they
need story/plot and a run/final-floor structure — the user's call), so this appendix only
defines the ruleset + math the future boss work must satisfy. It costs nothing to honor now
and prevents shipping placeholder HP walls. The current bosses (OVERSEER 250hp, CORRUPTOR
450hp, HELL_BARON 700hp) are flat placeholders flagged "to be re-derived via this ruleset".

THE SIX RULES (apply when a boss is built/retuned):

RULE 1 — TUNE HP TO FIGHT LENGTH, NEVER TO A FLAT NUMBER.
    bossEffectiveHp = expectedPlayerSustainedDpt(depth) * targetFightTurns * multiPhaseFactor
      targetFightTurns  = 18-40 (act boss); 40-60 (run-final boss, FUTURE)
      multiPhaseFactor  = 1.0 per phase the player effectively RE-fights (1.0 for a boss
                          that just splits one HP bar across phases)
      expectedPlayerSustainedDpt(depth) = the reference DPT (25) LIFTED by the offence
        power points the player is expected to have by that depth — NOT the depth-1 ref.
        GameMath.expectedPlayerSustainedDamagePerTurn(refDPT, expectedOffencePowerPoints).
    A boss must NEVER be a literal HP constant. (GameMath.bossEffectiveHitPoints)

RULE 2 — CAP THE FIGHT LENGTH FROM ABOVE TOO (no sponges).
    upperFightTurnsCap = targetFightTurns * 1.5  for a player who plays well.
    Check the actual length with GameMath.bossFightTurnsForPlayerDamagePerTurn(eHP, playerDpt).
    If the only way to hit the HP target drags past the cap, the boss is over-HP'd — add a
    PHASE or a damage-window mechanic, NOT more HP. HP is the worst difficulty lever.

RULE 3 — DAMAGE OUTPUT: lethal-but-counterable.
    Set boss DPT by the SURVIVAL CHECK: playerEHP / bossDpt ~= survivalCheckRatio * fightTurns,
    survivalCheckRatio in [0.4, 0.7] (target 0.5). So a no-heal player who eats most attacks
    dies BEFORE the fight ends (must dodge/cover/heal), but a player who avoids ~half and uses
    heals survives with margin. GameMath.bossDamagePerTurnForSurvivalCheck / bossSurvivalCheckRatio.
    HARD FAIRNESS CAP (inherits idea 4 pillar 5): no single boss attack may exceed 35% of
    player eHP, and ANY attack above 25% MUST be telegraphed one full turn ahead with a
    readable, avoidable cue. Unavoidable burst = banned.
    GameMath.bossSingleHitFractionOfEffectiveHitPoints vs BOSS_HARD_SINGLE_HIT_FRACTION (0.35)
    and TELEGRAPH_MAX_UNTELEGRAPHED_HIT_FRACTION (0.25).

RULE 4 — PHASES STRUCTURE THE THREAT CURVE.
    Split the bar into N equal phases (2-3 for act bosses); each triggers at an HP threshold,
    escalates ONE mechanic, and keeps per-phase TP rising but within the fairness cap. Phase 1
    teaches the pattern, the last phase tests it. Boss AI is pattern-driven (BossAttackPattern),
    NOT the trash-mob greedy stepper. GameMath.bossPhaseHealthThreshold(i, n) fixes the seams.

RULE 5 — THE BOSS IS A BUILD CHECK (the arena gates progress).
    Because the HP target is tied to expectedPlayerSustainedDpt(depth), an UNDER-powered player
    physically cannot out-DPS the fight window while an on-curve player can. The boss is the
    checkpoint where "are you on the idea-2 power curve?" gets answered. OPTIONAL enrage: after
    upperFightTurns, ramp boss damage so a stall-out/kiting player loses.

RULE 6 — REWARD SCALED TO COST (closes the economy loop).
    bossReward ~= (ammoSpent*ammoValue + healsSpent*healValue) * RISK_PREMIUM (>1).
    Priced by what the fight CONSUMES plus a risk premium, so a boss REFUNDS the fight plus a
    profit — never a net resource loss (punishes progress) and never a jackpot (breaks the
    economy). GameMath.bossReward / BOSS_REWARD_RISK_PREMIUM. Re-derive the current placeholders
    (XP_REWARD_BOSS_BASE 500, CREDIT_REWARD_BOSS_BASE 250) once the scarcity model (idea 3) is tuned.

THE BOSS CHECKLIST (apply when a boss is built/retuned):
  [ ] HP = expectedPlayerSustainedDpt(depth) * fightTurns * phases  (NOT a literal)
  [ ] fightTurns in target band; worst-case <= 1.5x (else add a phase, not HP)
  [ ] bossDpt set by the survival-check ratio; heals available make it winnable
  [ ] no un-telegraphed attack > 25% eHP; none > 35% at all
  [ ] N phases, each adds ONE mechanic, each within the fairness cap
  [ ] reward refunds expected ammo+heal spend * risk premium
  [ ] all numbers live in BalanceConfig, derived not literal
  [ ] entry added to the living balance table below
