--------------------------------------------------------------------------------
⚠️  READ THIS FIRST — THE CURRENT BALANCE IS NOT GOOD AND MUST BE REFINED  ⚠️
--------------------------------------------------------------------------------
The balance described in this document is the CURRENT state, not a target state.
It is far from perfect. Large parts of it have never been playtested — only
verified against a standalone arithmetic harness (BalanceReport) that checks the
numbers against their own formulas. Passing that harness proves the numbers are
INTERNALLY CONSISTENT with the contract; it does NOT prove the game feels good,
is fun, or is fair in practice. Treat every number here as PROVISIONAL.

This warning is repeated throughout the document, deliberately, at each system,
because each system has its own unresolved problems. Do not read any section as
"this is solved". Read every section as "this is where it stands today, and it
needs another pass." A consolidated list of the known problems is in SECTION 21.

Whenever you touch balance: change the numbers in the SINGLE SOURCE OF TRUTH
(util/BalanceConfig.java), re-run the auditor (SECTION 20), and assume the result
still needs human playtesting before it can be called "good".


================================================================================
SECTION 0 — THE TURN-BASED FOUNDATION (why the math is exact)
================================================================================
The game is strictly turn-based (Doom-RPG style). One player action = exactly
one world turn; every enemy acts once per player turn. Therefore TIME is measured
in TURNS, never seconds. There is no real-time DPS — only DAMAGE-PER-TURN (DPT).
This makes the entire balance model exact arithmetic instead of physics.

Consequences that everything below depends on:
  - Movement/rotation animation DURATION (seconds) does NOT change combat math —
    it only changes game feel and how fast the player can physically issue turns.
    (util/BalanceConfig.PLAYER_MOVE_DURATION / PLAYER_ROTATE_DURATION.)
  - "How long does X take" is always a turn count you can compute, never timing.
  - Ranged enemies may only attack the player on a shared cardinal line (same tile
    column OR same tile row) — never diagonally. Enforced by isSameCardinalLine()
    in enemy/EnemyManager.java. This is a HARD design rule, not a tuning number,
    but it shapes every ranged threat's real-world DPT.

Docs: docs/tick-system.txt, docs/doom-rpg-reference.txt, docs/game-balance-authority.txt.

⚠️ Not-good note: because everything is turn-exact, a single mis-set constant
propagates cleanly through the whole model — which is why so many sections below
are "in band on paper" yet still unproven in play.

SECTION 2 — THE FOUR PRIMITIVES + DERIVED SCORES (the core math)
================================================================================
All in util/GameMath.java. Everything else is derived from these four.

1. eHP — EFFECTIVE HIT POINTS            GameMath.effectiveHitPoints(...)
     eHP = (rawHP + armor) * 1/(1 - dodge) * H/max(1, H - R)
       H = average incoming hit, R = flat reduction.
     - Dodge multiplies survivability by 1/(1 - dodge) (a dodged hit deals 0).
     - Flat reduction: each landed hit of size H only removes (H - R).
     Canonical start (130 HP, 75 armour, 0 dodge, 0 R) -> 205 eHP (the reference).
     RULE: enemies currently have NO dodge/reduction, so enemy eHP == raw HP.

2. DPT — DAMAGE PER TURN
     BURST DPT   = damage of one fire action (one turn).
     SUSTAINED   = (clipSize * damagePerShot) / (clipSize + reloadTicks)
                                             GameMath.sustainedDamagePerTurn(...)
   2b. AMMO EFFICIENCY = damagePerShot / ammoPerShot   GameMath.ammoEfficiency(...)
     Run-budget = ammoEfficiency * (total ammo the economy supplies). This is the
     bridge to the scarcity model — governed by SUPPLY, not the reserve cap.

3. TTK — TURNS TO KILL                    GameMath.turnsToKill(...)
     turnsToKill = ceil(target.eHP / attacker.effectiveDPT)
     Feed ENEMY DPT + PLAYER eHP to get the player's Turns-To-Die (TTD).

4. TP — THREAT POINTS (one danger number per enemy)  GameMath.threatPoints(...)
     enemyDPT      = attackDamage / max(1, attackCadenceTurns)
     survivalTurns = enemy.eHP / REFERENCE_PLAYER_DPT   (= 25)
     TP            = enemyDPT * survivalTurns * positionalMultiplier
     positionalMultiplier (DESIGNER classification, BalanceConfig.POSITIONAL_MULT_*):
       1.00 melee | 1.15 fast-melee | 1.30 ranged | +0.25 if it applies DOT/stun/slow.
     TP is the currency the floor encounter budget spends.

DERIVED SCORES:
  weaponPowerScore = sustainedEffectiveDPT * sqrt(ammoEfficiency / 40)
                                             GameMath.weaponPowerScore(...)
  goldenRatio      = turnsToDie / turnsToKill          GameMath.goldenRatio(...)
  depthThreatScale = healthScale^(d-1) * damageScale^(d-1)
                                             GameMath.depthThreatScale(...)

REFERENCE ANCHORS (BalanceConfig SECTION 9):
  REFERENCE_PLAYER_DPT      = 25   (held fixed; also the golden-ratio TTK metric)
  REFERENCE_PLAYER_EHP      = 205  (the canonical start eHP; one difficulty)
  REFERENCE_AMMO_EFFICIENCY = 40   (weapon power-score normaliser)

⚠️ Not-good note: the whole model treats the shotgun's 25 sustained DPT as "the
player", ignoring found weapons, abilities, crits, and stat growth. Real player
DPT swings far above this. The anchors are a convenient fiction, not a measured
average — a known source of drift between "in band" and "actually balanced".

SECTION 3 — PLAYER SURVIVABILITY (the denominator of all difficulty)
================================================================================
File: BalanceConfig SECTION 1, plus the stat system in SECTION 7.

Base pools:
  PLAYER_MAX_HEALTH      = 130   (biggest single forgiveness dial; range 80–200)
  PLAYER_MAX_ARMOR       = 75    (armour soaks part of every hit)
  ARMOUR_ABSORB_FRACTION = 0.50  (fraction of each hit taken from armour, not HP)

Heals (HP/armour is a RESOURCE — see SECTION 12):
  MEDKIT_STIM_HEAL  = 32   ('+')      MEDKIT_FULL_HEAL = 90   ('H')
  ARMOUR_SHARD_VALUE= 14   ('a')      ARMOUR_VEST_VALUE= 62   ('A')
  (All ~1.8x their legacy values after the economy rescale, to track higher
   incoming damage. A heal is priced in "turns of survival bought" — SECTION 12.)

The five-step DAMAGE-MITIGATION PIPELINE (single source of truth; every actor
resolves damage in EXACTLY this order — GameMath, docs/game-balance-authority.txt):
  1. Directional/Guard modifier (player only): D' = D * facingMultiplier
  2. Power/positioning modifiers (if present): D'' = D' * weak*vulnerable*backstab
     (EXPOSED is not a multiplier — it sets ignoreBlock for step 3, one hit.)
  3. BLOCK absorption: absorbed = min(block, D''); D''' = D'' - absorbed
  4. Flat armour reduction: D'''' = max(0, D''' - armorReduction)
  5. Subtract from HP.
  BLOCK sits ABOVE armour ("I braced this turn"); overkill into Block is LOST.
  STATUS DoT (burn/poison/bleed) BYPASSES Block — direct HP loss.

PLAYER GUARD (directional, conditional eHP) — BalanceConfig SECTION 2 / GUARD_*:
  Tapping GUARD ends the turn and braces the marine.
  GUARD_FRONT_MULTIPLIER = 0.35 (heavy reduction inside the ±60° facing arc)
  GUARD_SIDE/BACK_MULTIPLIER = 1.0 (flanks land at FULL damage — read & rotate)
  GUARD_FRONT/BACK_HALF_ANGLE_DEGREES = 60
  Priced as a 1-turn opportunity cost; self-limiting vs flanks, so no hard cap.

STAT-DRIVEN survivability (attribute system, SECTION 7 below):
  TOUGHNESS -> +HP (TGH_HP_PER_POINT=5) and flat reduction (TGH_REDUCTION_PER_POINT=1).
  AGILITY   -> dodge (AGI_DODGE_PER_POINT=0.02, DODGE_CAP=0.35) + faster actions.

[RESOLVED by order 8] 205 reference eHP used to be "the normal mode's start only",
with the other three modes anchored to it by accident. The mode system is deleted:
there is exactly ONE difficulty, so 205 eHP is THE player anchor and every band and
telegraph cap derived from it protects the real player pool in every run (SECTION 17).

SECTION 6 — PLAYER PROGRESSION (XP curve, level-up cards, attributes)
================================================================================
File: BalanceConfig SECTION 7; docs/xp-level-progression.txt; progression/*.

XP CURVE (GEOMETRIC — re-shaped for pacing, new-game-balancr order 4):
  xpRequired(level) = XP_BASE_REQUIREMENT * XP_CURVE_GROWTH_PER_LEVEL ^ (level-1)
  XP_BASE_REQUIREMENT = 150, XP_CURVE_GROWTH_PER_LEVEL = 1.118.
  (L1->2: 150, L5->6: 234, L10->11: 409, ...)  GameMath.xpRequiredForLevelGeometric
  WHY geometric: the old polynomial (base*level^1.3) grew at a different rate than
  the enemy threat a floor's roster is worth (that grows GEOMETRICALLY), so pacing
  drifted. The growth 1.118 tracks the enemy compound (HEALTH*DAMAGE scale), so —
  with per-enemy XP DERIVED from depth-scaled TP — the player gains ~1 level/floor
  at EVERY depth. This is enforced: R-XP-PACE (available/required in [1.0,1.3]).
PER-ENEMY XP — DERIVED, not hand-set (order 4):
  xpReward = round(XP_PER_THREAT_POINT(0.35) * enemyThreatAtDepth). The 13 hand-set
  XP constants are DELETED; dangerous enemies automatically pay more and a new
  archetype can never ship with a forgotten XP value. Boss XP stays a placeholder.
CATCH-UP (rubber band, forward-only, order 4): a player > 1 level below the expected
  level for their depth gets XP * XP_CATCHUP_MULTIPLIER(1.5); never slows an
  at-or-ahead player.  GameMath.catchUpScaledXp; applied in PlayerProgress.addXp.

LEVEL-UP CARD SYSTEM (the build-diversity engine, idea 5):
  On each level-up, LEVEL_UP_CARDS_OFFERED = 3 cards are drawn from four pools.
  Every card costs the SAME power budget:
    LEVEL_UP_BUDGET_PP        = 12   (power points = %-gain to reference DPT or eHP)
    LEVEL_UP_BUDGET_TOLERANCE = 0.15 (a card must price into [10.2, 13.8] PP)
    LEVEL_UP_DRAW_BIAS_PER_PICK = 0.6 (biases offers toward the emerging build)
  THE TOTAL-PP INVARIANT: because every card is budget-equal, total player power
  at level L = L * 12 PP for EVERY build; only the SHAPE differs. This is what
  keeps all builds on the depth-coupling curve (SECTION 11).
  Card PP is computed from stat deltas via GameMath (damagePerTurnPowerPoints /
  effectiveHitPointPowerPoints), so it "cannot lie". Cards + magnitudes:
    Hollow Points (+6 dmg), Marksman Training (+3 MRK), Brutal Strength (+3 STR),
    Glass Cannon (+10 dmg / -18 HP), Combat Armor (+24 armour), Toughened Hide
    (+1 TGH), Vitality (+25 HP), Iron Constitution (+45 HP / -22 armour), Evasion
    Training (+5 AGI), Reckless Charge (+8 AGI / -12 armour).

ATTRIBUTE (STAT) SYSTEM (BalanceConfig SECTION 7 + GameBalance caps/bases):
  STRENGTH    -> +melee dmg     STR_MELEE_PER_POINT   = 0.05, cap 12
  MARKSMANSHIP-> +ranged dmg    MRK_DAMAGE_PER_POINT  = 0.04 (+accuracy 0.03), cap 12
  AGILITY     -> dodge + speed  AGI_DODGE_PER_POINT=0.02 (DODGE_CAP 0.35),
                                AGI_SPEED_PER_POINT=0.03 (floor AGI_MIN_DURATION_MULT
                                0.55), cap 10
  TOUGHNESS   -> +HP + flat red TGH_HP_PER_POINT=5, TGH_REDUCTION_PER_POINT=1
                                (min damage TGH_MIN_DAMAGE=1), cap 12
  The ONE canonical starting stat block lives in BalanceConfig SECTION 7
  (PLAYER_START_* = 2/2/2/2); there are no difficulty modes: see SECTION 17.

⚠️ Not-good note: the total-PP invariant is elegant on paper but assumes the
player only gains power from level-up cards. In reality found weapons, weapon
abilities (SECTION 5, unpriced), crits, and consumables all add uncounted power.
So "every build sits on the curve" is true only for the CARD contribution, not
for real total power. The curve the depth-coupling invariant defends is therefore
optimistic. Needs re-derivation once weapon power is priced in.

BOSS AI (Overseer Hunter-Killer brain — GameBalance BOSS_TACTIC_*): tactic-scoring

✅ FIXED (new-game-balancr order 5) — CYCLE-AVERAGED THREAT PRICING. Special move-sets
that raise a caster's EFFECTIVE DPT (buffs, debuffs, area strikes, summons) are now
PRICED automatically. EnemyType.baseThreatPoints() blends the DPT over the archetype's
special-ability cadence cycle (GameMath.cycleAveragedDamagePerTurn):
    cycleAveragedDpt = (basicAttacks * attackDamage + perCastSpecialDamage) / cycleTurns
                       + summonAmortisedDpt
Each verb converts to an equivalent-damage number via a pure GameMath.specialEquivalent*
formula (one per verb):
    AREA_STRIKE  -> its predicted slam damage (attackDamage * AREA_STRIKE multiplier)
    BUFF_SELF    -> extra damage the EMPOWERED buff adds over its duration
    DEBUFF WEAK  -> player DPT lost over duration * DEBUFF_TP_EQUIVALENCE (start 0.6 — a
                    defensive verb priced as offence, worth less than dealt damage)
    DEBUFF SLOW/BLIND -> enemy bonus turns gained * caster DPT * DEBUFF_TP_EQUIVALENCE

36-66 soldier band), so its HP was trimmed 115 -> 90 (true TP ~64, golden ratio 3.75).
COVERAGE now fails the build for any SpecialAbility with no registered equivalence
(BalanceSchema.SpecialVerbPricing); SELF_DESTRUCT is explicitly exempt (a death-triggered

magnitudes the formulas read still live in EnemyConstants/BalanceConfig SECTION 8.

never mitigate. EnemyType gains armorPool()/dodgeChance()/flatReduction() (all default 0

SECTION 9 — BOSSES (a separate ruleset; DERIVED, order 6)
================================================================================
Files: BossBalance (the derivation engine: statsForDepth -> BossStats), BossStats
(the derived block), BalanceConfig SECTION 14 (the inputs: per-boss TARGET_FIGHT_TURNS,
verb DPT-fractions, survival ratio, enrage, gate margin, reward), GameMath (BOSS
BALANCE RULESET block), BalanceSchema (R-BOSS-* rules), World.createBossForDepth
(spawn), BossFloorController (soft enrage), docs/game-balance-authority.txt (R-BOSS-*).

Bosses break the trash-mob math (a single entity meant to survive many turns vs a
PREPARED player), so the TP/golden-ratio bands do NOT apply. A boss is tuned to a
FIGHT-LENGTH target + phase-structured threat curve instead — and (order 6) every
number is DERIVED at spawn, never a flat constant. There are ZERO flat boss
HP/damage/XP/credit constants anywhere; BossBalance.statsForDepth(depth) computes the
whole stat block, so endless-mode bosses scale for free.

Current DERIVED bosses (BossBalance, at their canonical depths):
  Overseer   (d5)  715 HP  | bossDPT 18.6 | melee 14, charge 34, laser 21 | reward 1244cr
  Corruptor  (d10) 1120 HP | bossDPT 14.6 | acid 21                       | reward 1455cr
  Hell Baron (d15) 1615 HP | bossDPT 12.1 | fire 6, cleave 21(P1)/35(P2)  | reward 1712cr
  (verbs are FRACTIONS of bossDPT; all <= 17% eHP, well under the 25/35% caps)

THE SIX RULES (now LIVE — enforced by BossBalance + R-BOSS-* audit):
  R1 HP = expectedPlayerSustainedDpt(depth) * targetFightTurns * multiPhaseFactor
       (act boss 18–40 turns; per-boss target 22/28/34; NEVER a literal HP constant).
  R2 Cap fight length from above (<=1.5x target); SOFT ENRAGE (+8% DPT/turn past the
       cap, telegraphed "FURIOUS") enforces it by escalation, not a fail timer.
  R3 DPT set by survival check: playerEHP/bossDpt = ratio(0.4–0.7) * fightTurns (0.50).
       Verbs are fractions of bossDPT; no single hit > 35% eHP; > 25% MUST be telegraphed.
  R4 N equal phases (BOSS_PHASE_COUNT=2), each escalates ONE mechanic; seams via
       GameMath.bossPhaseHealthThreshold.
  R5 The boss is a BUILD CHECK: R-BOSS-GATE proves the DEPTH-1 starting loadout CANNOT
       win — turnsToKill >= 2.0x survivableTurns WITH max heals (margins 2.08/2.56/3.04,
       tightest at the first boss). R-BOSS-FAIR proves the expected loadout gets a fair
       fight (length in [target,1.5*target], survival ratio 0.50).
  R6 Reward = consumption * RISK_PREMIUM (1.3); XP flows from boss Threat Points. The
       route generator guarantees a reachable SHOP/CACHE the layer before every boss
       (pre-boss provisioning, 100-seed test). R-BOSS-AMMO proves the demand is coverable
       by reserve + arena budget (tests the BUILD, not full pockets).

Tune a boss via its *_TARGET_FIGHT_TURNS or the survival ratio (SECTION 14) — semantic
dials, never a raw HP number. Boss AI CHOREOGRAPHY (the Overseer Hunter-Killer brain) is
untouched: order 6 prices the fight, not the tactic brain.

SECTION 10 — DEPTH SCALING & THE COUPLING INVARIANT (the master curve)
================================================================================
File: BalanceConfig SECTION 3 + SECTION 9 invariant; GameMath depth methods.

Enemy threat COMPOUNDS per floor:
  HP:     baseHP  * ENEMY_HEALTH_SCALE_PER_DEPTH ^ (depth-1),  scale = 1.042
  Damage: baseDmg * ENEMY_DAMAGE_SCALE_PER_DEPTH ^ (depth-1),  scale = 1.073 (order 4)
  enemyThreatAtDepth = baseTP * depthThreatScale(1.042, 1.073, depth)
Credits scale LINEARLY: base * (1 + (depth-1)*CREDIT_DEPTH_SCALE), scale = 0.12.

Player power — THE HONEST TOTAL-POWER MODEL v2 (new-game-balancr order 4):
  playerPowerAtDepthV2 = cardPower(d) * gearRamp(d) * abilityPower(d)   (ALL sources)
    cardPower    = the old linear level-up term (v1)
    gearRamp     = order-2 gear curve in CONTINUOUS ramp form (reaches the step value
                   at each region end; no boundary jumps a fixed band can't absorb)
    abilityPower = 1 + expected weapon-ability PP / 100 (order-2 priced tables)
  The old v1 curve counted ONLY cards — a FICTION. v2 is honest and far steeper
  (v2(15) ~= 5.5 vs 2.68), which is WHY the enemy DAMAGE rate was re-fit up.

THE DEPTH-COUPLING INVARIANT (must hold or the game goes unfair/trivial):
  0.9 <= playerPowerAtDepthV2(d) / enemyThreatScale(d) <= 1.2   (order 4 uses v2)
                                             GameMath.depthCouplingRatio(...)
  Bounds: BalanceConfig DEPTH_COUPLING_RATIO_MIN/MAX. Enforced 1..15 (R-DEPTH).
  History: 1.08/1.06 broke by depth 5; 1.045/1.035; 1.042/1.032 (v1, under at 18+).
  Order 4: re-derived vs v2, DAMAGE re-fit 1.032 -> 1.073 (HEALTH held at 1.042 so
  order-3 scarcity is untouched). Now IN band 1..15 (~0.95..1.16) with NO under-band
  fudge; depths 16..20 (printed, not audited) degrade to the EASY side (on-curve
  player pulls slightly ahead), never unfair-hard. The gate stays in band at the
  re-fit rate (region-2 on-curve soldier golden ratio = 3.0, the fair edge).

Depth generosity bumps (BalanceConfig SECTION 3): at full depth, extra enemies
(LEVEL_GEN_DEPTH_ENEMY_BONUS_MAX=2), heavy-upgrade chance 0.60, +medkit 0.15,
+ammo 0.20, extra-ammo 0.50.

⚠️ Not-good note: the invariant is defended by a MODELLED linear player curve that
ignores found loot and abilities (which only help the player), so the real ratio
is "at least this favourable" — meaning the deep-floor "graceful hard edge" may
actually be easier than modelled, or the early game harder, depending on real loot
luck. Endless runs past depth ~20 are explicitly unbalanced (intentional graceful
degradation, i.e. it gets unfairly hard and that is currently accepted, not fixed).

SECTION 11 — ENCOUNTER BUDGET (difficulty as a dial, not an accident)
================================================================================
File: BalanceConfig SECTION 11; level/EncounterBudgetPlanner.java; GameMath.

The generator SPENDS a per-floor Threat-Point budget instead of rolling enemies at
random:
  floorThreatPointBudget(depth) = FLOOR_BASE_THREAT_POINT_BUDGET * depthThreatScale(depth)
  FLOOR_BASE_THREAT_POINT_BUDGET = 500 (depth 1).
Because both the budget AND each enemy's TP cost scale by the same depth curve, the
enemy COUNT stays ~constant across floors while each enemy gets stronger.

COMPOSITION RULES the planner enforces:
  ENCOUNTER_ANCHOR_BUDGET_FRACTION_MIN/MAX = 0.15 / 0.30 (one anchor bruiser/elite)
  ENCOUNTER_MAX_SINGLE_TYPE_FRACTION = 0.40 (variety)
  ENCOUNTER_PER_ROOM_TP_FRACTION_CAP = 0.25 (no un-winnable pile-up in one room)
  ENCOUNTER_BUDGET_FILL_TARGET_FRACTION = 0.95 (headroom so rosters don't overshoot)
  ENCOUNTER_ELITE_ANCHOR_FLOOR_CHANCE = 0.15 (min depth 3) — elite-gauntlet floors.
  Every roster must contain BOTH ranged and melee archetypes.

ENCOUNTER BUDGET V2 (new-game-balancr order 5) — three additions:
  1. TACTICAL ROOM CAPS: a room's TP cap is scaled by its GEOMETRY, read from the
     generator's room metadata (Room.isLarge + interior dims), never a hand tag —
     ROOM_OPEN_TP_MULTIPLIER 0.8 (a LARGE/open room has nowhere to break a ranged
     cardinal line, caps LOWER) | ROOM_CHOKEPOINT_TP_MULTIPLIER 1.1 (a narrow,
     corridor-like room the player can funnel, caps HIGHER). Applied per room via
     EncounterBudgetPlanner.Plan.perRoomThreatPointCap(open, choke) +
     GameMath.roomGeometryThreatCapMultiplier; wired in LevelGenerator (caverns are
     roomless/open so they only get the region dial).
  2. PACK COHERENCE: chaff spawns in packs of CHAFF_PACK_MIN..MAX (2..4). The
     golden-band chaff exemption ASSUMES packs (a lone chaff reads a harmless ~9
     golden ratio, balanced by pack TP); the planner now GUARANTEES it — a chaff type
     is only added when a full min-pack fits, and enters as a group. Proven by a
     100-seed generator test (no chaff ever appears alone).
  3. THE REGION DANGER DIAL (fixes problem 12): route regions stop being frequency-
     only. Each region declares REGION_TP_BUDGET_MULTIPLIER (A OUTER FACILITY 0.9 |
     B RESEARCH WING 1.0 | C REACTOR DEPTHS 1.15 | D THE BREACH 1.25) applied ON TOP
     of the depth curve (GameMath.regionScaledFloorThreatPointBudget), so a lethal
     region spends measurably MORE TP (more bodies) at the same depth. R-REGION (a
     new schema rule) checks the dial is bounded [0.8,1.3], monotonic non-decreasing,
     and that C/D out-dial A by >= REGION_TP_LETHAL_MARGIN. Node WEIGHT multipliers
     (RouteMapConstants) still own FLAVOUR (what kind of rooms); the TP dial owns HOW
     HARD. FAIRNESS: the dial scales the BUDGET (body count), NOT the per-enemy threat
     scale, so per-fight depth-coupling (R-DEPTH) holds in every region lane — region
     danger is an attrition tax of extra bodies, not an unfair per-duel spike.
  4. ELITE-GAUNTLET floors keep their 0.15 chance but must still fit the (region-
     scaled) budget — a composition choice, not a budget override.

Level-gen spawn/loot density (BalanceConfig SECTION 6):
  LEVEL_GEN_PROP_CHANCE=0.13, LEVEL_GEN_MAX_ENEMIES_PER_ROOM=3,
  credit chips per floor 3–7 (weights small 70 / medium 24 / large 6),
  per-room-type medkit/armour/ammo/weapon chances (server/large/armory/command/
  hazard rooms each have their own budget).

⚠️ Not-good note: the budget reproduces the SECTION 12 model floor "on average",
but the actual per-seed rosters are only spot-checked via BalanceReport. Room-level
distribution (which enemies end up crowded together) is governed by a load-balancer
plus a safety cap, not by a tactical-placement model — so a bad seed can still
produce a lopsided or trivially easy floor. This is untested in real play.


================================================================================
SECTION 12 — RESOURCE MANAGEMENT / SCARCITY ECONOMY (a core balance pillar)
================================================================================
Files: BalanceConfig SECTION 5 (levers) + SECTION 10 (model + bands); GameMath
scarcity block; docs/game-balance-authority.txt (RESOURCE SCARCITY MODEL).
This is one of the MOST important balance systems and the user's stated priority.

WHY IT MATTERS: scarcity is what turns a shooter into a roguelike. With infinite
ammo there are no resource DECISIONS. The goal is to land supply JUST BELOW comfort
so clever spending is rewarded and careless spending is punished — NOT to starve.

THE CENTRAL EQUATION (per floor, "fight everything" basis):
  DEMAND = sum of every enemy's eHP       (damage needed to clear the floor)
  SUPPLY = sum over ammo pickups of (boxSize * damagePerAmmoUnit)  (ranged only)
  S = SUPPLY / DEMAND
  TARGET: S in [0.75, 0.95] floor-wide AND < 0.60 for any SINGLE weapon.
    (BalanceConfig SCARCITY_RATIO_FLOOR_MIN/MAX/TARGET, SCARCITY_PER_WEAPON_MAX.)
  Ammo alone covers ~75–95% of a floor; the rest is melee/avoidance/reserves.

THE FOUR LEVERS (all in BalanceConfig):
  1 DROP FREQUENCY  ENEMY_AMMO_DROP_CHANCE=0.10, MELEE_KILL_AMMO_DROP_CHANCE=0.20,
                    LEVEL_GEN_AMMO_CHANCE_PER_ROOM=0.20                (SECTION 5)
  2 DROP SIZE       AMMO_BOX_BULLETS 15 / SHELLS 5 / CELLS 10 / ROCKETS 2,
                    RAILGUN_PICKUP_SLUGS 2, FLAME_PICKUP_FUEL 25, GRENADE 3 (SECTION 5)
  3 RESERVE CAP     AMMO_RESERVE_CAP_BULLETS 54 / SHELLS 24 / CELLS 38 / ROCKETS 26,
                    RAILGUN_MAX_SLUGS 8, FLAME_MAX_FUEL 50, GRENADE_MAX_AMMO 10 (SECTION 5)
  4 DEMAND          enemy density / eHP per floor (the TP budget)  (SECTION 2/11)
  Tune LEVER 4 (demand) + LEVER 2 (drop size) first — biggest effect.

ANTI-HOARD: reserve caps bank only ~RESERVE_BANKING_FLOORS_TARGET=1.5 floors of a
weapon's run-demand (GameMath.reserveBankingFloors). Enemy eHP compounds with depth
while the ammo depth bonus is gentler, so S tightens as you descend and hoards get
spent. Railgun slugs are the tightest gate (~1.0 floor) to honour its power
exception.

HEAL ECONOMY (HP is a resource too):
  INCOMING    = totalEnemyDPT * turnsEngaged * (1 - avoidanceFactor)
  HEAL_SUPPLY = medkits*avgHeal + armour*avgArmour
  netHpDrain  = INCOMING - HEAL_SUPPLY  (target: small NET LOSS, 5–15% of eHP/floor)
    (BalanceConfig HEAL_NET_DRAIN_FRACTION_MIN/MAX.)
  Each floor should cost some HP you don't recover, so HP slowly becomes precious.

THE MODEL FLOOR (depth 1 reference; BalanceConfig SECTION 10):
  6x Gore Biter + 3x Eye Tyrant + 2x Shell Brute + 1x Plague Hulk
  DEMAND = 720 damage, ~432 TP. All SECTION 5 levers are tuned against THIS floor.
  Current living-table result: S = 0.83 floor-wide, every per-weapon S < 0.6,
  netHpDrain 11.5% of eHP — all in band.

CREDITS (the currency economy):
  Per-kill credits (BalanceConfig SECTION 2): 5–40 (boss 250 placeholder).
  Credit chips per floor 3–7. Depth scale 0.12. Credit Fang ability (GameBalance).
  SHOP / UAC Fabricator (GameBalance SHOP_*): 1–2 machines/floor, 9 offers each,
  category weights, depth+rarity pricing, base prices per offer type.

⚠️ Not-good note (IMPORTANT): the CREDIT half of the economy is effectively BROKEN
as a balance lever. Credits are awarded everywhere, but the doc/idea history flags
that a real spending SINK (the shop) was a prerequisite blocker — currency with no
sink is a meaningless counter, not a resource. Shop constants EXIST in GameBalance,
but the shop's integration/pricing is unproven and was explicitly "blocked/deferred"
in the design notes. Until the shop is verified in play, treat all credit numbers,
shop weights, and shop prices as UNBALANCED placeholders. The ammo/heal half is
modelled but was verified only by the arithmetic harness — NEVER playtested. So
even the "in band" scarcity result is provisional and must be refined against real
play. This is the single biggest gap between "looks balanced" and "is balanced".

SECTION 14 — TELEGRAPH & FAIRNESS CONTRACT
================================================================================
File: BalanceConfig SECTION 13; IntentConstants; enemy intent system.
RULE: every attack that can deal > TELEGRAPH_MAX_UNTELEGRAPHED_HIT_FRACTION (0.25)
of reference eHP (~51 of 205) in ONE hit MUST be telegraphed or avoidable. Burst
damage without warning is banned — a death must feel like "I made a mistake".
Because the intent system pre-commits every direct attack one turn ahead, this rule
is satisfied by construction for all committed attacks. Remaining un-telegraphed
damage is only DoT ticks and environmental hazards.
Boss hard cap: no single hit > 35% eHP (BalanceConfig SECTION 14).

⚠️ Not-good note: the contract is satisfied "by construction" only for attacks that
go through the intent-commit system. Any new attack path that bypasses it (a new
special, a scripted boss verb, a hazard burst) can silently violate the cap. The
BalanceReport TELEGRAPH AUDIT only checks the attacks it knows about.

SECTION 16 — ROUTE MAP / ENDLESS DESCENT PACING (macro difficulty)
================================================================================
File: util/RouteMapConstants.java; route/*; docs/route-map-system.txt.
The run is an ENDLESS forward branching DAG. Difficulty pacing at the macro scale:
  REGION_BAND_SIZE = 5 (a region spans 5 depths, ending in a boss floor;
  == Constants.BOSS_FLOOR_INTERVAL, so bosses appear every 5 floors).
  First FIXED_REGION_COUNT regions are hand-named acts; beyond that every region is
  an endless "THE BREACH" cycle generated lazily.
  Branch shape: BRANCH_WIDTH 2–4, BRANCH_SPREAD_CHANCE 0.55.
  Per-region node-type weight multipliers tilt each act's feel WITHOUT hard-coding
  node lists:
    A "Outer Facility" — safe: +cache, -elite (footing).
    B "Research Wing"  — exploratory: +mystery/event.
    C "Reactor Depths" — lethal: +elite (1.6x), -rest/shop.
    D "The Breach" (endless) — relentless: +elite (1.8x), -rest/shop (relief scarce).
  Per-region combat-generator biases (rooms/caverns) also shift the biome.

✅ FIXED (new-game-balancr order 5) — THE REGION DANGER DIAL unifies macro pacing
with the micro TP contract. Each region now declares REGION_TP_BUDGET_MULTIPLIER
(A 0.9 | B 1.0 | C 1.15 | D 1.25) applied ON TOP of the depth curve
(GameMath.regionScaledFloorThreatPointBudget, spent by EncounterBudgetPlanner), so a
"lethal" region is budgeted-ly lethal — it spends measurably more Threat Points (more
bodies) at the same depth, not merely rolls dangerous nodes more often. The node-type
WEIGHT multipliers above stay for FLAVOUR (what kind of rooms); the TP dial owns HOW
HARD. R-REGION gates it (bounded [0.8,1.3], monotonic non-decreasing A<=B<=C<=D, C/D
out-dial A by >= REGION_TP_LETHAL_MARGIN). Per-fight fairness is preserved: the dial
scales body COUNT, not per-enemy threat, so depth-coupling (R-DEPTH) holds in every
region lane. (The endless "Breach" coupling degradation past depth ~20 in SECTION 10

SECTION 17 — ONE DIFFICULTY (superseded: the mode system was REMOVED)
================================================================================
[SUPERSEDED — RESOLVED BY REMOVAL, new-game-balancr order 8]
This section used to describe four difficulty modes (per-mode starting-attribute
tables in GameBalance). They are DELETED. The game has EXACTLY ONE difficulty and

File: util/BalanceConfig.java SECTION 7 — the ONE canonical starting block:
  PLAYER_START_STRENGTH / _AGILITY / _TOUGHNESS / _MARKSMANSHIP = 2 / 2 / 2 / 2

Why the modes went: they changed ONLY starting stats while enemy numbers, scaling,
loot, scarcity and every telegraph cap stayed anchored to the normal tier's 205 eHP —
so three of the four modes were never actually balanced. Rather than tuning four
games forever, three were deleted; the contract is now EXACT for the one real game.
The difficulty a player experiences comes from INSIDE the run: route choice and the
priced map (SECTION 16 + route economics), region danger, depth via the coupling
curve, and scarcity/loot swings inside the audited bands.

SECTION 20 — CONSOLIDATED LIST OF KNOWN PROBLEMS (why balance is NOT good)
================================================================================
Every item below is a place where the current balance is known to be weak,
unproven, or outright broken. This is not exhaustive — it is the floor, not the
ceiling, of what needs refinement.

  1. NOTHING has been playtested. Every rescale is harness-verified arithmetic
     only. "In band" ≠ "feels right". (SECTION 19)
  2. The CREDIT economy has no proven sink — the shop is deferred/unverified, so
     credits, shop weights, and shop prices are meaningless placeholders. (SECTION 12)
  3. WEAPON ABILITIES (crit/pierce/lifesteal/legendaries) are entirely UN-priced
     against the contract and self-labelled "PLACEHOLDER — flag for playtesting".
     [PARTLY RESOLVED by order 1: the values now live in BalanceConfig SECTION 15,
     and START_ROOM_ANY_TIER_ENABLED is false + enforced by R-FLAGS. The pricing
     itself is still open.] (SECTION 5)
  4. All THREE bosses are flat placeholder HP walls, reading UNDER their derived
     bands; boss rewards are arbitrary. Boss fights are effectively unimplemented. (SECTION 9)
  5. [RESOLVED by order 1] The "single source of truth" is now complete: status
     magnitudes, the ability catalogue, shop, and boss stats were consolidated into
     BalanceConfig (SECTIONs 8/14/15/16) with re-export shims, and the shim-integrity
     audit keeps them from diverging again. (SECTION 1, 15)
  6. [RESOLVED by order 8 — by REMOVAL] The four difficulty modes are deleted. The
     game has exactly ONE difficulty, started from the single canonical attribute
     block in BalanceConfig SECTION 7, so the 205 eHP anchor and every band/telegraph
     cap derived from it now describe the real player pool in every run. Modes cannot
     creep back: R-SINGLE-DIFFICULTY fails the build on mode-family naming. (SECTION 17)
  7. The contract anchors "the player" to a fixed 25 DPT / 205 eHP, ignoring found
     weapons, abilities, crits, and consumables — the model systematically
     under-counts real player power. (SECTION 2, 6)
  8. Endless depth (past ~15–20) already fails the depth-coupling invariant. It is
     labelled "intentional graceful degradation" but in practice means it becomes
     unfairly hard, unaddressed. (SECTION 10)
  9. [RESOLVED by order 5] Special-move / summon / buff casters now have their
     EFFECTIVE DPT PRICED into TP via cycle-averaging (EnemyType.baseThreatPoints ->
     GameMath.cycleAveragedDamagePerTurn + specialEquivalent* per verb). COVERAGE
     fails the build on any unpriced SpecialAbility; the one archetype that overflowed
     its band once priced honestly (Blight Corruptor) was trimmed back in. (SECTION 8)
 10. Content has repeatedly shipped BEFORE being priced (the necrotic faction
     corrupted every floor's budget until a later pass). [MITIGATED by order 1:
     BalanceAuditTest's COVERAGE rule fails the build when a weapon item,
     consumable, ammo type, or enemy role is unclassified/unpriced.] (SECTION 7)
 11. [RESOLVED by order 1] The two divergent DoT definitions were unified to one
     BURN base (4/turn) and one POISON base; the R-DOT rule fails the build if a
     second definition reappears. (SECTION 15)
 12. [RESOLVED by order 5] Macro pacing (route regions) and micro difficulty (TP
     budget) are now unified by the REGION DANGER DIAL (REGION_TP_BUDGET_MULTIPLIER,
     applied on top of the depth curve; R-REGION gates it). A "lethal" region is now
     budgeted-ly lethal — it spends measurably more TP at the same depth — while
     per-fight depth-coupling still holds in every lane. (SECTION 16)
 13. The Railgun is deliberately out of its power band, "gated by scarcity" that is
     itself unproven — so it is effectively overpowered right now. (SECTION 4)
 14. Falloff/engagement-band crediting for weapons uses muzzle numbers, not real
     engagement distances — an acknowledged approximation. (SECTION 2, 4)

BOTTOM LINE: the balance model is a coherent, well-documented SKELETON with a solid
math contract, but it is provisional throughout, unplaytested, incomplete in its
consolidation, and broken in the credit/boss/ability areas. It MUST be refined.
Do not present any current number to a user as a finished, correct value.

SECTION 21 — HOW TO CHANGE BALANCE SAFELY (workflow for future sessions)
================================================================================
SUPERSEDED by THE CHANGE PROTOCOL — docs/game-balance-authority.txt SECTION 7
(new-game-balancr order 9). That protocol is now the authority: every BalanceConfig
change ships with (1) a green `./gradlew test`, (2) a green `./gradlew balanceSim`
(the behavioural bands, played through the real systems), (3) regenerated living
tables, and (4) one CHANGELOG line saying which dial moved and why. The steps below
remain accurate as the DETAIL of step 1-2; read the protocol first.
  1. Change the number in util/BalanceConfig.java (the single source of truth —
     since order 1 EVERY gameplay magnitude lives there; the other *Constants
     files only re-export it).
  2. Declare/keep its role and band in util/BalanceSchema.java per the contract
     (docs/game-balance-authority.txt, new-content checklist):
       - new weapon  -> RangedWeaponSpec + item classification (role band)
       - new enemy   -> EnemyType.role() is the declaration (TP + golden bands)
       - new heal    -> HealPickupSpec (survival-turns-bought band)
       - new card    -> automatic (UpgradeCard.values() is iterated)
       - new boss    -> the six-rule checklist (SECTION 9)
  3. Run `./gradlew test` — BalanceAuditTest fails the build on any unwaived
     out-of-band value, live test flag, or unpriced content. A deliberate
     exception needs a WAIVER in BalanceSchema, never a band hack.
  4. Re-run BalanceReport and paste its tables over docs/game-balance-authority.txt
     SECTION 6; verify the DEPTH COUPLING table still holds (SECTION 10).
  5. Remember: a green auditor is NECESSARY, not SUFFICIENT. Flag anything you
     could not playtest as still-provisional — because it is.
