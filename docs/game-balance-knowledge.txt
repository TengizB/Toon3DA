--------------------------------------------------------------------------------
⚠️  READ THIS FIRST — THE CURRENT BALANCE IS NOT GOOD AND MUST BE REFINED  ⚠️
--------------------------------------------------------------------------------
The balance described in this document is the CURRENT state, not a target state.
It is far from perfect. Large parts of it have never been playtested — only
verified against a standalone arithmetic harness (BalanceReport) that checks the
numbers against their own formulas. Passing that harness proves the numbers are
INTERNALLY CONSISTENT with the contract; it does NOT prove the game feels good,
is fun, or is fair in practice. Treat every number here as PROVISIONAL.

This warning is repeated throughout the document, deliberately, at each system,
because each system has its own unresolved problems. Do not read any section as
"this is solved". Read every section as "this is where it stands today, and it
needs another pass." A consolidated list of the known problems is in SECTION 21.

Whenever you touch balance: change the numbers in the SINGLE SOURCE OF TRUTH
(util/BalanceConfig.java), re-run the auditor (SECTION 20), and assume the result
still needs human playtesting before it can be called "good".

ADDING CONTENT (an enemy, weapon, ability, perk, item, ammo type, status, hazard, room that places supply or
spawns, generator, node type, event, shop offer, region, or a new BalanceConfig number) follows THE CONTENT
BALANCE CONTRACT — docs/game-balance-authority.txt SECTION 5 "ADD CONTENT" (balance-overhaul order 8). The build
enforces it: RuleKind.ADMISSION's eighteen C-rules fail `./gradlew test` on any undeclared or unpriced item.


================================================================================
SECTION 0 — THE TURN-BASED FOUNDATION (why the math is exact)
================================================================================
The game is strictly turn-based (Doom-RPG style). One player action = exactly
one world turn; every enemy acts once per player turn. Therefore TIME is measured
in TURNS, never seconds. There is no real-time DPS — only DAMAGE-PER-TURN (DPT).
This makes the entire balance model exact arithmetic instead of physics.

Consequences that everything below depends on:
  - Movement/rotation animation DURATION (seconds) does NOT change combat math —
    it only changes game feel and how fast the player can physically issue turns.
    (util/BalanceConfig.PLAYER_MOVE_DURATION / PLAYER_ROTATE_DURATION.)
  - "How long does X take" is always a turn count you can compute, never timing.
  - Ranged enemies may only attack the player on a shared cardinal line (same tile
    column OR same tile row) — never diagonally. Enforced by isSameCardinalLine()
    in enemy/EnemyManager.java. This is a HARD design rule, not a tuning number,
    but it shapes every ranged threat's real-world DPT.

Docs: docs/tick-system.txt, docs/doom-rpg-reference.txt, docs/game-balance-authority.txt.

⚠️ Not-good note: because everything is turn-exact, a single mis-set constant
propagates cleanly through the whole model — which is why so many sections below
are "in band on paper" yet still unproven in play.

================================================================================
SECTION 2 — THE FOUR PRIMITIVES + DERIVED SCORES (the core math)
================================================================================
All in util/GameMath.java. Everything else is derived from these four.

1. eHP — EFFECTIVE HIT POINTS            GameMath.effectiveHitPoints(...)
     eHP = (rawHP + armor) * 1/(1 - dodge) * H/max(1, H - R)
       H = average incoming hit, R = flat reduction.
     - Dodge multiplies survivability by 1/(1 - dodge) (a dodged hit deals 0).
     - Flat reduction: each landed hit of size H only removes (H - R).
     Canonical start (130 HP, 75 armour, 0 dodge, 0 R) -> 205 eHP (the reference).
     RULE: enemies currently have NO dodge/reduction, so NEUTRAL enemy eHP == raw HP
     (EnemyType.neutralEffectiveHitPoints). Balance-overhaul order 3 (CP2) added the PRICED
     eHP (EnemyType.effectiveHitPoints) = neutral eHP / (1 + w x (m_BALLISTIC,trait - 1)),
     w = BalanceConfig.MATCHUP_TP_REFERENCE_WEIGHT — TP, XP and the encounter budget read the
     priced value; the R8 hit bands and R-LADDER read the neutral one. w ships at 0 (a DECISION
     of order 3 CP7 — w 0.25 / 0.5 put S-SUPPLY at 0.83 / 0.81), so priced == neutral today.

2. DPT — DAMAGE PER TURN
     BURST DPT   = damage of one fire action (one turn).
     SUSTAINED   = (clipSize * damagePerShot) / (clipSize + reloadTicks)
                                             GameMath.sustainedDamagePerTurn(...)
   2b. AMMO EFFICIENCY = damagePerShot / ammoPerShot   GameMath.ammoEfficiency(...)
     Run-budget = ammoEfficiency * (total ammo the economy supplies). This is the
     bridge to the scarcity model — governed by SUPPLY, not the reserve cap.

3. TTK — TURNS TO KILL                    GameMath.turnsToKill(...)
     turnsToKill = ceil(target.eHP / attacker.effectiveDPT)
     Feed ENEMY DPT + PLAYER eHP to get the player's Turns-To-Die (TTD).

4. TP — THREAT POINTS (one danger number per enemy)  GameMath.threatPoints(...)
     enemyDPT      = attackDamage / max(1, attackCadenceTurns)
     survivalTurns = enemy.eHP / REFERENCE_PLAYER_DPT   (= 25)
     TP            = enemyDPT * survivalTurns * positionalMultiplier
     positionalMultiplier (DESIGNER classification, BalanceConfig.POSITIONAL_MULT_*):
       1.00 melee | 1.15 fast-melee | 1.30 ranged | +0.25 if it applies DOT/stun/slow.
     TP is the currency the floor encounter budget spends.

DERIVED SCORES:
  R-ROLE scenario turns-to-clear              GameMath.roleScenarioClear(...)
    (balance-overhaul order 3 — replaced weaponPowerScore = sustDPT * sqrt(ammoEff/40),
     deleted with R-WEAPON; see SECTION 4)
  goldenRatio      = turnsToDie / turnsToKill          GameMath.goldenRatio(...)
  depthThreatScale = healthScale^(d-1) * damageScale^(d-1)
                                             GameMath.depthThreatScale(...)

REFERENCE ANCHORS (BalanceConfig SECTION 9):
  REFERENCE_PLAYER_DPT      = 25   (the DEPTH-1 anchor of GameMath.expectedPlayerAtDepth; TP yardstick)
  REFERENCE_PLAYER_EHP      = 205  (the canonical start eHP; one difficulty)
  REFERENCE_AMMO_EFFICIENCY = 40   (weapon power-score normaliser)

⚠️ Not-good note: the whole model treats the shotgun's 25 sustained DPT as "the
player", ignoring found weapons, abilities, crits, and stat growth. Real player
DPT swings far above this. The anchors are a convenient fiction, not a measured
average — a known source of drift between "in band" and "actually balanced".

SECTION 3 — PLAYER SURVIVABILITY (the denominator of all difficulty)
================================================================================
File: BalanceConfig SECTION 1, plus the stat system in SECTION 7.

Base pools:
  PLAYER_MAX_HEALTH      = 130   (biggest single forgiveness dial; range 80–200)
  PLAYER_MAX_ARMOR       = 75    (armour soaks part of every hit)
  ARMOUR_ABSORB_FRACTION = 0.67  (fraction of each hit taken from armour, not HP; was 0.50 until
                                  balance-overhaul order 4 CP3, H8). A HEAVY hit also SHREDS armour:
                                  the pool loses absorbed x ARMOUR_HEAVY_SHRED_MULTIPLIER 1.5 (capped at
                                  what is left; HP damage unaffected). STATUS SHIELD (H9): while armour > 0
                                  an ENEMY's WEAK / SLOWED / BLINDED / POISONED application is blocked and
                                  costs ARMOUR_STATUS_COST_FRACTION 0.10 x max armour (min 1); armour 0 ->
                                  applied; hazard tiles are NOT blocked. "ARMOUR HELD" floater.

VITALITY GROWTH (balance-overhaul order 1, R9): max HP AND max armour grow per
CHARACTER level — PLAYER_MAX_HEALTH * PLAYER_VITALITY_GROWTH^(level-1) (1.09), armour
likewise; card/stat bonuses stay FLAT on top. World.applyVitalityGrowth runs at every
level-up (PlayerStats.vitalityGrowthDelta). Level 10: 283 HP + 163 armour before cards.

Heals (HP/armour is a RESOURCE — see SECTION 12) are FRACTIONS OF MAX (R10), resolved
at the moment of use (GameMath.fractionOfMaximum), so a heal means the same at every
character level:
  stim '+'  0.18 max HP     field medkit 'H'  0.45 max HP
  shard 'a' 0.15 max armour security vest 'A' 0.60 max armour
  (Replaced the flat 32 / 90 / 14 / 62. R-HEAL now bands the FRACTION: small pickups
   [0.10, 0.25], large [0.40, 0.70].)

The five-step DAMAGE-MITIGATION PIPELINE (single source of truth; every actor
resolves damage in EXACTLY this order — GameMath, docs/game-balance-authority.txt):
  1. Directional/Guard modifier (player only): D' = D * facingMultiplier
  2. Power/positioning modifiers (if present): D'' = D' * weak*vulnerable*backstab
     (EXPOSED is not a multiplier — it sets ignoreBlock for step 3, one hit.)
  3. BLOCK absorption: absorbed = min(block, D''); D''' = D'' - absorbed
  4. Flat armour reduction: D'''' = max(0, D''' - armorReduction)
  5. Subtract from HP.
  BLOCK sits ABOVE armour ("I braced this turn"); overkill into Block is LOST.
  STATUS DoT (burn/poison/bleed) BYPASSES Block — direct HP loss.

HEAVIES (balance-overhaul order 4, CP1; BalanceConfig SECTION 23; enemy/HeavyAttack):
  A heavy = a committed-then-resolved attack: Shell Brute CHARGE, Rimeshell LANCE,
  AREA_STRIKE, Plague Hulk SELF_DESTRUCT. Damage = fraction x on-curve player max HP at the
  enemy's spawn depth x HEAVY_DAMAGE_SCALE (1.0): CHARGE/LANCE 0.50 (HEAVY_DAMAGE_FRACTION),
  AREA_STRIKE 0.45, SELF_DESTRUCT 0.55; R-HEAVY band 0.40-0.60; guarded (x GUARD_FRONT_HEAVY
  0.20, wired in CP3 — plus the RIPOSTE below) <= 0.12. At depth 1 (130 max HP): 65 / 59 / 72. DELETED constants:
  SHELL_BRUTE_CHARGE_DAMAGE_MULTIPLIER (2.4), SHELL_BRUTE_CHARGE_STOP_SHORT_CHANCE (0.75 — a
  reached charge always lands), PLAGUE_HULK_SELF_DESTRUCT_BLAST_DAMAGE_MULTIPLIER (3.0) and
  _MAX (68), EnemyConstants.AREA_STRIKE_DAMAGE_MULTIPLIER (1.35) and their shims. Boss
  telegraphed verbs may reach 50% eHP (R-BOSS-VERB-CAP override). See
  docs/game-balance-authority.txt R-HEAVY.

PLAYER GUARD (directional, conditional eHP) — BalanceConfig SECTION 2 / GUARD_*:
  Tapping GUARD ends the turn and braces the marine.
  GUARD_FRONT_MULTIPLIER (0.35) is DELETED (order 4 CP3, H7); the ±60° facing arc is now
  GUARD_FRONT_ORDINARY 0.50 (ordinary hits) / GUARD_FRONT_HEAVY 0.20 (heavy hits).
  RIPOSTE: a HEAVY hit that lands in the guarded front arc STUNS its attacker for its next turn
  (skipNextAction — bypasses resist; the intent reads STUNNED at once) and leaves it VULNERABLE for
  VULNERABLE_DURATION turns (+50% damage). No riposte vs bosses; none from a self-destruct (the source dies).
  GUARD has no cooldown.
  GUARD_SIDE/BACK_MULTIPLIER = 1.0 (flanks land at FULL damage — read & rotate)
  GUARD_FRONT/BACK_HALF_ANGLE_DEGREES = 60
  Priced as a 1-turn opportunity cost; self-limiting vs flanks, so no hard cap.
  HOW A READER ANSWERS A HEAVY (balance-overhaul order 4, CP7b — measured by the sim's TACTICAL policy and
  banded by S-HEAVY): every committed heavy marks its danger tiles in red; from a marked tile ONE action
  answers it — a close spread blast STAGGERS it (cancelled, H5), GUARD facing it cuts the hit to <= 12% max HP and
  ripostes it, or a step/strafe to an unmarked neighbour avoids it (H4). Played: TACTICAL answers 0.99 of the 1114
  heavies committed at it (NAIVE 0.18). Consequence recorded in the authority doc SECTION 8: a reading player no
  longer pays the half-pool hits, so S-SUPPLY's COMBAT exit health rose to 0.85 (band 0.55-0.80, OPEN).

STAT-DRIVEN survivability (attribute system, SECTION 7 below):
  TOUGHNESS -> +HP (TGH_HP_PER_POINT=5) and flat reduction (TGH_REDUCTION_PER_POINT=1).
  AGILITY   -> dodge (AGI_DODGE_PER_POINT=0.02, DODGE_CAP=0.35) + faster actions.

[RESOLVED by order 8] 205 reference eHP used to be "the normal mode's start only",
with the other three modes anchored to it by accident. The mode system is deleted:
there is exactly ONE difficulty, so 205 eHP is THE player anchor and every band and
telegraph cap derived from it protects the real player pool in every run (SECTION 17).

SECTION 10 — DEPTH SCALING & THE COUPLING INVARIANT (the master curve)
================================================================================
File: BalanceConfig SECTION 3 + SECTION 9 invariant; GameMath depth methods.

THE POWER LADDER (balance-overhaul order 1; BalanceConfig SECTION 20). Every floor has
a THREAT LEVEL = its depth (1..RUN_FINAL_DEPTH 25). Both sides climb FITTED compound curves:
  Enemy HP:     baseHP  * ENEMY_HEALTH_GROWTH ^ (d-1)   1.139  (d25 ~ 23x)
  Enemy damage: baseDmg * ENEMY_DAMAGE_GROWTH ^ (d-1)   1.097  (d25 ~ 9.2x)
  Weapon:       base * 1.08^(L-1) * rarity * levelGap(L - d)   (SECTION 4)
  Player pool:  max HP/armour * 1.09^(characterLevel-1) + flat cards (SECTION 3)
  enemyThreatAtDepth = baseTP * depthThreatScale(1.139, 1.097, d) (budget + XP ride it)
Credits scale LINEARLY: base * (1 + (depth-1)*CREDIT_DEPTH_SCALE), scale = 0.12.

THE ONE EXPECTED PLAYER: GameMath.expectedPlayerAtDepth(d) -> util/ExpectedPlayer —
weapon level d, the region's expected rarity (mean of the WEAPON_DROP_TIER band ends),
character level d, offence cards 0.5 x 12 PP/level as a %-lift, defence 0.25 x 12 PP/level
as flat eHP. Depth-1 DPT = REFERENCE_PLAYER_DPT 25, depth-1 eHP = REFERENCE_PLAYER_EHP 205.
The audit (R-LADDER), the boss derivation (BossBalance), scarcity supply growth
(expectedHitGrowthAtDepth), heal drain, card breakpoints and the sim all read it.

R-LADDER (replaces the retired depth-coupling invariant R-DEPTH and the gear gate
R-GEARGATE) — checked at every depth 1..25 for every role's reference archetype:
  L1 on-curve TTK/TTD within +/-15% of depth 1 (measured: TTK +/-13%, TTD +/-7%)
  L2 weapon d-2 -> TTK >= 1.5x (1.73), d-4 -> >= 2.5x (3.01), start weapon d>=5 -> >= 3x
  L3 weapon d+2 -> TTK >= 0.75x (0.78)   L4 level d vs d-1 on floor d: >= +25% (+32%)
  L5 each rarity step >= +8%, LEGENDARY >= +40%   L6 character d-3 -> TTD <= 0.80x
BalanceReport's LADDER table prints the TTK/TTD grid; the balance-sim LADDER REPORT
measures the same thing in PLAY (one-floor probes at every depth).

Depth generosity bumps (BalanceConfig SECTION 3): at full depth, extra enemies
(LEVEL_GEN_DEPTH_ENEMY_BONUS_MAX=2), heavy-upgrade chance 0.60, +medkit 0.15,
+ammo 0.20, extra-ammo 0.50.

⚠️ Not-good note (pre-ladder, kept for history — the ladder model now carries weapon
level, rarity and cards; abilities are still outside it): the invariant is defended by a MODELLED linear player curve that
ignores found loot and abilities (which only help the player), so the real ratio

SECTION 14 — TELEGRAPH & FAIRNESS CONTRACT
================================================================================
File: BalanceConfig SECTION 13; IntentConstants; enemy intent system.
RULE: every attack that can deal > TELEGRAPH_MAX_UNTELEGRAPHED_HIT_FRACTION (0.25)
of reference eHP (~51 of 205) in ONE hit MUST be telegraphed or avoidable. Burst
damage without warning is banned — a death must feel like "I made a mistake".
Because the intent system pre-commits every direct attack one turn ahead, this rule
is satisfied by construction for all committed attacks. Remaining un-telegraphed
damage is only DoT ticks and environmental hazards.
Boss verbs (R-BOSS-VERB-CAP, overridden by balance-overhaul order 4): un-telegraphed <= 25% eHP, TELEGRAPHED

R-HEAVY EXTENDS THE CONTRACT (order 4): the exception to "keep hits small" is a telegraphed HEAVY — it MUST be
40-60% of the on-curve max HP (HEAVY_DAMAGE_FRACTION_MIN/MAX), committed >= 1 full player turn ahead, with its exact
DANGER TILES shown (red floor markers, mini-map fill, 1.5x "!!" intent, off-screen edge pulse), AVOIDABLE from every
danger tile (H4: a walkable non-danger neighbour exists, else GUARD cuts it to <= HEAVY_GUARDED_MAX_FRACTION 0.12),
and CANCELLED by a stagger (H5). The 25% cap still binds every ordinary, un-telegraphed hit. The sim's S-HEAVY
band proves in play that a player who reads the floor answers them (authority doc SECTION 3 / SECTION 8).

⚠️ Not-good note: the contract is satisfied "by construction" only for attacks that
go through the intent-commit system. Any new attack path that bypasses it (a new
special, a scripted boss verb, a hazard burst) can silently violate the cap. The
BalanceReport TELEGRAPH AUDIT only checks the attacks it knows about. (A new HEAVY must also be a HeavyAttack
constant, which R-HEAVY iterates, and report its danger tiles — otherwise nothing marks it red.)

       - new perk    -> automatic (Perk.values() is iterated by R-PERK / R-CARRY)
       - new boss    -> the six-rule checklist (SECTION 9)
  3. Run `./gradlew test` — BalanceAuditTest fails the build on any unwaived
     out-of-band value, live test flag, or unpriced content. A deliberate
     exception needs a WAIVER in BalanceSchema, never a band hack.
  4. Re-run BalanceReport and paste its tables over docs/game-balance-authority.txt
     SECTION 6; verify the DEPTH COUPLING table still holds (SECTION 10).
  5. Remember: a green auditor is NECESSARY, not SUFFICIENT. Flag anything you
     could not playtest as still-provisional — because it is.
