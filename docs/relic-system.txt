RELIC SYSTEM — rare run-changing artifacts, priced in balance
==============================================================
Single source of truth for the relic layer. Update this doc in the same commit as any change to
`…toon3d.relic`, BalanceConfig SECTION 26, the relic rules in `util/BalanceSchema`, `util/RelicValuationModel`,
the relic `PerkModifier` kinds, the RELIC_OFFER phase in `world/World`, or the S-RELIC band in `sim/`.

Design document: `.claude/agents/ideas/relics-run-changing-artifacts.txt` (single file, ten checkpoints; its
IMPLEMENTATION NOTE lists where the shipped state differs from the designed catalog table — THIS doc is the
shipped state). Supersedes the rejected `roguelike_order_14_artifacts_and_special_relics.txt`.
Related: docs/game-balance-authority.txt (R-RELIC*, S-RELIC), docs/game-balance-knowledge.txt (SECTION 6B),
docs/route-map-system.txt (RELIC_CACHE, quarantine_locker), docs/xp-level-progression.txt (relics vs perks),
docs/sound-system.txt (RELIC_BONDED).


1. WHAT THIS IS
===============
A RELIC is a rare, named artifact that changes one rule for the rest of the run: kills heal you, doors you
open explode, the first hit on each floor does nothing, enemies arrive weaker. There are 36 of them in four
tiers — 10 COMMON, 11 RARE, 9 LEGENDARY, 6 CURSED. A run collects about five: one chosen at the start, one
after each of the first four bosses, and the odd one from a MYSTERY sector or a quarantine-locker EVENT. Each
is offered as a "choose one of N" card screen with a LEAVE IT plate, so two runs never play the same way.

THE MODEL (three sentences that decide every design question):
  - RUN-SCOPED. A relic lives and dies with the run. Death clears the hand; nothing is persisted (no discovery
    log, no StatsStore or StoryStore key, no schema bump). Held relics are never dropped, swapped or sold.
  - RULE-CHANGING, NOT STAT-STICKING. A relic is one to three `PerkEffect` rows (PerkModifier kind +
    magnitude) — the SAME vocabulary perks and keystones use. It is not a parallel effect system.
  - FOLDED INTO THE ONE BUILD SEAM. `PlayerBuild.recompute()` applies perks, then each relic's effect set at
    rank 1, then keystones, into the single `BuildStats` aggregate every damage, heal, kill, spawn and shop
    seam already reads — in World and SimWorld alike. That is why a relic is live everywhere with almost no
    new wiring, and why the balance valuation prices it with the machinery that prices a perk build.

Taking a relic costs NO turn: an offer is a hard-pause overlay, like the level-up screen. Every action is still
exactly one turn; triggered effects resolve inside turns the world already resolves (the kill, the door open,
the floor arrival, the damage entry) — nothing runs per frame.

The standing balance rule is R-RELIC-STACK: the relics a run is expected to hold must never out-carry one
committed perk build. See section 8.


2. THE PACKAGE
==============
`ge.tbegvadze.toon3d.relic` — headless (no LibGDX import anywhere in it). Dependencies point one way:
route -> relic -> progression/util. `relic` never imports `route`: the boss index and depth are passed in
(this is why `EventEffect` can carry a `RelicSource`). `util/RelicValuationModel` imports `relic`, the same
util <-> content pattern `BuildValuationModel` already has with `progression`.

  RelicRarity.java       enum COMMON / RARE / LEGENDARY / CURSED. Per-constant data: label, isCursed(),
                         glowPulses() (LEGENDARY — presentation only). Nothing switches on a rarity.
  RelicTrigger.java      enum ALWAYS / ON_KILL / ON_DOOR_OPEN / ON_FLOOR_ARRIVAL / ON_HIT_TAKEN /
                         ON_LOW_HEALTH / ON_LETHAL_HIT / ON_ENEMY_SPAWN; badgeLabel() is the card chip
                         ("ALWAYS", "ON KILL", "ON DOOR", "ON ARRIVAL", "ON HIT", "LOW HP", "LETHAL HIT",
                         "ON SPAWN"). A UI badge ONLY — the runtime is wired per PerkModifier kind.
  RelicValuation.java    enum CARRY / SUPPLY — which metric the rarity band reads (section 8).
  RelicSource.java       enum RUN_START / BOSS / MYSTERY_CACHE / QUARANTINE_LOCKER. Per-constant data: cardCount(),
                         allowedRarities(), rarityWeightsFor(bossIndex) (aligned with allowedRarities; the
                         row index is clamped), guaranteesRareOrBetter(). Counts and weights read BalanceConfig.
  RelicDefinition.java   immutable row + Builder: id (lower_snake), name (UPPER), rarity, trigger, valuation,
                         optional affinity (BuildTag), 1..N PerkEffects, effectText, costText (required iff
                         CURSED, forbidden otherwise). build() throws IllegalStateException on a missing field.
  RelicRegistry.java     register (rejects a duplicate id) / get / all / allOfRarity / size; registration order.
  RelicCatalog.java      THE CONTENT FILE: 36 `register()` calls (section 4). `RelicCatalog.registry()` is the
                         shared, lazily populated singleton (the RouteRegistries idiom) World, SimWorld, the
                         audit and the report all read.
  RelicText.java         `percent(float)` — the Perk.percent idiom; card text is BUILT from BalanceConfig so the
                         text can never drift from the numbers.
  RelicHand.java         the run's held relics: fixed array of RELIC_MAX_HELD (8), add(definition, playerBuild)
                         (false if held or full; otherwise calls playerBuild.addRelicEffects), holds, get,
                         count, clear. Allocation-free after construction.
  RelicOffer.java        mutable, pre-allocated roller output: source, depth, cards[RELIC_OFFER_MAX_CARDS], count.
  RelicOfferRoller.java  static `roll(source, depth, bossIndex, hand, stats, carriedOrRankedTags, seed, out,
                         registry)` and `seedFor(runSeed, depth, source)`; also `isEligible` (R5). Section 6.
  RelicRuntime.java      the per-run trigger runner, ONE class owned by World and SimWorld (never mirrored
                         code); implements `door/DoorOpenedListener`. beginFloor(...) and
                         onDoorOpenedByPlayer(col,row). Holds no relic ids: it reads the build live.
  RelicFeedbackListener  `onRelicTriggered(String text, boolean positive)`; World routes it to EventTextSystem,
                         the sim leaves it null.

Elsewhere (the pieces a relic touches):
  progression/PerkModifier   17 NEW kinds, each owning its apply body (section 3).
  progression/BuildStats     the new fields (identity defaults, reset in reset(), copied in copyFrom()), the

  render/RelicOfferOverlayRenderer, render/BuildPagePanel (RELICS section), render/InstanceReportRenderer

  util/RelicValuationModel   the relic pricing (section 8).  util/BalanceConfig SECTION 26.  util/GameMath

  route/EventEffect.relicOffer, route/MysteryOutcome.RELIC_CACHE, route/FacilityEvents quarantine_locker,

3. THE PERK-MODIFIER KINDS AND THE STACKING ORDER
=================================================
Seventeen new `PerkModifier` constants (no 18th: ALL_WEAPON_DAMAGE_COST already existed). Gain kinds ADD, cost
kinds and multiplier kinds MULTIPLY, boolean kinds OR — the unchanged PerkModifier stacking rule. Accessors on
BuildStats are the ONLY way a runtime seam reads them; every accessor of a relic-free build is byte-identical to
before (acceptance A11; the BalanceReport BUILDS table is unchanged).

  kind                      accessor / semantics
  ------------------------  ------------------------------------------------------------------------------
  ALL_WEAPON_DAMAGE         adds to the damage bonus of EVERY damage class (classDamageBonus)
  KILL_HEAL                 killHealFraction(): max-HP fraction healed on a credited kill (applyHealing — NOT a
                            treatment, so Field Medic / MEDIC'S GLOVE do not double-dip; the melee-kill-heal precedent)
  KILL_ARMOR                killArmorFraction(): max-armour fraction restored on a credited kill
  KILL_CREDIT_BONUS         killCreditMultiplier() = 1 + sum
  KILL_AMMO_REFUND          killAmmoRefundChance(): chance (min 1 round) to refund a round to the active weapon
  XP_MULTIPLIER             experienceMultiplier() = 1 + sum
  DOOR_BLAST                doorBlastFraction(): centre blast, in units of the reference soldier's HP
  DOOR_OPEN_HEAL            doorOpenHealFraction()
  CORPSE_BLAST              corpseBlastFraction(): the four neighbours of a killed enemy
  FLOOR_ARRIVAL_HEAL/_ARMOR/_AMMO   floorArrival{Heal,Armor,Ammo}Fraction(), applied by RelicRuntime.beginFloor
  FIRST_HIT_SHIELD          firstHitShield() — boolean
  LOW_HEALTH_DAMAGE         lowHealthDamageBonus(): every damage class below BUILD_BERSERK_LOW_HEALTH_FRACTION
  DAMAGE_TAKEN_MULTIPLIER   damageTakenMultiplier(), CLAMPED to >= RELIC_DAMAGE_TAKEN_MULTIPLIER_MIN (0.50)
  ENEMY_HEALTH_MULTIPLIER   enemyHealthMultiplier(), CLAMPED to >= RELIC_ENEMY_HEALTH_MULTIPLIER_MIN (0.50)
  CLIP_SIZE_MULTIPLIER      multiplies the existing clipSizeCostMultiplier (read by clipSizeMultiplier())

STACKING ORDER (PlayerBuild.recompute): reset -> PERKS at their ranks -> RELICS at rank 1 (each held
relic's effect set, in bond order) -> KEYSTONES. Relics therefore sit between perks and keystones: a keystone's
cost multiplier lands on top of the relic's gain, and a relic can never be modified by a rank. Because a relic
is a fixed-magnitude effect, the same relic is priced identically whatever else the player holds (the valuation
reads `BuildStats.ofEffects(...)` — the relic alone).

Magnitude conventions (BalanceConfig SECTION 26, `RELIC_<RELIC_ID>_<KIND>`): gain kinds are the fraction
itself (0.13 = +13%); DAMAGE_TAKEN / ENEMY_HEALTH multipliers and every `*_COST` kind are the MULTIPLIER
(0.92 = take 8% less; 1.15 on a cost-bearing relic = 15% more). Integer kinds are `int`. Boolean kinds carry no
constant — the catalog uses the keystone idiom `PerkEffect.of(kind, 1f)`.

bone_saw (BLADE), counterweight (BULWARK), asbestos_lining (PYRO). Every rarity keeps >= 3 non-affine relics
so an offer always fills (R-RELIC-SOURCE).

5. THE RUNTIME SEAMS
====================
Every seam is shared by World and SimWorld; every one is a read of a BuildStats accessor, so with no relic held
every term is zero or the identity and the game plays exactly as before.

  entity/Player
    - Shield (R11): at the top of the private `applyDamage(int, boolean heavy)` — the path public applyDamage,
      applyDirectionalDamage and applyOwnExplosionDamage all reach — if `firstHitShield()` and not spent this
      floor, the hit deals 0 and the shield is spent (`firstHitShieldEventPending`, polled through
      `consumeFirstHitShieldEvent()` for feedback). STATUS TICKS NEVER SPEND IT: they enter through
      `applyDoTDamage(int)`, a separate path ending in loseHealth.
      The player's OWN explosion (applyOwnExplosionDamage) is a hit and DOES spend it.
    - Damage multiplier (R12): `damage = max(1, round(damage x damageTakenMultiplier()))`, then the existing guard /
      armour / toughness pipeline unchanged. SECOND WIND (perk or relic) still has the last word.
    - `applyEventCostDamage(int)` (hub decision, CP2): route-event costs (a lost gamble bite, a health toll)
      BYPASS the shield and the multiplier — R11 is enemy attacks, heavies and explosions only.
    - `resetFloorBuildState()` re-arms the shield.
  enemy/EnemyManager
    - Kill terms (`applyRelicKillTerms(enemy, allowCorpseBurst)`): KILL_HEAL (applyHealing), KILL_ARMOR
      (applyArmor), KILL_AMMO_REFUND (rolled on `buildRandom` ONLY when the chance is positive, so a relic-free
      build draws nothing and every seeded stream is unchanged) and CORPSE_BLAST. They run for EVERY XP-awarding
      player kill: weapon kills (the BLOODLETTING path), burn/poison kills (`processDoTKill`), guard-reflect
      kills (`reflectIntoAttacker`, never bursts mid enemy turn) and relic-blast kills (never burst).
    - XP and credits: `depthScaledXpReward` x experienceMultiplier(), `depthScaledCreditReward` x
      killCreditMultiplier(), at every kill site, before KillXpListener / KillEventListener / KillCreditListener.
    - Spawn HP (R13): non-BOSS max and current HP x enemyHealthMultiplier(), applied to the floor's initial
      enemies in `setBuildStats` (the constructor builds them before the build is wired) and to every mid-floor
      spawn in `spawnEnemyInternal`. Bosses are never scaled (their HP is derived by BossBalance). Only enemies
      spawned after the relic is bonded change.
    - Low-health damage: the BERSERKER read (`isPlayerBelowBerserkThreshold`) is widened to every damage class
      for LOW_HEALTH_DAMAGE; BERSERKER's own melee term is untouched.
    - Corpse burst (R8): a dead enemy's four orthogonal neighbours each take `corpseBlastFraction` x 1.0 (centre
      empty) through `RelicBlastTarget`. A kill caused by ANY relic blast earns XP, credits and the other relic
      kill terms but NEVER bursts again (`resolvingCorpseBurst`, `activationRelicBlast` — no chains).
      `setRelicBlastTarget` is wired per floor.
  hazard/RelicBlastTarget  `detonateRelicBlast(tileColumn, tileRow, centreFraction, ringFraction, visualScale)`
    (5 arguments — the idea's 4 plus the visual scale), implemented by ExplosiveBarrelManager. R9: ENEMIES ONLY —
    never the player, never a barrel chain; damage is `GameMath.relicBlastDamage(fraction, referenceSoldierMaxHealth)`
    EXPLOSIVE through the matchup with the hazard-blast flag set (no weapon build terms, no Sapper multiplier);
    the 1.0 unit is the reference soldier's HP at the floor's depth. Visual: `impactEventListener.onEnemyKilled`
    at the centre, scale RELIC_BLAST_VISUAL_SCALE_DOOR 0.65 / _CORPSE 0.45 (EffectConstants).
  door/DoorOpenedListener  `onDoorOpenedByPlayer(tileColumn, tileRow)`, fired by `DoorManager.requestOpen` on
    CLOSED -> OPENING. PlayerController is the only caller of requestOpen, so every such open is the player's.
    Opening a door is turn-less (INTERACTING -> finishAction(false)); the blast resolves inside requestOpen,
    BEFORE any enemy acts.
  relic/RelicRuntime
    - beginFloor(level, player, inventory, blastTarget): called right after every `player.resetFloorBuildState()`
      (World `buildLevelDependentResources`; SimWorld `buildFloor`). Resets the per-floor door-trigger grid
      (allocated HERE, sized to the level, never in render), then applies FLOOR_ARRIVAL_HEAL / _ARMOR / _AMMO
      and reports each through the feedback listener. Arrival ammo refunds once per AMMO TYPE carried (R12), as a
      fraction of that type's reserve cap — two guns sharing BULLETS do not double the refill.
    - onDoorOpenedByPlayer: once per door TILE per floor (R10) — closes the open-close farm without a cooldown.
      Door blast centre = the tile beyond the door, opposite the player (door + signum(door - player)); if that
      is a wall the centre falls back to the door tile. Centre takes fraction x 1.0, the four neighbours
      fraction x RELIC_BLAST_RING_SHARE (0.60). Then DOOR_OPEN_HEAL. Tiles outside the level are skipped by the
      existing bounds check.
  World / SimWorld  One RelicHand and one RelicRuntime per run (a World is one run: both die with it). After a
    bond: `relicHand.add(def, playerBuild)` then the existing `applyBuildEffects()` (which already pushes
    max-HP / armour deltas and the extra loadout slot).
  Feedback strings (HudConstants RELIC_FEEDBACK_* / RELIC_SHIELD_ABSORB_TEXT) are GENERIC — "+N HP - RELIC",
  "SHIELD - HIT ABSORBED" — not per-relic names (the idea's "ABLATIVE SHELL - HIT ABSORBED" would need the
  runtime to know ids). The default font lacks U+2014 / U+2026, so every UI string uses " - " and "..".
  Kill heals show no text (the same as Bloodletting), to avoid spam.


6. SOURCES, OFFERS AND THE RELIC_OFFER PHASE
============================================
  SOURCES (RelicSource)
    RUN_START          3 cards, COMMON only. Queued on the first PLAYING frame of depth 1 after the staging room
                       (`!isStartingRoom`), so tag affinity reads the weapon the player just chose.
    BOSS               3 cards, rarity rolled per card from RELIC_BOSS_OFFER_RARITY_WEIGHTS[bossIndex]
                       ({COMMON, RARE, LEGENDARY}); at least one card RARE-or-better (the last card is re-rolled
                       RARE, then LEGENDARY, else the offer shrinks); NEVER CURSED. bossIndex = the BossTable rows
                       strictly shallower than the depth (0..3). Offered for depths 5, 10, 15, 20 — NEVER 25
                       (the run's VICTORY). Queued in the poll beside the BOSS_DEFEATED bark, once per floor.
    MYSTERY_CACHE      2 cards from RELIC_MYSTERY_OFFER_RARITY_WEIGHTS {COMMON, RARE}. Queued by the mystery
                       payout (World.applyLadderEffect) when the player LEAVES a RELIC_CACHE sector; opens on the
                       next floor's first idle PLAYING frame.
    QUARANTINE_LOCKER  2 cards, CURSED only. Queued by the quarantine_locker EVENT's BREAK THE SEAL; opens as soon
                       as the event overlay closes.
    Every offer has a LEAVE IT plate. A curse is only ever met behind a seal the player chose to break.
  ROLLING (RelicOfferRoller, R4-R6)
    - Deterministic: seed = `seedFor(runSeed, depth, source)` = floorSeed(floorSeed(runSeed ^ RELIC_OFFER_SEED_SALT,
      depth), source.ordinal()). Same seed, same cards, in World and SimWorld alike.
    - Eligibility (R5): never already held; never an affinity relic unless the player carries a weapon of that tag
      or holds a perk rank in it; never a relic whose every effect is a boolean the build already has.
    - Fallback: if the rolled rarity has no eligible relic, the card falls back RARE, then COMMON, then LEGENDARY —
      only among the rarities the source allows (a RUN_START offer is COMMON only; a MYSTERY offer never turns
      LEGENDARY). CURSED neither stands in for anything nor has a stand-in: a locker offer with too few eligible
      CURSED relics shows fewer cards. With zero eligible relics the offer is skipped and logged.
    - At RELIC_MAX_HELD (8) offers are skipped with event text "RELIC CAPACITY REACHED". There is no slot cap to
      manage; about five relics are expected.
    - World queues REQUESTS (source, depth, bossIndex) and ROLLS when the offer opens, so the roll sees the build
      the player actually has by then. A relic already held, or a tag acquired in between, is therefore honoured.
  THE PENDING QUEUE (R7)
    At most RELIC_PENDING_OFFER_CAPACITY = 2 requests wait, first in first out; a full queue drops the newcomer
    (logged). A pending offer survives floor transitions and is dropped on death (a mutual kill with a boss: DEAD
    wins). An offer opens only in PLAYING, with the player IDLE, no pending level-up and no bark panel mid-fade
    (a bark HELD at full opacity never blocks: it has no timer). It opens after a pending level-up and before a
    pending story exchange.
  THE PHASE (R14, R15)
    `RunPhase.RELIC_OFFER` (private enum in World). Legal transitions: PLAYING -> RELIC_OFFER (pending offer,
    idle); RELIC_OFFER -> PLAYING (card tapped or LEAVE IT); RELIC_OFFER -> PAUSE_MENU -> RELIC_OFFER (the pause
    button works and returns to the SAME offer through `pauseReturnPhase`). Nothing else enters or leaves it, and
    death cannot happen in it (the world is frozen). It is a hard-pause overlay: barks queue, no exchange opens,
    the thumb clusters are not drawn, and event text is not drawn (a previous bond's line would sit on the cards).
    Taps are ignored for HudConstants.RELIC_OFFER_INPUT_LOCKOUT_SECONDS = 0.4 s after it opens — and again after
    an app pause/resume or a return from the pause menu — so a thumb mashing FIRE cannot pick a card blind.
    Tapping a card: `chooseRelicOfferCard(index)` bonds it (hand + applyBuildEffects + `RunStats.recordRelicBonded`
    + `Gdx.app.log("Relic", ...)`), event text "RELIC BONDED - <NAME>", and RELIC_BONDED plays through
    `gameAudio.playMenu`. LEAVE IT bonds nothing. Both close the overlay and resume play on the same turn.
    Public API on World: getRelicHand(), getActiveRelicOffer(), chooseRelicOfferCard(int), leaveRelicOffer(),
    getRelicOfferOpenSeconds().
  ROUTE CONTENT (docs/route-map-system.txt has the full rows)
    MysteryOutcome.RELIC_CACHE — weight MYSTERY_WEIGHT_RELIC_CACHE = 3 (BalanceConfig; mirrored in
    RouteMapConstants), ScanTone.REWARD_RICH, delegates to the SUPPLY CACHE profile, reward =
    `EventEffect.relicOffer(MYSTERY_CACHE)`. FacilityEvents "quarantine_locker" — BREAK THE SEAL ->
    relicOffer(QUARANTINE_LOCKER); SELL THE SEAL -> credits(EVENT_CREDIT_FLOORS_LARGE), the same payout as
    distress_beacon's IGNORE (so R-EVENT-VALUE is met by the sell choice alone). `RouteEconomicsModel
    .ladderRewardPrice` adds progress PP = `RelicValuationModel.offerPowerPoints(source, depth)` for a relic
    offer, and RouteEconomics carries a NodeEconomics row for RELIC_CACHE.

8. BALANCE — HOW A RELIC IS PRICED AND CAPPED
=============================================
Relics are balance-bearing: BalanceConfig SECTION 26, four schema rule kinds, balance-bearing `GameMath`
formulas, `BuildValuationModel` / `RelicValuationModel`, and `sim/`. THE CHANGE PROTOCOL (authority SECTION 7)
applies in full: green `./gradlew test`, green `./gradlew balanceSim`, regenerated SECTIONS 6 and 8, one
CHANGELOG line. The rules live in docs/game-balance-authority.txt SECTION 3 (R-RELIC, R-RELIC-CURSE,
R-RELIC-STACK, R-RELIC-SOURCE, S-RELIC); this section is the model behind them.

THE PRICE OF A RELIC
  A relic's GAIN is measured exactly the way R-CARRY measures a build: the kill-speed lift x the survival lift,
  geometric means over the eight reference scenarios S1-S8, on a two-gun kit (the affinity tag's kit, else the best
  pair from every weapon; kit size = 2 + extraLoadoutSlots, so FOURTH HOLSTER's slot counts). The code path is
  `BuildValuationModel.carryOf(BuildStats, BuildTag kitTag|null, depth)` — extracted from `carry(BuildTag)`,
  which now calls it (the BUILDS table is byte-identical) — fed `BuildStats.ofEffects(relic.effects())`, i.e. the
  relic ALONE. `RelicValuationModel.carryLift(def, depth)` is that score; `gain(def, depth)` is carryLift for a
  CARRY relic and the SUPPLY_TOTAL ratio (with / without) for a SUPPLY relic.
  Why SUPPLY exists: economy relics (credits, ammo, drops, XP) add supply, which the carry conversion under-reads —
  the same reason SCAVENGER's R-CARRY row is waived. They are banded on the SUPPLY_TOTAL ratio instead.
  Scale: a perk rank is worth about x1.07-1.08 carry at depth 15 (the worst committed build, MARKSMAN, 1.751
  over its ranks + keystone: measured 1.0725 vs RELIC_PERK_RANK_EQUIVALENT_LIFT 1.08 +/- 0.03). So COMMON is about
  half a rank to one rank, RARE about one to one and a half, LEGENDARY about one and a half to two and a half,
  and CURSED nets about one rank AFTER its cost.

THE BANDS (BalanceConfig SECTION 26; reference depths RELIC_REFERENCE_DEPTHS = {5, 15, 25})
  rarity     CARRY band          SUPPLY band
  COMMON     [1.03, 1.08]        [1.06, 1.20]
  RARE       [1.06, 1.13]        [1.15, 1.35]
  LEGENDARY  [1.10, 1.22]        (none — no SUPPLY legendary)
  CURSED     [1.05, 1.18]        [1.20, 1.60]
  RELIC_CARRY_BAND_LEGENDARY's top is 1.22, widened from the designed 1.20 under the CP5 hub licence (a band
  new in this feature, <= 0.02): SECOND HEART's Second Wind flag alone prices 1.205 at depth 5.
  RELIC_CURSED_MIN_LOSS = 0.10 (a cursed relic's cost effects alone cost >= 10% somewhere).

THE FOUR AUDIT RULES (util/BalanceSchema; evaluated by BalanceAuditTest)
  R-RELIC          every non-CURSED relic's gain is in its rarity x valuation band at every reference depth.
                   The band FLOOR is the "felt" test: a relic whose kinds the valuation does not read prices at
                   1.00 and fails, so an unpriced effect kind cannot ship.
  R-RELIC-CURSE    every CURSED relic: gain in the CURSED band at every reference depth AND the loss of its COST
                   effects ALONE (PerkModifier.isCostAt, via RelicValuationModel.costLoss -> worstLoss with a null
                   niche = every probe counts) is >= RELIC_CURSED_MIN_LOSS at some reference depth. Measured on the
                   cost effects alone because worstLoss over the whole relic reported spurious losses for pure
                   gains (the Incinerator-S2 cell).
  R-RELIC-STACK    at every BossTable depth (5/10/15/20/25): expectedHandLift(d) <= the WORST non-waived R-CARRY tag
                   score ("a run's expected relics never out-carry one committed build"), AND bestHandLift(d) <=
                   the BEST non-waived R-CARRY score x (1 + BUILD_CARRY_TOLERANCE) ("even the luckiest hand stays
                   inside the build spread"). Both ceilings are read LIVE from buildCarryResults(); no new
                   number. bestHandLift is AFFINITY-CONSISTENT: the non-affine relics plus the affine relics of at
                   most ONE BuildTag (a two-gun build cannot use every tag-affine relic), best over every tag.
  R-RELIC-SOURCE   structural: every rarity has >= RELIC_OFFER_MAX_CARDS non-affine relics (an offer always fills);
                   each source's weight row sums to 1 (+/- 1e-4) and has one weight per allowed rarity; no
                   duplicate ids; every CURSED relic has a cost line AND at least one cost kind;
                   RELIC_PERK_RANK_EQUIVALENT_LIFT is within RELIC_PERK_RANK_EQUIVALENT_TOLERANCE of the measured
                   per-rank lift; nodeOfferRatePerFloor() > 0.
  COVERAGE gains a row per relic: it resolves its rarity, trigger, valuation and a band for that rarity x valuation.
  Existing rules that now read relics: R-ROUTE-PRICED (the RELIC_CACHE NodeEconomics row), R-MYSTERY-EV v2 and
  R-HONEST-SAFE (the new outcome), R-EVENT-VALUE (quarantine_locker). The BalanceReport prints a RELICS table (per
  relic: rarity, valuation, affinity, gain at d5/d15/d25, band, cursed cost, status) and a RELIC STACK table.

RELIC STACK, live (BalanceReport)  — expected hand / ceiling, best hand / ceiling
    d5   1.086 / 1.751   1.175 / 2.497      d20  1.479 / 1.751   1.933 / 2.497
    d10  1.191 / 1.751   1.392 / 2.497      d25  1.695 / 1.751   2.290 / 2.497
    d15  1.320 / 1.751   1.606 / 2.497
  (expected relics held: 1.03 / 2.07 / 3.11 / 4.15 / 5.19 at d5 / 10 / 15 / 20 / 25; node offers 0.00791 per
  floor.) THE SLACK AT d25 IS THIN: 1.695 vs 1.751, 3.2% (CP5 measured 1.719 / 1.8% at the placeholder cache weight
  before CP6 lowered it to 3). Raising any COMMON/RARE magnitude, or the cache weight, can break the d25 row. Retune
  a relic's own magnitude first.

THE HAND MODEL (RelicValuationModel; all assumptions stated, not hidden)
  expectedRelicCount(d) = RELIC_VALUATION_START_TAKE_SHARE (1.0) + BossTable rows strictly shallower than d +
  (d - 1) x nodeOfferRatePerFloor().   nodeOfferRatePerFloor() = (wMYSTERY / wNodes) x (wRELIC_CACHE / wMysteryPool)
  + (wEVENT / wNodes) x (wLocker / wEventPool) x RELIC_VALUATION_EVENT_TAKE_SHARE.
  expectedHandLift(d) multiplies each source's rarity-weighted MEAN lift raised to its expected count (an offer is
  worth its mean card, not its best — the player chooses, so this under-reads, which R-RELIC-STACK's best-hand
  ceiling then covers). bestHandLift(d) takes the round(expectedRelicCount) highest carry lifts reachable by that
  depth: LEGENDARY only through the bosses passed (at most one per boss), CURSED only through node offers.
  `offerPowerPoints(source, depth)` = `GameMath.relicPowerPoints(rarity-weighted mean carryLift of the source's
  pool)` — what the route economics add to a relic-offering node's progress price.

VALUATION ASSUMPTIONS (SECTION 26; printed by BalanceReport; the sim's RELIC REPORT prints played-vs-model)
  RELIC_VALUATION_KILL_SHARE         0.60  share of a floor's bodies a kill-triggered relic fires on
  RELIC_VALUATION_DOORS_PER_FLOOR    3     doors the player opens per floor
  RELIC_VALUATION_DOOR_FIGHT_SHARE   0.30  share of fights that open through a door the player just opened
  RELIC_VALUATION_CORPSE_ADJACENCY   0.50  share of a corpse burst that lands on remaining group members
  RELIC_VALUATION_EVENT_TAKE_SHARE   0.50  share of quarantine lockers broken open (vs sold)
  RELIC_VALUATION_START_TAKE_SHARE   1.0   every run holds the start relic
  RELIC_VALUATION_LOCKER_EVENT_WEIGHT 1    the locker's event weight until it is registered (it is; the model reads
                                           the registered weight and counts it once)
  PLAYED vs MODEL (sim, report-only): kills fired-on share 0.48 played vs 0.60 modelled; doors per floor 2.03 played
  vs 3 modelled — the model is generous to kill and door relics, which the thin stack slack absorbs.
  Model approximations to know: a boss offer belongs to boss index = BossTable rows strictly shallower than its
  depth; a hand AT a depth holds what was acquired strictly before it; every floor 1..d-1 is one weighted node pick
  (boss floors among them are a small over-count); lifts are evaluated at the depth asked, not the depth of
  acquisition.

HOW EACH KIND IS PRICED (BuildValuationModel terms, each a `GameMath` formula with its comment block)
  KILL_HEAL / KILL_ARMOR   floor sustain: bodiesPerFloor x KILL_SHARE x fraction (armour scaled by armourRatio x
                           maxArmorMultiplier) — the shape of melee-kill heal.
  DOOR_OPEN_HEAL           floor sustain: DOORS_PER_FLOOR x fraction.
  FLOOR_ARRIVAL_HEAL/_ARMOR floor sustain: + fraction, once per floor.
  FIRST_HIT_SHIELD         floor sustain: + one reference-soldier hit as a max-HP fraction; duel: the first hit absorbed.
  DAMAGE_TAKEN_MULTIPLIER  floorIncoming x m; duel damage x m; hits-to-die / m.   (relicIncomingMultiplier, relicDuelDamage)
  ENEMY_HEALTH_MULTIPLIER  scenario and duel target eHP x m; floorIncoming x m (fights shorten in proportion).
  LOW_HEALTH_DAMAGE        every scenario hit x (1 + m x BUILD_BLADE_LOW_HEALTH_TURN_SHARE) — BERSERKER's term, all classes.
  ALL_WEAPON_DAMAGE / CLIP_SIZE_MULTIPLIER   already read (classDamageBonus / buildClipActions).
  DOOR_BLAST               GameMath.relicDoorOpenerTurns: with probability DOOR_FIGHT_SHARE the fight opens with a
                           blast (centre on the lead target, ring on group members), reusing the barrelOpenerTurns walk.
  CORPSE_BLAST             GameMath.relicCorpseBurstScenarioTurns: in a group of n, each of the first n-1 kills deals
                           fraction x refSoldierHP x CORPSE_ADJACENCY to the remaining group.
  KILL_CREDIT_BONUS        SupplyValue.credits += killCredits x bonus.   KILL_AMMO_REFUND  SupplyValue.ammo += bodies x share x
                           chance x the floor's mean ammo PP per unit.   FLOOR_ARRIVAL_AMMO  SupplyValue.ammo += fraction x the
                           kit's ammo stack caps x PP per unit.   XP_MULTIPLIER  a new SupplyValue.experience component =
                           bonus x EXPECTED_LEVELS_PER_DEPTH x EXPECTED_PERK_POWER_PP_PER_PICK per floor (counts in SUPPLY_TOTAL
                           and in the carry's supply-to-heal conversion).
  worstLoss(stats, excludedNiche, depth) accepts a null niche (every probe counts).
  ZERO-VALUE HALVES (known blind spots): the carry model has no term for MELEE_DAMAGE (bone_saw's +25% — the relic
  is priced by MELEE_KILL_HEAL alone), BURN_TURNS, KNOCKBACK_BONUS, ARC_CHAIN_JUMP, GUARD_REFLECT or RANGE_BONUS. These
  are real in play and priced at nothing, so those relics are UNDER-valued in the audit. They sit in their bands
  anyway, which is why they may be tuned up only after the valuation learns the term. Boolean-only effects
  (FIRST_HIT_SHIELD, SECOND_WIND, WIDE_GUARD_ARC, FIRE_TILE_IMMUNE) price through their own flag terms.
  `GameMath.relicPowerPoints(lift)` = SHOP_PERK_RANK_POWER_POINTS x ln(lift) / ln(RELIC_PERK_RANK_EQUIVALENT_LIFT),
  0 for lift <= 1: a relic in perk-rank currency, which is how the route's ledger prices an offer.

EXPECTED PLAYER AND THE LADDER (decision D3)
  `ExpectedPlayer` is NOT changed. Relics are bounded BONUS power accounted BESIDE the on-curve player, capped
  by R-RELIC-STACK against R-CARRY's own scores. Folding them in would re-derive boss HP, TP and every ladder band.
  Bosses, TP and R-LADDER stay derived from the relic-free on-curve player. The LadderReport probes carry no relics;
  its extra column "relics (expected)" prints expectedRelicCount(depth).

THE SIMULATOR — S-RELIC (sim/BehavioralBands; RuleKind.SIM_RELIC)
  Five probe rows (BalanceSimulator.relicProbePolicies(), SIM_RELIC_PROBE_SEED_COUNT = 120 seeds each), each a
  TACTICAL variant that LEAVES every relic offer (`declinesRelicOffers`) and is instead GRANTED one relic at depth-1
  arrival, round-robin over the rarity's NON-AFFINE pool by run index (`SimWorld.nonAffinePool`) — so every relic
  gets floor/ceil(120 / pool) runs:
      TACTICAL-NO-RELIC     granted nothing: the baseline
      TACTICAL-RELIC-COMMON / -RARE / -LEGENDARY / -CURSED   one relic of that rarity
  (`sim/RelicProbe` is the enum; `RelicProbe.NONE` is plain TACTICAL, which takes offers through
  `TacticalPolicy.chooseRelic`: the card with the highest `carryLift` at the nearest reference depth, a CURSED card
  only if STRICTLY higher, LEAVE IT when none lifts carry above 1.0.) NAIVE and HOARDER take offered[0].
  SimWorld resolves offers at trigger time (not queued): resolveRunStartRelic, resolveBossRelicOffer,
  payMysteryOutcome -> offerRelic. It does NOT mirror EVENT choices (it never applied them): the locker is not
  played in the sim. It uses the same RelicRuntime and wiring as World.
  Bands use MEAN ending depth (medians are integers near 3):
      SR1  each COMMON / RARE / LEGENDARY row: mean depth / NO-RELIC in [1 - 0.10, 1 + 0.40]
      SR2  the CURSED row: in [1 - 0.15, 1 + 0.40]
      SR3  LEGENDARY mean depth >= COMMON ("rarity is felt")
      SR4  every non-affine relic with >= SIM_RELIC_MIN_RUNS_PER_RELIC (10) probe runs: ratio in [0.75, 1.60]
           ("no trap, nothing mandatory")
      SR5  every non-affine relic got >= 10 probe runs (always enforced)
      SR6  standard TACTICAL mean relics held at run end >= 1.0 (the acquisition wiring is live)
  Tag-affine relics are banded by the audit only: a probe start weapon may not carry their tag, which would make
  them look like traps (AS17). Measured at CP8: NO-RELIC mean depth 3.15; SR1 COMMON / RARE / LEGENDARY 1.02 / 1.02 /
  1.03; SR2 CURSED 1.04; SR3 1.01; SR4 30 relics, 0.86..1.12; SR5 minimum 13 runs; SR6 1.01. SR6 IS THIN: it
  reads the start relic (TACTICAL took it on 200 / 200 runs), so it proves the RUN_START wiring, not the boss or
  mystery paths. The depth bands are weak by construction — TACTICAL dies near floor 3 — so the audit is the tighter gate.
  Reports: SimReport RELIC REPORT (per-row mean/median depth; per relic runs, mean depth, ratio; TACTICAL offers
  seen / taken / left by source; MODEL vs PLAYED kills and doors); RoundSummary row R1 "relic rows mean-depth lift
  LEGENDARY / NO-RELIC" (IN/OUT); LadderReport column "relics (expected)". No waiver was needed.

TUNING ORDER IF A RULE FAILS (decision D7)
  1. Retune that relic's own SECTION 26 magnitude — relics are new numbers and may be tuned freely.
  2. For R-MYSTERY-EV: lower MYSTERY_WEIGHT_RELIC_CACHE. (The idea's floor was 4; it had to go to 3 — see below.)
  3. NEVER move an existing pre-relic number or band to make a relic fit.
  4. A waiver (reason + expiry, authority SECTION 4) only for an S-RELIC sim line made unmeasurable by the
     order-7 round-pending state. None is in force.
  The cache weight: the pre-relic mystery table already sat at R-MYSTERY-EV 1.2917 of its 1.30 ceiling; weight 4
  gives 1.3022, weight 3 gives 1.2996 (margin 0.0004). The table total is now 103 (16 + 18 + 18 + 18 + 14 + 16 + 3).
  Mystery relic caches are therefore RARER than designed (about 0.8% of floors yield a node offer).


9. ADD A RELIC (the recipe)
===========================
  1. Pick the rule it changes. If it needs an effect no PerkModifier expresses, add a PerkModifier constant with its
     own apply body and a typed BuildStats accessor read at ONE owning seam (section 5), AND teach the valuation to
     price it (a BuildValuationModel term + a GameMath formula with the Formula / Derivation / Edge cases block).
     An unpriced kind prices at 1.00 and R-RELIC fails it — by design.
  2. Add its magnitudes to BalanceConfig SECTION 26 as `RELIC_<RELIC_ID>_<PERK_MODIFIER_KIND>` (gain kinds the fraction;
     multiplier / cost kinds the multiplier; ints as int). Never a literal in the catalog or the text.
  3. Add ONE `registry.register(RelicDefinition.builder()...)` call to `RelicCatalog.bootstrap`: id, name, rarity,
     trigger (the card badge), valuation (CARRY unless it is an economy relic), optional affinity, effects, effectText
     built with `RelicText.percent(...)` from the constants, and — iff CURSED — costText. No switch anywhere.
  4. Run `./gradlew test`. The magnitude must land in its rarity x valuation band at 5/15/25 (R-RELIC / R-RELIC-CURSE),
     R-RELIC-STACK must hold (mind the d25 slack), and COVERAGE must resolve it. Read the RELICS table in BalanceReport
     for the gain; tune ONLY the new relic's own numbers.
  5. Run `./gradlew balanceSim`. A NON-AFFINE relic enters the probe rows automatically (round-robin); SR4 and SR5
     must hold. A tag-affine relic is audit-only.
  6. Regenerate authority SECTIONS 6 and 8, add the CHANGELOG line, update this doc's catalog table (and the
     knowledge doc's SECTION 6B counts). No new test (Testing Policy: relics ride the existing balance tests).
  A new SOURCE is a RelicSource constant (card count, allowed rarities, weight rows, guarantee flag) plus one
