ROUTE MAP SYSTEM
================
Branching-facility route map: a Slay-the-Spire-style, forward-only layered DAG the player descends,
picking one node per floor. The map is generated once per run from the run's master seed (so a seed
reproduces an identical map) and drives which generator/config builds each next floor.

Code lives in `core/.../route/` (pure, headless — no LibGDX imports) plus the World wiring below.

  order-1  data model + registries (NodeTypeRegistry, GeneratorRegistry, RouteRegistries.bootstrap)
  order-2  RouteMapGenerator — the layered DAG, node types, pre-rolled combat generators
  order-3  World integration & the node->floor pipeline   <-- THIS SECTION
  order-4+ overlay drawing, touch selection, fog, affixes, special level profiles (see idea files)
  order-10 narrative EVENT nodes + region theming/ambience + the REGION_GATE ceremony (this file, end)


WORLD INTEGRATION & THE NODE->FLOOR PIPELINE (order-3)
=====================================================
The connective tissue that turns "player stepped on the exit portal" into "route map opens, a node
is committed, the NEXT floor is generated from that node." It replaces the old hard-coded generator
switch with a node-driven pipeline.

ROUTE_SELECT phase
------------------
`World.RunPhase.ROUTE_SELECT` is a paused overlay phase modelled on SHOP_OPEN:
  - the simulation is paused (World.update returns early — no enemy ticks, no player movement, the
    weapon HUD is frozen);
  - the 3D world stays DRAWN but static behind the overlay (render() runs its world passes every
    frame regardless of phase);
  - the on-screen touch controller is hidden (render gating excludes ROUTE_SELECT, as it does
    SHOP_OPEN / INVENTORY_OPEN / WEAPON_INSPECT);
  - `viewport.apply()` still runs every frame in Main.render() (CLAUDE.md rule — never gated on phase).

The overlay itself is `render/RouteMapOverlay` — an order-3 STUB carrying the presented candidates and
a commit callback (present(List<RouteNode>) / onNodeCommitted). Order-4/order-6 replace its body with
real drawing + touch while keeping that present/commit contract. Order-3 auto-commits the FIRST
presented candidate each frame to prove the pipeline end-to-end.

Hook points (World.java)
------------------------
  onDescentRequested()   — staging exit or a route-map-less world goes straight to FADING_OUT;
                           otherwise it extends the map if needed, presents getSelectableNext() and
                           enters ROUTE_SELECT. If SHOW_FORCED_NODE_CARD is false and the only pick is
                           a forced BOSS/REGION_GATE, it auto-commits instead of showing a card.
  commitRouteNode(next)  — routeMap.commitTo(next); pendingNode = next; append the node id to the run
                           route string; then FADING_OUT (hands back to the existing fade machinery).
  FADING_OUT completion  — at staging exit: routePlan = RegionPlan.defaultPlan();
                           routeMap = routeMapGenerator.generate(runSeed, routePlan);
                           autoCommitFirstNode() puts the cursor on a depth-1 node (floor 1 is entered,
                           not chosen — the first real branch is the descent FROM floor 1).
                           Every floor is then built with rebuildForLevel(buildNextFloor()).

The pipeline (buildFloorForNode)
--------------------------------
  1. NodeTypeDefinition  = RouteRegistries.nodeTypes().get(node.type)
  2. NodeLevelProfile    = RouteRegistries.levelProfiles().getOrDefault(def.levelProfileId())
  3. LevelPlan plan      = profile.resolve(node, depth, floorSeed(runSeed, depth))
                           -> { GeneratorId, LevelGenConfig, List<GuaranteedContent>, EnemyBudgetOverride }
  4. LevelGenConfig cfg  = applyEnemyBudget(plan.config(), plan.enemyBudget())
                           (folds the budget scale into config.enemyBudgetScale; null override = 1.0)
  5. ILevelGenerator     = RouteRegistries.generators().create(plan.generatorId(), seed, cfg)
  6. Level level         = generator.generate(depth)
  7. for each guarantee: guarantee.applyTo(level)   (post-generation, so any generator can host any
                                                     node's guarantees — generators and node contents
                                                     stay orthogonal)
  then rebuildForLevel(level) exactly as before (re-seeds enemies, rolls shop stock, places chips…).

Order-3 shipped ONE profile: `DefaultCombatProfile`, registered under "combat_standard" AND set as the
registry FALLBACK, so every node type resolves to a playable combat floor. Order-7 adds the framework
below plus the two thin forwarders `ShopProfile` ("shop") and `BossProfile` ("boss"); the bespoke
CACHE/REST/ELITE/MYSTERY/EVENT/GATE profiles land in order-8/9/10, each one register() line.

Boss floors: `GameMath.isBossFloor(depth)` stays the single authority. DefaultCombatProfile returns
GeneratorId.BOSS_ARENA on any boss depth, and RouteMapGenerator already forced a BOSS node there, so
the two agree by construction.

SPECIAL LEVELS: THE PROFILE SYSTEM (order-7)
============================================
A NodeLevelProfile answers "when the player enters a node of THIS type, what floor do they get?"
Nothing switches on node type directly — order-3's pipeline is all registry lookups
(def.levelProfileId -> NodeLevelProfileRegistry -> profile -> LevelPlan). Adding a special level
later = write one profile + register it in RouteRegistries.registerLevelProfiles; ZERO World edits.

The LevelPlan contract ( …toon3d.route.LevelPlan ):
  GeneratorId          generatorId  — which registered generator builds the base floor
  LevelGenConfig       config       — biases that generator (props/rooms/lighting/pickups); may be null
  List<GuaranteedContent> guarantees — applied POST-generation (pipeline step 7)
  EnemyBudgetOverride  enemyBudget  — null = normal depth budget; else a SCALE on it (never a freeze)

Orthogonality trick — post-generation guarantees:
  A CACHE must contain crates+ammo whether its base floor is rooms_mst, a cavern, or a corridor. So a
  profile does NOT need a bespoke generator per node: it picks ANY suitable generator, biases it via
  LevelGenConfig, then STAMPS guaranteed symbols afterward. Guarantees are built by the `Guarantees`
  factory and placed by `GuaranteedContentStamper` (pure, deterministic from floorSeed):
    Guarantees.pickup(symbol, count, Placement, seed)   — PICKUP kind (e.g. '6' ammo box, 'H' medkit)
    Guarantees.prop(symbol,   count, Placement, seed)   — PROP kind   (e.g. '=' weapon rack, 'C' crate)
    Guarantees.brightenFloors()                         — TILE_THEME kind (order-8): promotes every
                                                          'u'/'f' floor tile to lit 'l' for a CALM read
  (Forced SPAWN and richer TILE_THEME repaint kinds arrive with the profiles that need them in
  order-9 — no unused machinery ships early. The STATION heal kind landed in order-8 not as a
  GuaranteedContent — a station needs runtime state World owns — but as a Level heal-station registry;
  see CALM NODES below.)
  Placement (…toon3d.route.Placement): NEAR_SPAWN | NEAR_EXIT | FARTHEST_ROOM | CENTER_ROOM |
  SCATTERED | GATED_ROOM. Resolved against the floor's 'p' spawn / '>' exit anchors and walkable-tile
  distances. The stamper writes ONLY on legal walkable tiles — never over a wall, prop, column, door,
  shop machine '@', 'p', '>', or an existing pickup — and only symbols already in tile-symbols.txt.

Enemy budget overrides (respecting the balance contract):
  EnemyBudgetOverride is a multiplier on the depth-scaled Threat-Point budget spent by
  EncounterBudgetPlanner. It is threaded via LevelGenConfig.enemyBudgetScale into all three standard
  generators (LevelGenerator / LinearCorridorGenerator / CavernGenerator). The depth ramp is applied
  FIRST, then the scale — so a SHOP at depth 8 is depth-8-scaled AND calm, never depth-frozen.
  Helpers: EnemyBudgetOverride.calm() (0.35x, CACHE/REST), .light() (0.5x, SHOP), .scaled(x). Clamped
  to [0.1, 4.0].

V1 profile catalog (levelProfileId -> profile):
  combat_standard -> DefaultCombatProfile  (order-3 baseline + registry fallback)
  shop            -> ShopProfile           (order-7: standard floor, .light() budget; vending already
                                            guaranteed on every floor by World.seedVendingMachines)
  boss            -> BossProfile           (order-7: forwards to GeneratorId.BOSS_ARENA; the boss is
                                            seeded by BossFloorController)
  supply_cache    -> CacheProfile          (order-8: bright depot, calm budget, owned-ammo + medkit +
                                            armour + crates payoff; see CALM NODES)
  rest_medbay     -> RestProfile           (order-8: MedBayGenerator clinic + auto-doc heal station;
                                            see CALM NODES)
  elite_hotzone / mystery                  -> order-9   (ELITE / MYSTERY)
  event / region_gate                      -> order-10  (EVENT / GATE)
  Until a bespoke profile is registered, the FALLBACK (DefaultCombatProfile) keeps that node type
  playable, so partially-implemented catalogs never break a run.

Add-a-new-special-level recipe (guaranteed by this framework):
  1. Existing generator + config + guarantees enough? -> write a NodeLevelProfile only.
     Else -> write an ILevelGenerator (register in GeneratorRegistry) AND a profile naming it.
  2. (new node kind) add RouteNodeType + NodeTypeDefinition (levelProfileId -> your profile,
     iconPainterId -> new icon) and a weight in RouteMapConstants / region tables.
  3. register(new YourProfile(...)) in RouteRegistries.registerLevelProfiles.
  4. Update this doc.
  => the special level appears on random maps with NO edits to World, the overlay, or generator
     selection.

DEPTH RAMP INVARIANT (roguelike_order_16)
-----------------------------------------
A node changes only the KIND/flavour of a floor and its rewards — NEVER the depth. The RAW
currentDepth is threaded straight through to generate(depth) and the enemy scaler. Choosing a "safe"
node costs loot/tempo, never the clock. No NodeLevelProfile may override the depth it is handed.

RUN TELEMETRY
-------------
Each commit appends the node's id to `RunStats.routeString` (RunStats.recordRouteNode /
getRouteString) — a compact, shareable summary of the incursion, e.g.
"cache-event-elite-combat-boss-…". World also logs "RouteMap" build/commit lines to Gdx.app.log.

Fallback: file-loaded / test worlds (`new World(Level)` / `new World(String)`) never build a route
map; buildNextFloor() falls back to the depth-driven pickLevelGenerator so they still descend.

CALM NODES: SUPPLY CACHE & MED-BAY / REST (order-8)
===================================================
The two "breathe and refuel" special levels — the strategic counterweight to ELITE/COMBAT. The player
routes here by CHOICE, paying with a skipped reward node, so each delivers an unambiguous, deterministic
payoff and reads as visibly SAFE within ~2 seconds. Constants live in RouteMapConstants (CACHE_* /
REST_* / HEAL_STATION_SYMBOL) and LevelGenConstants (MED_BAY_*).

  HONEST-SAFE-NODE RULE (design invariant): a node whose icon promises safety MUST be safe. Route
  planning collapses if the icon language can't be trusted, so the CACHE keeps only light stragglers
  and the REST clinic is genuinely empty. A "med-bay ambush" is a DIFFERENT node (MYSTERY, order-9)
  with its own icon — never a REST node wearing REST's face.

SUPPLY CACHE  (RouteNodeType.CACHE, profile "supply_cache", CacheProfile)
  A UAC forward depot. Reuses a STANDARD generator (fixed to ROOMS_MST for a tidy depot read) with a
  bright, hazard-free config (no unlit/flicker floors, no radioactive barrels; crates + lockers + one
  cargo bay + columns; medkit/armour chances bumped). Budget = EnemyBudgetOverride.calm() (light
  chaff, never elite, never zero — a cache is not a free heal; depth ramp still applied first).
  Guaranteed payoff (post-generation, FARTHEST_ROOM = the deep cargo bay, deterministic from floorSeed):
    - brightenFloors() TILE_THEME so the depot never reads unsafe
    - CACHE_MEDKITS 'H' + CACHE_STIMS '+'
    - CACHE_ARMOUR: 'a' shard shallow, 'A' vest from depth CACHE_ARMOUR_VEST_DEPTH
    - CACHE_CRATES 'C' + CACHE_LOCKERS 'L' as set dressing
    - CACHE_AMMO_BOXES ammo boxes across the player's OWNED ammo types (smart ammo — see below)
  The reliable WEAPON payout is the ELITE node; the cache stays about consumables so the two read
  distinctly.

  SMART (owned-aware) AMMO — the LevelPlan.ammoCache seam:
    A profile can't see the arsenal (resolve() has no player state), and a GuaranteedContent only gets
    the Level. So CacheProfile attaches an AmmoCacheRequest (count + Placement) to its LevelPlan, and
    World.fulfillAmmoCache reads the loadout's ammo types (Weapon.getAmmoType -> pickupTileChar),
    distributes the boxes evenly across the OWNED symbols (falling back to all 5 types for a melee-only
    run), and stamps via GuaranteedContentStamper. Owned-logic lives in World (which legitimately owns
    the arsenal) but is driven by a generic plan FIELD, not a per-node-type switch — the order-3 seam
    holds.

MED-BAY / REST  (RouteNodeType.REST, profile "rest_medbay", RestProfile + MedBayGenerator)
  A bespoke curated clinic (GeneratorId.MED_BAY) — chosen over random rooms because legibility IS the
  sanctuary read. Layout: approach corridor -> central ward (auto-doc at centre) -> 1-2 cryo-pod
  alcoves -> exit a few tiles PAST the auto-doc so the heal is on the natural path out. Deterministic
  from floorSeed; only the alcove side and whether a second alcove appears vary. Tiles (all from
  tile-symbols.txt): 'M' medical walls dominant, 'N' reinforced-glass viewing window, 'Z' cryo-wall
  alcove frames, 'S' emergency-strip approach; '&' bio-pods, 'I' specimen tanks, 'T' terminals, '%'
  generator; sparse 'm'/'O'/'f' decals. Emits ZERO enemy spawn points — the honest sanctuary.

  THE AUTO-DOC HEAL STATION (the STATION kind):
    Reuses the holo-workstation 'W' as the auto-doc prop (RouteMapConstants.HEAL_STATION_SYMBOL) — NO
    new tile symbol; the interactivity is logic layered on that tile. The generator registers the tile
    via Level.markHealStation(); World copies the floor's getHealStationTiles() on every rebuild into
    chargedHealStations. In the PLAYING update, the FIRST time the player steps ORTHOGONALLY ADJACENT
    to a charged station (the 'W' tile itself is solid), a ONE-TIME heal fires — REST_HEAL_FRACTION of
    max HP — reusing the medkit heal path (player.applyHealing + green "AUTO-DOC +N HP" event text +
    heal particles + edge vignette). The station is then consumed (removed), so it can never be farmed:
    one heal per station, one station per rest floor. Auto-trigger on adjacency = no new touch button
    or run phase (mobile-friendly).
    REST_OFFERS_CHOICE (default FALSE) reserves the 2-option "PATCH UP vs FIELD MOD" overlay for when a
    permanent-boon system exists; until then REST is an honest plain heal.

DANGER / GAMBLE NODES: ELITE HOTZONE & MYSTERY (order-9)
========================================================
The "press your luck" side of the map — the counterweight that makes the CALM cache/rest (order-8) a
real trade-off. ELITE is a KNOWABLE deliberate risk for a bigger reward; MYSTERY is an UNKNOWN box with
deliberately NEUTRAL expected value. Both are NodeLevelProfiles (order-7). Constants live in
RouteMapConstants (ELITE_* / AFFIX_* / MYSTERY_*). Everything is deterministic from floorSeed/nodeSeed;
all combat scaling still flows through the depth ramp (EnemyBudgetOverride scales it, never bypasses it).

FloorEffects — the headless-profile → World seam:
  A profile is pure/headless, so it cannot light red-alert, spawn an EventText, or touch RunStats. It
  attaches a FloorEffects (redAlert / stingText / statLogToken) to its LevelPlan; World stashes it in
  pendingFloorEffects during buildFloorForNode and calls applyPendingFloorEffects() AFTER
  rebuildForLevel (which clears red-alert every transition), so a DANGER floor's pulse survives. NONE
  is the do-nothing default an ordinary floor carries.

ELITE HOTZONE  (RouteNodeType.ELITE, profile "elite_hotzone", EliteProfile)
  A containment breach — fewer bodies but MEANER, hazards live, red alert pulsing. Uses the node's
  pre-rolled combat generator (the SHAPE is a normal floor; the danger is budget + affix + hazards).
  Config: radioactive barrels up (ELITE_RADIOACTIVE_BARREL_WEIGHT), an arena room, flicker/unlit dread,
  lock-and-key ON so clearing the floor can literally unlock the vault. FloorEffects = redAlert +
  ELITE_STING_TEXT. Budget = ELITE_BUDGET_SCALE of the raw depth budget (a mini-setpiece). Reward
  (~1.5x, GATED_ROOM = deep vault, deterministic from floorSeed): an owned-ammo vault (ELITE_AMMO_BOXES
  via the same AmmoCacheRequest seam as CACHE), a depth-scaled armour drop ('a' shard / 'A' vest from
  ELITE_ARMOUR_VEST_DEPTH), medkits/stims, a weapon-rack '=' display, cover columns 'P'. (A true
  guaranteed WEAPON SPAWN is a future upgrade — weapon spawns come from WeaponSpawnPoints, not stampable
  tiles — so the reliable payout is the ammo/armour/consumable vault + the rack as its visual promise.)

  NODE AFFIXES (NodeAffixRegistry + NodeAffixDefinition):
    Rolled at MAP-GEN (RouteMapGenerator.rollAffix, AFFIX_ROLL_CHANCE_ELITE, from the node's affix
    sub-stream) onto ELITE nodes; the token (NodeAffix) is stored on the node, shown as an icon
    corner-tag (order-5) and appended to the map hint. An affix is a bundle of TYPED modifiers — there
    is NO bespoke per-affix code path; each modifier routes through an existing system. EliteProfile
    looks the definition back up by id and folds it in (applyToConfig + budgetScaleMultiplier +
    extraGuarantees). v1 catalog (register one line in RouteRegistries.registerAffixes to add more):
      - IRRADIATED  : + radioactive-barrel weight + extra 'g' barrels (hazard pools).
      - OVERCLOCKED : budget ×AFFIX_OVERCLOCKED_BUDGET_MULT (enemies "hit harder" ≈ more Threat spent).
      - SWARM       : budget ×AFFIX_SWARM_BUDGET_MULT (the one exception to fewer-bodies — crowd control).
      - FORTIFIED   : extra cover columns 'P' + an extra armour pickup (a slugfest).
      - VOLATILE    : extra explosive barrels 'E' (the arena itself is a weapon for both sides).

MYSTERY  (RouteNodeType.MYSTERY, profile "mystery", MysteryProfile — a META-profile)
  The icon is always '?'; the payload is the surprise. On ENTRY (not map-gen, so a scanner reveals only
  a tone) MysteryOutcome.rollFor(nodeSeed) draws a hidden outcome from a weighted table (MYSTERY_WEIGHT_*
  sum to 100, tuned EV ≈ a normal combat floor). MysteryProfile then either DELEGATES to another
  registered profile (so MYSTERY inherits every special level in the pool, now and future) or builds the
  outcome's floor directly, then stamps MYSTERY_STING_TEXT + logs the resolved outcome. Table:
      VAULT_JACKPOT (18) : built — bright lightly-guarded super-cache (MYSTERY_VAULT_AMMO_BOXES + armour).
      SECRET_WARREN (18) : built — server rooms + lock-and-key + gated loot (rewards searching).
      TRAP_GAUNTLET (18) : built — dense hazards (traps degrade to 'E'/'g' barrels), loot NEAR_EXIT.
      AMBUSH        (18) : delegates → "elite_hotzone" (combat-heavy lockdown; keeps its red alert).
      LORE_SIGNAL   (14) : delegates → "rest_medbay" (near-combat-free; EVENT profile order-10 degrade).
      MALFUNCTION   (14) : built — failing sector: hazards, unlit, NO reward (bad-but-survivable).

  FAIRNESS RULES (design invariants):
    - Pre-scan the card is ALWAYS '?'. A SCANNER (order-6) reveals only the ScanTone BUCKET
      (REWARD-RICH / HIGH RISK / QUIET), derived from the same nodeSeed — several outcomes share a
      bucket, so a scan narrows but never pinpoints (informed gambling). Shown via the overlay hint when
      the focused MYSTERY card is scanned.
    - The resolved outcome is HIDDEN but LOGGED: RunStats.annotateLastRouteNode appends it to the route
      string (e.g. "mystery:VAULT") so the post-run route story is complete.
    - No outcome is a pure "you lose the run" trap — worst case wastes a hop + some resources, always
      survivable. Delegated outcomes re-stamp MYSTERY's sting/log but preserve a delegate's own redAlert.

  GRACEFUL DEGRADATION: where a referenced system isn't implemented yet the outcome falls back to the
  nearest available effect (traps → barrels, secret rooms → server rooms + lock-and-key, lockdown waves →
  the ELITE combat delegate, relics/EVENT → loot/rest). Each degrade is noted in-code so it can be
  upgraded when the real system ships, without changing the table shape.

OVERLAY VISUAL SPEC (order-4) — the "FACILITY NAV" console
==========================================================
RouteMapOverlayRenderer (…toon3d.render, Renderable+Disposable) draws the full-screen UAC nav
console over the frozen 3D world during RunPhase.ROUTE_SELECT. Every pixel is procedural
(ShapeRenderer + BitmapFont) — NO textures. All layout/colour numbers live in RouteMapConstants
(OVERLAY VISUAL SPEC section) + RouteMapColorPalette; nothing hardcoded inline.

GLOW WITHOUT AN FBO: the idea sketched an additive FrameBuffer bloom, but this project keeps all
per-frame FrameBuffer work out of the loop (FrameBuffer.end() resets the GL viewport and corrupts
the FitViewport letterbox mid-frame — see WeaponHudRenderer). The bloom is instead faked with
concentric additive-blended discs (glBlendFunc SRC_ALPHA, ONE) drawn through the one ShapeRenderer.

SCREEN BANDS (world coords, 1280x720, Y-up):
  TITLE PLATE   y 648..712  — "FACILITY NAV — SELECT VECTOR", region crest (left), "DEPTH n -> n+1" (right)
  MAP VIEWPORT  y 150..640  — hologram schematic (bottom->top flow: CURRENT low, candidates high)
  LEGEND STRIP  y  96..150  — focused node's hint line
  CONFIRM BAR   y  12.. 92  — [◀ CANCEL] ......... [ENGAGE ▶] (visual targets; touch is order-6)

MAP LAYOUT: rows = layers around the CURRENT layer (one history row below, MAP_LOOKAHEAD_LAYERS
above). Row 0 (current) + row 1 (selectable next) draw full size/opacity; distant rows shrink
(DISTANT_SCALE_STEP) and fade (DISTANT_ALPHA_STEP) into the descent; the history row is dimmed
(HISTORY_ALPHA). Each layer's nodes are sorted by laneIndex and spread evenly, centred on X=640.

NODE CARD: rounded-rect data slug (150x120), translucent accent fill + 2px accent border. Layers:
additive glow halo (AVAILABLE/CURRENT only, boosted when focused/committed), the procedural per-type
node icon (order-5 IconPainter — see NODE ICON VOCABULARY below), centred drop-shadowed label
(truncated to width), 1-4 risk pips (RouteMapColorPalette.pipCount/pipColor by DangerTier,
green->amber->red). State decor: CURRENT=rotating diamond reticle, VISITED=check mark, AVAILABLE=idle
bob, FOCUSED=pulsing selection ring + 1.06 scale, LOCKED/BYPASSED=steel. Risk pips + state glyphs are
the shared RouteGlyphs painters (order-5) so every node type gets consistent card chrome for free.

CONNECTORS: quadratic-bezier conduits (GameMath.quadraticBezier per axis) from card top to card
bottom; hot edges (leaving CURRENT/AVAILABLE) carry an additive travelling pulse dot; the taken path
draws a brighter "locked route" history spine.

COLOUR: RouteMapColorPalette resolves NodeTypeDefinition.accentColorId (combat/elite/cache/shop/rest/
mystery/event/boss/gate) and RouteRegion.themeId (outer_facility/research_wing/reactor_depths/
the_breach) to pre-allocated Colors — the ONLY place accent ids become Colors, keeping …route
headless. Region tint colours the frame/legend; RED ALERT (GameState.redAlert) pulses the trim
amber->red.

CRT TREATMENT: upward-scrolling scanlines + edge vignette over the viewport, ~2% whole-hologram
flicker, and a rare sync brighten.

ANIMATION: single overlayTimeSeconds/phaseTimeSeconds drive OPENING (0.35s boot sweep reveals nodes
bottom->top) -> IDLE (bob/flicker/pulse loops) -> COMMIT (0.4s: chosen conduit flares, chosen card
grows, others recede) -> DONE. No allocations in render(); the whole layout is precomputed in
present(RouteMap).

WORLD WIRING: onDescentRequested() calls routeMapOverlayRenderer.present(routeMap) alongside the
order-3 RouteMapOverlay.present(candidates). Order-4 has no touch yet (order-6), so the console
auto-focuses the first candidate and, after AUTO_SELECT_HOLD_SECONDS, drives its own COMMIT; World's
paused ROUTE_SELECT branch watches isReadyForSelection()/isCommitFinished() and fires the existing
RouteMapOverlay.commit(node) -> commitRouteNode -> FADING_OUT pipeline (contract unchanged). Order-6
replaces the auto-driver with real tap hit-testing against the card/confirm-bar targets defined here.


NODE ICON VOCABULARY & HOW TO ADD ONE (order-5)
===============================================
Every node icon and region crest is drawn from ShapeRenderer primitives only — NO image assets (a
hard product requirement). Code lives in `core/.../render/routeicons/` (the render sub-package; it is
the only render code that draws the map's icon language). Icons are DIRECT-drawn straight into the
overlay's single ShapeRenderer each frame — never baked to a FrameBuffer, because FrameBuffer.end()
resets the GL viewport and would corrupt the FitViewport letterbox mid-frame (same reason the order-4
glow is faked with additive discs). This keeps the pipeline viewport-safe and allocation-free with no
FBO to dispose. Painters switch fill/line with shapes.set(...) (auto-flushing) inside the overlay's
one begin()/end() icon pass; they hold no timers (animationT is passed in) so they stay deterministic.

REGISTRY, NOT A SWITCH: the overlay never switches on node type. NodeTypeDefinition.iconPainterId
selects an IconPainter via IconPainterRegistry.get(id).paint(...). RouteIconBootstrap registers the v1
painters (the render-layer twin of RouteRegistries.bootstrap, since IconPainter touches LibGDX and so
cannot live in the headless route package). Unknown ids fall back to PlaceholderIconPainter (a diamond).

ICON CATALOG (one IconPainter class each; geometry in one line):
  icon_combat  COMBAT  — crosshair: thin ring + N/E/S/W ticks + bright centre dot.
  icon_elite   ELITE   — skull in a hazard diamond: arc-fan cranium dome, dark eye sockets, jaw notch.
  icon_cache   CACHE   — iso supply crate: front face + slanted top/side, X strap, "+" ammo tick.
  icon_shop    SHOP    — hexagon coin + credit rune (ring + two bars) + down-arrow dispense tick.
  icon_rest    REST    — med cross inside a soft ring + tiny heartbeat trace beneath.
  icon_mystery MYSTERY — "?" glyph (hook arc + stem + dot) inside a slowly-rotating segmented ring.
                         ALSO the fog icon: any un-revealed node draws this regardless of real type.
  icon_event   EVENT   — comms beacon: pulsing broadcast arc fan rising from a bright base node.
  icon_gate    REGION_GATE — airlock hatch: outer+inner ring, radial locking bolts, central seam
                             (drawn ICON_GATE_SIZE_SCALE larger — a convergence beat).
  icon_boss    BOSS    — horned command skull (reuses the ELITE skull) + horns (bezier), brow, spine,
                         pulsing red eye-socket ember; full hazard-diamond frame; drawn a touch larger.

REGION CRESTS (RegionCrestPainter + RegionCrestPainterRegistry, keyed by RouteRegion.themeId; drawn on
the title plate at CREST_CENTER_X): outer_facility=gear ring, research_wing=molecule/atom (orbiting
electrons), reactor_depths=radiation trefoil, the_breach=cracked/corrupted sigil. Fallback=ring badge.

SHARED GLYPHS (RouteGlyphs, reused by the order-4 cards): riskPips (1-4 dot meter), lockGlyph,
checkGlyph (VISITED), hereReticle (rotating CURRENT diamond), affixTag (corner tag for a NodeAffix,
order-9). Centralised so a new node type opts into the same card chrome for free.

GEOMETRY MATH: non-trivial icon maths reuses GameMath (pointOnCircleX/Y for arc fans + radial bolts,
quadraticBezier for horns/heartbeat, rotateVectorX/Y for tilted orbits, lerp) — never inlined.
RouteIconSupport holds the shared primitive draws (disc/ring/diamond/arcFan/polygonOutline/
bezierStroke) and accent brighten/darken (mix toward WHITE_CORE / DARK_SOCKET, out-param, no alloc).

ADD A NEW NODE ICON (4 steps):
  1. Write `class MyNodeIconPainter implements IconPainter` in render/routeicons (draw from primitives;
     read accent.a as the master opacity; use RouteIconSupport helpers; no allocation in paint()).
  2. Register it: RouteIconBootstrap.registerIconPainters -> register("my_node_icon", new ...()).
  3. Point the node type at it: NodeTypeDefinition.iconPainterId("my_node_icon") in RouteRegistries.
  4. Done — the overlay draws it with zero edits. Add the one-line geometry note to this catalog.
A new region crest is the same recipe against RegionCrestPainterRegistry, keyed by the region themeId.

================================================================================
INTERACTION & CONTROLS (order-6) — two-thumb navigation of the FACILITY NAV console
================================================================================
Platform law: MOBILE ONLY, touch only, no keyboard ever. All state below lives in
RouteMapOverlayRenderer (the UX object) — NOT in RouteMap (RouteMap stays pure run state).
Selection never mutates route data until COMMIT. Constants: util/RouteMapConstants.java.

INPUT ROUTING
  During RunPhase.ROUTE_SELECT the world sim is frozen (like SHOP_OPEN) and the movement/action
  cluster (TouchControllerRenderer) is HIDDEN. World.handleRouteSelectTouch() polls the raw pointer,
  ALWAYS unprojects through the game viewport (project invariant — never raw pixels), and forwards to
  the console. A small movement is a TAP; movement past DRAG_START_THRESHOLD is a PAN drag. The tap is
  consumed from TouchInputState so it can never leak into the hidden move cluster.

SELECTION MODEL — tap-to-focus, tap-to-ENGAGE (two-step; a descent is irreversible)
  1. TAP a candidate card -> FOCUSED (ring + scale-up + glow; its hint slides into the legend strip;
     the conduit brightens). One focus at a time; tapping empty space clears it (unless forced).
  2. ENGAGE button is DISABLED/dimmed (ENGAGE_DISABLED_ALPHA) until a node is focused; then it lights
     and ready-pulses. TAP ENGAGE -> COMMIT flare -> World.commitRouteNode -> FADING_OUT.
  RouteMapOverlayRenderer.onTap() returns a PointerResult {NONE, FOCUS_CHANGED, ENGAGED, INVALID,
  FRAMING_TOGGLED, CANCEL}; World reacts (thunk shake on ENGAGED, back-out on CANCEL).
  FORCED node (single candidate / all-BOSS layer): auto-focused; ENGAGE copy becomes DESCEND TO BOSS /
  BREACH BULKHEAD; still a deliberate tap. Skipped entirely if SHOW_FORCED_NODE_CARD is false (order-3).
  Optional shortcut DOUBLE_TAP_ENGAGE (default OFF for safety): second tap on the focused card engages.
  CANCEL policy ALLOW_PORTAL_BACKOUT (default false): the portal opened the map and leaving IS
  committing, so CANCEL is a no-op that keeps browsing; when true it dismisses via RouteMapOverlay
  .cancel() (no listener fires) and resumes PLAYING on the same floor.

HIT-TESTING (no per-touch allocation)
  Card world-rects come from the layout computed once per present()/pan/framing-toggle. Each hit-rect
  is inflated to at least MIN_NODE_HIT_SIZE + NODE_HIT_PADDING so a shrunk/distant card stays thumb-
  tappable. Nodes are culled to the viewport band (isNodeDrawable) so panned-away rows are neither
  drawn nor tappable. Selection cues never rely on colour alone (ring + scale + glow all say "this one").

PAN / FRAMING (plan ahead on a small screen)
  The two decision layers (CURRENT + next) are always framed at home (panY == 0) — you never scroll to
  make the actual choice. VERTICAL DRAG pans (direct manipulation: drag down to look further down the
  run at the dim distant layers). Momentum flick decays (PAN_MOMENTUM_DECAY); a spring clamps to
  [minPanY, 0] with PAN_MAX_OVERSCROLL slack; releasing within PAN_SNAP_BACK_THRESHOLD of home snaps
  back so the choice is always reachable. minPanY is derived from the topmost laid-out row.
  MAP / DETAIL toggle (top-right of the viewport) swaps DETAIL (roomy default) and MAP ("fit region",
  MAP_FRAMING_COMPRESSION shrinks gap + scale); toggling re-lays out and resets the pan. Pinch-zoom is
  gated behind PINCH_ZOOM_ENABLED (default OFF — the toggle is the v1 path). MAP_PAN_ENABLED gates pan.

FOG & LONG-RANGE SCANNER (reveal layer)
  REVEAL_CURRENT_REGION (v1 default true): present() reveals every node in the CURRENT region (a real
  plan within the act) while the NEXT region stays ghosted '?' until its REGION_GATE is crossed.
  MYSTERY nodes always render the '?' icon regardless of reveal (payload is the surprise, order-9).
  Scanner is a relic hook (order-14 defines the item): setScannerActive(boolean) shows the SCANNER
  ACTIVE readout; triggerScanReveal() calls RouteMap.revealRegion(nextRegion) and plays the scan-sweep
  wipe (SCAN_SWEEP_SECONDS) that un-ghosts the revealed cards. Gated by SCANNER_REVEAL_ENABLED.

FEEDBACK (make the choice feel weighty; all flag-gated, core works on visuals alone)
  FOCUS  -> ring + scale-up + hint slide + light haptic tick (HAPTIC_FOCUS_MS) + audio-blip hook.
  ENGAGE -> commit flare + conduit surge + firmer haptic (HAPTIC_ENGAGE_MS) + console-thunk screen
            shake (ImpactEffectSystem.triggerUiThunk, ENGAGE_THUNK_*) fired from World.
  INVALID (locked/distant/disabled-ENGAGE tap) -> red border flash (INVALID_FLASH_SECONDS) + dull
            haptic buzz (HAPTIC_INVALID_MS); never a silent no-response.
  Haptics gate: HAPTICS_ENABLED wraps every Gdx.input.vibrate() so the desktop dev build no-ops.

COMMIT ANIMATION LOCK
  onTap() ignores all input unless phase == IDLE, so during OPENING and the COMMIT flare a second
  ENGAGE can never double-descend (mirrors PlayerController's action lock). The order-4 auto-select
  timer is retired: isReadyForSelection() now always returns false — a descent is a deliberate tap only.


NARRATIVE / EVENT NODES & REGION THEMING (order-10)
===================================================
The two "texture the run" additions that turn the map from a difficulty selector into a JOURNEY:
narrative EVENT nodes (non-combat decisions) and REGION THEMING (the act-band identity + the
ceremonial REGION_GATE bulkhead). Both extend by REGISTRATION — a new event / region is data + a
registry line, never a core edit — and both reuse the order-3/7/9 seams (profiles, LevelPlan,
FloorEffects) so nothing switches on node type.

EVENT NODES (RouteNodeType.EVENT, profile "event", EventProfile)
  A small curated NON-COMBAT beat — the map's "? room": a distress beacon, an abandoned stash, a
  surviving tech, a corrupted shrine, a data terminal. Routing here trades a combat reward for a
  DECISION. EventProfile builds the bespoke EventRoomGenerator floor (GeneratorId.EVENT_ROOM): a
  tight room around one central interactable ('W' holo-workstation, reused — NO new tile symbol),
  the exit set a couple of tiles past it, ZERO enemy spawns (EVENT_BUDGET_SCALE is near-zero too).
  The profile rolls one FacilityEvent from the node seed and attaches its id to the LevelPlan
  (LevelPlan.withEventId — the order-10 plan seam), plus an entry sting + the event id as a
  telemetry token (FloorEffects).

  THE EVENT REGISTRY (the content system):
    FacilityEvent  = { id, title, weight, narrativeLines[], EventChoice[1..3] }
    EventChoice    = { label, description, EventEffect }
    EventEffect    = a TYPED bundle (heal / armourToFull / ammoBoxes / grantXp / revealNextRegion /
                     nextFloorBudgetBonus / gamble{lootChance,failDamage} / result+fail+log text).
  Every choice routes through an EXISTING system, so there is NO bespoke per-event code path — the
  same trick NodeAffix uses. FacilityEventRegistry.rollFor(nodeSeed) draws deterministically
  (weightedChoiceIndex + RouteRng, like MYSTERY). Adding an event is one register() line in
  FacilityEvents.registerAll. v1 catalog: distress_beacon (reveal vs ammo), abandoned_stash (a
  gamble locker), surviving_tech (escort: armour + hotter next floor, vs keycard), corrupted_shrine
  (full heal + hotter next floor, vs XP), data_terminal (pure-lore breather, guaranteed XP).

  WORLD SIDE (the headless registry can't touch World, by design): EventRoomGenerator marks the
  interactable via Level.markEventStation(); World copies getEventStationTiles() into
  armedEventStations on every rebuild (mirroring the order-8 heal-station seam) alongside the floor's
  pendingEventId. In the PLAYING update, the first time the player steps ORTHOGONALLY ADJACENT to the
  interactable, World opens RunPhase.EVENT_CHOICE and presents the event on EventChoiceOverlayRenderer
  (a full-screen choice-card overlay REUSING the level-up card UI pattern). A tap resolves the choice:
  applyEventChoice() applies the EventEffect through existing paths (heal path + particles/vignette,
  applyArmor, itemInventory.addAmmo across OWNED ammo types, playerProgress.addXp,
  RouteMap.revealRegion, a one-shot pendingNextFloorBudgetBonus folded into the NEXT floor's budget),
  a GAMBLE rolls the floor seed (loot on success, a survivable bite + fail sting on failure — never a
  lost run), and the chosen token is appended to the run's route story
  (RunStats.annotateLastRouteNode, e.g. "event:distress_beacon:answered"). Adjacency-trigger + a
  paused phase = no new touch button (mobile-friendly), consumed once per floor.

REGION THEMING / ACTS (RegionAmbienceRegistry)
  order-2's RegionSpec/RegionPlan already own each act's DISTRIBUTION (node-type + generator weight
  biases). Order-10 adds each region's IDENTITY as a RegionAmbience row keyed by RouteRegion.themeId
  in RegionAmbienceRegistry (register once at bootstrap; NOTHING hard-codes the list — a new region is
  one row + a crest). A RegionAmbience carries: displayName, crestPainterId (order-5 crest) +
  overlayThemeId (order-4 tint), wallPalette (the wall symbols its generators lean on), enemyFactionId
  (which faction dominates — a hook EnemyManager reads later), the AMBIENCE HOOKS (redAlertFrequency,
  lightingMoodId, musicId — ids/flags the audio + red-alert systems read LATER; NO audio assets added
  here), bossId, and gateFlavour (the REGION_GATE announce copy). v1 regions: outer_facility (cool
  steel, baseline demons), research_wing (clinical, lab horrors), reactor_depths (amber-hot, reactor
  brutes, red-alert common), the_breach (corrupted violet, necrotic, endless — also the fallback).

  REGION-ENTRY ANNOUNCE (generic, not gate-specific): World tracks lastAnnouncedRegionIndex and, on
  each floor build, computes routePlan.regionForDepth(currentDepth); the first time it crosses into a
  new region it fires the "ENTERING: <NAME>" beat + the region's gateFlavour (EventText), logs the
  region to RunStats.recordRegionEntry, and logs the faction/music hooks. This fires on EVERY region
  transition (boss OR gate), so theming reads even though the default band size == boss interval means
  a literal REGION_GATE node is rarely injected.

REGION_GATE (RouteNodeType.REGION_GATE, profile "region_gate", GateProfile)
  The forced convergence node at a region boundary that ISN'T a boss depth (RouteMapGenerator injects
  it at region.lastDepth() when !isBossFloor). GateProfile builds the bespoke GateAirlockGenerator
  floor (GeneratorId.GATE_AIRLOCK): a 3-wide approach, a 1-tile 'B' blue-door bulkhead with a blue
  keycard 'b' waiting on the approach (so the airlock ALWAYS opens — reuses DoorManager, never a
  soft-lock), a threshold room, then the exit; near-zero budget, ZERO enemy spawns. A pacing breath +
  a visible chapter break. (Boss depths still defer to the arena — GameMath.isBossFloor is the single
  authority, matching every profile.)

RUN TELEMETRY (order-10 additions)
  RunStats.recordRegionEntry(index, name) -> getRegionsEntered() ("0:OUTER FACILITY | 1:RESEARCH
  WING …"); the chosen event + choice is annotated onto the EVENT node's route token. Together the
  route string + regions-entered string are the full "run story" the route-map vision promises.

RECIPE — ADD AN EVENT / A REGION (guaranteed by this framework)
  New EVENT : write a FacilityEvent (title + narrative + 1-3 choices, each a typed EventEffect) and
              register it in FacilityEvents.registerAll. No World / overlay / generator edits.
  New REGION: add a RegionAmbience row (crest + tint + palette + faction + hooks + boss + gate copy)
              in RouteRegistries.registerRegionAmbience, its RegionSpec band in RegionPlan, and a
              crest painter (order-5). The region then themes + announces itself with no World edits.

CAPTURED CREATIVE FOLLOW-ONS (documented for future idea files, NOT built here)
  The idea file's "what else the map needs" list — MAP LEGEND/KEY (order-6), ROUTE HISTORY RIBBON on
  the death screen, SEED SHARE on the menu/death screen, META UNLOCKS that register new node
  types/events/regions, and a DYNAMIC RISK PREVIEW — remain future work. Each plugs into the same
  registries (NodeType / Generator / Event / RegionAmbience / Affix), so each is a registration, not a
  rewrite. See .claude/agents/ideas/branching-facility-route-map-order-10.txt.
