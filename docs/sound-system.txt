GAMEPLAY SOUND SYSTEM — procedural SFX
======================================
Single source of truth for the gameplay audio layer. Update this doc in the same commit as any
change to `…toon3d.audio`, `util/SoundConstants` or the synthesis formulas in `util/GameMath`.

Design documents: `.claude/agents/ideas/procedural-sound-effects.txt` (orders 1-5) and
`.claude/agents/ideas/procedural-sound-effects-order-6.txt` (order 6 — the still-silent moments and the
Half-Life-inspired retune; see section 13).
Implemented: orders 1-6. What is still owed (a real-device listening pass) is listed under NOT YET
DONE in section 11.


1. WHAT THIS IS
===============
Every gameplay sound in the game is SYNTHESISED FROM CODE at first launch. There are no .wav or
.ogg assets, and there must not be any: the project's whole art pipeline is procedural (walls,
props, weapon sprites, HUD, route icons are all drawn from primitives), and audio follows the same
rule for the same reasons — no licensing, no asset size, and a sound is retuned by editing a number.

This layer is the WORLD making noise: guns, damage, impacts, enemies, explosions. It is deliberately
separate from `render/StoryAudio`, which is ORA's voice — four speaker stings and three interface
cues for the narrative UI. The two share only `audio/PcmWavWriter` and have independent settings,
because somebody may well want her stings without gunfire, or gunfire without them.

THE STANDING RULE, inherited from the story layer: **the game must be fully playable and fully
understandable with audio off.** Every sound here is redundant with something already on screen —
the HP bar carries the number, the event text names GUARDED vs FLANKED, the ammo digits say the gun
is loaded. Audio is a second channel for information the player already has, never the only one.


2. THE PACKAGE
==============
`ge.tbegvadze.toon3d.audio` — split headless / LibGDX, like the tileset subsystem.

HEADLESS (usable from `sim/`; `WaveformKind` imports only `MathUtils`, which is pure math):
  GameSoundId.java        enum — the stable id of every sound; the call-site vocabulary.
  SoundCategory.java      enum — the five mix buses (PLAYER_WEAPON / PLAYER_STATE / ENEMY /
                          ENVIRONMENT / INTERFACE).
  WaveformKind.java       enum — NOISE / SINE / SQUARE / CHIRP_SINE / CHIRP_SQUARE /
                          EXPONENTIAL_CHIRP_SINE / METAL (order 6). Each constant implements
                          `sampleAt` with its OWN body (the `EnemyType` idiom), so the synthesiser
                          holds no switch.
  SoundLayer.java         immutable one-voice recipe + fluent Builder.
  SoundDefinition.java    id + category + layers + volume + priority + cycleSpread +
                          minimumRetriggerSeconds + loudness + an optional room echo (order 6),
                          + Builder.
  SoundRegistry.java      register/get by ordinal; weapon -> fire sound, weapon -> impact sound and
                          enemy family x moment -> voice bindings (plus a per-moment fallback).
                          Array-backed, no HashMap on a firing path.
  GameSoundCatalog.java   `bootstrap()` — THE CONTENT FILE. One `register(...)` per sound.
  SoundMixer.java         the mixing rules: per-turn category counters, re-trigger windows, voice
                          pressure, the story duck, the variation cycle. Pure state + a clock.
  SfxVolumeSetting.java   ON / QUIET / OFF, with the volume multiplier for each.
  NoiseListener.java      the noise-propagation seam (order 5): `onNoise(column, row, loudness,
                          category)`. No consumer yet — see section 12.

IN THE ENEMY PACKAGE (order 3), so `EnemyManager` never imports audio:
  enemy/EnemyVoiceMoment.java    enum ALERT / ATTACK / DEATH, + WIND_UP (order 6 — never a family
                                 voice; resolves through the fallback to ENEMY_WIND_UP). (The design placed this in `audio/`;
                                 it moved to `enemy/` because the listener that names it is fired
                                 from `EnemyManager`, and the enemy layer must not import audio.)
  enemy/EnemyVoiceListener.java  `onEnemyVoice(Enemy, EnemyVoiceMoment)`, the ALERT + DEATH hook.

IN THE DOOR PACKAGE (order 4), so `DoorManager` never imports audio:
  door/DoorStateListener.java    `onDoorOpening(column, row)` / `onDoorClosing(column, row)`.

LIBGDX (the only three classes here that import `com.badlogic.gdx` beyond MathUtils):
  PcmWavWriter.java       PCM -> 44-byte RIFF/WAVE -> local file cache -> `Gdx.audio.newSound`.
                          SHARED with `render/StoryAudio`, which was refactored onto it so the
                          codebase has one WAV writer rather than two that can drift.
  SoundSynthesizer.java   recipe -> float accumulator -> soft clip -> PCM16.
  GameAudio.java          the facade. `Disposable`. Owns one `Sound` per id.

Why a new package and not `render/`: gameplay sound is fired from the SIMULATION —
`PlayerController`, `World`, the enemy attack path — and putting the engine in `render` would force
the input and enemy packages to import a renderer. `entity/ImpactEventListener` and
`enemy/EnemyAttackListener` exist precisely to prevent that coupling; both say so in their comments.
Nothing here runs inside `render()`, owns a GL resource, or touches a camera.


3. THE SYNTHESIS TOOLKIT (util/GameMath)
========================================
`storyStingSample()` — the story layer's sine/square oscillator times a SYMMETRIC linear fade — is
correct for a UI blip and completely wrong for gunfire, which is broadband noise with a hard
transient and an exponential decay. These primitives are the gameplay toolkit. All are pure, and
all run at synthesis time only (startup), never per frame.

  whiteNoiseSample(seed, index)           SplitMix64-finalised hash noise. DETERMINISTIC, which is
                                          what makes the WAV cache valid forever.
  onePoleCoefficient(cutoffHz, rate)      exp(-2*PI*fc/fs), the pole for the filters below.
  onePoleLowPassStep(prev, in, coef)      y = (1-c)x + c*y'. Unity gain at DC, cannot amplify.
  onePoleHighPassStep(prevOut, prevIn,    y = c*(y' + x - x'). Separates a gunshot's bright crack
                      in, coef)           from its low blast body. BAND-PASS = high-pass then
                                          low-pass (that is what `SoundLayer.bandPass` sets up).
  percussiveEnvelope(i, total, attack,    linear attack, then a NORMALISED exponential decay that
                     decayRate)           reaches exactly zero at the last sample. The
                                          normalisation is the point: any non-zero final sample is
                                          a step discontinuity, i.e. an audible click.
                                          decayRate 2 = soft swell, 6 = gunshot, 12 = click.
  linearChirpPhase(...)                   phase = the INTEGRAL of frequency, not f(t)*t — the
  exponentialChirpPhase(...)              classic beginner bug sweeps at double the intended rate.
                                          Linear reads MECHANICAL (every gun); exponential reads
                                          MUSICAL (railgun charge, death).
  amplitudeModulation(hz, t, depth)       unipolar chop. depth 1 = full ring mod: "chainsaw" at
                                          35 Hz, "electricity" at 60 Hz.
  softClipUnit(value)                     Pade [3/2] tanh. Summed layers saturate instead of hard
                                          clipping, which is what makes phone audio painful.
                                          Exactly 1 at |v|=3, so the clamp joins it continuously.
  toPcm16(value)                          round to signed 16-bit, clamped.
  sfxDistanceVolume(...)                  inverse-square + a linear taper over the last tiles, so
                                          nothing POPS to silence at the cutoff. EUCLIDEAN in tile
                                          space — deliberately NOT the Chebyshev metric gameplay
                                          range uses: range is a RULE, audio distance is a
                                          PERCEPTION, and conflating them makes diagonals wrong.
  sfxStereoPan(...)                       dot with the project's right-of-facing vector
                                          (directionY, -directionX), normalised, scaled by
                                          PAN_STRENGTH so a hard pan never empties one earbud.
  sfxRearFactor(...)                      a source behind is quieter (and, at the call site, duller)
                                          — the only front/back cue available with cardinal facing.
  sfxStackedVolume(...)                   geometric damping of the Nth voice in a turn.
  sfxPitchFromCycle(...)                  the variation cycle (below).
  metalBarSample(f0, t, damping)          (order 6) struck metal: free-free bar partials at the
                                          INHARMONIC ratios 1 : 2.756 : 5.404 : 8.933, each decaying
                                          faster than the last, so the bright end of a clang dies
                                          first. Behind `WaveformKind.METAL`.
  echoTailSeconds(delay, feedback, floor) (order 6) repeats until feedback^n < floor, times delay.
  endFadeGain(i, total, fade)             (order 6) linear fade forcing the last sample to 0.

Sample rate is `GAME_SFX_SAMPLE_RATE_HZ = 22050`, half the story layer's. A phone speaker
reproduces almost nothing usable above ~10 kHz and every noise layer is low-passed below 6 kHz
anyway. Each WAV declares its own rate in its header, so the two layers never have to agree.

Per-layer pipeline in `SoundSynthesizer`: oscillator -> high-pass -> low-pass (cutoff may sweep)
-> amplitude modulation -> envelope -> layer amplitude -> accumulate at the layer's delay offset.
Then once for the whole sound: [room echo + end fade, order 6, only if the recipe has one] -> soft
clip -> PCM16.

THE ROOM ECHO (order 6): `SoundDefinition.Builder.roomEcho(delaySeconds, feedback, dampingHz, wetMix)`
is a feedback delay line with a one-pole low-pass in the loop, applied once to the summed layers:
    echo[n] = lowPass( dry[n - D] + feedback * echo[n - D] ),   out[n] = dry[n] + wetMix * echo[n]
so every repeat is quieter AND duller than the last — what concrete does to a gunshot. The tail is
`echoTailSeconds` long (to GAME_SFX_ECHO_SILENCE_LEVEL, ~-40 dB), capped so the whole sound stays
within GAME_SFX_MAX_DURATION_SECONDS; because the cap can cut the tail short, an echoed sound takes a
GAME_SFX_END_FADE_SECONDS linear end fade so its last sample is 0. The echo parameters join the WAV
cache key ONLY when present, so recipes without one keep their existing cached files. Loud events
only: ballistic fire, railgun, rocket, explosions — never UI, pickups, voices or the player's body.
FILTERING HAPPENS BEFORE THE ENVELOPE, deliberately — filtering an already-enveloped signal smears
its attack transient, and the transient is what makes a gunshot read as a gunshot on a small speaker.


4. THE CATALOG
==============
70 sounds today, under `GAME_SFX_MAX_DISTINCT_SOUNDS = 72`. The cap was 64 through order 5 and was
raised to 72 by order 6 at the OWNER's explicit request for more sounds (idea file D1). Exceeding the
cap is still a design failure, not a reason to raise the constant again on an agent's own judgement.

  weapon fire      14, one per ItemType weapon row, + WEAPON_FIRE_DEFAULT
  weapon state     RAILGUN_CHARGE, DRY_FIRE, RELOAD_START, RELOAD_COMPLETE, WEAPON_SWITCH
  player state     HURT_LIGHT, HURT_HEAVY, GUARDED, FLANKED, DEATH, MOVE_BLOCKED
  impact           BALLISTIC, ENERGY, MELEE, BLOCKED
  enemy / world    ENEMY_ATTACK_RANGED, BARREL_EXPLOSION
  enemy voices     18 = six EnemyFamily x { ALERT, ATTACK, DEATH }   (order 3)
  facility         DOOR_OPEN, DOOR_CLOSE, DOOR_LOCKED, STAIRS_DESCEND,
                   PICKUP_AMMO / _MEDICAL / _ARMOUR / _KEYCARD / _WEAPON / _CREDIT,
                   PLAYER_HEAL, LEVEL_UP, KILL_CONFIRM, FOOTSTEP       (order 4)
  order 6          HEAL_STATION, LOW_HEALTH_WARNING, ENEMY_WIND_UP, TERMINAL_ACCESS,
                   UI_MENU_OPEN, UI_MENU_CLOSE

HISTORY: at order 4 the catalog was full. The design's own tally (62) omitted LEVEL_UP and
KILL_CONFIRM, so order 4 came in three over. Three rows were CUT rather than the cap raised:
  ENEMY_ATTACK_MELEE, ENEMY_DEATH  the order-2 generics. With all six families voiced they could never
                                   play; an unbound family now borrows the ABERRATION voice instead.
  DOOR_UNLOCK                      a keycard unlock opens the door in the same instant on the same
                                   tile, so DOOR_OPEN already says it — two sounds there were mush.
Two slots remain after order 6; past that, anything added must REPLACE a row. The next cut candidate
is still FOOTSTEP (see below).

HEAL, HEAL_STATION and LEVEL_UP are the only HARMONICALLY PLEASANT sounds in the catalog, on purpose: in a
game this grim, "you are less hurt" and "you got stronger" are where the ear may relax. Pickups are
short receipts, never events. KILL_CONFIRM (0.18) and FOOTSTEP (0.12) are the floor of the mix;
FOOTSTEP also has the lowest priority, so it is the first voice dropped under pressure.

ENEMY VOICES ARE PER FAMILY, NEVER PER `EnemyType`. The player learns six sound-shapes, not twenty,
and a new archetype in an existing family inherits its family's voice for free. Each family is ONE
BASE RECIPE — a function from a moment's SHAPE to layers — expanded into three sounds by
`registerFamilyVoice(...)`. The shape is what the moments share across every family (ALERT 0.20 s
and rising, ATTACK 0.15 s and hardest, DEATH 0.40 s and falling); the recipe is the family's
character:
  ABERRATION  wet: low-passed (1.3 kHz) noise under a rising sine gurgle (90 -> 130 Hz)
  UNDEAD      dry rasp: band-limited noise chopped at 18 Hz; no tone at all
  INSECT      chitter: 2.5-6 kHz noise chopped at 55 Hz
  MACHINE     servo: a swept square + a relay tick; the only family with NO noise
  DEMON       the loudest and longest: a 70 -> 110 Hz moan under broadband noise
  GOLEM       struck stone: 180 Hz + an INHARMONIC 2.76x partial over low-passed grit
Voices play at the enemy, pitched DOWN by its `heightMultiplier`, so two archetypes of one family
still differ by size. A family with no binding borrows the ABERRATION voice (the baseline bestiary)
for all three moments — heard, never silent, and no extra synthesised sound.
A RANGED attack keeps the shared ENEMY_ATTACK_RANGED launch whatever the family: "it shot at me"
versus "it swung at me" is the lane rule made audible, and must not depend on the family.

THE DESIGN RULE BEHIND THE NUMBERS: ballistic weapons are NOISE (broadband body + bright crack +
low punch); energy weapons are PITCHED (descending tones where the ballistics are noise). That
contrast is what makes fourteen weapons distinguishable by ear on a phone speaker. Melee weapons
separate by MASS: fist dull, knife bright, hammer heavy, chainsaw continuous.

IMPACTS ARE KEYED BY THE WEAPON THAT FIRED, NOT BY THE TARGET — buckshot patters, plasma sizzles, a
hammer thuds. Four impact recipes therefore cover every weapon against every enemy, forever, and a
new enemy needs no new impact sound. `GameAudio` remembers the last weapon fired (an impact always
follows a shot) so no effect system has to be told which weapon is equipped.

Volumes are pre-mix and were derived with the shotgun as the anchor. They are PLACEHOLDERS for a
playtest pass on a real device; retuning one is a one-line edit in the catalog.


5. VARIATION
============
Zero pre-baked variants: every sound is exactly one cached WAV and all variety comes from
`Sound.play(volume, pitch, pan)`, which is free on both backends.

A CYCLE plus a JITTER, never pure randomness — random sequences repeat values, and a chaingun that
fires the same pitch twice in a row sounds broken. `GAME_SFX_PITCH_CYCLE` has no equal adjacent
entries; `cycleSpread` scales its excursion per sound (0.15 for the double barrel, which should
sound identical every time; 1.0 for the chaingun, which should obviously vary). The jitter reuses
`whiteNoiseSample`, so the same play count always yields the same pitch and an audio bug reproduces.


6. DISTANCE, DIRECTION AND MIXING
=================================
The player's own weapon is a SEPARATE entry point (`playPlayerWeapon`) from positional sound
(`playAt` / `playAtWorld`): it is in your hands, so it is always centre, always full volume, never
attenuated. No caller should have to remember to pass the player's own tile.

Mixing rules, all in `SoundMixer`:
  1. PER-TURN CATEGORY CAP. ENEMY caps at 3 voices a turn; the rest are DROPPED, never queued —
     a growl arriving a second after its turn is a lie about where things are.
  2. STACK FALLOFF. The Nth voice of a category in a turn plays at 0.7^(N-1). Three swings become
     one loud, one medium, one faint, which reads as three attacks; three equal ones read as noise.
     This single rule does most of the anti-mush work.
  3. MINIMUM RE-TRIGGER INTERVAL per sound, from its definition (chaingun 0.04 s, footsteps 0.10 s).
  4. GLOBAL VOICE PRESSURE. A decaying count of recently started voices; over the cap, the
     LOWEST-priority request loses. An approximation — the backend's live voice count cannot be
     queried — that exists to stop a barrel chain starving the player's own gunshot. Sits well under
     Android SoundPool's default of 16.
  5. STORY DUCK, one-way. Gameplay sound starting within GAME_SFX_STORY_DUCK_SECONDS of a story
     sound plays at GAME_SFX_STORY_DUCK_FACTOR, so a gunshot never buries ORA's sting. `StoryAudio`
     runs a cue-played listener each time one of its sounds ACTUALLY starts (never while its SOUND
     knob is off), which `World` wires to `GameAudio.noteStoryCuePlayed`. The reverse is not
     needed: story cues are quiet, sparse, and never carry information alone.

APPLICATION RESUME: `World.onApplicationResume` calls `GameAudio.onApplicationResume`, which drops
the mixer's re-trigger timestamps, voice-pressure window, duck stamp and per-turn counters, so the
first sounds after the OS hands the app back are not judged against stale state. Nothing needs
stopping on PAUSE: every sound is under a second and the OS pauses the audio device itself.

RANGED LAUNCH PITCH: the shared ENEMY_ATTACK_RANGED plays at the shooter's FAMILY launch pitch
(`registerFamilyVoice`'s `launchPitch`: DEMON 0.70, UNDEAD 0.80, ABERRATION 0.90, GOLEM 1.00,
MACHINE 1.15, INSECT 1.35) divided by its size — one recipe, so "it shot at me" never depends on the
family, but who shot is still audible. A per-family launch RECIPE would cost six sounds the cap has
no room for.

THE TURN BOUNDARY IS DETECTED BY TIME, not by a call from the tick bus
(`GAME_SFX_TURN_WINDOW_SECONDS`). This is a deliberate departure from the design document, which
proposed an explicit `beginTurn()` from `World`. Every sound a turn produces is fired within the
same frame — the player acts, then every enemy resolves in one instant — so a short elapsed window
identifies a turn exactly as well, and cannot be silently missed. That matters because a missed
reset is not a small bug: the per-turn counters would climb forever and every enemy sound after the
third would be dropped for the rest of the run. `SoundMixer.beginTurn()` remains as an explicit
reset for a hard boundary; correctness does not depend on it being called.

While a hard-pause overlay owns the screen, gameplay sound does not start AT ALL (`setSuppressed`).
A bark queues behind a modal; a gameplay sound is simply not made, because the world is not ticking
and nothing in a frozen world should be audible. The mixer clock keeps running so re-trigger windows
stay honest across the pause.


7. OWNERSHIP AND THE DISPOSE CHAIN
==================================
`World` owns exactly ONE `GameAudio`, constructed beside `storyAudio` and disposed in the same
chain. Every system that fires a sound receives it by setter injection; nothing else constructs one.
Four systems each synthesising their own copy of the catalog would be four times the device voices
and four times the file writes, for identical audio.

DEGRADES TO COMPLETE SILENCE when `Gdx.audio` is null — headless test runs, `sim/SimWorld`, a device
with no audio. Every play method becomes a no-op rather than throwing. This is what keeps the
balance simulator and the whole existing test suite working untouched.

9. THE SETTING
==============
A fifth knob on the codex's settings strip: EFFECTS, cycling ON -> QUIET -> OFF.
Three states rather than a slider because three states are one tap and fit the existing strip
geometry, and because the commonest real request for phone game audio is neither "loud" nor "off"
but "in the background". Persisted through the existing `StoryProgressStore` under
`GAME_SFX_SETTING_KEY`; additive, no `SCHEMA_VERSION` bump. Independent of the story layer's SOUND
knob, and pushed into `GameAudio` by `World.applyStoryAccessibilitySettings()`.

Its four string ids live in `narrative/CodexStrings` AND `assets/story/story-strings.properties`,
like every other story string — `StoryLocalizationTest` fails if they drift apart.


10. ADD A SOUND (the recipe)
============================
0. Check the cap (70 of 72 used after order 6): past it, a new sound REPLACES a row.
1. Add a constant to `GameSoundId`.
2. Add ONE `register(...)` call in `GameSoundCatalog`, describing its layers.
3. For a weapon: one `bindWeapon(...)` and one `bindWeaponImpact(...)` line in the same file.
   For a new ENEMY FAMILY: three `GameSoundId`s and one `registerFamilyVoice(...)` call (its base
   recipe) — it registers the three sounds and binds them. A new `EnemyType` in an EXISTING family
   needs no audio work at all.
4. Fire it from the relevant system (inject `GameAudio` by setter if it does not already have it).
5. Update this doc.

That is the whole procedure. There is NO edit to the synthesiser, the mixer, the registry or any
switch statement — the same "never a switch statement" discipline as `route/RouteRegistries` and
`tileset/EnvironmentSpriteRegistry`. A weapon with no binding falls back to WEAPON_FIRE_DEFAULT
rather than being silent, which is a bug nobody notices in review and everybody notices in play.

TESTING: none. Per CLAUDE.md's Testing Policy, new tests are written only for game balance, and no
formula here is balance-bearing. `./gradlew test` and `./gradlew balanceSim` must produce IDENTICAL
results before and after any change to this layer — a difference means audio has leaked into
gameplay state, which is the one thing that would make this layer dangerous.


11. THE MIX (order 5) AND WHAT IS STILL OWED
=============================================
THE TUNING PASS THAT WAS DONE is an OFFLINE one: every recipe synthesised, run through a rough
phone-speaker curve (two one-pole high-passes at 250 Hz, a low-pass at 8 kHz — a phone reproduces
almost nothing below ~200 Hz and is strongest where the ear is most sensitive), and its loudest
50 ms RMS x base volume compared in dB against the SHOTGUN anchor. An unweighted RMS was tried
first and is badly wrong for this: it rates the sub-heavy sounds (hurt, hammer, death) loud and the
bright ones (insect, plasma, pickups) quiet — the opposite of a phone. What the curve found, and the
fix for each:
  PLAYER_DEATH louder than BARREL_EXPLOSION (the ceiling)   volume 1.00 -> 0.80
  MOVE_BLOCKED inaudible (all 90 Hz)   + a 220 Hz layer, noise low-pass 400 -> 1100 Hz, vol 0.55
  FOOTSTEP ~25 dB under KILL_CONFIRM (all < 350 Hz)   low-pass 1400 Hz, amp 1.0; volume stays 0.12
  RAILGUN_CHARGE louder than the shotgun (a tell, not a shot)   0.50 -> 0.28
  FIRE_PLASMA / FIRE_ARC_CANNON above the shotgun (pitched = phone sweet spot)  0.42 / 0.50
  PLAYER_GUARDED / FLANKED ~+5 dB over the shotgun   0.40 / 0.48 (still at the shotgun's level)
  PICKUP_MEDICAL level with the shotgun (a receipt!)   0.25;  PLAYER_HEAL 0.45;  IMPACT_BLOCKED 0.35
  family voices spread ~10 dB, ABERRATION (the fallback) quietest, DEMON not loudest
    -> ABERRATION low-pass 700 -> 1300 Hz, base 0.65; UNDEAD 0.65; INSECT 0.65; DEMON 0.80.
       Now within ~4 dB of each other with DEMON loudest.
Resulting anchors on the curve: shotgun 0, barrel +7.7 (still the ceiling), death +6.8, family
ALERTs -9..-5, KILL_CONFIRM -16.6, MOVE_BLOCKED -14.3, FOOTSTEP -27.4.

NOT YET DONE — and it cannot be done from code:
  A LISTENING PASS on a real phone speaker AND on cheap earbuds (the design's BALANCE NOTES order:
  master first, then weapons against the shotgun, then the enemy stack falloff with six awake
  enemies, then GAME_SFX_REFERENCE_TILES). Every number above is a better-founded placeholder,
  not a verdict. "Delete whatever the playtest hated" waits on that playtest.

DECLINED from the open questions, deliberately:
  RAILGUN "capacitor full" second tone (Q3) — redundant with the event text, and the catalog is at
    its cap; a pitch-shifted replay of RAILGUN_CHARGE would read as a second charge, not "ready".
  region-flavoured ALERT pitch (Q5) — makes an audio parameter depend on persistent narrative
    state for atmosphere alone. If it ever happens: a per-region pitch table in the catalog, never
    an `if` in the mixer.

FOOTSTEPS are flagged in the design as the highest-risk entry and the first candidate for deletion.
The standing rule, inherited from the story layer's pacing budget: the fix for "too much sound" is
to DELETE ROWS, never to add another toggle.

12. THE NOISE SEAM (order 5)
============================
RELATIONSHIP TO `.claude/agents/ideas/noise-propagation-and-3d-sound-cues.txt` (NOT IMPLEMENTED):
that system decides what ENEMIES hear (gameplay, deterministic, must run headless in `sim/`); this
one decides what the PLAYER hears (presentation, mutable, switchable off). They must not be merged
— but they share the EVENT, so that system inherits every firing site here instead of growing its
own.

Every `SoundDefinition` declares a `loudness` 0..100 (all 64 do, explicitly; 0 = makes no noise:
the player being hurt or dying, LEVEL_UP, KILL_CONFIRM). `GameAudio.setNoiseListener(...)` takes an
`audio/NoiseListener`, and every play entry point reports
    onNoise(originTileColumn, originTileRow, loudness, category)
— at the source tile for positional sounds, at the player's tile for sounds at the ear (so a
FOOTSTEP or a gunshot is reported where the player stands). Primitives, so nothing allocates.

THE RULE THAT MAKES IT SAFE: the noise is reported BEFORE every presentation gate — the EFFECTS
setting (even OFF), hard-pause suppression, the distance cutoff, the mixer's caps and re-trigger
drops, and whether a WAV exists at all. Muting the game can never change what an enemy hears.
`GameAudio` constructs fine headless (it bootstraps the registry and simply synthesises nothing),
so `sim/SimWorld` can own one to receive noise when that system lands. The `category` lets a
consumer ignore, e.g., the enemies' own voices. Nothing implements the listener yet.


13. ORDER 6 — THE SILENT MOMENTS AND A HALF-LIFE-INSPIRED FACILITY
===================================================================
Spec: `.claude/agents/ideas/procedural-sound-effects-order-6.txt`.

THE SILENT MOMENTS. Healing was the worst gap: only the HEAL button's path played PLAYER_HEAL, so a
medkit used from the INVENTORY and the auto-doc HEAL STATION restored HP in silence. Both are wired
now (section 8), plus the suit's LOW_HEALTH_WARNING, the shared ENEMY_WIND_UP telegraph, terminal /
event-console chatter and the inventory's open/close blips. Every one is still redundant with
something drawn (green heal text + particles, the HP bar, the rim-flash telegraph, the overlay).

THE RETUNE — inspiration, never imitation. No recreated or sampled Half-Life sound, and no voice
(there is no VO in this game). What was taken is the production LANGUAGE of an industrial research
facility heard through its own hard rooms:
  ROOMS      room echo on pistol, shotgun, double barrel, chaingun, assault rifle (short and dry on
             the rapid-fire pair), railgun, rocket and BARREL_EXPLOSION (the longest — the room
             answers a blast, cut at 1.0 s and faded).
  METAL      WaveformKind.METAL in the doors' seated clank, reload clacks (mag out; mag seated +
             slide racked), PICKUP_AMMO / _WEAPON / _ARMOUR, the pistol's two-bounce casing, the
             shotgun's pump, PLAYER_GUARDED (a blow glancing off the guard now RINGS), the
             WEAPON_SWITCH tick and FOOTSTEP (a boot on grating). PLAYER_FLANKED keeps its dulled,
             detuned clang — "wrong" must stay audibly different from "guarded".
  PNEUMATICS DOOR_OPEN = seal hiss -> slide -> clank; DOOR_CLOSE = slide -> clank -> seal hiss;
             DOOR_LOCKED = the DENY buzz (two squares a few hertz apart, so it beats).
  THE SUIT   clean edged bleeps (SQUARE through a low-pass, never raw): PLAYER_HEAL (injector hiss +
             a rising fifth-then-octave), HEAL_STATION (charger hiss, climbing charge, two confirm
             bleeps), PICKUP_ARMOUR (a rising charge whine), LEVEL_UP (a bleep before the triad),
             LOW_HEALTH_WARNING, and a FLATLINE tone at the end of PLAYER_DEATH — which still ends
             inside the 1.0 s cap, so the DEATH STROKE's silence is untouched.
  HANDLING   the shotgun PUMPS after the shot, the pistol drops a casing, and fist / knife / hammer
             WHOOSH before contact (the contact layers start 60 ms behind the swing).

VERIFIED OFFLINE (a scratch render, not a committed test): all 70 sounds <= 1.0 s, peak <= 92 % after
soft clip; every sound ends on 0 except FIRE_CHAINSAW, RAILGUN_CHARGE (both untouched since order 5)
and ENEMY_WIND_UP, which end at +/-2 LSB (~-84 dBFS — below audibility; the percussive envelope reaches
exactly zero one sample past the buffer on a slow attack). `./gradlew balanceSim`'s summary was
byte-identical before and after, which is the proof that no sound leaked into gameplay state.

NOT DONE HERE (next order): fire ignition / hazard crackle, the golem-ability events (spire, shard,
crust), route-map and pause-menu UI sounds, a bullet ricochet (no wall-hit event exists to hang it on).
Each needs a new seam in another package. The real-device listening pass (section 11) now covers the
order-6 recipes too.
