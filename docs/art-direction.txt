ART DIRECTION — "LIT BY THE MACHINE"
=====================================
The style bible. Single source of truth for the game's look: the palette, the five lighting
moods, the atmosphere grade, what is exempt from it, and the floor/ceiling materials.
Created by visual-identity-order-1; every later visual-identity order extends it in the same
commit as its code. Ideas: .claude/agents/ideas/visual-identity*.txt.


1. PILLARS
----------
Darkness is the canvas. Each of the five regions has ONE coloured atmosphere: a near light, a far
haze, a horizon colour and a floor/ceiling material. One screenshot is enough to tell how deep you
are. Things that glow and mean something are never tinted or fogged. Threats read above the world,
and the world sits back. The interface uses exactly two inks: SUIT AMBER on gunmetal (the player's
own suit, ORA's colour) and FACILITY CYAN on near-black (everything the facility shows you).
Semantic combat colours are reserved and never decorate chrome.

Series rules (repeated by every order):
  V1  No new image/font/audio ASSET files, no new dependency. Everything new is generated in code.
  V2  No custom ShaderProgram. SpriteBatch / ShapeRenderer colour multiplication (and, since
      render-performance-full-hd, the floor/ceiling as vertex colours on textured quads through the
      default shader) only, so every GLES2 phone behaves the same.
  V3  No allocation in any render() path.
  V4  The 2D game is untouched: no symbol, rule, turn cost, balance number, persistence key or touch
      hit area changes.
  V5  Semantic colours are sacred (red damage, blue defence, purple special, yellow movement intent,
      green health/buff) — CombatPalette / ArtDirection, never decoration.
  V6  Emissive exemption (SECTION 5).
  V7  Not balance-bearing: zero new tests; verified by build + run.
  V8  Readability beats mood. If a mood makes an enemy, pickup, number or button harder to read on a
      phone, the mood loses.

3. THE FIVE MOODS — render/LightingMood + LightingMoodRegistry + LightingMoods.bootstrap()
-----------------------------------------------------------------------------------------
One mood per route region, keyed by RegionAmbience.lightingMoodId() (route-map order 10's hook, now
CONSUMED). Numbers live in ArtDirection (MOOD_<ID>_*), rows in LightingMoods.bootstrap().
Tints are RGB multipliers whose Rec.601 luminance is in [0.95, 1.05] — the grade shifts HUE with
distance, never exposure. Fog distances in tiles.

  id                 region             near tint           far tint            fog       vignette  floor / ceiling
  cool_steel         A OUTER FACILITY   (0.92,1.00,1.10)    (0.62,1.08,1.40)    1.5-11.0  0.40      deck_grating_steel / ceiling_strip_lights
  clinical_white     B RESEARCH WING    (1.00,1.00,0.98)    (0.80,1.12,0.92)    1.5-11.0  0.30      lab_tile_white / ceiling_panel_grid
  amber_hot          C REACTOR DEPTHS   (1.10,0.98,0.80)    (1.55,0.86,0.40)    1.5-10.0  0.45      reactor_grate_hot / ceiling_pipes
  corrupted_violet   D THE BREACH       (1.08,0.95,1.02)    (1.70,0.62,1.10)    1.0-8.0   0.55      breach_flesh_membrane / ceiling_torn_conduit
  core_white_violet  E THE CORE         (0.98,0.98,1.12)    (1.05,0.80,1.85)    1.5-11.0  0.50      core_circuit_plate / ceiling_lattice
Horizon colours (packed RGBA): see ArtDirection MOOD_<ID>_HORIZON_FLOOR_PACKED / _CEILING_PACKED.

Resolution (World.resolveLightingMood, called in buildLevelDependentResources before any renderer is
built): DEV override (SECTION 8) → routePlan.regionForDepth(currentDepth).themeId → RegionAmbience →
lightingMoodId → registry. No plan / depth outside the plan / no ambience → fallback cool_steel with
one log line. Logs "Atmosphere mood=<id>". Floors change behind a fade, so moods switch at level build
(no blending).

Fail-loud (R11): LightingMoods.bootstrap() throws IllegalStateException if any region of
RegionPlan.defaultPlan() names a mood that is not registered, or a mood names an unregistered material.


4. THE GRADE PIPELINE — render/AtmosphereGrade
----------------------------------------------
For a surface at distance d tiles with the existing scalar shade s (falloff × face × tile brightness,
clamped exactly as before, including the minimum-brightness floor):
  fog     = GameMath.atmosphereFogFactor(d, fogStart, fogEnd)      clamped smoothstep
  tint    = lerp(near, far, fog)                                    per channel
  tint    = lerp(WHITE, tint, strength(surface class))              per channel
  channel = clamp01(s × tint.channel)
then the red-alert boost/dampen exactly as before, on top. The muzzle-light splash (section 11, order 2)
is NOT folded into that clamped multiplier: it is added afterwards (albedo × lightAdd), so only the final
colour clamps. BLACKOUT, tile lighting and the shade floor
all feed s, upstream of the grade.

Strength by surface class (ArtDirection): GRADE_STRENGTH_ENVIRONMENT 1.00 (walls, doors, columns,
floor, ceiling, props, decals, pickup bodies, shop machine body), GRADE_STRENGTH_ENEMY 0.50 (enemy
bodies — threats read warmer and cleaner than the haze behind them), GRADE_STRENGTH_WEAPON 0.60.

Where it runs:
  WallRenderer          per column, on WORKER threads → static AtmosphereGrade.evaluateInto into the
                        column's own `gradeScratch` (never the shared evaluate() fields).
  FloorCeilingRenderer  on the GPU (render-performance-full-hd): per TILE CORNER of the view lattice for the
                        near region (AtmosphereGrade.evaluateInto at the corner's depth, interpolated
                        perspective-correctly across the tile) and per ROW of the far band (`rowTintTable`,
                        ctor + setRenderResolution). The texel factor is GameMath.floorSpanAdjustedShade /
                        floorSpanRedFactor / floorSpanGreenBlueFactor - the CPU caster's expression, now the
                        vertex colour. See "FLOOR / CEILING PIPELINE" below.
  PropRenderer          per sprite (render thread, grade.evaluate()); depth in tiles. The muzzle-light add
                        is read right after evaluate() (bodyLightAdd*), zeroed for emissive draws, and drawn as an additive
                        re-draw of the body.
                        Contact shadow BEFORE the body (section 10).
  ShopMachineRenderer   body sprite only (+ additive muzzle-light re-draw of the body; contact shadow before it).
  EnemyRenderer         body: shade × level.getTileBrightness(enemy tile) (R5, like props) → existing min
                        clamp / dormant dampen / BLACKOUT floor → grade 0.5 → status and boss tints lerped
                        ON TOP, ungraded. Muzzle light is added to the graded body colour at FULL strength
                        (not 0.5) as an additive re-draw after the sprite columns; the status and boss tints are unaffected. Contact shadow BEFORE the body
                        (section 10); enemy sheets are alpha-cut at load (section 9).
  WeaponHudRenderer     no distance term: lerp(WHITE, near, 0.6) × clamp(player tile brightness,
                        0.80, 1.15), channels capped at 1 (AtmosphereGrade.evaluateWeaponTint →
                        setWeaponTint). Frame draws only; muzzle/idle effect sprites untinted.
  ViewVignetteRenderer  radial alpha (clear inside 55% of the normalised elliptical radius, quadratic
                        ramp reaching full alpha exactly at the VIEW corners — the ramp is measured in
                        view coordinates even though the quad is oversized — GameMath.vignetteAlpha), colour = the mood's ceiling
                        horizon colour, alpha = mood.vignetteAlpha. Drawn after every world pass
                        (including impact particles) and immediately BEFORE WeaponHudRenderer.render;
                        the weapon, hit vignette, mini-map, HUD, touch buttons and every overlay draw
                        over it. Oversized by VIGNETTE_SHAKE_MARGIN_WORLD_UNITS so screen shake never
                        exposes its edge.
The mini-map is UI and is not graded.


5. EMISSIVE EXEMPTION (V6)
--------------------------
Never graded (their tile light is unchanged from before this order — they keep the scalar
shade they always had, so their colour is identical under every mood): enemy health bars, HP text, name tags, intent/telegraph
icons, beam/affliction/shard/crust/haze overlays, boss enrage/repair tints and afterimages, the keycard
aura, weapon-pickup tier glow, credit-chip aura, the shop machine's aura/window/status light/dispense
drop/holo layers, hazard fire and toxic frames and the portal (PropRenderer: Level.isHazardDecal ||
Level.isStairsDown — existing predicates, no symbol switch), enemy attack effects, impact particles, the
guard shield, every vignette. Textures that mix body and glow in one image (AI core node, holo table)
are graded as bodies.


6. MATERIALS — render/SurfaceMaterialRegistry + SurfaceMaterials.bootstrap()
----------------------------------------------------------------------------
Ten 64×64 (RenderConstants.SURFACE_MATERIAL_SIZE) packed-RGBA8888 int[] textures, row-major
`row*64+column`, row 0 = the tile's south edge, column 0 = west — the layout FloorCeilingRenderer
samples. Generated on the CPU, deterministic (GameMath.combineHash, never java.util.Random), cached
once and SHARED across floors (read-only).
Value band (R9, pre-shade average luminance): floors 0.10-0.24, ceilings 0.06-0.18, so floor and
ceiling always sit below the walls.
  deck_grating_steel     steel plates, 32-texel seams, diamond tread, corner bolts
  ceiling_strip_lights   32-texel panels with one fluorescent lens each (texture only, not a light)
  lab_tile_white         16-texel tiles, value jitter, grout, the odd stain
  ceiling_panel_grid     acoustic panels with a slim recessed light slot
  reactor_grate_hot      coarse 16-texel grating (6-texel bars — an 8-texel period aliases into moire
                         at backdrop distance), ember underglow in each cell, low-contrast chevron wear
  ceiling_pipes          two pipes along X with highlight rows and clamp rings
  breach_flesh_membrane  Worley-style cellular veins, wet specks, a stray deck-plate fragment
  ceiling_torn_conduit   torn panel edges, hanging conduits, fleshy growth blobs
  core_circuit_plate     orthogonal traces with node pads on an 8-grid
  ceiling_lattice        diagonal lattice beams with crossing nodes


Mip chain and LOD (render-quality follow-up): SurfaceMaterialRegistry caches, per material, 4 levels
(RenderConstants.SURFACE_MATERIAL_MIP_LEVELS): level 0 = the 64x64 texels, levels 1..3 = 32, 16, 8, each a
2x2 box filter (per-channel R,G,B,A average, rounded) of the previous level, same row-major layout and
orientation. getPixels(id) = level 0; getPixels(id, level) the rest. Built once, shared, read-only.
FloorCeilingRenderer keeps ONE level per ROW of the tier's row model (row distance is player-independent, so the
table is rebuilt only with the tint table on construction / resolution change) with
GameMath.surfaceMaterialMipLevel; a near-region TILE uses the level of the row at its centre depth
(GameMath.floorRowAtDepth), the far band uses its row's level. The screen term keeps the old backdrop width as a
reference (GameMath.floorMipReferenceColumnCount: 540 rows -> 960, 180 -> 320), so the table is byte-identical:
  screenTexels = rowDistance * (2*tan(halfFov)) / referenceColumns * 64     (GameMath.floorScreenFootprintTexels)
  depthTexels  = |rowDistance(row) - rowDistance(row+1)| * 64               (GameMath.floorDepthFootprintTexels)
  level = clamp(floor(log2(max(1, max(screenTexels, depthTexels) * SURFACE_MATERIAL_MIP_BIAS))), 0, 3)
The DEPTH footprint is what causes distant floor speckle (one backdrop row spans a long stretch of floor far
away) and dominates the screen-X term. Row distances are the clamped row values; the last row reuses
the previous difference. The table is then forced non-decreasing up the screen, so the clamped far band
(zero depth difference) keeps the last level instead of un-blurring.
Near rows stay level 0 (crisp pixel-art texels); only distant rows blur. The table uses the default player FOV.
Sampling at level L: one GL Texture per level (render/SurfaceMaterialTextures: wrap Repeat, filter Nearest, no GL
mipmaps), texel = frac(tile coordinate) * edge - the CPU caster's index, same orientation.

FLOOR / CEILING PIPELINE (render-performance-full-hd) - GPU, SpriteBatch DEFAULT shader only (V2 honoured)
Nothing is shaded per pixel on the CPU and nothing is uploaded per frame (the old 960x540 CPU backdrop, its 2 MB
per-frame upload and its worker pool are gone). One batch, per frame:
  1. FAR BAND - the rows at or past FLOOR_MAX_VISIBLE_DISTANCE_CELLS (all one clamped distance) as ONE strip of
     horizontal spans: the clamp-depth row walked across the tile grid (GameMath.floorSpanAxisCrossingParameter),
     runs of equal tile brightness merged, split at FLOOR_SPAN_MAX_TILES, UVs rebased (floorSpanUvRebaseShift).
     It starts FLOOR_BAND_OVERLAP_ROWS below the clamp row and is drawn first, so no seam can show.
  2. NEAR REGION - one quad per visible floor tile, in TILE coordinates, through a projective batch matrix
     (GameMath.floorPlaneClipMatrix: w = depth, near clip FLOOR_PLANE_NEAR_TILES, far clip = the clamp). The GPU
     interpolates the tile's own 0..1 UVs and its four corner colours perspective-correctly; the plane is the
     exact inverse of the floor-row mapping, so it meets the walls as the CPU caster did. Tiles are culled to the
     view wedge and grouped by material level (at most 4 binds per surface).
  3. Base pass with blending off; ADDITIVE layers (SRC_ALPHA, ONE) only for factors above 1: a mood tint above 1.0
     is first BAKED into the per-floor material textures per channel when the brightest texel stays <= 255
     (GameMath.materialChannelBakeScale; every colour of that surface is divided by the scale), so in practice the
     additive layer only carries the muzzle light (GameMath.colourFactorExcessLayer).
Why tiles and not one quad per row: CP4 of render-performance-full-hd measured the row version (540 one-pixel-tall
full-width quads) and the software GPU was triangle-bound on them - slower than the CPU backdrop. A few hundred
tile quads cost about what HD's old backdrop did. Draw calls: about 10 per frame (2 band + up to 4 per surface).

RENDER RESOLUTION TIERS
Full HD (the default) is the QUALITY tier: 1920 ray columns, 540 floor/ceiling rows.
HD is the lighter tier: 1280 columns, 180 rows (RenderResolution.getFloorCeilingRowCount(); RenderConstants
RENDER_RESOLUTION_*_FLOOR_CEILING_ROWS). Both sample the floor at the device's native horizontal resolution.
COST (render-performance-full-hd CP7, the 4-core capture VM - llvmpipe shares the CPUs, so only RELATIVE numbers
in one session mean anything, never phone numbers): one session, two interleaved reps, mean frame ms.
    pose                 old FULL_HD (B0)   old HD (B1)   now FULL_HD   now HD
    P1 standing, 5 moods   14.1-15.6          9.7-10.8      11.5-12.2     10.3-11.3
    P2 rotating            14.5-15.6          10.2-11.2     12.5          10.8
    P3 walking             18.2-22.3          13.9-16.0     11.9          13.1
    P4 muzzle flash        18.9-22.0          14.9-15.6     12.1          14.8
  Floor/ceiling pass: CPU 3.15 -> 0.56 ms; GPU-attributed (probe sync) 6.20 -> 2.72 ms (old HD 2.72);
  upload 2 MB/frame -> 0; draw calls ~10. Full HD now costs about 20% less than before and less than old HD
  while moving and fighting; standing still it is still ~1 ms over old HD (1.5x wall + billboard columns, and
  the full-screen view vignette, ~2.3 ms on this software GPU, is the same at both tiers).
The phone check is the owner's: build with RenderConstants.PERF_PROBE_FORCE_ON = true and read the probe readout.


7. RECIPE C — add a mood or a material
--------------------------------------
Add a MATERIAL: one `register(id, generator)` row in SurfaceMaterials.bootstrap() plus its
MATERIAL_ID_* constant in ArtDirection; keep it in the R9 band (measure the average luminance in a
throwaway main — never a committed test); deterministic hashing only.
Add a MOOD: the MOOD_<ID>_* constants in ArtDirection (near/far luminance in [0.95, 1.05]), one
register() row in LightingMoods.bootstrap(), and name it from the region's RegionAmbience row
(route/RouteRegistries). Bootstrap fails loud if either side is missing. No switch anywhere.
A new REGION must name a registered mood (docs/route-map-system.txt).


8. DEV MOOD OVERRIDE
--------------------
`-Dtoon3d.forceMood=<id>` (a JVM system property, read once per floor build) forces that mood on every
floor and logs "Atmosphere mood=<id> (forced)"; an unknown id is ignored with a warning. Nothing sets
it on Android. Pass it locally, e.g. `JAVA_TOOL_OPTIONS="-Dtoon3d.forceMood=amber_hot" ./gradlew
lwjgl3:run` — never commit it. It is the only way to check regions C-E without a 20-floor run.


9. SPRITE CONDITIONING (visual-identity-order-2)
------------------------------------------------
render/EnemySpriteSheets is a static, session-lifetime holder of the enemy textures. Each enemy PNG
(9 sheets under assets/textures/enemies; the PNG files are never edited) is decoded into a Pixmap
(converted to RGBA8888 if needed), then hard-alpha-cut in one pass, in 16 KB chunks, over its bytes
(EnemyConstants.ENEMY_SPRITE_ALPHA_CUT = 0.50): a texel with alpha/255 below the cut becomes RGBA 0,
every other texel becomes fully opaque with its RGB kept. The Pixmap is uploaded (Nearest filter) and
disposed. The procedural fallback sheet (file missing) is already opaque, is not conditioned, and is
cached the same way.
  Why 0.50: the 4.5-16% of texels with mid alpha (128-254) are anti-aliased EDGE texels in body
  colour, not a dark glow; turning them opaque gives a crisp silhouette with no outline, while a
  near-opaque cut chews ragged edges. No per-path override exists or is needed.
  Cache: get(path, fallbackRed, fallbackGreen, fallbackBlue) returns the cached Texture.
  EnemyRenderer brackets its nine gets with beginLoadBatch()/endLoadBatch(); the end call logs
  "EnemySpriteSheets conditioned N sheets in M ms" once per app session (a `logged` flag), later floors
  and runs only hit the cache. Measured (PNG decode included, budget 400 ms): 379 ms with the earlier whole-copy
  pass on a quiet machine; the in-place chunked pass is ~2x faster than that version in a same-session
  comparison (476-582 ms vs 1209 ms on a noisy Xvfb/llvmpipe VM).
  Lifetime: World is rebuilt per run, so the cache is static. EnemyRenderer.dispose() does NOT dispose
  the sheets; Main.dispose() calls EnemySpriteSheets.disposeAll() after the world is disposed.
  Textures are unmanaged (Pixmap-built), like every procedural texture here.


10. CONTACT SHADOWS (visual-identity-order-2)
---------------------------------------------
Every upright billboard gets a soft ellipse on the floor so nothing floats.
  render/ContactShadow (static helper):
    buildTexture()   64x32 (RenderConstants.CONTACT_SHADOW_TEXTURE_*) white ellipse, alpha =
                     GameMath.contactShadowAlpha(r) = (1 - r^2)^2, Linear filter. Each renderer owns and
                     disposes its own copy.
    alphaAtDepth(mood, depthTiles)  CONTACT_SHADOW_ALPHA 0.50 x (1 - CONTACT_SHADOW_FOG_FADE 0.80 x fog),
                     fog = atmosphereFogFactor at the billboard depth (0 with no mood).
    draw(batch, texture, wallRenderer, columnCount, columnWidth, centerWorldX, floorLineY, shadowWidth,
         depth, alpha)  one quad per column with float UVs, skipping columns the wall z-buffer hides
                     exactly like the sprite; colour = ArtDirection.WORLD_SHADOW (never graded). It
                     leaves the batch colour set; the caller sets the sprite colour next.
  Geometry: centred on the billboard's screen X, vertical centre ON THE FLOOR LINE (the wall-stripe draw
  bottom at the billboard's depth, BEFORE any hover, bob or lunge offset); width = projected billboard
  width x a fraction; height = width x CONTACT_SHADOW_HEIGHT_RATIO 0.22.
  Classification (by the predicates the loops already use, no symbol switch):
    enemies (incl. bosses, live and upright)           WIDTH_FRACTION_ENEMY 0.70, width taken BEFORE the
                                                        lunge scale; EYE_TYRANT alpha x HOVER_ALPHA_SCALE 0.55
    Level.isPropSolid tiles (incl. generated props)     PROP 0.85 (alpha 1: they stand on the floor)
    medical / armour / ammo / keycard pickup tiles      PICKUP 0.60 x HOVER_ALPHA_SCALE (they float with a
                                                        bob above the floor line, like a hovering enemy)
    weapon pickups + credit chips (ground items)        PICKUP 0.60 x HOVER_ALPHA_SCALE (they float at eye
                                                        height, so the shadow sits well below the sprite)
    shop machine                                        SHOP 0.90
    NONE: walkable decals, hazard fire/toxic, the portal (stairs), corpse/blood stains, boss afterimages,
    aura/glow layers, runtime crystal spires.
  Shadows are drawn BEFORE the sprite and are never recorded in the SpriteOccluderBuffer, so a nearer
  prop's redrawInFront restores over them like over the sprite.


11. MUZZLE LIGHT (visual-identity-order-2)
------------------------------------------
Firing a gun briefly lights the nearby world in the weapon's colour, through the same grade.
  Catalog: render/MuzzleLightCatalog (ItemType-ordinal table, one register row per weapon, WARM fallback
  for an unbound weapon). Colours in ArtDirection (MUZZLE_WARM / _ENERGY / _FIRE), peaks and timing in
  EffectConstants:
    WARM (1.00,0.82,0.55) peak 1.50   pistol, shotgun, double barrel, chaingun, assault rifle, rocket
    ENERGY (0.60,0.90,1.00) peak 1.50 plasma, railgun, arc cannon
    FIRE (1.00,0.55,0.20) peak 1.70   incinerator
    none (peak 0: no pulse)           fist, knife, hammer, chainsaw
  Peaks were raised from the spec's 0.35/0.40 after the on-screen check: the light scales the surface's
  own albedo (additive pass), and this game's materials are deliberately dark (order-1 R9), so 0.35 added only
  +2..4/255. At 1.5 a surface at the player's feet briefly reaches ~2.5x its lit colour.
  Formula (R8): intensity i = peak x (1 - elapsed / MUZZLE_LIGHT_DURATION_SECONDS 0.10), floored at 0;
  for a surface d tiles away  light = GameMath.muzzleLightFalloff(d, MUZZLE_LIGHT_RADIUS_TILES 4.0) x i
  with falloff = max(0, 1 - d/radius)^2. The surface colour is
        colour = albedo x clamp01(shade x tint)  [then red alert]  +  albedo x light x muzzle.colour
  with ONLY the final framebuffer colour clamped. (The first implementation added the light to the shade
  multiplier and clamped it; near surfaces already sit at multiplier ~1.0 (MAX_LIGHTING_SHADE), so the light
  was clamped away and measured +2..3/255. Decision: the light must be able to exceed the clamp.)
  How each surface does it:
    floor + ceiling (GPU)  GameMath.floorSpanRedFactor / floorSpanGreenBlueFactor: base factor (alert maths
                           and its red min(1,..) exactly as before) PLUS the corner's light add (falloff at
                           the corner depth); the part above 1 is drawn by the additive layer
                           (colourFactorExcessLayer), only for tiles whose corners carry it.
    walls / doors / columns  the base column draws are unchanged. Workers fill the per-column light add
                           (gradeScratch[3..5] -> surfaceLight* / doorPanelLight*). A separate PHASE 3 in
                           WallRenderer.render re-draws the same column slices with additive blending
                           (GL_SRC_ALPHA, GL_ONE), colour = light add, alpha 1 so the texture still masks.
                           A door-panel column re-draws the panel only (DELIBERATE: the surface behind
                           it is covered, and lighting both would double-light the panel). Blend func switches exactly twice
                           per frame (to additive, back), and the pass is skipped at intensity 0.
    props / pickups / chips / weapon pickups / decals (PropRenderer.drawMuzzleLightPass)
                           after each lit sprite's base column loop: additive re-draw of the same columns
                           with the same wall z-test and a "nearer recorded sprite" skip. Two blend
                           switches per LIT sprite only (a sprite with no light, or an emissive one whose
                           add is zeroed, costs nothing).
    shop machine body      additive re-draw right after the body; the next layer is additive anyway, so no
                           extra blend switch.
    enemy body             additive re-draw of the sprite columns after the base loop, before health bars
                           and the other overlays; two blend switches per lit enemy.
  Applied at full strength regardless of the surface's grade strength (a lit enemy is the point) to walls,
  doors, columns, floor, ceiling, props, decals, pickup bodies, the shop body and enemy bodies. NEVER to
  emissive draws, overlays, health bars, shadows or the weapon sprite.
  A new pulse restarts the clock (chaingun fire refreshes, never stacks). Skipped by a branch at
  intensity 0.
  Threading contract: the light state is a per-frame SNAPSHOT mutated only by pulseMuzzleLight, update
  and resetLight, all on the render thread inside World.update before any renderer starts its frame.
  Worker threads (WallRenderer columns) read it only through lightAddInto / precomputed
  tables; render-thread code reads atmosphereGrade.lightAddRed/Green/Blue right AFTER evaluate()
  (never after evaluateWeaponTint). Walls carry it in gradeScratch[3..5]; the floor evaluates the falloff
  per tile CORNER of its view lattice (x the frame intensity x colour); the far band carries no light.
  Listener site: PlayerController.setWeaponFiredListener (a Consumer<ItemType>; input never imports
  render) is invoked right after the only gameAudio.playPlayerWeapon call in tryFire, so a dry fire, a
  railgun charge turn, a reload and every melee swing emit no light; World wires it to
  AtmosphereGrade.pulseMuzzleLight. Only the player's own shot lights the world (no explosions, barrels,
  plasma bolts or enemy attacks).
  Clock: AtmosphereGrade.update(deltaTime) runs in World.update only while the world is PLAYING, so it
  pauses with every hard-pause overlay and resumes after; resetLight() runs on floor build.


12. TYPOGRAPHY (visual-identity-order-3)
----------------------------------------
ONE procedural pixel font for every word in the game. No TTF/OTF/.fnt asset and no FreeType (V1): the
font is code.
  render/PixelFontGlyphs   the glyph table, DATA ONLY: codepoint + rows ('#' ink, '.' empty, '/' between
                           rows, top row first) + baseline offset (font-pixel row the glyph's bottom
                           sits on; 0 = baseline, negative = descender, positive = raised punctuation).
  render/FontFace          REGULAR (shift 0) / HEAVY (shift 1).
  render/GameFonts         session holder: initialise() (Main.create, before the World), newFont(face),
                           dispose() (Main.dispose, after the World).
GRID (font pixels; ArtDirection PIXEL_FONT_*): cap height 7, x-height 5, descender 2, line height 11
  (7 + 2 + 2 leading above the cap), letter spacing 1, space advance 3. Capitals 5 wide (I 3, M and W 7,
  both with a centre stem), A round-topped so it never reads as R. Lowercase true x-height with clear
  ascenders/descenders. Digits 0-9 are TABULAR (all 5 wide, same advance in each face), so HUD counters
  never jitter; the zero is slashed.
COVERAGE (both faces): printable ASCII 32-126 plus — · … × ▶ ◀ → ● • ◇ ± ≈ ° ‘ ’ “ ” (scanned from every
  shipped string, 2026-10-19). Any other character draws the FALLBACK glyph (BitmapFontData.missingGlyph):
  a hollow 5x7 box. Never blank, never a crash. The em dash exists as a glyph; whether copy USES it is the
  narrative authority's call (docs/narrative-authority.txt), not art direction's.
FACES: HEAVY = each REGULAR glyph OR-ed with itself shifted 1 px right (ink width +1, advance +1),
  derived in GameFonts, never a second table. HEAVY is used for: FramingScreenRenderer's title and death
  stroke, BossHudRenderer.nameFont, HudRenderer's ammo readout, EventTextRenderer, ImpactEffectRenderer
  (damage numbers). Everything else is REGULAR. (The reprint card's SYSTEM block is drawn by the shared
  StoryPanelRenderer, which also draws every bark, so it is REGULAR until a later order styles panels.)
ATLAS: each font pixel rasterised as a solid 4x4-texel white square (PIXEL_FONT_ATLAS_TEXELS_PER_PIXEL),
  1 font pixel of transparent padding between glyphs, both faces + fallback shelf-packed into ONE
  power-of-two atlas at most 512x512 (currently 512x512), Linear min/mag (crisp-chunky at FitViewport's
  non-integer scales; Nearest would shimmer). Built from a Pixmap at initialise; the Pixmap is freed after
  upload. KNOWN LIMITATION: like every Pixmap-built texture here it is unmanaged, so a lost Android GL
  context does not rebuild it (LibGDX preserves the EGL context on pause by default; the old default
  font's file texture was managed).
METRIC MATCH: glyph metrics are in atlas texels; each font's data multiplies every setScale by
  PIXEL_FONT_TARGET_CAP_HEIGHT / (7 x 4) = 11 / 28, so setScale(1) gives cap height 11 — the measured cap
  height of the LibGDX 1.14.1 default font (lsans-15) the pixel font replaced. Every existing setScale
  constant therefore keeps its cap height; only advance widths differ. Initialise logs both numbers.
  Consequence: getScaleX() reports the base-inclusive scale, and BitmapFontData.scale(amount) must not be
  used (nothing does).
SHARING RULE: all text comes from GameFonts.newFont(face) — NEVER `new BitmapFont()` anywhere else. Each
  call returns a NEW BitmapFont with its own BitmapFontData (each renderer keeps its own scale and colour)
  over the SHARED atlas region; the font does not own the atlas (ownsTexture false), so a renderer's
  font.dispose() never frees it. Never call setFilter on a font's texture — it is the shared atlas.
  GameFonts.dispose() frees the atlas exactly once. newFont before initialise throws
  IllegalStateException — a standalone launcher (the lwjgl3 story showcases) calls initialise()/dispose()
  itself. The atlas outlives every World (rebuilt per run), like EnemySpriteSheets.
TYPE SCALE (ArtDirection TYPE_*, setScale multipliers over the metric-matched base; adopted screen by
  screen in orders 4-6): CAPTION 1.00, BODY 1.25, LABEL 1.50, HEADING 2.00, DISPLAY 3.50. Nothing shipped
  is drawn below CAPTION once its screen adopts the scale; the sites still below it are listed in the
  visual-identity-order-3 checkpoint handover.
ADD A GLYPH: one glyph(...) row in PixelFontGlyphs (every row the same length; pick the baseline offset
  so it sits on the grid above), and its character in the COVERAGE line above. The atlas sizes itself;
  GameFonts throws at startup if it would exceed 512x512.


13. UI KIT (visual-identity-order-4)
------------------------------------
The interface vocabulary, defined ONCE in render/UiKit (static, stateless, no `new` in any primitive) and
coloured from SECTION 2. Every ShapeRenderer primitive expects begin(ShapeType.Filled) — outlines are
filled quads, so a screen never churns Line/Filled — and caller-enabled blending. Pieces never overlap,
so a translucent panel shows no darker seams. Geometry constants (ArtDirection UI_*): UI_CHAMFER 8,
UI_PLATE_CHAMFER 12, UI_BORDER_THICKNESS 2, UI_BRACKET_LENGTH 14 (UI_BRACKET_LENGTH_COMPACT 7 for plates
too small for 14 beside their text), UI_BRACKET_THICKNESS 3, UI_BRACKET_INSET 4, UI_METER_GAP 2,
UI_DIVIDER_THICKNESS 1 / UI_DIVIDER_TICK_LENGTH 6 / UI_DIVIDER_TICK_THICKNESS 3, UI_TEXT_SHADOW_OFFSET
1.5, UI_TEXT_SHADOW_ALPHA 0.85, UI_PANEL_ALPHA_HUD 0.82 (HudConstants.HUD_PANEL_ALPHA references it),
UI_SCRIM_ALPHA 0.75 (used from order 5), UI_PLATE_DISABLED_ALPHA_SCALE 0.5, BOSS_HEALTH_SEGMENTS 20.
PRIMITIVES
  panel     R1  rectangle with all four corners cut at 45 degrees by UI_CHAMFER, filled, with a
                UI_BORDER_THICKNESS border band (the gap between the outer octagon and the octagon inset
                by the thickness; GameMath.insetChamfer keeps the diagonal band as thick as the straight
                edges). A general overload takes chamfer, border alpha and thickness; a zero alpha or
                thickness skips that part (the mini-map draws its fill first and its border last).
                fillOctagon draws just a chamfered fill.
  brackets  R2  THE SIGNATURE: four L-shaped corner marks, arms UI_BRACKET_LENGTH, UI_BRACKET_THICKNESS
                thick, inset UI_BRACKET_INSET. Short enough to read as a frame, not a box.
  plate     R3  anything tappable, chamfered by UI_PLATE_CHAMFER (an overload takes chamfer + bracket arm).
                render/PlateState carries each state's choice as per-constant data (no switch):
                  IDLE      fill UI_PANEL at the caller's alpha, border UI_LINE
                  PRESSED   fill UI_PANEL_RAISED at the caller's (pressed) alpha, border = ink, full alpha
                  SELECTED  fill UI_PANEL_RAISED, border = ink, plus brackets in the ink
                  DISABLED  fill UI_PANEL and border UI_LINE, both at 0.5x alpha
  meter     R4  `segments` cells separated by UI_METER_GAP; lit cells in the on-colour, the partial last
                cell lit from its left edge, the track drawn only where a cell is NOT lit (no double
                blend). Fraction 0 draws only the track. A caller that must light whole ticks only (the
                HUD's fixed-tick bars) passes a whole-tick fraction.
  divider   R5  a UI_LINE rule with a short ink tick at its left end.
  text      R6  a UI_INK_BLACK drop shadow at UI_TEXT_SHADOW_ALPHA, offset down-right by
                UI_TEXT_SHADOW_OFFSET x (capHeight / PIXEL_FONT_TARGET_CAP_HEIGHT) — i.e. it grows with the
                type step — then the text; restores the font's colour. An aligned/wrapped overload takes
                targetWidth + Align (there is no GlyphLayout overload: a layout bakes its colours, so it
                cannot be tinted for the shadow).
INK RULE (R8). The in-play layer is SUIT ink: accents SUIT_AMBER, secondary accents SUIT_AMBER_DIM,
  neutrals UI_*. Amber appears in exactly three roles: brackets, the active/pressed state, and the
  player's own resources (ammo pips, melee meter, player marker, weapon dots). FACILITY_CYAN only where
  the facility speaks: the mini-map EXIT marker and the BLACKOUT NAV OFFLINE text. Semantic colours only
  where they carry their meaning: the HP ramp (CombatPalette.DAMAGE -> HEALTH_GREEN), ARMOUR_BLUE, earned
  things CREDITS_GOLD (XP meter, credits, the shop marker), harm DAMAGE (enemies, low HP, an empty clip).
  Green is health or a buff and nothing else.
WHERE IT IS USED (order 4 — the in-play layer; overlays and menus are orders 5 and 6):
  hud/HudRenderer               panel + SUIT_AMBER_DIM brackets; labels UI_TEXT_SECONDARY, values
                                UI_TEXT_PRIMARY; weapon slots are plates (active SELECTED in amber with
                                compact brackets, filled IDLE, empty DISABLED); NAV OFFLINE plate.
  input/touch/TouchControllerRenderer  each button a chamfered panel (TOUCH_BUTTON_CHAMFER 16 — drawing
                                only; TouchButton.contains is a plain rect): idle UI_PANEL + UI_LINE rim +
                                bone icon, pressed UI_PANEL_RAISED + SUIT_AMBER rim + amber icon, locked
                                dimmed icon. USE keeps permanent amber brackets. Icon halo UI_INK_BLACK.
  render/LevelRenderer (+ Player.render's marker)  UI_INK_BLACK 0.70 frame, every tile and grid line
                                clipped to the chamfer (GameMath.clipPolygonToHalfPlane), border + brackets
                                on top.
  render/BossHudRenderer        panel + brackets round a 20-cell DAMAGE meter, SUIT_AMBER phase tick.
  render/EventTextRenderer      every line through UiKit.text; colour table by code (WHITE primary, GREY
                                secondary, GOLD/AMBER SUIT_AMBER, GREEN HEALTH_GREEN, BLUE DEFENSE, ARMOUR
                                ARMOUR_BLUE, RED DAMAGE, CREDIT CREDITS_GOLD).
                                The boss state label sits under the boss panel; with the boss bar's
                                pre-existing overlap of the mini-map it lands on the map (layout follow-up).
  render/ImpactEffectRenderer   damage numbers HEAVY + shadow: hit UI_TEXT_PRIMARY, kill SUIT_AMBER.
TYPE SCALE ADOPTION (R15): every text draw on these screens is a TYPE_* step (via a named constant); no
  raw literal reaches setScale. Old scales moved to a step that keeps their hierarchy: event text 1.8 ->
  LABEL (one step below the banners, so an ability banner still reads louder than "THREAT LV"), ability
  banners 2.0/2.6 -> HEADING (SLAM louder through its punch-in + underline) and 3.2 -> DISPLAY. Damage numbers
  start at LABEL and grow CONTINUOUSLY with the hit to 2x LABEL (DAMAGE_NUMBER_MAX_EMPHASIS) — deliberately
  off-step: the size itself carries how hard the hit was.
