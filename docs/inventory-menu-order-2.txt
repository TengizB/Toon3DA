inventory-menu-order-2 — Inventory Menu Redesign: Weapon Slots Panel (Left Side)
==================================================================================

PREREQUISITE: inventory-menu-order-1 (layout & architecture)


WHAT WAS BUILT
--------------
WeaponSlotsPanel (render/WeaponSlotsPanel.java) fills the left panel
(x=20–520, y=110–645) with 4 structured weapon slots: 3 ranged gun slots +
1 melee slot, each 470px wide × 100px tall.

Data model was also extended: Loadout gained a locked third gun slot so the UI
can always render a permanent LOCKED slot at index 2.


SLOT LAYOUT (bottom-Y of each rect, all at x=35, width=470, height=100)
------------------------------------------------------------------------
  Gun slot 1  (loadout slot 0)  y = 507   INV_WEAPON_GUN_SLOT_1_Y
  Gun slot 2  (loadout slot 1)  y = 401   INV_WEAPON_GUN_SLOT_2_Y
  Gun slot 3  (LOCKED forever)  y = 295   INV_WEAPON_GUN_SLOT_3_Y
  — dashed section divider —    y = 280   INV_WEAPON_SECTION_DIVIDER_Y
  Melee slot                    y = 145   INV_WEAPON_MELEE_SLOT_Y
  Section labels: "RANGED" at y=613, "MELEE" at y=253


SLOT VISUAL STATES
------------------
EMPTY  — dark bg (0.10,0.10,0.12), plain border, "— EMPTY —" centered dim text.
FILLED — warm bg (0.11,0.10,0.09), dim amber border (0.50,0.36,0.00).
ACTIVE — amber-tint bg (0.14,0.12,0.05), pulsing amber border (sin 4 Hz, 0.7–1.0
          alpha), + "ACTIVE" badge pill (60×18px) top-right corner.
LOCKED — very dark bg (0.08,0.08,0.09), dashed border (8px on / 4px off),
          padlock shape (ShapeRenderer rect body + semi-circle shackle arc),
          "LOCKED" text + "Unlock at Level 10" hint.


RENDER PASSES (3 passes per frame, no allocations inside render)
----------------------------------------------------------------
Pass A — ShapeRenderer.Filled: slot backgrounds, ACTIVE badge rect, lock body.
Pass B — ShapeRenderer.Line:   slot borders (solid/dashed/pulsing), section
                                divider dashes, shackle arc, amber accent lines.
Pass C — SpriteBatch + BitmapFont: section labels, weapon thumbnails, info zone
                                    text, empty/locked labels, ACTIVE badge text.


WEAPON THUMBNAILS
-----------------
WeaponHudRenderer.getWeaponTexture(Weapon) returns the cached FrameBuffer Texture
for the weapon's procedural sprite. Scaled to fit the left 280px of the slot using
min(dst_w/src_w, dst_h/src_h). Null-safe: melee / unregistered weapons fall back
to text-only display.


INFO ZONE (right 185px of slot, x_offset=288 from slot left)
-------------------------------------------------------------
4 text lines stacked from slot top (16px step):
  Line 1 — Weapon display name (amber if ACTIVE, dim otherwise)
  Line 2 — Ammo type name ("Melee" for melee slots)
  Line 3 — Clip / max clip ("—" for melee)
  Line 4 — Ammo reserve ("Unlimited" for melee)


DATA MODEL CHANGES
------------------
WeaponConstants.java
  WEAPON_SLOT_COUNT            = 3   (was 2)
  WEAPON_GUN_SLOT_LOCKED_INDEX = 2   (new — slot 2 never receives a weapon)

Loadout.tryEquip() skips slot index WEAPON_GUN_SLOT_LOCKED_INDEX.

WeaponSlotsPanel reads from PlayerInventory (via setPlayerInventory):
  gun slot 0/1   → loadout.getSlot(0/1)
  gun slot 2     → always LOCKED state (no weapon lookup)
  melee slot     → playerInventory.getMeleeWeapon()
Active state:    loadout.getActiveSlotIndex() == slotIndex  (or isMeleeSelected())

integration is deferred to Part 4; locked-slot flash deferred to Part 4.
