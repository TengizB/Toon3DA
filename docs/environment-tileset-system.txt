TARGET MODEL (one paragraph)
============================
A level-file SYMBOL is not a fixed piece of art — it is a SLOT in a fixed CATEGORY (WALL, COLUMN,
SOLID_PROP, FLOOR_DECAL, ...). A symbol's category/gameplay meaning never changes, but WHICH sprite
fills that slot is chosen PER LEVEL from a large registered POOL. Symbols come in two tiers: FIXED
symbols (player start 'p', exit '>', doors, keycards, pickups, ammo, enemy spawns, hazards) keep a
permanent meaning AND sprite and are never reassigned; FLEXIBLE symbols (the wall/decor visual
symbols) keep a fixed category but get their sprite assigned per level by a deterministic,
rule-governed allocator. No level loads the whole art library: each level draws a small palette
(as many distinct sprites as it has free symbols) from the pool, so per level the palette is small
but across all levels the variety is huge. Adding a new wall/prop/column sprite — or a whole new
room — is ONE registration line, never an edit to the generator, the renderers, or Level (the same
"never a switch statement" discipline as route/RouteRegistries.bootstrap()).


LEGACY vs TARGET — WHICH IS LIVE
================================
Until this migration completes, the LEGACY 1:1 symbol->sprite mapping is what actually RENDERS
(via the legacy LevelPalette default, order-3). Where THIS doc and an older doc or class comment
disagree, THIS doc describes the TARGET; the transition banner stamped on the older doc/comment
(">>> TILESET MIGRATION IN PROGRESS <<<") tells the reader to consult the ORDER STATUS TABLE below
for which parts are actually live. Do not treat "one symbol = one fixed sprite" as permanent truth
while that banner is present anywhere in the tree.

1. ART CATALOG & REGISTRIES  [DONE — order-1]
   The `…toon3d.tileset` package (headless, no LibGDX imports) is the data-driven ART CATALOG: the
   fixed set of tile CATEGORIES and a registry of every environment SPRITE the game can draw. order-1
   is pure data + registration — NO per-level binding, NO allocator, NO renderer change. The legacy
   WallRenderer texture table and PropRenderer switch stay the runtime authority; the registry exists
   in parallel so later orders can enumerate the inventory instead of hardcoding a sprite list.

   CLASSES (all in …toon3d.tileset):
     * TileCategory (enum) — the FIXED semantic class a symbol MEANS; never varies per level. Four
       FLEXIBLE-eligible visual members, one per existing Level predicate group:
         WALL       (Level.isWall)      rendersAsStripe=true,  blocksMovement=true
         COLUMN     (Level.isColumn)    rendersAsStripe=true,  blocksMovement=true
         SOLID_PROP (Level.isPropSolid) rendersAsStripe=false, blocksMovement=true
         FLOOR_DECAL(Level.isPropDecal, non-pickup) rendersAsStripe=false, blocksMovement=false
       Metadata only (id, rendersAsStripe, blocksMovement) — consumers route a sprite to the wall vs
       billboard pipeline by reading rendersAsStripe(), never a hardcoded char check. Doors, pickups,
       keycards, ammo, hazards, enemy spawns, player-start, and exit are FIXED symbols and are NOT in
       this enum or the sprite registry (order-2 formalises the FIXED/FLEXIBLE split).
     * EnvironmentSpriteDefinition (immutable value; Builder) — one concrete piece of art. Fields:
       id (STABLE string), category, displayName (tooling/logging only), heightMultiplier
       (billboard height fraction; 1.0 for WALL/COLUMN), occluder (writes z-buffer; mirrors
       Level.isPropOccluder), textureGeneratorId (= id for v1; kept separate so sprites can share a
       generator later), themeTags (Set<String> coherence hints; empty allowed). No LibGDX types; no
       colours (those live in the texture generators, order-6). Builder defaults: heightMultiplier 1.0,
       occluder true, textureGeneratorId = id.
     * EnvironmentSpriteRegistry — register(def) / get(id) (never null for a registered id) /
       allInCategory(category) (the allocator's variety pool, unmodifiable) / contains(id) / size().
       Duplicate id throws IllegalStateException (route-registry discipline); get(unknown) throws
       IllegalArgumentException. Insertion-ordered so counts/order are reproducible.
     * TilesetRegistries — bootstrap hub, the twin of route/RouteRegistries. sprites() returns the
       shared singleton; bootstrap() is idempotent and registers ALL v1 sprites via private
       registerWalls()/registerColumns()/registerSolidProps()/registerDecals() helpers. Called once
       from World.create() next to RouteRegistries.bootstrap().

   v1 INVENTORY (exactly today's art — no additions): 21 walls (x c v t w h j G k N Q S M Z U X D F
   + observatory " ' `), 1 column (P → "column_round"), 17 solid props (g E T L C # % & = @ I J W +
   observatory ; \ | <), 8 floor decals (m s . O e + observatory ? ] -). STELLAR_OBSERVATORY art is
   tagged themeTag "observatory" (TilesetRegistries.THEME_TAG_OBSERVATORY) so the catalog is complete
   yet a later allocator only pulls it for that room, preserving today's containment rule. Heights are
   copied from the SAME RenderConstants the renderer reads (inline PropRenderer literals for g/E/T/L/C/
   m/s/./O were first hoisted into RenderConstants.PROP_HEIGHT_* and referenced from both places — no
   re-hardcoded values, no behaviour change).

   STABLE SPRITE-ID SCHEME: category prefix + descriptor, e.g. "wall_plain", "wall_cryo",
   "column_round", "prop_locker", "decal_blood". Ids are the key palettes/seeds use to stay
   reproducible across code changes and MUST NOT be renamed once shipped.

   RECIPE (add a wall/prop/column/decal sprite): build one EnvironmentSpriteDefinition + one
   register() line in the matching TilesetRegistries helper. Nothing else in this order references a
   specific char; nothing downstream switches on a hardcoded sprite/category list — it asks a registry.

   TESTS (headless, core/src/test/.../tileset/TilesetRegistriesTest): get() never null for a
   registered id; per-category counts equal the count of chars Level's predicates accept today (guards
   the inventory is complete and nothing was dropped); duplicate-id throws; bootstrap() idempotent;
   height/occluder metadata matches legacy values; observatory art carries the containment tag.

2. SYMBOL BUDGET (FIXED vs FLEXIBLE)  [DONE — order-2]
   The SAFETY BOUNDARY of the whole series: the authoritative declaration of which level-file symbols
   the per-level allocator (order-4) MAY reassign a sprite to (FLEXIBLE) and which it must NEVER touch
   (FIXED). Isolated as one small, heavily-tested config so the allocator can trust it and a reviewer
   can see, in one place, exactly what is safe to vary. Pure config + a small value object — NO
   allocation logic (order-4), NO per-level binding (order-3). Headless, no LibGDX.

   WHY THE SPLIT EXISTS: get it wrong and a level could repaint the exit '>' or a keycard 'r' as a
   wall, breaking gameplay. The dangerous direction is OVER-declaring flexibility (marking a gameplay
   symbol reassignable); UNDER-declaring is merely less variety. So flexibility is declared EXPLICITLY
   and everything else is FIXED by default (fail-safe): any char not listed as flexible — including
   unknown chars — resolves to FIXED without being enumerated.

   SymbolClass (enum, …toon3d.tileset): FIXED (permanent meaning AND sprite) / FLEXIBLE (fixed
   category/meaning, sprite chosen per level from the category pool).

   AUTHORITATIVE FIXED / FLEXIBLE PARTITION (v1):
     FIXED — permanent meaning AND sprite; NEVER reassigned. These keep exactly their current handling
       and (except the two sprite-bound exceptions below) are NOT in the sprite registry:
         * Special: player start 'p', exit '>'.
         * Doors: d R Y B.  Floor lighting: (space) l u f  (brightness multipliers, not sprites).
         * Pickups: r y b + H a A  and ammo 6 7 8 9 0.  Hazards: i (fire) q (toxic).
         * Enemy spawns: 1 2 3 4 5 ! $ ^ ~ z K V * n.
       FIXED symbols that DO map to a sprite (the only entries in fixedAssignments):
         * 'x' plain wall -> "wall_plain" (see PLAIN-WALL RULE below).
         * shop '@' -> "prop_vendor" (World.placeMachine stamps it solid; it must always render as the
           vendor machine, so although '@' sits in the SOLID_PROP category it stays FIXED).
     FLEXIBLE — category fixed, sprite assigned per level:
         * WALL:       c v t w h j G k N Q S M Z U X D F " ' `  (every isWall char except 'x').
         * COLUMN:     P  (meaning "column" is permanent; the filling sprite is flexible — round today,
                          square after order-9).
         * SOLID_PROP: g E T L C # % & = I J W ; \ | <  (every isPropSolid char except the shop '@').
         * FLOOR_DECAL: m s . O e ? ] -  (the "pure" decals; pickup/hazard/stairs decals are FIXED).
       The STELLAR_OBSERVATORY room art (" ' ` ; \ | < ? ] -) is FLEXIBLE by category; its room
       containment is preserved by the allocator via the order-1 "observatory" sprite theme tag, NOT by
       the budget.

   PLAIN-WALL RULE: 'x' is the 80-90% default wall and hand-crafted levels lean on it heavily, so it
   stays a FIXED WALL slot permanently bound to "wall_plain". Flexibility applies to the ACCENT walls,
   where variety actually reads; this keeps generic corridors legible and every existing hand level's
   bulk walls unchanged.

   SymbolBudget (immutable value object, …toon3d.tileset):
     * fixedAssignments(): Map<Character,String> — char -> permanently-bound sprite id (only the
       sprite-bound FIXED symbols: 'x'->"wall_plain", '@'->"prop_vendor"). Non-sprite FIXED symbols are
       simply absent.
     * flexibleSlots(): Map<TileCategory,List<Character>> — the reassignable symbols per category.
     * symbolClassOf(char) -> SymbolClass (fast lookup; FIXED for anything not declared flexible).
     * categoryOfFlexibleSymbol(char) -> TileCategory (null if the char is not flexible).
     * fixedSpriteId(char) / isFixed(char) / isFlexible(char) — convenience readers.
     * static SymbolBudget.standard() — builds the canonical v1 partition above from TilesetConstants;
       the single source the allocator consumes. Stores STRUCTURE only (which char is which
       class/category) — it does NOT choose which sprite fills a flexible slot (order-4's job).
   Both returned maps and their lists are unmodifiable.

   TilesetConstants.java (…toon3d.util, a NEW split-constants file): holds the partition as named string
   tables so changing it is a one-constant edit, never a code change:
     FIXED_WALL_SYMBOL="x", FIXED_WALL_SPRITE_ID="wall_plain",
     FLEXIBLE_WALL_SYMBOLS, FLEXIBLE_COLUMN_SYMBOLS, FLEXIBLE_SOLIDPROP_SYMBOLS, FLEXIBLE_DECAL_SYMBOLS,
     FIXED_SPRITE_SYMBOLS / FIXED_SPRITE_IDS (index-aligned; the shop '@'->"prop_vendor" exception),
     PALETTE_SEED_SALT (long; reserved here for order-4's palette-seed derivation, unused until then).

   REVISED tile-symbols.txt RULE (transitional; order-9 does the full STRICT-RULE rewrite): a FIXED
   symbol is permanent (meaning AND sprite); a FLEXIBLE symbol now carries a CATEGORY, not a fixed
   sprite — its art is assigned per level within that category. Adding environment art becomes
   "register a new SPRITE in the category pool" (order-1 RECIPE), not "consume a scarce symbol"; new
   symbols become rare. The tile-symbols.txt banner is tightened this commit to say flexible symbols
   carry a category, not a fixed sprite.

   TESTS (core/src/test/.../tileset/SymbolBudgetTest): fixed and flexible sets disjoint; no char in two
   flexible categories; every gameplay symbol (doors, pickups, ammo, hazards, enemy spawns, start, exit,
   shop) resolves to FIXED via the fail-safe default; 'x' FIXED and bound to "wall_plain"; '@' FIXED and
   bound to "prop_vendor"; every flexible symbol maps to a real order-1 category with a non-empty pool;
   unknown char defaults to FIXED; returned maps/lists unmodifiable.

3. PER-LEVEL BINDING (LevelPalette)  [DONE — order-3]
   The PER-LEVEL BINDING object: for ONE level, which sprite each environment symbol renders and which
   category each symbol belongs to. order-3 builds this data structure and threads it onto Level with a
   LEGACY default; it does NOT generate palettes from a seed (order-4) and changes NO renderer (order-7).
   Because Level defaults to the legacy palette, order-3 attaches a palette to every level with zero
   visible change — the "ship the identity transform first, then vary it" discipline the route series used.

   CLASSES (all in …toon3d.tileset, headless — strings/enums only, no LibGDX, no textures):
     * LevelPalette (immutable value object) — the binding for one level. Resolution methods:
         - categoryOf(char) -> TileCategory, or null if the symbol is not an environment symbol
           (doors/pickups/ammo/hazards/enemy-spawns/start/exit return null — the existing fixed paths
           handle them, not the palette).
         - spriteIdOf(char) -> String (the stable EnvironmentSpriteDefinition id this level renders for
           the symbol); null for non-environment symbols. FIXED symbols return their permanent binding
           ('x' -> "wall_plain", '@' -> "prop_vendor"); FLEXIBLE symbols return whatever was assigned (the
           legacy palette returns today's fixed art).
         - hasBinding(char) -> boolean.
       Built via a package-private Builder (the only builders are LevelPalettes and the order-4
       allocator). bind() validates category+spriteId non-null BEFORE mutating either map, keeping the
       invariant "a symbol is in both the category and sprite maps, or neither." IMMUTABLE once built, so
       it is safe to read from WallRenderer's worker threads (order-7) via happens-before from level
       construction. ID-ONLY: it holds no textures — the render layer turns ids into textures in order-6.
     * LevelPalettes (static factory) — LevelPalettes.legacy() builds the palette reproducing today's
       exact global mapping. It is the ONLY place that still encodes the historic 1:1 symbol->sprite
       table, and it does so MECHANICALLY: for each category it zips a registration-ordered symbol string
       against that category's EnvironmentSpriteRegistry pool (allInCategory), so char[i] renders pool[i].
       A length mismatch throws loudly, so registry drift cannot silently corrupt the mapping. The result
       is memoised as one shared immutable singleton (hand levels pay no per-level cost) via
       double-checked locking. legacy() calls TilesetRegistries.bootstrap() first so the shared registry
       is populated before it is read.

   WHY A LEGACY DEFAULT (the migration lever): the renderers and Level predicates stay the runtime
   authority until order-7. To switch them safely we need a palette that yields EXACTLY today's mapping
   ('Z' -> wall_cryo, 'M' -> wall_medical, 'P' -> column_round, ...). That is the legacy palette. With it
   as Level's default: order-3 attaches a palette everywhere with zero visible change; hand-crafted
   assets/levels/*.txt keep legacy forever (fixed symbols, never change appearance); order-7 can flip
   renderers to "read the palette" and nothing changes until order-4/8 produce varied palettes for
   generated levels.

   LEVEL WIRING (the only change outside the tileset package this order):
     * Level gains an immutable `LevelPalette palette` field. A NEW package-private constructor takes an
       explicit palette; the EXISTING 3-arg constructor delegates to it with LevelPalettes.legacy(), so
       every LevelLoader / LevelGenerator / *Generator call site compiles unchanged and renders identically.
     * public LevelPalette getPalette() — never null; the getter order-7's renderers will call.
     * Level's static category predicates (isWall/isColumn/isPropSolid/...) are UNCHANGED and remain the
       category authority until order-7; order-3 only ADDS the palette, it routes no read through it.

   TESTS (headless): LevelPaletteTest (tileset pkg) — legacy().spriteIdOf across every category
   ('Z'->wall_cryo, 'x'->wall_plain, 'P'->column_round, '@'->prop_vendor, '.'->decal_blood, ...); each
   symbol maps to its correct TileCategory; the legacy palette covers the whole registry 1:1 (every
   registered sprite id is some symbol's binding, and every bound id is registered); non-environment
   symbols (doors/pickups/ammo/hazards/enemy-spawns/start/exit) resolve to null; legacy() is a memoised
   singleton. LevelPaletteWiringTest (level pkg, for the package-private constructor) — a Level built with
   no palette defaults to legacy; an explicit palette is carried through unchanged.
