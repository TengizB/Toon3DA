TILE SYMBOL REFERENCE
=====================
Single source of truth for every character used in level .txt files.

FIXED vs FLEXIBLE (the shipped model — see docs/environment-tileset-system.txt for the full system).
A level-file symbol is a SLOT in a fixed CATEGORY; its category/meaning never changes. Symbols come
in two tiers:
  * FIXED — permanent meaning AND sprite; never reassigned. Player start 'p', exit '>', floor
    lighting, keycards, pickups, ammo, hazards, enemy spawns, and the shop '@'.
    A FIXED symbol's row below is a permanent binding.
  * WALL SLOTS, DOORS AND THE COLUMN (generated-wall-art order 2) — a wall symbol names a SLOT (a wall
    GROUP + SLOT); the floor's REGION WALL SET names the picture. Doors d R Y B and the column 'P' keep
    their fixed meaning; their pictures also come from the region set. See the WALLS table below,
    docs/wall-art-creation-guide.txt (6.4, 7) and docs/environment-tileset-system.txt section 15.
  * FLEXIBLE — fixed CATEGORY, sprite chosen PER LEVEL from that category's registered pool by the
    deterministic allocator. The decoration props/decals are flexible. For a flexible symbol, the "sprite" column below is the LEGACY DEFAULT (what hand-crafted
    levels and the legacy palette render) — NOT a permanent binding; a generated level may render a
    different sprite of the same category.

ADDING ART NO LONGER CONSUMES A SYMBOL. New prop/decal art is RECIPE A (register one
EnvironmentSpriteDefinition + one texture generator); new WALL art is a face of a region wall set
(docs/wall-art-creation-guide.txt RECIPES); a new room is RECIPE B (register one
RoomBlueprint). Neither needs a new symbol and neither edits the generator/renderers/Level. See the
RECIPES in docs/environment-tileset-system.txt §9. New level-file SYMBOLS are now rare — needed only
for a genuinely new FIXED gameplay meaning.

STRICT RULE — adding a NEW level-file SYMBOL (rare; FIXED meanings only):
Introducing a new symbol still requires updating THIS file in the SAME commit, plus wiring its
category into Level.java (isWall/isPropSolid/… — now backed by tileset/SymbolBudget + SymbolCategories)
and any FIXED handling it needs. No symbol may be used in a level file or recognised by game code
unless it appears here first. But before adding a symbol, check whether you actually want RECIPE A
(new art) or RECIPE B (new room) instead — the common cases need NO new symbol.

Authority class: Level.java — isWall(), isColumn(), isPropSolid(), isPropDecal(), and the
pickup/door/special checks are the single runtime CATEGORY source of truth (a symbol's category is
symbol-intrinsic; only its sprite is per-level, via LevelPalette). When this file and the code
disagree, fix the code to match this file.

WALLS (solid — block movement and raycasting)
---------------------------------------------
A wall symbol names a SLOT of the floor's REGION WALL SET (generated-wall-art order 2; the table is
TilesetConstants.WALL_SLOT_TABLE). Every one is a WALL to Level.isWall; the picture comes from the floor's
region set (set A, outer_facility, on every floor until regions B-E ship their own). BASE slots carry
variants, picked by the renderer per tile face. Generated levels write only 'x' for walls; the LevelFinisher
dresses them by the placement rules (docs/wall-art-creation-guide.txt section 7). In a HAND-MADE level the
symbols are drawn as written, read through this table with set A.
sym  group        slot        what it is (in every region's style)
x    HALL         BASE        The dominant hall / generic-room wall (3 variants). Use for most walls.
k    HALL         STRUCTURE   Pilaster / rib / frame: the hall rhythm and the door frames.
S    HALL         LIGHT       The region's light source (emissive; set A's tube may flicker).
c    HALL         SERVICE     Pipes, risers, valves — the building working.
'    HALL         VENT        Grilles, hatches, extraction mouths.
h    HALL         MARKER      Signage, stencils, quota boards (focal; 1-3 per floor).
G    HALL         BREACH      The NEXT region leaking through (grows with depth in a region).
M    MEDICAL      BASE        Medical room wall (2 variants).
Q    MEDICAL      ACCENT      Medical room's telling fixture (set A: dispenser + scrub hatch).
X    SECURITY     BASE        Security room wall (armory, command centre, gate airlock).
w    SECURITY     ACCENT      Security fixture (set A: mesh-fronted rifle niche).
Z    CONTAINMENT  BASE        Containment wall (cryo chamber, containment block).
N    CONTAINMENT  ACCENT      Containment fixture (set A: dogged frosted porthole).
U    MACHINERY    BASE        Machinery wall (power plant, atmospheric plant, reactor).
j    MACHINERY    ACCENT      Machinery fixture (set A: breaker panel).
t    RESEARCH     BASE        Research wall (server room, research lab).
D    RESEARCH     ACCENT      Research fixture (set A: wall terminal).
v    STORAGE      BASE        Storage wall (salvage bay, supply cache, storage bay).
"    STORAGE      ACCENT      Storage fixture (set A: shutter half up).
F    SIGNATURE    BASE        The region's special-room wall (observatory, gore nest, boss arena, event room).
`    SIGNATURE    ACCENT      The special room's fixture.
A slot a set lacks falls back (ACCENT / BREACH -> BASE of the group, others -> HALL BASE).

DOORS (solid until opened; runtime state managed by DoorManager)
----------------------------------------------------------------
Pictures: the floor's region set (door_<letter>_plain / red / yellow / blue); the keycard colour shows only
on the lock panel and the frame stripe, emissive, in the exact keycard colours.
d   Plain door          Unlocked. Opens on player interaction.
R   Red keycard door    Locked. Requires red keycard (pickup 'r').
Y   Yellow keycard door Locked. Requires yellow keycard (pickup 'y').
B   Blue keycard door   Locked. Requires blue keycard (pickup 'b').

SPECIAL TILES
-------------
p   Player start        Exactly one per level. Never on a map edge.
P   Cylindrical column  Solid. Rendered as 3D cylinder (ray-circle intersection). Picture: one of the region set's
                        two columns (round / square), picked per floor. GENERATED placement (level-generation-
                        overhaul R25/R28/G3): a room's architecture pillar slots (BARE kit 2-4, LINEAR's
                        four-pillars / avenue / altar), spaced columns on 3-wide hall spines, cave FORMATIONS
                        (clusters of 1-3 in open ground), the start room's four framing columns — never in a door
                        clearance zone, never plugging a passage.
>   Portal / exit       Level exit. Full-height walk-in gate on a steel platform, its doorway a cyan field receding to a
                        bright core, GENERATED + ANIMATED
                        (generated-prop-art order 1). Exactly one per generated level.

SYMBOL BUDGET
-------------
Total printable ASCII characters: 95  (codes 32-126)
Assigned to a FIXED or FLEXIBLE symbol:  91
Unassigned characters:                    4

The symbol/sprite-reuse system (docs/environment-tileset-system.txt) REMOVED the scarcity this budget
used to track. Symbol count no longer limits how much environment art or how many rooms the game can
have: art is added by RECIPE A (register a sprite in a category pool) and rooms by RECIPE B (register a
blueprint), NEITHER of which consumes a symbol. The 91 assigned symbols split into:
  * FIXED symbols — permanent meaning AND sprite (start/exit/floor-lighting/keycards/pickups/ammo/
    hazards/enemy-spawns, plus the shop '@'). Authoritative list: the FIXED partition in SymbolBudget
    (docs/environment-tileset-system.txt §2).
  * WALL SLOTS (21), the four DOORS and the column 'P' — fixed meaning, picture from the floor's region
    wall set (generated-wall-art order 2; docs/environment-tileset-system.txt section 15).
  * FLEXIBLE symbols — a fixed CATEGORY, sprite per level: the decoration props/decals.

Unassigned characters (available if a genuinely new FIXED gameplay meaning is ever needed):
) / , _
  ) / , _ — and 'o' — were historically pencilled in for the EXCAVATION_SITE room design,
  .claude/agents/ideas/excavation-monolith-chamber-room.txt — NOT IMPLEMENTED. '}' from that block is
  now the Verdant Spiresower enemy-spawn marker and ':' its runtime crystal-spire prop; 'o' is now the
  Sump Wretch enemy-spawn marker (sump-wretch-acid-death), so EXCAVATION_SITE may not use it. " ' ; ? < \ ] - | `
  are ASSIGNED: " ' ` are wall slots (STORAGE ACCENT, HALL VENT, SIGNATURE ACCENT); ; ? < \ ] - | are the
  STELLAR_OBSERVATORY room's FLEXIBLE props/decals, kept in that room by the "observatory" theme tag.)
  ('~' and '*' are Ghoul / Blight Corruptor enemy-spawn markers; '(', '{' and '[' are the Auric
  Sentinel, Cinderforge Colossus and Rimeshell Lancer markers, taken from that same pencilled-in
  excavation block — the golem faction claims the bracket block, so if EXCAVATION_SITE is ever built it
  uses the remaining brackets and '_' instead.)
Uppercase taken: K V (enemy spawns), D F (wall slots), I J W, Z (wall slot) — check WALLS / DOORS above.
Lowercase taken: 'z' (Crawler spawn), 'o' (Sump Wretch spawn), e i j n q ('i' fire hazard, 'q' toxic hazard).

PREFERRED SYMBOLS FOR A NEW FIXED SYMBOL (rare)
------------------------------------------------
- Uppercase letters for new solid/blocking gameplay things; lowercase for walkable/decal ones.
- Punctuation only when clearly readable in a plain-text editor.
- Avoid: \ | < > (confusing in text editors); " ' (quoting conflicts). (The STELLAR_OBSERVATORY room
  used \ | < " ' deliberately — it is procedurally generated, rarely hand-edited.)

ADDING ENVIRONMENT ART OR A ROOM — USE A RECIPE (no new symbol)
---------------------------------------------------------------
For the COMMON cases, do NOT add a symbol:
- New wall / column / prop / decal ART → RECIPE A (docs/environment-tileset-system.txt §9): register one
  EnvironmentSpriteDefinition + one texture generator. It appears on generated levels automatically.
- New ROOM → RECIPE B: register one RoomBlueprint. It competes in generation automatically.

ADDING A NEW FIXED SYMBOL — CHECKLIST (only for a genuinely new gameplay meaning)
--------------------------------------------------------------------------------
1. Pick an unassigned character from the list above.
2. Add it to this file (correct section, with description and notes).
3. Wire its CATEGORY into Level.java's predicates. Flexible categories are data-driven via
   tileset/TilesetConstants + SymbolBudget + SymbolCategories; a FIXED gameplay symbol adds its own
   dedicated check.
4. Add its FIXED sprite/texture handling (WallRenderer/PropRenderer) and any Constants entries — a FIXED
   symbol keeps a permanent sprite. (A new FLEXIBLE symbol instead just names a category whose pool the
   allocator fills; adding the ART for that pool is RECIPE A, not this checklist.)
5. Update the SYMBOL BUDGET counts above.
6. Commit all of the above together — never add a symbol in code without updating this file in the same
   commit.
